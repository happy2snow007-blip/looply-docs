**v0.4 → v0.5 变更**：对齐后台原型 **v0.14 → v0.15**——**移除「终端」字段，Collection 不再区分终端**：①新建/编辑向导由 4 步回到 **3 步**，原独立「适用范围」步并入「基本信息」步（放在基本信息字段下方），适用范围只剩**市场 + 渠道**（无终端选择）；②**每个 Collection 默认同时服务 PC + 移动端**——基本信息（标题/副标题/Banner）与图文筛/快筛**恒按 PC + 移动端两端分别配置**（不再是"按终端多选后才分端"，而是始终两端必配）；商品来源/市场/渠道/URL/Meta/排序/通用筛选器不分端；③**列表页去掉「终端」列与终端筛选**；④数据模型移除 `device` 字段；⑤选品规则渠道锁定提示改为「回到『基本信息』步」。其余逻辑沿用 v0.4。
**v0.3 → v0.4 变更**：对齐后台原型 **v0.12 → v0.14** 的全部净变更——①**终端（PC / 移动端）多选 + 分端配置**：新建/编辑向导由 3 步增至 4 步，新增独立「适用范围」步（终端 + 市场 + 渠道）；终端多选时标题/副标题/Banner/图文筛/快筛需按终端分别配置，保存时校验各端均完成；列表页新增「终端」列与筛选；删除「入口图」字段，Banner 改分端横图；渠道在「适用范围」选定后，选品规则中的渠道条件锁定。②**枚举值排序模型重写（核心）**：由原「仅可拖拽调序」升级为**数据源驱动的排序策略 + Pin 固定位**——4 种策略（数据源默认序 / 数值升序 / 字母序 A→Z / 按商品数降序），可选范围按数据源类型给定（属性源开放全部、品牌/系列/标签为文本型、成色默认跟随源），所有源默认「数据源默认序」；运营可在「Pin」列输入序号把某值固定到绝对位置，其余按策略自动填充。③**「数据源默认序」口径明确**：按数据源排序值（`sort_order`，非负整数 0–9999、越小越靠前）升序；无排序值或排序值并列时，按**选项创建时间升序**兜底（最早在前），保证稳定可预测。④**术语统一**：展示类型「文字卡片→双列卡片」「折叠面板→单列文本」；排序固定位统一用「Pin」（原「锚定」）。⑤**backend_category 展示样式收紧为仅「分组」**（全量纳入三级结构）。⑥**图文筛规则构建器统一**：复用通用条件构建器（与选品规则同字段体系），自动选品时默认带入 Step 商品来源的选品规则可再收窄。⑦**展示样式术语「树形→分组」**：原「树形(tree)」对应的前台呈现为分组(标题+值)，统一改称「分组」；属性源去掉「滑块」、去掉无意义样式，开启「按作用域分组」时展示样式固定为「分组」；按作用域分组的组标题由后端用中点直接拼接「类目名·品牌名·系列名」下发，与类目「分组」样式的数据结构一致。⑧前台 C 端逻辑不变。
**v0.2 → v0.3 变更**：按 PRD 写作规范自检整改——①后端核心逻辑（§4.5）、候选值范围（§3.2.2）、自动选品规则结构（§2.1 rule_config）由伪代码/JSON 改为文字描述业务逻辑；②统一术语「Collection 落地页」（不再混用「类目页/类目浏览页」），正文中残留的「类目页」均为前台原型文件名（如 `looply-类目页-Mobile-v0.2.html`），属真实文件引用保留不改；③§5 依赖与风险表去除「接口」字样，改为「服务能力/返回数据」等业务依赖表述，异常表「接口报错」改为「请求失败 / 服务无响应」（PRD 不含接口契约）；④页面流转图、页面布局示意图保留为可视化辅助（非逻辑伪代码）。

## 版本要点（v0.1 → v0.2）

本次合并不是简单拼接，筛选体系经历了整体重构，关键变更如下：

1. **前后台合一**：原两份文档（后台 PRD v0.1 + 前台落地页 PRD v1.6）合并为单一文档，统一术语与字段口径。
2. **筛选体系重构（核心）**：由原「左侧筛选面板 + Quick Filters」两件套，升级为 **图文筛 / 快筛 / 通用筛选器** 三模块。
   - **通用筛选器**（原"抽屉筛/左侧面板"）：**零配置、按商品池动态生成**，维度/排序/样式由「筛选维度管理」全局统一，Collection 内不再逐项配置。
   - **快筛**：运营在 Collection 内**从全局维度池挑选维度 + 排序**，不再配置预设条件（原 `quick_filter_preset` 废弃）。
   - **图文筛**：全新模块，图文/纯文卡片，每项预置一组筛选条件（维度间 AND、同维度多值 OR，不支持嵌套/OR 组合）。
3. **展示类型精简为 5 种**：双列卡片 / 单列文本 / 滑块 / 颜色卡片 / 分组（原 6 种 checkbox/range/color_swatch/size_grid/radio/search_list 废弃），且**同一维度可在不同筛选模块分别配置展示样式**，前端按后端返回的 `display_type` 渲染，不按字段名硬编码。
4. **状态三态**：Collection 状态由 active/archived 两态升级为 **draft（草稿）/ active（启用）/ inactive（关闭）** 三态。
5. **价格只支持滑块**：范围最小固定 $0、最大取商品池最高价向上取整到百位（不足 $100 按 $100），由前端按各 Collection 商品池动态生成；自定义价格分档（价格带）移至 V2。
6. **多市场 / 多渠道落地**：基础信息新增 `market_id`（美国/欧洲/加拿大）与 `channel_id`，控制商品池范围；价格筛选币种**跟随所选市场支持的币种枚举**（读市场模块配置）。
7. **值归一化与 size_system 高级能力精简**：枚举值取自商品模块，运营仅可调整前台展示顺序，不可增删/合并；尺码走 attribute(size) 维度，移除跨体系换算 / ONE SIZE 策略 / 品牌尺码兼容（后续按需重启）。
8. **条件构建器扁平化**：仅保留单层 AND/OR 逻辑选择器，不支持 Magento 式嵌套分组。
9. **排序枚举对齐**：`recommended / newest / price_low_to_high / price_high_to_low`（Most Relevant 并入 recommended）。**v0.4 起移除 `manual`（Featured）排序项**：无论自动/手动选品均按选定排序规则展示，Pin 固定位不受影响（见 §4.5.4）。

> v0.1 中不与上述冲突的机制章节（Meta SEO 降级链、商品准入与状态同步、前台收藏）整体保留。

## 一、概述

### 1.1 背景与目标

Looply 是转转国际业务旗下面向海外市场的大牌二手奢侈品电商平台，切入品类为二手奢侈品（包袋、首饰、配饰）。

**当前问题**：商品系统已完成后台类目（backend_category）和属性体系建设，但后台类目是面向数据管理的内部分类，无法直接作为消费者浏览导航入口。缺乏前台商品分组与展示能力。

**本模块目标**：
- 搭建前台商品分组系统（Collection），让运营灵活创建、管理商品展示分组（即「主题货架」落地页）。
- 支持两种选品模式（自动规则选品 / 手动精选），覆盖绝大多数运营场景。
- 提供全局筛选维度管理，让每个 Collection 页面具备合理筛选能力（图文筛 / 快筛 / 通用筛选器三模块）。
- 为消费者提供流畅的前台浏览体验，「零空结果」——筛选候选值完全由服务端计算下发，前端只渲染有值的项。

**设计原则**：
- 前后台完全解耦：Collection 是展示分组，不干预商品自身上下架状态。
- 扁平结构：Collection 无层级嵌套（Shopify 模式），导航层级由独立 Navigation 模块承载。
- 商品粒度为 **listing 级**：每件实物商品独立展示，不按 SPU 聚合，与商品系统一致。
- 筛选字段前后台统一：直接使用后台筛选维度英文标识（dimension key）作为通用字段名，零映射。
- 零 AI 依赖（MVP）：所有功能纯配置驱动。

### 1.2 范围与不做什么

| 范围 | 说明 |
|---|---|
| 后台管理端 | 仅 PC 端，不做移动端适配 |
| 前台落地页 | **V1 仅 Mobile**，PC 端独立规划（V2）|
| 前台集内搜索 | V1 仅保留搜索入口图标，搜索逻辑 V2 |
| Collection 内分享 | V1 不做 |
| 底部相关推荐 | V2 规划 |
| 筛选条件保存 | V2 规划 |
| 价格带筛选 | V1 价格只支持 Slider，价格带（Price Band）V2 |
| 前台导航菜单管理 | Navigation 模块独立建设，本模块不含 |
| 广告 Feed 分类映射 | 独立模块处理，不纳入 Collection |
| AI 动态推荐规则 | MVP 不依赖 AI，所有选品规则纯配置 |
| 混合选品模式（规则+手动置顶）| 后续增强，MVP 两种模式互斥 |
| 值归一化 / 跨尺码体系换算 | 精简，枚举值取自商品模块，运营不可增删/归一化（仅配排序策略 + Pin）；ONE SIZE 策略、品牌尺码兼容后续按需 |
| 条件构建器嵌套分组 | 不支持，仅单层 AND/OR |
| 收藏夹的降价/到货通知 | 依赖通知体系，MVP 不做 |

### 1.3 用户角色

| 角色 | 描述 | 主要操作 |
|---|---|---|
| 运营 | Looply 内部运营，负责商品分组与日常选品 | 创建/编辑 Collection、配置选品规则、配置图文筛/快筛、管理筛选维度 |
| 超级管理员 | 系统管理员 | 管理全局筛选维度池、维度展示样式与排序、配置系统级 Collection（All Products）|
| 消费者（C 端 Mobile 用户）| 访问 Looply 的海外用户 | 浏览 Collection 页、筛选/排序商品、收藏商品 |
| 匿名用户 | 未登录访客 | 浏览 Collection 页、筛选商品、收藏商品（存本地）|

### 1.4 核心场景

**后台管理端：**
1. 运营创建季节性 Collection（如 Holiday Gifts），设置自动选品规则、选定市场/渠道，配置图文筛与快筛。
2. 运营创建编辑精选 Collection，手动挑选商品，调整商品排列顺序（Position / Pin）。
3. 运营临时关闭某 Collection（活动结束），保留配置，下次活动一键恢复。
4. 超级管理员创建全局筛选维度（如 Color 维度关联 color + bag_color 属性），并按筛选模块配置展示样式，供各 Collection 引用。

**前台 C 端（Mobile）：**
1. 消费者进入某 Collection 落地页，浏览 Banner 与商品，点击图文筛切换子主题。
2. 点击快筛 Chip 展开二级面板筛选，或打开通用筛选器（抽屉）多维度组合 Apply。
3. 在快筛二级面板（Clear）或通用筛选器（Reset）内调整 / 重置筛选条件，或切换排序。
4. 收藏感兴趣商品（未登录也可收藏，存 localStorage）。

### 1.5 全局页面流转

```
【后台管理端】（PC）
Collection 列表页
  ├─→ 新建 Collection（Step 1 基本信息（含适用范围）→ Step 2 商品来源 → Step 3 筛选配置）
  └─→ Collection 详情页（同 3 步向导，编辑）
        └─→ [手动选品] 侧滑抽屉：选品器

筛选维度管理页
  └─→ 维度编辑页（数据源 + 各模块展示样式 + 枚举值排序策略/Pin）

【前台 C 端】（Mobile）
首页 home_collections / Shop 页 shop_collections ──→ Collection 落地页
Collection 落地页 ──→ 商品详情页（点击商品卡）
Collection 落地页（筛选/排序状态，同页内更新）
```

### 1.6 术语说明

| 术语 | 说明 |
|---|---|
| Collection | 前台商品分组，Shopify 式扁平结构，无层级嵌套；对应 URL `/collections/{slug}`，本模块核心管理对象 |
| backend_category | 后台类目，商品系统已有，用于属性作用域与数据管理，不直接面向消费者；可作为筛选维度数据源之一 |
| listing | 一件实物商品的渠道挂牌记录，Collection 中商品的最小粒度 |
| filter_dimension | 筛选维度，封装属性/品牌/价格/类目等数据源，作为前台筛选器的配置层 |
| 图文筛 | 运营配置的图文/纯文标签列表，用户点击切换子主题商品池；每项预置一组筛选条件 |
| 移动端快筛 | **仅移动端**的横排滚动 Chip 栏（吸顶），点击展开二级筛选面板；维度由运营在 Collection 内从全局池挑选并排序。PC 端形态无此交互，故快筛为移动端专属、不分端 |
| 通用筛选器 | 全量属性筛选面板（前台抽屉式）。**零配置**——按当前 Collection 商品集合从全局维度池动态匹配，维度/排序/样式全局统一 |
| display_type | 维度展示样式：双列卡片 / 单列文本 / 滑块 / 颜色卡片 / 分组（内部 key `tree`）；由筛选维度管理全局配置，前端按后端返回值渲染 |
| 分端配置 | Collection **不区分终端**（无终端字段）。基本信息（标题/副标题/Banner）**恒按 PC + 移动端两端分别配置**（两端规格不同）；**图文筛、快筛均为移动端专属**——PC 端无图文筛栏 / 快筛栏形态，二者不分端、仅移动端展示、无适用终端字段（见 §2.6.1 / §2.6.2）|
| 固定位置（Pin / Position）| 将商品或枚举值/类目固定到指定绝对位置（绑 key 不绑下标）；其余项按排序策略/源序自动填充剩余位。商品下架后其固定位置记录清除。**v0.16 起后台 UI 文案统一用「固定位置」**（原「Pin」），内部字段 key 不变 |
| 排序策略 | 枚举值在前台的排序方式：数据源默认序 / 数值升序 / 字母序 A→Z / 按商品数降序；可选范围按数据源类型给定，详见 §2.5。**品牌（brand）例外：固定「字母序 A→Z」、不可改、不提供固定位置** |
| Collection 全集 | 该 Collection 下所有 `listing_status = active` 的商品，不附加任何用户筛选条件，是候选值计算的锚点 |
| rule_config | 自动选品规则的 JSON 配置（单层 AND/OR） |
| WYSIWYG | 后台商品列表顺序与前端展示顺序完全一致 |
| source_type | Collection 商品来源类型：rule（自动选品）/ manual（手动选品）|
| All Products | 系统级内置 Collection，覆盖所有 active listing，不可删除、不可关闭 |

### 1.7 多语言 / 多市场 / 多渠道 / 分端策略

| 项目 | 说明 |
|---|---|
| 前台语言 | MVP 英语为主，结构预留多语言；广义多语言由平台**翻译模块**统一管理，前台按当前语言取、缺失 fallback 默认语言原值 |
| 后台语言 | 简体中文界面；Collection 标题等面向前台的字段以英文录入 |
| 筛选名称多语言取数 | 筛选维度的**分组标题、节点展示名**（一级类目名、品牌名、系列名、枚举值展示名等）按当前语言取数，**优先级：运营在维度配置的「前台展示名」（注册翻译 key）> 翻译模块多语言名 > fallback 默认语言原值**。数据来源差异：品牌/系列在商品系统有英文专名列（`brand_name_en`/`series_name_en`）；**一级类目仅单列、无英文列**，其英文需运营配展示名或翻译模块补齐，否则 fallback 出原值。后端按当前语言解析每段后拼好整串下发，前端不拼接、不翻译（见 §2.5 组标题取数）|
| 分端（PC / 移动端）| Collection **不区分终端、无终端字段**；每个 Collection 默认同时服务 PC + 移动端。**基本信息（标题、副标题、Banner）恒按 PC + 移动端两端分别配置**（两端规格不同）；**图文筛、快筛均为移动端专属**——PC 端无图文筛栏 / 快筛栏形态，二者仅移动端展示、不分端、无适用终端字段（见 §2.6.1 / §2.6.2）。商品来源、市场、渠道、URL、Meta、排序、通用筛选器等不分端 |
| 市场（market_id）| 多市场落地：美国市场 / 欧洲市场 / 加拿大市场。控制商品池范围，单选；新建 Collection 时必选 |
| 渠道（channel_id）| 读商品中心渠道管理（如美国官网商城 / 德国旗舰店 / 英国官网商城），控制商品池范围，单选；选定后**选品规则中的「渠道」条件锁定为此渠道**（见 §2.1） |
| 货币 | **跟随市场**：每个市场在「市场模块」中定义其支持的结算币种枚举；价格筛选币种从所选市场支持币种中取（单币种自然锁定、多币种限定可选、默认取首项），不在筛选处自由输入 |
| 时区 | 后台显示 UTC+8；前台按市场时区展示；「最近 N 天」等时间条件以 UTC 计算 |
| 合规 | 收藏功能使用 localStorage，无服务端数据采集，MVP 暂不涉及 GDPR 专项 |

## 二、后台管理端

> 后台仅 PC 端。UI 关联：后台原型 v0.16（`looply-类目管理-后台-v0.16-antd.html`）。

### 2.1 公共组件：条件构建器

**功能描述**

条件构建器是规则编辑器，用于：
1. 自动选品模式：定义 Collection 的商品准入条件（保存为 rule_config）。
2. 手动选品模式：在选品器抽屉中筛选候选商品（不保存为规则）。
3. 图文筛项规则：图文筛每项预置一组筛选条件（§2.6.1），与上述同一字段体系（v0.14 起统一，不再单独维护图文筛专用构建器）。

**逻辑结构（扁平，不嵌套）**

- 顶部一个逻辑选择器：「满足以下 **所有（AND）** / **任一（OR）** 条件的商品将被自动收录」。
- 其下为若干条件行，无子分组、无嵌套。
- 同一条件行内多个值为 OR；条件行之间按顶部逻辑选择器（AND/OR）组合。
- 界面底部固定说明：「同一条件内多个值为 OR · 条件之间按逻辑选择器组合 · 不支持嵌套分组」。

> 与 v0.1 的区别：移除 Magento 式多层嵌套分组，仅保留单层逻辑，降低运营与查询复杂度。

**条件字段枚举**

| 字段 | 来源 | 可用操作符 | 值输入控件 | 备注 |
|---|---|---|---|---|
| backend_category | backend_category 表 | 属于 / 不属于 | 树形多选（TreeSelect） | 选择后台类目节点，可多选 |
| brand | brand 表 | 等于其中之一 / 不等于其中任一 | 搜索多选 | |
| series | brand_series 表 | 等于其中之一 / 不等于其中任一 | 文本/多选 | |
| price | listing.price | 区间（最小值—最大值）| 币种 + 双值数字输入 | 币种跟随市场支持币种；金额禁负数 |
| condition | 商品成色（grade）| 等于其中之一 / 不等于其中任一 | 枚举多选 | **枚举级数待商品系统确认**（设计稿 5 级 Like New/Excellent/Very Good/Good/Fair；PRD 历史曾对齐为 A/B/C）；前台展示文案与级数以商品系统真实枚举为准，PRD 不写死 |
| channel | 渠道 | 等于其中之一 / 不等于其中任一 | 枚举多选 | 控制渠道范围。**该 Collection 已在「基本信息」步「适用范围」选定渠道时，本条件锁定为该渠道**（渲染为禁用下拉 + 锁图标，Tooltip「渠道已锁定为『基本信息』步『适用范围』配置的渠道，如需更改请回到『基本信息』步」）；未选渠道时禁用并提示「请先在『基本信息』步『适用范围』选择渠道」 |
| listing_date | listing.listed_at | 最近 N 天 / 介于 | 数字+「天」/ 日期选择 | 「最近 N 天」为动态滚动窗口，每日凌晨重评估 |
| stock_status | listing.stock_status | 等于其中之一 / 不等于其中任一 | 枚举多选 | 枚举：在库 / 在途 / 在售 / 已售 |
| tag | 商品标签系统（预留）| 包含其中之一 / 不包含其中任一 | 标签多选 | 多值字段 |
| title | listing.title / spu.name | 包含 / 不包含 | 文本输入 | 关键词模糊匹配 |
| custom_attribute | attribute_def.* | 动态（取决于属性控件类型）| 二级选择：先选属性，再选操作符和值 | 见下方 |

**操作符体系**

| 操作符组 | 操作符 | 适用字段类型 |
|---|---|---|
| 单值枚举组 | 等于其中之一 / 不等于其中任一 | brand、series、condition、stock_status、channel、single_select 属性 |
| 类目组 | 属于 / 不属于 | backend_category |
| 多值字段组 | 包含其中之一 / 不包含其中任一 | tag、multi_select 属性 |
| 数值组 | 区间（介于）| price、number_input 属性 |
| 文本组 | 包含 / 不包含 | title、text_input 属性 |
| 时间组 | 最近 N 天 / 介于 | listing_date |

**自定义属性（custom_attribute）二级交互**

- 第一级：从已关联后台类目的属性池中选择属性（如 bag_size、color、material、hardware）。
- 第二级：按属性输入控件类型（input_type）切换可用操作符和值控件：
  - single_select → 等于其中之一 / 不等于其中任一 + 枚举多选
  - multi_select → 包含其中之一 / 不包含其中任一 + 枚举多选
  - number_input → 区间 + 数字输入
  - text_input → 包含 / 不包含 + 文本输入

**rule_config 规则结构说明（扁平）**

自动选品规则以「逻辑关系 + 条件列表」两部分存储：

- **逻辑关系**：整组条件之间的连接方式，取 AND（同时满足）或 OR（满足其一），仅单层，不支持嵌套分组。
- **条件列表**：每个条件由「字段 + 操作符 + 值」三要素构成。字段可为后台类目、品牌、自定义属性、价格等；自定义属性需额外记录所属属性标识；价格条件需额外记录币种。

举例：当逻辑关系为 AND 时，一组条件可表达为「后台类目属于 bags 或 shoulder，且 品牌属于指定品牌，且 颜色属性包含 Red 或 Black，且 价格介于 $500–$5000（USD）」——即同时满足全部四个条件的商品纳入该 Collection。

**校验规则**

| 规则 | 说明 |
|---|---|
| 每个条件行必须填写操作符和值 | 缺项时禁止保存或提示「请补全所有条件」 |
| custom_attribute 必须先选属性 | 未选属性时操作符和值控件不出现 |
| price 区间：最小值 < 最大值，且均 ≥ 0 | 不满足时提示「价格区间无效」；金额输入禁负数 |
| listing_date 最近 N 天：正整数 | 否则提示「请输入正整数天数」 |
| 自动选品可无条件 | 无任何条件时允许保存，系统视为「全量 active listing」 |

### 2.3 新建 Collection（向导流程）

3 步向导：Step 1 基本信息（含适用范围）→ Step 2 商品来源 → Step 3 筛选配置。

**Step 1：基本信息**

> Collection **不区分终端**；标题、副标题、**标题/副标题文字色值**、Banner **恒按 PC + 移动端两端分别配置**（PC / 移动端左右并排各一份，各带终端图标列头）。文字色值用于适配各端 Banner 背景对比度。

| 分组 | 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| 基本信息 | Collection 标题 | 文本（分端）| ✅ | 前台页面标题；实时生成 URL Slug（Slug 不分端）。移动端 placeholder「移动端标题」，PC「e.g. Shoulder Bags」|
| 基本信息 | 状态 | 下拉 | — | 草稿 / 启用 / 关闭，默认草稿 |
| 基本信息 | 页面副标题 | 文本（分端）| 选填 | 前台 Banner 副标题。**PC 最大 60 字符；移动端最大 30 字符**（移动端规格更紧凑）|
| 基本信息 | 标题色值 | 颜色（分端）| ✅ | 前台**标题**文字颜色；色盘（光谱 + 预设）取色或输入 hex（如 `#FFFFFF`）。两端各配一份以适配 Banner 背景。非翻译文本 |
| 基本信息 | 副标题色值 | 颜色（分端）| ✅ | 前台**副标题**文字颜色；色盘取色或输入 hex。两端各配一份。非翻译文本 |
| 基本信息 | Banner 图 | 图片（分端）| 选填 | 页面顶部 Banner，**横图，PC 与移动端比例不同需分别上传**：移动端 2:1（建议 1080×540），PC 16:9（建议 1600×900）|
| 适用范围 | 市场 | 下拉 | ✅ | 控制商品池范围；单选（美国/欧洲/加拿大市场）|
| 适用范围 | 渠道 | 下拉 | ✅ | 读商品中心渠道管理；单选。**选品规则中的「渠道」条件将锁定为此渠道**（见 §2.1）|
| URL 与 SEO | URL Slug | 文本 | ✅ | 自动生成可改；全局唯一；仅 `a-z0-9-`；系统前缀 `/collections/`（不分端）|
| URL 与 SEO | 完整 URL | 只读 | — | `https://looply.com/collections/{slug}` |
| URL 与 SEO | Meta Title | 文本 | 选填 | 留空按降级链自动生成（见 §4.1）|
| URL 与 SEO | Meta Description | 多行 | 选填 | 建议 120-160 字符，留空自动生成 |

> 页面内分三块:**基本信息** → **适用范围**（市场 + 渠道,放在基本信息下方）→ **URL 与 SEO**。适用范围只含市场、渠道,**无终端字段**。
> 与 v0.3/v0.4 的区别：**删除「入口图」字段**（首页卡片/导航入口缩略由 Navigation 模块承载）；**v0.5 起取消独立「适用范围」步**，市场/渠道并入「基本信息」步下方；标题/副标题/Banner 恒分端配置。

「下一步」解锁条件：两端标题、**两端标题色值 / 副标题色值**、URL Slug、市场、渠道均已填写/选定。

**Step 2：商品来源**（互斥单选）

**模式 A 自动选品**：提示「通过后台类目、品牌、价格等条件组合自动匹配商品，新上架符合条件的商品自动纳入，售出/下架自动移出。」
- 条件构建器（§2.1），渠道条件锁定为 Step 1「适用范围」所选渠道。
- 排序配置（SortConfig）：勾选启用的排序项 + 指定一个默认排序。新建时**默认开启全部排序项、默认排序为「推荐排序」**。前台按选定排序规则展示，Pin 固定位不受影响（见 §4.5.4）。
- 商品列表区：保存后按规则展示匹配商品（WYSIWYG）；商品按选定排序规则插入，Pin 列可固定位置。

**模式 B 手动选品**：提示「手动添加商品，只有明确添加的商品才会出现在前台。适合编辑精选、活动专题。」
- 排序配置（同上）：手动圈定的商品在前台**仍按选定排序规则展示**，Pin 固定位不变。
- 「+ 添加商品」打开侧滑抽屉选品器（见 §2.4）。
- 已选商品列表（空态引导「点击添加商品开始选品」）。

Step 2 完成条件：手动选品需至少 1 件商品；自动选品无强制（无条件 = 全量）。

**Step 3：筛选配置**：见 §2.6。新建未保存时显示锁定态「请先保存 Collection 并配置商品来源」。**移动端图文筛、移动端快筛均仅作用于移动端、不分端**（见 §2.6.1 / §2.6.2）。

**校验规则**

| 字段 | 规则 | 触发 |
|---|---|---|
| Collection 标题 | 非空（PC + 移动端两端均需非空）| 失焦 + 提交 |
| 标题色值 / 副标题色值 | 非空（PC + 移动端两端均需配置）；合法 hex（`#RRGGBB`）| 失焦 + 提交 |
| URL Slug | 非空；仅 `a-z0-9-`；全局唯一；不能用保留词（all、new、search、shop）| 失焦 + 提交 |
| URL Slug 唯一性 | 冲突提示「该 Slug 已被使用，建议：{name}-2」 | 失焦 + 提交 |
| 市场 / 渠道 | 启用上线前必选 | 提交 |
| 筛选模块配置 | 启用的移动端图文筛/移动端快筛模块各需 ≥1 条选项（两模块均仅移动端、无适用终端，仅校验是否有选项），否则拦截保存（见 §2.4 保存校验）| 保存 |

**异常处理**：Slug 冲突行内错误；保存失败 Toast 且不清空输入；图片上传失败行内提示重试。

### 2.4 Collection 详情页（编辑向导）

与新建向导结构相同的 3 步向导（基本信息（含适用范围）→ 商品来源 → 筛选配置），编辑已有 Collection。

**All Products 特殊规则**

| 字段 | 可编辑 |
|---|---|
| Collection 标题 | ❌ 锁定（"All Products"）|

### 2.5 筛选维度管理

**功能描述**：维护全局筛选维度池。运营/管理员在此注册维度并配置展示样式与枚举值顺序；各 Collection 的快筛从池中挑选引用，通用筛选器按商品池自动匹配整池维度。

**说明文案**：筛选维度是数据源的封装层，支持 7 种数据源类型：属性(attribute)、品牌(brand)、系列(series)、价格(price)、成色(condition)、后台类目(backend_category)、标签(tag)。展示类型有 5 种，决定该维度在图文筛/快筛/通用筛选中的呈现样式：**双列卡片**、**单列文本**、**滑块**（价格）、**颜色卡片**（仅色系属性 color_family）、**分组**（类目 / 按作用域分组的属性）。

**维度列表字段**

| 列名 | 说明 |
|---|---|
| 维度名称 | 维度英文名（dimension key 对应展示名）|
| 数据源 | attribute / brand / series / price / condition / backend_category / tag |
| 关联属性 | attribute 类型展示所关联属性（可多个，如 color + bag_color）；其余「—」|
| 选项数 | 当前枚举值数量（price 为「—」）|
| 状态 | 启用 / 停用（开关）|
| 操作 | 「编辑」|

> 支持拖拽排序：维度顺序即通用筛选器的**全局统一展示顺序**（所有 Collection 一致）。

**新建/编辑维度（维度编辑页）**

| 字段 | 必填 | 说明 |
|---|---|---|
| 维度名称（EN）| ✅ | 如 Brand、Color、Cloth Sizes (US)；**全局唯一（按 en 源文判重，见 §4.6）**。文本存翻译服务、业务表存 key |
| 数据源 | ✅ | 7 选 1，选择后触发级联 |
| 关联属性 | attribute 必填 | attribute 类型时，选择关联属性（单个/多个）|
| 关联类目 | — | backend_category 时展示：固定三级、全量纳入、无需勾选；可为各级节点配置**前台展示名**（留空用后台名；展示名以**多语言 key 注册到翻译模块**、按当前语言取数，见下方专项约定与 §1.7），并按「Pin 区 + 跟随区」调整顺序 |
| 按作用域分组 | — | attribute 时展示的开关：开启后枚举值按命中的类目/品牌/系列作用域分组展示。详见下方专项约定 |
| 展示类型（分模块）| ✅ | 见下方「分模块展示样式」|
| 价格范围 | 只读 | 含 slider 时展示：$0 — 商品池最高价⌈百位⌉，标「动态」，不可手动设置 |
| 枚举值排序 | — | 非价格/非类目/非标签维度：取自商品模块的枚举值，配置**排序策略 + Pin 固定位**，不可增删。详见下方「枚举值排序专项约定」|
| 状态 | — | 启用 / 停用 |

**数据源 → 可用展示样式矩阵**

| 数据源 | 可用展示样式 |
|---|---|
| attribute | 双列卡片 / 单列文本（去掉「滑块」）；**颜色卡片**仅属性=色系 color_family 时可选；**分组**仅开启「按作用域分组」时出现（且此时固定为「分组」），关闭分组时无「分组」选项。见下方专项约定 |
| brand | 双列卡片 / 单列文本 |
| series | 双列卡片 / 单列文本 |
| condition | 双列卡片 / 单列文本 |
| price | 滑块（固定）|
| backend_category | 分组（固定）|
| tag | 双列卡片 / 单列文本 |

> **backend_category 仅支持「分组」**（v0.14 起）：后台类目固定三级结构、全量纳入，需保留层级关系供前台逐级勾选，故不再提供双列卡片/单列文本的打平样式。
> **属性源去掉「滑块」**：滑块仅价格维度使用。属性源开启「按作用域分组」开关时，展示样式**固定为「分组」、不可改**（各筛选模块均锁定）。
> **「颜色卡片」仅限色系（color_family）属性**：商品侧单独建有「色系」属性（命名即「色系」/`color_family`），并维护「色系 → 颜色值」映射表（如 红色系 ⊇ 大红/酒红/砖红）。筛选维度管理中，**只有数据源=属性且关联属性=色系（color_family）时，展示类型才出现「颜色卡片」选项**（前台展示色块）；其它属性及其它数据源不出现「颜色卡片」。

> **展示样式与候选值返回结构的关系**（解决原"collapse 多级结构返回数据待确认"）：
> - **双列卡片 / 单列文本**：均返回**打平的候选值列表**（类目维度即末级类目/叶子节点拍平）。两者数据结构相同，区别仅在前端呈现——双列卡片平铺为 Chip，单列文本用可折叠分组样式呈现同一组打平值。
> - **分组（内部 key `tree`）**：返回**「分组标题 + 值列表」的两层结构**，前端用同一套分组组件渲染。两类场景**结构完全等价**（分组标题不可勾、值可多选）：①**类目**——标题=一级类目名（仅作分组标题、不可勾），值=该范围内的三级（末级）类目名（可勾，前台匹配语义详见 §3.2.2）；②**按作用域分组的属性**——标题=后端用中点拼接的「类目名 · 品牌名 · 系列名」（不可勾），值=该作用域组内的枚举值（可勾）。
> - 各样式下每个返回节点均携带：`value`（节点 code）、`display_name`（运营在维度配置中为该节点配置的前台展示名，留空取后台名）、`count`（当前商品池内匹配数量，count=0 不返回/物理隐藏）。分组样式额外携带分组标题与层级信息。
> - 分组样式的层级/分组深度按当前 Collection 商品池实际能匹配到的内容动态决定。

**分模块展示样式（核心变化）**

同一维度可在不同筛选模块分别配置展示样式。各模块支持的样式范围：

| 筛选模块 | 支持的展示样式 |
|---|---|
| 图文筛 | 双列卡片 / 颜色卡片 |
| 快筛 | 双列卡片 / 单列文本 / 滑块 / 颜色卡片 / 分组 |
| 通用筛选 | 双列卡片 / 单列文本 / 滑块 / 颜色卡片 / 分组 |

> 某数据源在某模块下的可选样式 = 数据源允许 ∩ 模块支持。当交集只有 1 项时固定展示、不可改；当交集为空（如 price 在图文筛）时该模块不可用该维度。前端按后端返回的 `display_type` 渲染，不按字段名硬编码。

**枚举值来源与归一化（精简）**
- 枚举值**取自商品模块**，自动同步，运营**不可增删、不可合并归一化**，仅可配置前台**排序策略 + Pin 固定位**（见下方「枚举值排序专项约定」）。
- `count = 0` 的值前台实时隐藏。商品数口径 = 全站「在架 + 有库存」命中该值的商品数。
- 色系（color_family）维度的色值（hex）、色系名称由商品侧「色系 → 颜色值」映射表（商品系统维护）提供，本模块只读；前台「颜色卡片」据此展示色块。

> 与 v0.1 的区别：移除 value_mapping 拖拽归一化分组、size_system 专属配置（跨体系换算、ONE SIZE 策略、品牌尺码兼容）。尺码走 attribute(size/ring_size 等) 维度，按枚举值排序策略展示。

**枚举值排序专项约定（v0.14 重写：排序策略 + Pin 固定位）**

枚举值取自商品模块、运营不可增删；其前台展示顺序由「**排序策略**」与「**Pin 固定位**」两层决定。适用于 attribute / series / condition 数据源（**brand 固定字母序 A→Z、不可改、不提供固定位置**，见下方 brand 专项；price 走滑块无枚举、backend_category 走类目树 Pin、tag 走双栏勾选另见各自专项）。

**① 排序策略（4 种）**

| 策略 | 含义 | 新值落位 |
|---|---|---|
| 数据源默认序（默认）| 按数据源自身顺序展示：选项配有排序值（`sort_order`）时按排序值升序；无排序值或排序值并列时，按**选项创建时间升序**兜底（最早在前）| 新同步的值按数据源排序值 / 创建顺序自动落位，无需人工整理 |
| 数值升序 | 按数值大小升序展示（如 5 < 5.5 < 6 < 10，非字符串序）| 新值按数值大小自动插入正确位置 |
| 字母序 A→Z | 按字母字典序 A→Z 展示 | 新值按字母顺序自动插入正确位置 |
| 按商品数降序 | 按命中商品数从多到少展示（热门值靠前）| 新值按当前商品数自动落位，排序随商品数实时变化 |

- **排序值规范**：数据源默认序引用的 `sort_order` 复用全局「排序值规范」（非负整数 0–9999，数字越小越靠前；见全局约定）。
- **兜底口径**：所有自动策略在「值相同 / 分值并列」时，统一回退到数据源默认序（排序值 → 创建时间），保证多个新值/同分值时顺序确定、可复现。

**② 排序策略的可选范围（按数据源类型给定）**

可选策略**按数据源类型固定**，不依赖对具体值形态的猜测（属性源无法保证选项的存储类型——`number_input` 存数值、其它控件也可能写入数字，故放开由运营自选）。各源默认策略均为「数据源默认序」：

| 数据源 | 可选策略 |
|---|---|
| attribute | 数据源默认序 / 数值升序 / 字母序 A→Z / 按商品数降序（全部）|
| brand | **固定「字母序 A→Z」，不可改、不提供固定位置**（见下方 brand 专项）|
| series | 数据源默认序 / 字母序 A→Z / 按商品数降序 |
| tag | 数据源默认序 / 字母序 A→Z / 按商品数降序（tag 另走双栏勾选，排序在已选区拖拽，见 tag 专项）|

> **成色（condition）：保留枚举值 + 可 Pin，但不提供排序策略**。成色为平台固定业务序（如 Like New → Excellent → Good → Fair），取自商品模块、运营不可增删。维度编辑页**保留枚举值列表、不展示「排序策略」选择器**；新增成色值按「数据源默认序」自动插入；运营仍可在「Pin」列输入序号把个别成色固定到指定位置，其余按数据源默认序填充剩余位置，清空取消固定。

> **品牌（brand）：固定「字母序 A→Z」，不可改、不提供固定位置**。品牌枚举取自商品模块、运营不可增删。维度编辑页**不展示「排序策略」选择器、也不展示「固定位置」列**，仅以只读列表呈现当前枚举值（已按字母序 A→Z 排好）。前台一律按字母序 A→Z 展示，中文品牌按拼音 A→Z（实现见上「字母序 / 拼音序」说明）；新增品牌按字母顺序自动插入正确位置，运营无需也不可人工整理或 Pin 个别品牌。**品牌名混入数字或「字母+数字」（如 `3.1 Phillip Lim`、`A.P.C.`、`Off-White`）时，与其它字母序维度一致走下方「混合形态防呆（三段式）」**：纯字母（A→Z）在前 → 「字母+数字」居中 → 纯数字在末。（与成色的区别：成色固定业务序、仍可 Pin 个别位置；品牌完全锁定，连 Pin 也不提供，故混合形态只能按三段式自动排序、不能手工微调。）**锁死的另一原因**：前台品牌筛选面板提供 A-Z 字母索引滑动定位（见 §3.6），该交互要求品牌列表严格按首字母单调有序、同字母连续相邻；若开放 Pin 把个别品牌置顶，会把该字母区段拆散到多处、破坏索引定位语义，故 brand 不提供 Pin。

- **属性源未选关联属性时**：不展示枚举值列表与策略，提示「请先选择关联属性；选定后将载入该属性的枚举值并可配置排序策略」。
- **字母序 / 数值序的混合形态防呆（三段式）**：当维度的枚举值混合了「纯数字」「字母+数字」「纯字母」不同形态时，字母序与数值序均采用三段式排序，避免「19 排在 2.55 前」「数字与文字混排」等反直觉结果（**适用所有走字母序的维度，含固定字母序的 brand**）：
  - **字母序 A→Z**：纯字母（A→Z）在前 → 「字母+数字」（按其中字母 A→Z，字母相同再按其中数值）居中 → 纯数字（按数值小到大）在末。
  - **数值升序**：纯数字（按数值小到大）在前 → 「字母+数字」（按其中数值小到大，数值相同再按其中字母）居中 → 纯字母（A→Z）在末。
  - 形态判定：含字母且含数字=「字母+数字」；仅含数字=「纯数字」；其余=「纯字母」。命中混合形态时前端给出说明提示；如需完全自定义顺序，用 Pin 固定。

> **实现说明（字母序 / 拼音序）**：字母序对中文按**拼音 A→Z**排序，由前端 `localeCompare` 与服务端/数据库的**拼音排序规则（collation，如 MySQL `utf8mb4_zh_0900_as_cs`、PostgreSQL ICU `und-u-co-pinyin`）**实现，**无需为枚举值单独存储拼音字段**——后端只配中文即可，排序能力来自字符集规则、非数据本身。多音字按 collation 的默认读音排序（如「重」可能取 zhong 而非 chong），如个别值顺序不符预期，用 Pin 固定位调整，不引入逐条拼音配置。

**③ 固定位置（内部 key：Pin / position）**

> **v0.16 术语变更**：后台 UI 全部由「Pin」改为「**固定位置**」（运营反馈「Pin」易误解为别针），内部字段 key 不变。
> **v0.16 交互变更**：枚举值排序列表中的**序号移到选项框外**（常驻框左侧，作为绝对位置编号），不随选项框移动；原序号在框内会随固定/重排一起移动，易被误解为项目自带编号。

- 在枚举值列表的「**固定位置**」列输入序号，可把某值**固定到同维度内的绝对位置**（绑值 key、不绑下标）；未固定的值按当前排序策略自动填充剩余位。
- 同一序号被占用时，新值**顶替**原固定值，原值恢复按策略自动排序，并 Toast 提示「位置 N 原为「{旧值}」，已被「{新值}」顶替，「{旧值}」恢复自动排序」。
- 序号越界自动收敛到 [1, 总数]；清空固定位置框即取消固定。
- 已固定的值在列表中以「固定 N」标记标识。

> 「按点击量 / 点击率 / 销量等指标排序」为二期规划（需前台埋点统计），本期不提供。

**属性（attribute）数据源专项约定：按作用域分组**

部分属性的同名枚举值在不同类目下语义并不一致（典型如 `size`：服装的 S/M/L 与鞋类的 36/37/38），若全站打平展示会造成跨类目混排、语义错乱。为此 attribute 维度提供「按作用域分组」开关。

- **开关位置与显示条件**：维度编辑页，数据源选择「属性(attribute)」时即显示该开关；在未选定具体「关联属性」前，开关置灰并提示「请先选择关联属性」，选定后可用。
- **默认值**：开关**默认一律不启用（关闭）**，由运营按需手动开启。对同名值跨类目语义不同的属性（如 `size`、`bag_size`）在开关旁给出「建议开启」文案提示，但**不改变默认态**（仍默认关闭）；全站语义一致的属性（如 `color`、`material`）无提示。运营开启后以维度配置为准。
- **展示样式与开关联动**：**关闭**「按作用域分组」时，展示类型**不出现「分组」选项**（无分组结构可下发，只能选双列卡片/单列文本/颜色卡片）；**开启**后展示样式**固定为「分组」、不可改**（各筛选模块锁定并提示）。
- **开启后的展示**：枚举值按商品命中的「类目 / 品牌 / 系列」作用域规则**自然归组**，组内排序**固定为「数据源默认序」**（分组后组内值较少，靠固定位置手动微调即可），**不展示排序策略下拉**；组间不合并。
- **组内排序：数据源默认序 + 固定位置（跨组按全局位次联动）**：每个作用域组内提供「**固定位置**」输入框（逻辑同上文「枚举值排序③」）。未固定的值按「数据源默认序」（商品侧 `sort_order` 升序、无值/并列按创建序兜底）填充；运营在「固定位置」框输入序号，把某值固定到指定位次。
  - **跨组联动口径（关键）**：固定位置按「**属性值**」全局记忆（落「维度 + 属性值 → 位置」，不按组存储）。这里的「相同位置」指**全局位次**，而非"各组里的第几格"——即同一属性值在任一组固定后，其它包含该值的组都把它放到**该全局位次**上；各组**按全局位次给本组拥有的值排序、本组没有的值跳过**，因此各组实际显示的行号可能不同，但相对先后一致，不会出现「A 组 M 在 L 前、B 组 M 在 L 后」的矛盾。
    - 例：全局位次 S→1、M→2、L→3、XL→4、XXL→5 时——「类目」组(M,L,XL)显示 M、L、XL；「类目+品牌」组(S,M,L,XL)显示 S、M、L、XL；「类目+品牌+系列」组(S,M,XXL)显示 S、M、XXL。在任一组把 M 固定到 S 前，所有含 M 的组一致生效。
  - **联动单位按属性类型分两类**（依据商品系统数据结构）：
    - **普通枚举属性**（material / color / hardware 等）：各作用域组的可用值都是同一份**全局候选列表**（`attribute_option`）的子集（命中即用、不跨层合并），故全属性共用**一套全局位次**；默认复用商品侧 `attribute_option.sort_order`，运营在任一组固定位置即写入该属性的全局位次记录。
    - **尺码属性**（值约束=size，值来自 `size_system` / `size_value`）：按**尺码体系**各维护一套全局位次（默认复用体系自带的 `size_value` 顺序）。**同一体系的作用域组共享该体系位次、联动一致；不同体系的组互不影响**（不同体系是不同的 size_value 集合，跨体系本就不应联动——例如服装组绑 IT 体系、某品牌组绑 Moncler 专属体系，从根上不存在「成员不一致如何联动」的歧义）。
  - **打平态与分组态两套独立存储**：关闭「按作用域分组」（打平态）用「排序策略 + 固定位置」（见上文「枚举值排序专项约定①②③」，落 `value_pins`）；开启（分组态）固定「数据源默认序」+ 固定位置（落 `value_order_grouped`：普通属性一套全局位次、尺码属性按体系各一套）。切换开关只切换生效哪套配置，互不共享、不串味。
  - **分组依据**：以商品命中的作用域规则实例为组（三层作用域同时生效、命中即停、不跨层合并）。
  - **组间排序（嵌套，运营不手动调组序，系统自动决定）**：① 先按**一级类目排序**（商品端类目 `sort_order`），同类目聚为一片；② 同类目内按**品牌名 A→Z**；③ 同品牌内按**系列名 A→Z**。中文名按拼音 A→Z。尺码按体系分组时组间序沿用此嵌套规则，体系不另作为排序键。
  - **组标题**：由**后端用中点直接拼接「一级类目名 · 品牌名 · 系列名」**（空段跳过）后下发，前端原样展示（不再由前端拼接）；作用域组合动态增减时无需运营维护。
  - **组标题多语言取数（前台多语言场景）**：组标题各段名称按**前台当前语言**取，**统一优先级：运营在维度配置的「前台展示名」（注册翻译 key）> 翻译模块多语言名 > fallback 默认语言原值**。各段数据来源——**品牌名 / 系列名**：商品系统有英文专名列（`brand_name_en` / `series_name_en`），按当前语言取对应专名；**一级类目名**：商品系统仅单列 `category_name`、无英文列，其多语言依赖翻译模块，缺失则 fallback 原值。因此为避免组标题中英混排，**运营可在本维度的类目节点配置「前台展示名」并由系统注册多语言 key 到翻译模块**（见下方「后台类目专项」），由翻译模块产出各语言版本。后端**按当前语言解析好每段后拼成整串下发**，前端原样展示、不参与拼接与翻译。
  - **组合异步生成**：刚开启「按作用域分组」时，后端需异步扫描全站商品并归类，作用域组合**不会即时生成**（通常数分钟，组合多时更久）。运营可先保存维度、稍后回页面**刷新**查看实际分组；生成完成前前台按已有结果展示并增量同步。
  - **与类目「分组」样式数据结构一致**：均为「标题 + 值」结构——属性作用域分组的「标题=类目名·品牌名·系列名、值=组内枚举值」，类目维度的「标题=一级类目名、值=三级类目名」；前端用同一套分组组件渲染。
- **关闭后的展示**：枚举值平铺为单一列表，按「枚举值排序」配置的策略统一排序。
- **落库**：维度配置持久化 `scope_grouped`（布尔）。开启时 `display_type_*` 固定为 `tree`（分组）。

**后台类目（backend_category）数据源专项约定：全量纳入与顺序合并**

后台类目数据源**固定三级结构、全量纳入**：类目模块（商品侧）是唯一真相源，类目的增删自动同步进本维度，运营**不可勾选剔除**，仅可为各级节点配置前台展示名（留空用后台名）。

> **类目名称多语言**：商品系统的类目名仅 `category_name` 单列、**无英文/多语言列**。前台展示（含分组标题的一级类目段、分组样式的各级节点名）按当前语言取数，**优先级：运营在本维度配置的「前台展示名」（系统据此注册多语言 key 到翻译模块）> 翻译模块对该类目原名的多语言译名 > fallback 默认语言原值**。MVP 英语为主时，建议运营为面向前台的一级类目配英文展示名（或由翻译模块补齐类目英文），否则该段 fallback 出默认语言原值、可能与英文的品牌/系列段混排。

由于全量纳入，类目顺序需在「商品侧源排序」与「运营人工调整」之间合并。规则与其它筛选器的 Pin 范式一致：**Pin 区 + 跟随区**。

- **源排序来源**：取商品系统类目表 `backend_category` 的 `sort_order`（非负整数，数字越小越靠前；详见商品系统 PRD 与商品主数据 ER）。该字段为同一父类目（`parent_id`）下兄弟节点的局部序，归商品运营维护，**可为空/未填**。
- **跟随区**：运营未手动调整的类目，按源 `sort_order` 升序排列；`sort_order` 为空或并列时，按 `category_id` 升序兜底（近似创建先后，保证排序稳定、可预测）。源端调整排序或新增类目时，跟随区自动重算，完整继承商品侧顺序。
- **Pin 区**：运营在本维度拖拽过、或在行首 Pin 框输入序号的类目 = **显式 Pin**到同级内的绝对位置（位置记录**绑类目 key、不绑下标**），始终保持人工位；其余跟随项自动填充剩余空位。
  - 拖拽到、或输入到已被占用的 Pin 位时，**顶替**原 Pin 项，原项恢复跟随源排序并 Toast 提示「位置 N 原 Pin 项已让出，恢复跟随源排序」。
  - 节点行以「Pin N」标记，提供「取消」操作恢复跟随。
  - **原位固定**（如把当前第 1 位 Pin 到第 1 位）或**长列表远距离移动**，可直接在行首 Pin 框输入序号，无需拖拽。
- **新增类目落位**：新同步进来的类目先进跟随区，按其源 `sort_order` 自然落位（撞到 Pin 位则顺延其后），运营可拖拽/输入序号归位或保持跟随。
- **删除类目**：商品侧删除某类目时，本维度对应节点移除，其 Pin 记录一并清除。
- **拖拽限制**：仅同级、同父节点内调位；不支持跨级、跨类目；父级位置变化时其下子级整体跟随，子级各自的顺序不受影响。
- **落库**：维度配置持久化 Pin 记录（类目 key → Pin 位置），不持久化跟随区顺序（跟随区每次按源排序实时计算）。

**标签（tag）数据源专项约定**

标签数据源的枚举值与其他数据源不同：并非"取全量自动同步、仅可调序"，而是由运营从标签库中**显式勾选**子集作为前台筛选项。

- **标签池范围**：读商品系统「标签管理」，**仅取适用对象为「渠道商品」或「通用」且状态=启用的标签**。原因：Collection 前台展示的是渠道商品（listing），实物商品标签绑定在实物层、不在 listing 上，用于前台筛选既需跨表关联、语义也不对位，故排除。
- **选择交互**：双栏选择器。左侧为**待选区**（标签池），右侧为**已选区**（前台筛选项）。
  - **待选区已被选入的标签从待选列表中移除，不可重复选择**；从已选区移除后该标签重新出现在待选区。
  - 待选区支持**模糊搜索**与按**适用对象（渠道商品 / 通用）筛选**查看；每个标签展示其适用对象徽标。
  - **待选区按标签名称「字母序 A→Z」排序**：英文按字母 A→Z，中文按拼音 A→Z；名称为「字母+数字」「纯数字」等混合形态时，沿用枚举值字母序的三段式兜底（纯字母 → 字母+数字 → 纯数字，见前文「字母序 / 数值序的混合形态防呆」）。标签库新增标签同步进来后，按此规则自动落到待选区的正确位置，无需人工整理。拼音序由 collation 实现、无需存拼音字段，多音字处理同前文「实现说明」。
  - 已选区支持**拖拽排序**（决定前台展示顺序），不提供适用对象筛选（已选为运营手工策展的有序小集合，徽标已足够区分）。
- **前台展示名**：已选区每个标签可单独配置**前台展示名**，留空则使用标签原名。
- **数据落库**：保存维度时持久化已选标签的有序列表（tag key + display_name + sort_order）。前台筛选按该列表渲染，标签命中商品数 `count=0` 时实时隐藏。

| 标签数据源可用展示样式 | 双列卡片 / 单列文本 |
|---|---|

**校验规则**

| 字段 | 规则 |
|---|---|
| 维度名称（EN）| 非空；**全局唯一——保存时拿 en 源文向翻译服务查重**（译文允许碰撞，唯一性只认 en 源），重复提示「该维度名称已存在」|
| attribute 类型：关联属性 | 至少选 1 个 |
| backend_category 类型：关联类目 | 全量纳入，无需勾选，无此校验 |

**停用维度规则**：停用前检查引用。有引用时弹窗「该维度正在被以下模块引用，停用后这些模块将不再展示该筛选项：{Collection · 模块列表}。确认停用？」

**异常处理**：枚举值扫描超时 → 「扫描中，请稍后刷新」；保存失败 → Toast 并保留编辑状态。

向导 Step 3（筛选配置），三模块平铺。前台展示效果可通过「前台预览」弹窗（Mobile/PC 切换）实时查看。**预览切到 PC 端时不渲染快筛栏**（快筛为移动端专属）。

#### 2.6.1 移动端图文筛

**仅移动端**的图文/纯文标签列表，用户点击切换子主题商品池。PC 端形态无图文筛栏，故图文筛为移动端专属、不分端、无适用终端字段。

**模块配置**

| 字段 | 说明 |
|---|---|
| `module_enabled` | 模块开关；关闭时前台（移动端）不展示图文筛行 |

**图文筛项（每项）**

| 字段 | 中文名 | 说明 |
|---|---|---|
| `status` | 是否展示 | active / inactive，临时隐藏单项 |
| `label_text` | 展示文案 | 用户可见文案，如「Chanel Classic」|
| `image_enable` | 是否展示图片 | 选项级开关。TRUE = 图文模式（需配图）；FALSE = 纯文本模式（无图）。逐项独立 |
| `image_url` | 图片 | `image_enable=TRUE` 时上传单张图片（移动端，建议 160×160）；`image_enable=FALSE` 时无需上传 |
| `filter_condition` | 筛选条件 | 复用通用条件构建器（§2.1，与选品规则同字段体系）预置一组筛选项：维度间 AND、同维度多枚举值 OR，**不支持 OR 组合/嵌套**；基于当前 Collection 商品池生效 |

**图文筛规则构建器（v0.14 统一为通用条件构建器）**
- 不再单独维护图文筛专用构建器，改用 §2.1 通用条件构建器，字段体系与选品规则一致。
- 引导语为「条件的商品在前台点击时被筛出」；同时满足以下**全部**筛选项（维度间 AND）；同一维度内多选枚举值为 OR；每个维度最多用一次。
- **默认带入规则**：新增图文筛项时，自动选品 Collection 默认带入 Step 商品来源配置的选品规则（可在此基础上增删条件 / 收窄，如只保留某品牌）；手动选品 Collection 无规则可继承，需自行配置。
- **前台展示结果口径**：= 当前 Collection 商品池 ∩ 本卡片规则。故规则中超出 Collection 范围的值不会生效（前台无对应商品）。
- 价格维度支持区间（币种跟随市场支持币种、金额禁负数、去 spinner）。
- 数量限制：active 项 4–8 个（仅 `module_enabled=TRUE` 时生效）。
- **保存校验**：模块启用时需 ≥1 条 active 选项（见 §2.4）。
- 前台仅展示运营配置的 active 图文筛项，**无系统级「All」项**（默认无标签激活 = 展示全集）。

#### 2.6.2 移动端快筛

**仅移动端**的横排滚动 Chip 栏（吸顶），运营从全局维度池挑选热门维度。PC 端形态无快筛栏，故快筛为移动端专属、不分端、无适用终端字段。

**模块配置**：`module_enabled` 开关。

**快筛项（每项）**

> **v0.7 变更**：快筛确定为**移动端专属**——后台模块名为「移动端快筛」，**去掉适用终端配置**（去掉 v0.16 早期短暂引入的 `devices` 字段、列表行内终端勾选、添加弹窗的终端选择）。「添加快筛选项」弹窗仅从全局维度池勾选维度，添加后在列表中调整排序、临时隐藏单项。

| 字段 | 说明 |
|---|---|
| `dimension_key` | 从全局维度池挑选的维度英文标识，必填 |
| `enabled` | 是否展示，临时隐藏单项 |
| `sort_order` | 从左到右展示顺序，分 Collection 配置 |

- 运营仅「挑哪些维度」「排序」，**不配置预设条件**（原 quick_filter_preset 废弃）。
- 每项展示样式由该维度的全局配置（快筛模块样式）决定，运营不在快筛项上单独配样式。
- 数量限制：active 项 1–8 个。
- **仅移动端展示**：快筛无适用终端字段，前台仅在移动端渲染快筛栏；PC 端不展示（前台预览切到 PC 端时不渲染快筛栏）。

#### 2.6.3 通用筛选器（零配置）

通用筛选器即前台抽屉筛，**零配置、动态生成**。

**模块配置**：仅 `module_enabled` 开关（关闭则前台不展示通用筛选器入口）。

**生成与展示规则**
- 展示哪些维度：按当前 Collection 商品池动态匹配（某维度在当前范围内有 ≥2 个不同值才展示），运营不挑选、不隐藏单维度。
- 维度顺序：由筛选维度管理的全局统一排序决定，所有 Collection 一致。
- 每个维度展示样式：由该维度全局配置（通用筛选模块样式）决定。
- 运营若需调整维度范围/顺序/样式，统一在「筛选维度管理」全局修改。

> **三模块关系**：图文筛 = 运营预置的子主题入口（一组 AND/OR 规则）；快筛 = Collection 内从池中挑选的热门维度（选项和排序分 Collection）；通用筛选器 = 全量动态呈现（维度/排序/样式全局统一）。

### 3.2 数据逻辑层

#### 3.2.1 Collection 全集
Collection 全集 = 该 Collection 下所有 `listing_status = active` 的商品，不附加任何用户筛选条件，是候选值计算的锚点，不随用户操作改变。

#### 3.2.2 筛选候选值规则
候选值完全由服务端计算下发，前端不做本地计算/过滤。

**候选值范围**

候选值范围由三部分逐层求交得到：先取 Collection 全集，再与当前激活的图文筛项范围求交，最后与搜索词过滤结果求交。即在「该 Collection 下全部在售商品」的基础上，叠加当前图文筛子主题与搜索词的限定，得到用于计算各筛选项可选值的商品集合。

> 候选值范围**不包含**已应用的快筛/通用筛选器条件——即快筛与通用筛选器的可选项**互不影响、互不缩减**，避免「越筛越少」：在快筛选了某品牌，不会缩减通用筛选器中其他维度的可选范围，反之亦然。

**联动方向规则**

| 触发 | 影响范围 | 是否反向影响 |
|---|---|---|
| 图文筛选中 | 缩小商品池 → 重算快筛 + 通用筛选器候选项 | 快筛/通用筛选器**不影响图文筛**（图文筛各项数量不随快筛/通用筛选器变化）|
| 快筛应用 | 仅刷新商品列表与计数 | **不缩减**通用筛选器及其他维度的候选项；选中态同步到通用筛选器（见 §3.8.8）|
| 通用筛选器应用 | 仅刷新商品列表与计数 | **不缩减**快筛及其他维度的候选项；选中态同步到快筛（见 §3.8.8）|

**其他规则**
- 图文筛选中状态变化后，快筛和通用筛选器候选值随之更新（服务端按新图文筛范围重算）。
- 后端不下发的属性值前端物理隐藏，不渲染、不占位。
- 后端返回候选值时同步返回每个值的商品数量。
- 用户已选值始终保留为选中态，仅在切换图文筛、提交新搜索词、用户主动移除时清空（见 §3.2.3）。
- 快筛与通用筛选器共享同一套筛选状态（双向同步，见 §3.8.8）。

**候选值返回结构（按 display_type 区分）**

服务端下发候选值时，每个候选项至少携带三项信息：**值标识**、**前台展示名**（按当前语言取数，优先级：运营在维度配置的展示名「注册翻译 key」> 翻译模块多语言名 > fallback 默认语言原值；详见 §1.7「筛选名称多语言取数」）、**该值在当前范围内的商品数量（count）**。结构分两类：

- **双列卡片 / 单列文本 / 颜色卡片 / 滑块**：返回**打平的候选值列表**（结构一致，仅前端呈现不同）。类目维度用双列卡片或单列文本时，下发的就是末级类目的打平列表，不含父子层级。例如「Color」维度下发 Black、Brown、Beige 等若干并列值，每个值带展示名与商品数量；颜色维度还附带色值（color_hex）与色系名，取自 Color Dictionary。
- **分组（内部 key `tree`）**：返回**「分组标题 + 值列表」的两层结构**，类目与「按作用域分组」属性**结构完全等价**——分组标题不可勾、值节点可勾（多选），每个值节点带 `value` / `display_name` / `count`，分组节点带 `group_title`。类目维度：标题=一级类目名（不可勾）、值=该范围内的三级（末级）类目名（勾选语义见下方「类目（分组）筛选的匹配语义」）；按作用域分组的属性：标题=「类目名·品牌名·系列名」（不可勾）、值=组内枚举值。前端用同一套分组组件渲染，不按维度分叉。

补充规则：
- 商品数量为 0 的值不下发（前端物理隐藏）；分组下若某父节点/某组的全部子项数量均为 0，则该父节点/组也不下发。
- 分组的层级/分组深度由当前商品池实际能匹配到的内容动态决定。
- 前端不依据字段名判断展示形态，一律按维度配置的 display_type 渲染。

**类目（分组）筛选的匹配语义（重要）**

后台类目按「分组标题 + 值」结构展示：**一级类目仅作分组标题、不可勾选**；用户**只勾选末级（三级）类目**。该结构与「按作用域分组」属性完全一致（标题不可勾、值可多选）。

- **仅末级可勾、覆盖即匹配**：用户勾选某个三级类目，语义为条件「`backend_category 属于该三级类目`」成立——该三级类目覆盖范围内的全部商品被纳入。一级标题仅用于归类展示，点击不产生筛选条件。
- **不提供「勾父节点 = 选中全部子节点」**：一级是纯标题，无勾选态、无半选态；运营/用户若想覆盖某一级下全部商品，需逐个勾选其下三级类目（或在该一级标题下提供的全部三级值中多选）。
- 多选 OR：同一维度内勾选多个三级类目时，彼此为 OR（命中任一即纳入）。

> v0.8 变更：废弃 v0.7「各层级节点均可独立勾选 / 勾父节点覆盖即匹配 / 子节点 UI 自动全选」口径。现口径下，category 一级=分组标题（不可勾）、三级=可勾值，前台匹配仅以所勾三级类目的覆盖范围为准。

一句话：一级类目只是分组标题，用户勾哪个三级类目，就匹配该三级类目覆盖的全部商品。


#### 3.2.3 筛选状态重置规则

| 触发动作 | 重置范围 | 后续动作 |
|---|---|---|
| 点击 / 切换图文筛项（含再次点击取消激活、回到全集）| 清空所有快筛 + 通用筛选器已选条件 | 按新图文筛范围的商品集合**重新动态匹配**快筛/通用筛选器候选项 |
| 提交新搜索词 | 清空所有快筛 + 通用筛选器已选条件 | 按搜索结果重新匹配候选项 |
| 清空搜索词（点 ✕）| **不重置**，恢复搜索前列表 | — |
| 快筛/通用筛选器内的应用（Apply）| **不清空**已选 | 仅刷新商品列表与计数；不缩减其他维度候选项（§3.2.2 互不影响）|

> 关键区分：**只有图文筛切换和新搜索词会清空快筛/通用筛选器已选**；快筛/通用筛选器自身的筛选只刷新商品列表、不互相缩减候选项、保留已选。图文筛清空后需按图文筛对应商品内容重新匹配出可用筛选维度与候选值。

#### 3.2.4 空态与降级规则

| 状态 | 触发 | 建议处理 |
|---|---|---|
| Collection 不可用 | `status ≠ active` 或 slug 无效 | 404 / 友好提示页 + 跳转引导 |
| 合集内商品全部下架 | 商品池为空，无筛选 | 空内容提示 + 浏览其他合集入口 |
| 筛选后 0 件 | 有激活条件但交集为空 | 空结果提示 + 清空筛选入口 |
| 图文筛无 active 项 | 模块启用但无 active 项 | 图文筛整行隐藏，不占位 |
| 某筛选维度无候选值 | 当前范围内该维度无值 | 该 Chip / 维度节物理隐藏 |
| Banner 图加载失败 | 图片请求失败 | 整区隐藏，不占位 |
| 网络异常 | 请求失败 / 服务无响应 | 错误提示 + 重试 + 骨架屏保持 |
| 加载中 | 首次进入/刷新 | 双列骨架屏占位 |

### 3.3 顶导栏

始终固定。左：← 返回；中：Collection 标题（读 `title`，居中）；右：搜索图标（V1 仅图标，逻辑 V2）+ 购物车图标。V1 不展示分享按钮和 Logo。

**背景**：未滚过 Banner 时透明 + 白色图标；滚过 Banner 高度后白底 + 深色图标。透明→白渐变从滚动距离 = Banner 高度 ×70% 开始。

### 3.4 Banner 区域
展示头图（`banner_image_url`）、标题（`title`）、副标题（`subtitle` 若有），随页面滚动。图片加载失败时整区不展示、不占位，页面直接从图文筛行开始。

### 3.5 图文筛（移动端）
横向滚动，随页面滚动不吸顶。**图文筛为移动端专属交互，PC 端无此栏**。
- 图文型（`image_enable=TRUE`）：图片 + 文字；纯文型（FALSE）：仅文字。
- **单选**：同一时刻最多一个标签激活；默认无标签激活，展示全集。
- 点击标签 → 触发 Auto-Scroll → 清空所有快筛/通用筛选器条件 → 按新标签范围刷新。
- 再次点击已激活标签 → 取消激活，回到全集。
- 无系统级「All」项；所有项 inactive 或模块关闭时整行隐藏。

### 3.6 快筛栏（移动端）

横向滚动，越过图文筛底部后吸顶。**快筛为移动端专属交互，PC 端无此栏**。

**整体布局**：按 `sort_order` 从左到右渲染 `enabled=TRUE` 的维度 Chip；某维度在当前范围内有 ≥2 个不同值才渲染，否则物理隐藏。

**交互**：点击 Chip → 快筛栏立即吸顶 → 二级面板从快筛栏下缘向下打开。面板底部固定两按钮：
- **Clear**：清空当前维度已选项，面板保持打开。
- **Apply**：提交选中项，关闭面板，触发 Auto-Scroll，刷新列表。
- 未改动时 Apply 等同关闭，不刷新；Clear 后直接关闭 = 恢复打开前状态。

**Chip 状态**：无选中值=默认样式展示维度名；有选中值=高亮 + 右侧已选数量角标。

**View All 规则**

| 条件 | 行为 |
|---|---|
| 候选项 ≤ 8 | 全部展示 |
| 候选项 > 8 | 默认展示前 8 + View All 入口 |
| 点击 View All | 展开为可滚动区，展示全部，入口隐藏 |

> 若维度存在分组，View All 的 8 阈值按所有分组内选项**总数**统一计算。

**各 display_type 二级面板**
- **滑块（price）**：V1 只支持 Slider。范围最小固定 $0、最大取商品池最高价向上取整百位（不足 $100 按 $100）；币种跟随市场支持币种。滑块上方实时显示区间（如「$200 — $1,000」）；初始 $0~最大值；拖回两端 = 无价格条件；范围由后端按商品池动态返回，不入库；不适用 View All。
- **颜色卡片（color）**：色块圆形矩阵 + 色系名称，读 Color Dictionary（color_code → display_name + color_hex）；多选；不适用 View All。
- **双列卡片（card）**：候选值摊平为 Chip，多选，适用 View All。类目维度用此样式时，后端只返回**末级类目**打平列表（不展示父级层级）。
- **单列文本（panel）**：候选值同样为**打平列表**（与双列卡片数据结构一致），仅以可折叠分组样式呈现；多选，适用 View All。
- **分组（tree）**：「分组标题 + 值」的两层结构。**分组标题不可勾，仅末级值可勾（多选）**。类目维度：标题=一级类目名、值=三级（末级）类目名（勾选语义见 §3.2.2「类目（分组）筛选的匹配语义」）；按作用域分组的属性：标题=「类目名·品牌名·系列名」、值=组内枚举值。两者结构等价，前端同一套分组组件渲染。适用于类目（backend_category）与开启「按作用域分组」的属性。

**品牌（brand）维度的 A-Z 字母索引**

品牌维度（双列卡片 / 单列文本）候选项较多，前台在面板侧附 **A-Z 字母索引条** + 滑动定位：点击 / 滑动某字母，列表跳转至该字母开头的品牌起始位置。

- **依赖前提**：索引定位要求品牌列表**严格按首字母单调有序、同首字母连续相邻**。brand 维度后台固定「字母序 A→Z」、**完全锁死（无排序策略、无固定位置 Pin）**正是为保证此单调性（见 §2.5 brand 专项）——故同字母品牌不会被拆散到多处，点击任一字母都能定位到该字母**唯一连续的**品牌区段。
- **`#` 档**：以**数字开头**的品牌（如 `3.1 Phillip Lim`）按三段式排在纯字母段之后，A-Z 26 档无对应字母，统一归入索引条末尾的 **`#` 档**承接（`A.P.C.`、`Off-White` 等首字符为字母者仍归 A/O 段，不入 `#`）。
- **空字母档**：当前商品池内无某字母开头的品牌时，该字母在索引条置灰 / 不可点（具体样式由 UI 定，见 §8.7）。
- **中文品牌**：按拼音首字母归档（见 §2.5「字母序 / 拼音序」说明）。

### 3.7 工具栏

固定在快筛栏下方，吸顶时紧贴其下缘。左排序、右通用筛选入口。
- **排序**：点击弹出排序列表（单选，选中立即生效并关闭）；Chip 展示当前排序名；可选项与文案全部读后台配置，前端不硬编码。
- **通用筛选入口**：图标 + 文字，有已选条件时带角标；点击打开通用筛选器（§3.8）。

### 3.8 通用筛选器（前台抽屉）

由工具栏通用筛选入口触发，从左侧滑出。

**整体结构**：宽度约屏幕左侧 2/3，右侧约 1/3 露出底层（无遮罩）；一级维度列表纵向排列。各维度顺序与是否展示由筛选维度管理全局配置决定（零配置），并按当前商品池动态过滤。

**内部展示规则**：各维度展示形式与快筛**完全一致**（display_type、View All、颜色矩阵、价格 Slider 均相同）。唯一区别：通用筛选器一级维度**纵向排列**，快筛**横向滚动**。

**开关路径**

| 路径 | 触发 | 应用变更 |
|---|---|---|
| 打开 | 点击工具栏通用筛选入口 | — |
| 关闭 A | 点击 ✕ | 否 |
| 关闭 B | 点击右侧露出区域 | 否 |
| 关闭 C | 向右滑动关闭手势 | 否 |
| 提交 | 点击底部 Apply | 是 |

**Apply 按钮**：文案「Apply · N items」，N = 通用筛选器条件 × 快筛条件 × 搜索词预计算交集数；N=0 时置灰「No items match」。点击：关闭 → 应用 → 更新快筛 Chip 角标 → 更新已选条件标签 → 触发 Auto-Scroll → 刷新列表。

**Reset 按钮**：清空通用筛选器内部选中，**不影响快筛**；Reset 后 Apply 预计数更新为当前快筛 + 搜索词范围的商品数；不关闭抽屉。

**维度显示规则**：某维度在当前范围内有 ≥2 个不同值才渲染，否则整节物理隐藏（已选项所在维度始终保留）。

#### 3.8.8 快筛与通用筛选器双向联动

快筛与通用筛选器**共享同一套筛选状态**（同一维度同一值在两处是同一份选中数据），因此双向实时同步：

- **快筛 → 通用筛选器**：快筛中选中某维度某值，打开通用筛选器时该维度对应项已是选中态。
- **通用筛选器 → 快筛**：通用筛选器中选中某值并 Apply 后，对应快筛 Chip 显示选中高亮 + 已选数量角标。
- **共同作用于商品列表**：两者的已应用条件共同参与最终商品列表的过滤（AND），但**互不缩减对方及其他维度的候选项**（§3.2.2 互不影响），两侧已选值均保留。
- **移除同步**：在任一侧取消某已选值，另一侧同步取消。
- **Reset**：通用筛选器内 Reset 仅清通用筛选器内部选中、**不清快筛**（不动图文筛与搜索词）；快筛二级面板内 Clear 仅清当前维度。

### 3.9 商品网格

双列网格（V1 固定双列，列数不可配）；商品卡复用首页 Feed 组件；排列顺序完全由后端决定；加载中同比例骨架屏；点击卡片跳商品详情页。

**分页 / 加载（分端）**

| 端 | 加载方式 |
|---|---|
| 移动端（APP + 移动端 Web/H5）| **无限流加载**：每 **20 个**商品一屏，触底前预加载下一屏。本 Collection 商品全部展示完后**不循环、不停止**，接「触底推荐区」（见下方）|
| PC（Web）| **传统翻页**：每页 X 个（X 由 UI 确定，见 §8.7），底部页码器（1 / 2 / 3 …）；翻到最后一页即结束，**不接触底推荐区** |

**触底推荐区（仅移动端）**

移动端本 Collection 商品全部滑完后，依次展示：
1. **分割线 + 文案**：分割线 + 「Explore our picks for you」。
2. **推荐 feed**：商品集为**全站商品**（不限本 Collection），**推荐逻辑复用主页「For You」推荐**——同一套推荐引擎与排序规则，本模块不另行定义算法（算法细节归推荐模块）。
3. 推荐 feed 沿用 For You 自身的无限流加载规则继续向下滚动。

> 设计意图：移动端「无限滚动」体验完整保留；滚过本 Collection 全集后，内容源从「本 Collection」平滑切换到「全站 For You」，避免从头循环造成的重复曝光。PC 端走分页、不接推荐区，便于深链到指定页与 SEO 收录。

## 四、通用机制

### 4.1 机制：Meta SEO 降级链

Collection 页 `<title>` 和 `<meta name="description">` 按降级链自动生成，确保运营未填 SEO 字段时每页也有合理 Meta。每次页面被请求时服务端按字段优先级动态生成。

**Meta Title 降级链**

| 优先级 | 条件 | 输出 |
|---|---|---|
| 1 | `seo_title` 有值 | 直接使用 |
| 2 | `seo_title` 空 | `{title} \| Looply` |

**Meta Description 降级链**

| 优先级 | 条件 | 输出 |
|---|---|---|
| 1 | `seo_description` 有值 | 直接使用 |
| 2 | `seo_description` 空 | `Shop {title} at Looply. Authenticated pre-owned luxury at up to 70% off retail.` |

**规则说明**：标题为必填，保证降级链末级永远能兜底。后台 Meta 输入框 placeholder 直接展示降级优先级说明；SEO 字段下方实时展示「生效预览」（字段为空时灰色斜体展示降级默认值，格式参考 Google 搜索结果样式）。

### 4.2 机制：商品准入与状态同步

Collection 是展示分组，不控制商品本身上下架。

**商品准入条件**（须同时满足）：
1. `item_status = 销售中`；
2. 在当前渠道有 `listing_status = active` 的渠道商品记录。

**状态变化处理逻辑**

| 场景 | 自动选品 | 手动选品 |
|---|---|---|
| 商品上架（listing active）| 匹配规则时自动纳入 | 不自动纳入（需手动添加）|
| 商品下架（off_shelf）| 自动移出前端展示 | 前端不展示，后台保留记录（灰显 +「已下架」badge）|
| 商品售出（sold）| 自动移出 | 前端不展示，后台保留记录（灰显 +「已售出」badge）|
| 商品重新上架 | 匹配规则时自动回来 | 自动恢复前端展示，position 保留 |

**自动选品 Pin 记录清除**：商品因下架/停售/售出移出自动选品 Collection 时，同步清除其在本 Collection 的 pin 记录；重新上架后重新匹配进 Collection 但无 pin 位置（未固定态），需重新 pin。原因：避免 pin 位置冲突，MVP 取最简方案。

**手动选品商品保留**：手动选品商品下架/售出后 `fc_manual_product` 记录保留，后台灰显，前端不展示；重新上架自动恢复展示、position 保留；运营可手动移除不可用商品。

**隐藏与移除的区别**

| 操作 | 适用模式 | 数据变化 | 前端 | 可恢复 |
|---|---|---|---|---|
| 隐藏（Hide）| 自动 + 手动 | 自动：加排除记录 `fc_hidden_product`；手动：`is_hidden=true` | 不展示 | ✅ |
| 移除（Remove）| 仅手动 | 删除 `fc_manual_product` 记录 | 不展示 | ❌ 需重新添加 |

**自动选品隐藏实现**：最终展示集合 = 规则匹配商品 − 隐藏列表商品（`fc_hidden_product` 独立存储，不改 rule_config）。

**上架时间条件同步频率**：「最近 N 天」与「介于」每日凌晨（UTC+8 00:00）重新评估，超范围商品自动移出；不提供分钟级实时同步。

### 4.3 机制：前台收藏（Favorites）

消费者点击商品卡心形按钮收藏。MVP 未登录用户数据存 localStorage，后续登录时合并到服务端。

**未登录用户**：
1. 点击心形 → 立即变实心（红色）+ Toast「Added to Favorites」（2 秒消失）。
2. 数据：`localStorage.set('looply_favorites', [...listing_ids])`。
3. 再次点击 → 取消收藏，恢复空心 + Toast「Removed from Favorites」。

**已登录用户**（非 MVP，占位）：收藏直接写服务端。

**收藏夹页（/favorites）**【⚠️ 待设计稿】：读 localStorage，批量获取商品最新状态后渲染；已售/下架商品标「Sold」灰显保留；空态「No favorites yet. Start exploring!」。

**后续迁移路径**（非 MVP）：登录时前端将 localStorage 收藏 merge 到服务端（取并集去重，已售标记保留）；merge 后清空 localStorage；收藏夹页顶部引导「Sign in to get price drop alerts and restock notifications」。

**已知局限（MVP 可接受）**：换设备/清缓存丢失；无法行为归因；多标签页无原生同步（概率极低）。决策依据：MVP 无通知体系，强登录即时 ROI 不足，优先降低摩擦（参考 Shopify Swym Wishlist Plus 默认模式）。

### 4.4 机制：商品多归属与 PDP 面包屑主归属

> v0.12 说明：原「品牌驱动 Collection（品牌页）」独立机制已删除——品牌页实质就是「选品规则含 brand 条件」的普通 Collection，运营按普通 Collection 创建、在选品规则里加一个 brand 条件即可，无需任何专属字段或入口。本节仅保留与之无关、原误挂于此的「商品多归属」规则（R-19）。

商品可同时归属多个 Collection（如一件 Chanel 包同属「Chanel」「新到货」「手袋」多个 Collection）。前台商品详情页（PDP）的面包屑 / BreadcrumbList 结构化数据**恒取该商品的主归属 Collection**（`primary_collection`，优先取品类类 Collection），不随用户从哪个 Collection 点进来而变化，保证 PDP 面包屑稳定、SEO 路径唯一。`primary_collection` 字段由商品管理模块维护（见 §5 依赖）。

### 4.5 机制：后端核心逻辑

> 本节收拢前台/筛选相关的服务端计算逻辑，供后端实现参考。本文档只描述业务规则与计算口径，不含技术契约，具体出入参由研发与前端另行对齐。

#### 4.5.1 商品池与全集的构建顺序

后端按以下顺序逐层求交，得到前台某一时刻应展示的商品集合：

1. **准入过滤**：先筛出商品状态为「销售中」且在当前渠道挂牌状态为 active 的商品（§4.2）。
2. **Collection 商品池**：在准入结果之上按选品模式求交——自动选品（rule）模式取「准入结果 ∩ 规则配置（rule_config）命中商品」再扣除人工隐藏排除表（fc_hidden_product）；手动选品（manual）模式取「准入结果 ∩ 人工选品关联表（fc_manual_product，未隐藏项）」。
3. **市场/渠道范围**：按该 Collection 配置的市场（market_id）与渠道（channel_id）进一步限定。
4. **图文筛范围**：若有激活的图文筛项，再与该项预置筛选条件（filter_condition）求交。
5. **搜索词范围**：若存在搜索词（V2 能力），再与搜索结果求交。
6. **用户筛选**：最后与用户已应用的快筛、通用筛选器条件求交，得到最终商品列表。

- **Collection 全集** = 步骤 ③ 的结果（不含图文筛/搜索/用户筛选），是候选值计算的锚点。
- **最终商品列表** = 步骤 ⑥，用于商品网格与结果计数。

#### 4.5.2 筛选候选值计算（与 count 口径）

候选值由服务端计算，前端不本地过滤。**关键口径**：因快筛与通用筛选器「互不影响」（§3.2.2），候选值计算的基准范围**不叠加用户已应用的快筛/通用筛选器条件**：

候选值基准范围由 Collection 全集、当前图文筛项、搜索词范围三者求交得到（不叠加用户已应用的快筛/通用筛选器条件）。某一维度下某个值的商品数量（count），即为在该候选值基准范围内、命中该值的商品数。

- 即：在快筛选了 Brand=Chanel，不会使 Color 维度各值的 count 变化（互不缩减、避免越筛越少）。
- `count = 0` 的值不返回（前端物理隐藏）；某维度在基准范围内 < 2 个不同值时整维度不返回。
- 用户已选值即使在新基准下 count 变化也保留为选中态（仅图文筛切换/新搜索词/主动移除才清空，§3.2.3）。
- 返回结构按 display_type 区分（打平 / 分组，§3.2.2）；每值带 `value` / `display_name` / `count`。
- 颜色维度的 `color_hex` / 色系名由 Color Dictionary 关联返回（商品系统维护，本模块只读）。

#### 4.5.3 价格范围与币种

- **范围**：按【最终商品列表前的基准范围】动态计算 `min=$0`、`max=商品池最高价向上取整到百位`（不足 $100 按 $100），运行时返回、不入库。
- **币种**：读 collection.market_id → 市场模块定义的**支持币种枚举**，取首项为默认币种；价格条件按该币种与 listing 价格比对。多币种市场下前端在该市场支持币种内可切，单币种自然锁定。

#### 4.5.4 排序

- 前端不硬编码，全部读后台排序配置（排序配置见 §2.3 Step 商品来源 SortConfig，枚举见 §8.4）；客户端只传 `sort_key`，排序由后端执行。
- 排序项枚举：`recommended` / `newest` / `price_low_to_high` / `price_high_to_low`。**不含 `manual`（Featured 手动排序）项**（v0.14 已移除）。
- `recommended`：后端综合算法（MVP 因子建议：上架时间新近度 + 价格区间分布 + 库存热度，权重后端定，可迭代）。
- `newest`=listed_at DESC；`price_low_to_high/price_high_to_low`=价格升/降序。
- 兜底：Collection 未配置排序时返回全部排序项、默认 `recommended`。

**Pin 固定位与排序规则的关系（自动 / 手动选品统一）**

无论自动选品还是手动选品，前台商品列表均**按用户选定的排序规则**（默认 `recommended`）展示，不再有独立的「手动排序」项。Pin 与排序规则叠加：

- **Pin 固定的商品位置不变**：运营在商品列表 Position 列 Pin 的商品，固定在其指定位置，不受排序规则影响。
- **其余商品按排序规则填充剩余位置**：未 Pin 的商品按当前排序规则（如 `recommended`）排序，依次填入未被 Pin 占用的位置。
- **商品入池即按排序规则插入**：商品自动进入 Collection（自动选品命中）或从数据源拉入时，默认按当前选定排序规则插入商品池；Pin 位置不变，剩余位置按规则重排。
- 此即「Pin 区 + 跟随区」范式在商品维度的应用（与枚举值 / 类目排序范式一致，见 §2.5 / R-30）。

#### 4.5.5 定时与同步任务

| 任务 | 频率 | 说明 |
|---|---|---|
| 「最近 N 天」/「介于」时间条件重算 | 每日凌晨 UTC+8 00:00 | 超出范围商品移出自动选品 Collection（§4.2），不做分钟级实时 |
| 自动选品 Pin 清除 | 商品移出时触发 | 商品下架/售出移出时清除其 pin 记录（§4.2）|
| 商品数统计 | 实时 / 准实时 | 列表页商品数、候选值 count |

#### 4.5.6 性能策略（MVP）

- 候选值与计数每次条件变动实时计算；MVP 数据量小（Collection < 20、单池商品量有限）暂不强制预计算。
- 后续可对【候选值基准范围】结果按 (collection_id + 图文筛项 + 搜索词) 维度缓存，用户侧快筛/通用筛选器切换不击穿缓存（因其不参与候选值基准计算）。

### 4.6 机制：前台文案多语言接入

> 依据 `多语言模块-PRD-v3.1`、`商品系统-PRD-v1.7`、`商详页-PRD-v1.6` 对齐。本节统一本模块所有前台可见文案的多语言处理口径。

**总原则（存储口径，v0.14 修正）**
- 平台**翻译模块**是所有本地化内容的**唯一存储与翻译源**；翻译按**四元组寻址**：`resource_type + resource_id + field_name + language_code`。
- **业务表不存任何文案文本（含 en 源文）**，只存该文案的 **`translation_key`**（= `resource_type.field_name`，配合行主键 resource_id 定位）。运营在后台录入/编辑文案时，文本写入翻译服务的 en 源记录；后台列表/详情**按 en 从翻译服务取源文展示**，业务表本身无文本可读。
- 前台按当前语言向翻译服务取译文；取不到按翻译模块 fallback：译文 → 过期旧译文 → 源语言（en）。
- 文案修改 → 更新翻译服务 en 源文 → 翻译模块自动重译（AI 来源自动覆盖、manual 来源标记过期待运营确认）；翻译进行中前端无感知、取数走 fallback。
- 源语言本期硬编码 `en`；业务表如需记录可加 `source_language_code`（结构化标记，非文本）。

**① 后台业务动态文案（entity_field 类型，共 7 类）**

由本模块在开发联调阶段**通过翻译服务 API 自动注册** `translatable_field_config`（resource_type + field_name）；运营创建/编辑时把文本写入翻译服务（resource_id = 该行业务主键）。**业务表对应列存 `translation_key`、不存文本**；后台按 en 取源文展示。resource_id 取下表「定位主键」列。

| 文案 | resource_type | field_name | 定位主键 resource_id | 业务表存储 |
|---|---|---|---|---|
| Collection 标题 | collection | title | collection_id | collection.title = key |
| Collection 副标题 | collection | subtitle | collection_id | collection.subtitle = key |
| Meta Title | collection | seo_title | collection_id | collection.seo_title = key |
| Meta Description | collection | seo_description | collection_id | collection.seo_description = key |
| 图文筛展示文案 | fc_visual_filter | label_text | fc_visual_filter.id | fc_visual_filter.label_text = key |
| 维度名称 | filter_dimension | dimension_name | dimension_id | filter_dimension.dimension_name = key |
| 维度节点展示名（类目各级 + 标签） | filter_dimension | display_name | dimension_id + 节点 value | 维度配置 JSON 内存 key |

> 即每条文案的全局 key = `{resource_type}.{field_name}` + 行 resource_id；业务列存的就是这个引用，文本只在翻译服务。
>
> **唯一性校验例外（dimension_name）**：维度名称要求全局唯一，但业务列存的是 key（非文本）、且唯一性不能跨语言（译文可碰撞）。故唯一性**锚定 en 源文**：保存时拿 en 源文向翻译服务查重，重复则拦截。这是写时业务校验，非 DB 唯一约束。其余文案字段（title/label_text 等）无唯一性要求，不涉及。

**② 由上游统一翻译、本模块只取数不注册的名称**

- **属性枚举值**（颜色/材质/尺码等）：商品系统侧已注册翻译（`resource_type=attribute_option`，商详页单品页同源使用），本模块筛选器作为调用方按当前语言取译文。
- **品牌名 / 系列名**：商品系统侧管理（品牌名多为奢侈品专名，常被术语表标记禁译）。
- **类目名（各级）**：本模块筛选维度配置的「前台展示名」优先（运营配的展示名注册翻译）；未配则取类目原名的翻译模块译名；再 fallback 原文。与 §2.5 / §1.7 口径一致。

**③ SEO 降级兜底文案的多语言**：§4.1 降级链末级的兜底串（如 `{title} | Looply`、`Shop {title} at Looply...`）**本身是多语言的**（固定串部分按语言取译文）；串内嵌的 `{title}` **直接取该 Collection title 已翻译的当前语言内容拼接，不重新翻译**。后端按当前语言拼好整串返回。

**④ 前端固定 UI 文案（语言包，不逐条注册 key）**

Collection 前台落地页的静态字串（按钮、提示语、固定标签等），**由前端按「语言包」（i18n language pack）方式维护**，不在多语言后台逐条注册 key。依据 `多语言模块-PRD-v3.1`（§2.2 注、§3.3 实现方式说明）：static_content 的后台 key 注册流程仅为**参考方案**，技术团队最终采用语言包实现——产品需求是「这些文案可多语言、可维护」，但**不要求逐条产生 key、不走 entity_field API 注册**。下表为前端组织语言包的 **key 参考与 en 源文**（field_name 为语言包内建议键名，非后台注册项）：

### 5.2 风险

| 风险项 | 描述 | 缓解措施 |
|---|---|---|
| 筛选候选值计算性能 | 每次条件变动实时请求全量候选值 | 后端预计算 / 缓存策略；MVP 数据量小暂不优化 |
| Price Slider 端点值 | 空合集时最高价兜底待定 | 后端定兜底（不足 $100 按 $100）|
| 自动选品每日同步延迟 | 「最近 N 天」每日凌晨同步，最长 24h 延迟 | 标注为设计决策，「New Arrivals」类可接受 |
| URL Slug 变更 SEO 影响 | 改 Slug 后原 URL 失效 | 提示运营配置 301；301 由 SEO 工程师独立处理 |
| `tree`（分组）多级结构返回数据 | 「分组」展示样式的候选值结构 | **已定**：双列卡片/单列文本返回打平列表、分组返回「标题+值」结构（类目=父子级、作用域分组=组标题+组内值）（见 §2.5 / §3.2.2）|
| 市场→币种传递链路 | 所选市场需下发至价格筛选币种 | 明确市场字段下发路径（原型中尚未完全打通）|
| localStorage 收藏丢失 | 清缓存/换设备丢失 | 记录为可接受 MVP trade-off |
