# Looply V1.2 产品需求 PRD

**版本**：v0.1  
**日期**：2026-09-18  
**状态**：迭代中

## 一、概述

### 1.1 版本目标

V1.2 在现有用户端及运营后台能力基础上进行增量调整。本 PRD 统一记录 V1.2 已确认需求；未涉及的现有规则保持不变，并以对应模块当前 PRD 和最新 UI 为基线。

### 1.2 当前范围

本版当前已确认：

1. 首页 Banner 改为多语言整图配置。
2. 首页 Feed 恢复 `Deals` Tab。
3. Shop 新增横向大图展示样式，并同步调整导航配置。
4. 修正首页和 Shop 配置中的图片上传尺寸提示。
5. 优化首页和 Shop 配置的报错文案及错误展示。
6. Recent searches 增加单条删除与清空全部能力。
7. PC 导航展开面板增加图文推荐位，并同步调整 PC 导航后台配置。
8. 首页 Banner、PC 导航、首页 Collection 入口和 Mobile Shop 支持按国家配置与展示。
9. Sell 服务支持按国家配置开放状态，并联动 Footer、Contact Us 等页面的 Sell 入口和信息。
10. Footer 的 Shop 链接、法律文件和社媒账号按国家展示。
11. 移动端公共顶部导航按最新 UI 调整视觉样式。

## 二、需求说明

### 2.1 首页 Banner 改为多语言整图配置

#### 2.1.1 用户端展示

1. Banner 展示当前终端、当前语言对应的完整图片。
2. 标题、副标题、按钮文案及按钮视觉均制作在图片中，页面不再叠加独立文字或按钮组件。
3. 整张 Banner 图片为同一个点击区域，点击任意位置均进入该 Banner 配置的跳转目标。
4. 首页 Banner 最多展示 4 个，现有排序及轮播规则保持不变。
5. PC 与 Mobile 分别使用对应终端图片：

| 终端 | UI 1×展示基准 | 上传尺寸 |
|---|---:|---:|
| PC | `1920×747px` | `3840×1494px（2×）` |
| Mobile | `440×322px` | `880×644px（2×）` |

#### 2.1.2 运营后台配置

**修改位置**：CMS > 首页配置 > 首页 Banner。

1. 移除标题、标题颜色、副标题、副标题颜色和按钮文案配置项；保留图片 Alt 配置项。
2. 图片配置跟随顶部所选终端：选择 PC 时配置 PC 图片，选择 Mobile（App）时配置 Mobile 图片。当前国家全部已启用语言的上传位从上到下直接展示，每种语言一张图，可直接上传或替换。
3. 同一 Banner 的各语言图片共用目标类型、目标配置、排序和上线状态。目标类型可选 `Collection` 或 `自定义 URL`；选择 `Collection` 时必填关联 Collection，选择 `自定义 URL` 时必填目标 URL。
4. 图片未齐可保存下线草稿；当前终端配置上线或保存上线状态时，校验该终端全部已启用语言图片，缺图则保留编辑内容并阻止上线，提示见 2.1.4。
5. 当前国家新增语言时，启用该语言前必须补齐所有已上线 Banner 对应的 PC、Mobile 图片；存在缺图时不允许启用该语言。

6. 右侧预览使用横向语言页签，选中语言显示紫色文字与下划线；绿点表示当前终端该语言已上传图片，红点表示缺图。切换页签后预览对应图片；缺图时显示空态。
7. 保留现有配置列表、新增、编辑、排序、上下线、关联 Collection 和落地页操作。

#### 2.1.3 存量 Banner 处理

1. V1.2 上线前，所有存量 Banner 必须按新版规则重新上传 PC、Mobile 及全部已启用语言的完整图片。
2. V1.2 不兼容旧版“图片＋独立文字／按钮”展示方式。
3. 未完成新版图片配置的存量 Banner 不允许发布。

#### 2.1.4 校验提示

| 场景 | 提示文案 |
|---|---|
| 当前语言缺少图片 | `请上传{语言}的{终端} Banner 图片` |
| 当前终端上线时多个语言缺图 | `请先上传以下语言的{终端} Banner 图片：{语言列表}` |
| 启用新语言时存在已上线 Banner 缺图 | `请先补齐以下 Banner 的{语言}图片：{Banner列表}` |

#### 2.1.5 数据与埋点调整

1. 客户端公共参数新增 `locale_code`，由当前实际生效的站点语言上下文提供，并由统一客户端埋点 SDK 自动附加到全部客户端事件。
2. `locale_code` 使用产品实际生效的稳定 Locale Code，例如 `en-US`、`es-US`；不得从浏览器语言、IP 或 URL 推断。语言上下文尚未取得时允许不传，不使用默认语言补值。
3. Banner 切换继续使用现有 `ui_interaction`：
   - 点击轮播圆点：`interaction_name=home_banner`、`action=change`、`element_id=banner_dot`；
   - 手势滑动：`interaction_name=home_banner`、`action=change`、`element_id=banner_swipe`。
4. Banner 整图点击继续使用现有 `ui_interaction`，统一记录为：`interaction_name=home_banner`、`action=select`、`element_id=banner_item`、`target_id=目标 page_id`。整张图片只发送一次点击事件。
5. 图片中的按钮文案和按钮视觉仅属于图片内容，不构成独立交互控件；新版不新增或触发对应的独立按钮点击事件，无需对原按钮点位增加额外处理逻辑。
6. Banner 切换与整图点击均增加 `position_id`，取值为当前 Banner 在首页轮播中的实际展示位置 `1–4`。排序调整后按事件发生时的位置上报，不使用 `0` 或空位序号。
7. 本期使用 `position_id` 分析第 1–4 个 Banner 展示位的使用情况，不将其解释为稳定 Banner 身份；运营替换图片或调整排序后，同一 `position_id` 可以对应不同素材。
8. 不上报图片 URL、图片中文字、按钮文案或其他素材内容。

### 2.2 首页 Feed 恢复 Deals Tab

#### 2.2.1 展示规则

1. 首页 Feed 在 PC、Mobile 恢复 `Deals` Tab。
2. 当前首页 Feed 有 `For You`、`New Arrivals` 两个入口；本次恢复 `Deals`，共三个 Tab。
3. Tab 顺序固定为：`For You`、`New Arrivals`、`Deals`。
4. `Deals` 复用现有 Feed 商品卡、分页加载、加载状态、失败重试及商品点击规则。

#### 2.2.2 商品范围

1. 首页 Feed 的 `Deals` 商品池仅包含后台已打 `save` tag 的可售商品。
2. 前端不自行判断或计算商品是否属于 `Deals`，也不根据价格字段临时生成商品池。
3. 商品的 `save` tag 失效或移除，或商品变为不可售后，自动退出 `Deals` 商品池。

#### 2.2.3 排序规则

`Deals` 商品排序由搜推服务处理，综合参考用户行为、商品热销程度、竞品价格、近期降价和降价力度。

#### 2.2.4 Tab 展示条件

当前国家和渠道下，`Deals` 商品池数量达到 20 个时展示 `Deals` Tab；少于 20 个时隐藏。

#### 2.2.5 埋点

`Deals` 复用现有 Feed Tab 曝光、切换、商品曝光和商品点击事件，Tab 稳定标识使用 `deals`。

### 2.3 Shop 新增横向大图样式

#### 2.3.1 用户端展示

1. 现有 Shop 图文卡片样式命名为「方形图卡」，展示规则保持不变。
2. Shop 右侧内容区新增「横向大图」样式。图片采用横版比例，商品卡片按单列自上而下排列。
3. 每个一级导航只使用一种展示样式，其下末级导航不混用方形图卡和横向大图。
4. 两级导航下，二级导航为末级导航；三级导航下，二级导航为分组标题，三级导航为末级导航。
5. 横向大图不叠加独立标题、说明或按钮文案；图片中的展示文字由运营按语言制作在图片内。末级导航名称仍作为导航结构字段保留，用于导航菜单和配置识别。
6. 点击横向大图后，按该末级导航配置的目标类型和目标值进入 Collection 或自定义 URL。
7. 横向大图前台展示尺寸为 `238×93px`。

#### 2.3.2 运营后台配置

**修改位置**：CMS > Shop页 > 导航配置。

1. 一级导航新建、编辑表单增加「卡片样式」，可选「方形图卡」或「横向大图」。
2. 两级模式在二级导航配置图片；三级模式在三级导航配置图片。
3. 每个末级导航必须上传与所属一级导航展示样式对应的图片；缺少图片时不允许保存该末级导航。
4. 图片上传区根据所属一级导航的展示样式，显示对应的上传尺寸要求。
5. 名称、目标类型、关联 Collection 或自定义 URL 沿用现有字段及校验规则；目标类型为 `Collection` 时只校验关联 Collection，目标类型为 `自定义 URL` 时只校验目标 URL。

| 卡片样式 | 上传区尺寸要求 |
|---|---|
| 方形图卡 | `130×130px（2×）` |
| 横向大图 | `476×186px（2×）` |

### 2.6 Recent searches 删除

1. PC Web 常驻展示单条删除按钮和 `Clear all`；单条删除及清空全部均立即执行，不弹出确认。
2. Mobile Web 与 App 默认仅展示 `Delete`；点击后进入删除模式，展示单条删除按钮、`Clear all` 和 `Done`。
3. Mobile Web 与 App 的单条删除立即执行；点击 `Clear all` 时先弹出确认，确认后清空全部并退出删除模式。
4. 删除最后一条记录或清空全部后，隐藏整个 `Recent searches` 模块。
5. 游客删除结果仅作用于当前浏览器的匿名记录；登录用户的删除结果同步到同一账号的其他设备。
6. 删除 Recent searches 不删除已经生成的 Search event。
7. PC Web 与 Mobile Web 的完整交互、文案、异常和数据规则以《Looply Web 全局搜索 PRD v0.5》第 10.3 节为准；App 复用其中 Mobile Web 规则。

### 2.7 PC 导航展开面板推荐位

1. PC Web 顶部导航展开面板增加图文推荐位；每个推荐位由图片、标题文案、说明文案、目标类型和目标配置组成，整个推荐位均可点击。
2. PC 导航内容按列优先排列：按配置顺序从第一列自上而下填充，每列最多展示 7 行；第一列填满后，从第二列第一行继续排列，依次类推。系统按当前启用导航项数量计算列数：0 项为 0 列，1–7 项为 1 列，8–14 项为 2 列，此后每增加 7 项增加 1 列。推荐位数量按实际列数计算：0 列不配置；1 列 3 张；2 列 2 张；3–4 列 1 张；5 列及以上不配置。
3. 0 列及 5 列以上时，后台不生成推荐位配置区，前台不展示推荐位。
4. 推荐位在对应一级导航的二/三级导航钻取页配置；图片、标题文案、说明文案、目标类型和对应目标配置均为必填。目标类型可选 `Collection` 或 `自定义 URL`；推荐图前台展示尺寸为 340 × 210 px；上传区提示“建议上传 2 倍及以上图片，推荐尺寸不低于 680 × 420 px（展示比例 34:21）”。该提示不作为保存校验条件，系统不限制固定倍数或固定像素尺寸。
5. 后台在现有二/三级导航钻取页的导航列表下增加「导航推荐图」配置区；推荐位 1、2、3 按顺序单列向下排列，右侧 PCPreview 按前台实际布局实时预览。
6. 配置区展示系统识别的文字导航列数和应配置的推荐位数量；列数变化后立即刷新配置卡片。当前应生成的任一推荐位配置不完整时，不允许保存。
7. 每个推荐位包含图片、标题文案、说明文案、目标类型和对应目标配置；上传、替换、删除图片或修改文案、目标配置后，保存前实时同步到右侧预览。
8. Demo 使用 [PC 导航推荐图配置 antd 原型 v8](/Users/zz/Documents/Looply/outputs/looply-PC导航推荐图配置-antd-原型-v8.html)。
9. 标题文案和说明文案按现有 PC 导航多语言入口配置；图片和 Collection 各语言共用。
10. 完整后台交互、校验和边界规则以《Looply Shop PC 导航栏配置 PRD v1.4》第 4.8 节为准。
11. 推荐位曝光和点击必须同时携带所属一级导航稳定 ID、推荐位稳定 ID、当前位置 `1–3` 和目标 Collection 稳定 ID，支持按“一级导航入口 > 具体推荐位”统计曝光、点击和 CTR。
12. 一方曝光新增 `ui_impression`；点击复用 `ui_interaction`。GA4 使用 `view_promotion` 和 `select_promotion`，两端使用同一组稳定标识。

### 2.8 按国家配置与展示

#### 2.8.1 公共规则

1. 配置页不展示或切换 Market；运营人员只选择国家。系统根据国家自动推导所属 Market，Market 作为内部路由和数据隔离字段。
2. 国家筛选跟随当前 CMS 入口展示在该入口内容区上方；首页配置、Shop 配置、PC 导航配置等入口分别维护自己的当前国家筛选值，不要求入口之间共享选中状态。
3. 首页 Banner、PC 导航、首页 Collection 入口、Mobile Shop、Sell、Footer 及相关国家内容均以国家为唯一配置归属；切换当前入口的国家后，列表、编辑内容和预览展示该国家的数据。
4. 渠道和终端作为当前入口国家配置下的其他筛选维度；C 端使用用户当前已生效国家读取对应渠道、终端的内容，语言用于选择该国家配置范围内的图片或文案版本。
4. 修改某国家配置、排序或启停状态，仅影响该国家对应配置。
5. 国家切换后重新读取对应内容；返回页面、缓存恢复及请求失败时，均保持当前国家范围，不展示其他国家的旧内容。

#### 2.8.2 首页与导航配置

首页配置入口保留 `首页 Banner`、`首页 Collection` 和 `SEO 配置` 三个坑位。V1.2 本次仅调整 Banner；首页 Collection 与 SEO 沿用现有配置能力和交互，不因本次未改动而移除入口。

| 配置模块 | 按国家配置的内容 | 前端展示要求 |
|---|---|---|
| 首页 Banner | Banner 图片、关联 Collection、跳转目标、排序和上线状态 | 按当前国家、终端和语言展示；多语言成图规则继续执行 2.1 |
| PC 导航 | 各级导航名称、顺序、跳转目标、启停状态，以及所属推荐图 | 展示当前国家的导航与推荐位；推荐位规则继续执行 2.7 |
| 首页 Collection 入口 | 入口图片、文案、关联 Collection、顺序和上线状态 | 按当前国家展示对应配置，点击进入对应目标 |
| Mobile Shop | 一级导航、下级分组、图文入口、顺序、跳转目标和启停状态 | 展示当前国家的导航与内容；卡片样式继续执行 2.3 |

各模块内的下级内容使用所属配置的国家范围。以上跳转保持当前国家上下文，落地页读取对应国家及其系统推导 Market 的数据。

#### 2.8.3 Sell 按国家开放

1. 后台按国家配置 Sell 服务是否开放，前端统一读取当前国家的开放状态。
2. 开放国家正常展示 Sell 服务入口及相关信息；未开放国家隐藏全站 Sell 入口和引导内容，包括 Footer 的 Sell 链接及相关内容、Contact Us 页的 Sell 联系信息。
3. 未开放国家直接访问 Sell 地址时，按服务未开放状态处理，不能发起新的 Sell 服务申请。
4. 切换国家后，Sell 服务状态与各页面相关内容同步按新国家更新。

#### 2.8.4 Footer 按国家配置

Footer 在所有使用该公共组件的页面上，统一按当前国家展示以下内容：

| 内容 | 后台配置与前端规则 |
|---|---|
| Shop 链接 | 按国家配置入口名称、顺序和跳转目标，替换固定链接清单 |
| 法律文件 | 按国家关联适用的法律文件，展示对应语言的已批准且生效版本；公共 Footer 与 Contact Us 使用同一份法律文件映射 |
| 社媒账号 | 按国家配置展示的平台及账号链接，点击进入该国家配置的社媒账号 |
| Sell 相关内容 | 展示条件统一执行 2.8.3 |

法律文件沿用现有版本管理规则，保留文件类型、适用市场/国家、语言、版本号、生效日期和审核状态；缺少适用的有效版本时阻止该国家上线，不以其他国家文件代替。

#### 2.8.5 数据与埋点

现有客户端事件复用，统一携带事件发生时页面实际生效的国家；国家切换后同步更新，隐藏的 Sell 内容不产生曝光。字段复用、空值、重试、平台接入及验收统一执行[V1.2 国家上下文埋点补充](../../docs-数据采集与埋点/一方平台开发基线/looply-V1.2-国家上下文埋点补充-v0.1.md)。IP 国家、账号资料国家和业务市场不能代替当前生效国家。

### 2.9 移动端顶部导航样式调整

1. Mobile Web 与 App 使用公共顶部导航的页面，统一按 V1.2 最新 UI 调整顶部导航视觉样式。
2. 本次只调整视觉表现和 UI 已明确的响应式适配；顶部导航现有内容、入口、点击行为、页面跳转、登录态差异、吸顶规则及业务数据来源保持不变。
3. 返回、搜索、Logo、页面标题及右侧操作等元素是否展示，继续执行各页面现有业务规则；本需求不新增或删除功能入口。
4. 默认态、滚动态、按下态、加载态及不同语言下的布局，以最新 UI 中对应状态为验收基准；UI 未覆盖的状态复用现有公共顶部导航规则。
5. 本次不新增埋点事件。顶部导航中已有可点击入口继续沿用原有埋点；仅样式变化不触发事件调整。
6. 开发前必须补充可访问的最终 UI 链接或节点、版本时间及适用页面清单；未取得上述信息前，不得以本 PRD 推导具体尺寸、颜色或元素位置。

## 四、验收要点

1. Banner 前台不再叠加独立标题、副标题或按钮组件。
2. 编辑页只展示当前终端的图片上传位，全部已启用语言纵向展开；当前终端任一语言缺图时不能上线，缺图可保存下线草稿。右侧横向语言页签正确展示图片、缺图空态及红绿状态。
3. 存量 Banner 未重新上传新版完整图片时不能发布。
4. 新语言缺少任一已上线 Banner 图片时不能启用。
5. 所有客户端事件按规则携带当前实际生效的 `locale_code`；语言上下文未取得时不伪造默认值。
6. Banner 圆点切换、手势切换及整图点击均携带事件发生时的 `position_id`，取值为 `1–4`。
7. Banner 整图点击使用 `banner_item`，单次点击只上报一次；图片中的按钮视觉不形成独立点击事件。
8. PC、Mobile Feed 的 Tab 顺序符合 §2.2.1，`Deals` 是否展示按 §2.2.4 验收。
9. `Deals` 商品池和排序分别符合 §2.2.2、§2.2.3。
10. 按 §2.2.4 验证商品池数量为 19、20 个及跨越门槛时的 Tab 显隐。
11. Shop 每个一级导航只展示一种图卡样式，两级和三级导航均能正常展示横向大图。
12. Shop 横向大图使用末级导航名称作为图片中央文案，点击后按已配置目标跳转。
13. Shop 末级导航缺少当前展示样式的图片时不能保存。
14. 首页 Banner、首页 Collection 和 Shop 导航图片上传区显示 2.4 规定的尺寸要求。
15. 首页和 Shop 后台的字段错误、上传失败、保存失败、状态失败及加载失败按 2.5 展示，且失败后已填内容不丢失。
16. PC Web 的单条删除和 `Clear all` 常驻展示且无需确认；Mobile Web 与 App 仅在进入删除模式后展示单条删除和 `Clear all`。
17. Mobile Web 与 App 清空全部前展示确认弹窗；取消后保持删除模式，确认后清空并退出删除模式。
18. 登录用户的删除结果可同步至同一账号的其他设备；删除操作不影响 Search event。
19. PC 导航按配置顺序列优先排列，每列最多 7 行；0、1–7、8–14、15–21、22–28、29 项及以上分别形成 0、1、2、3、4、5 列，并按 0、3、2、1、1、0 个推荐位展示。
20. 推荐位缺少图片、标题文案、说明文案或 Collection 时不能保存；完整配置后前台图片及两段文案展示正确，点击进入所选 Collection。

21. 同一 Market 下两个国家使用相同语言时，四类运营内容仍分别命中各自国家配置；修改、排序和启停互不影响。
22. 配置页只允许按国家切换配置；Market 不作为运营配置维度，由系统根据国家自动推导。
23. 切换国家、刷新、返回及加载失败后，页面不混用其他国家内容，跳转保持当前国家上下文。
24. 未开放 Sell 的国家隐藏 Footer、Contact Us 及其他页面相关入口和信息；直接访问不能发起新的 Sell 服务申请。
25. Footer 的 Shop 链接、法律文件和社媒账号与当前国家配置一致；法律文件与 Contact Us 共用适用国家的有效版本。

26. 国家公共参数与页面实际使用的配置一致；完成 2.8.5 引用文档的全部场景验收，并核对请求与落库；不因国家维度调整重复发送现有事件。
27. Mobile Web 与 App 的公共顶部导航在适用页面按最终 UI 展示；现有入口、跳转、登录态、吸顶及埋点行为不因样式调整发生变化，不同语言下无截断或重叠。
