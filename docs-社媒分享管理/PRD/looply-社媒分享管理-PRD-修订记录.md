| v1.1（修订） | 2026-09-15 | 产品 + Claude | **补充 2.3.2 短链点击解析的「参数合并规则」**，填补原 PRD 空白：原文仅写"302 重定向到 long_url"，未定义请求 URL 参数与 `long_url` 参数的合并策略，存在 FB / IG 点击时平台自动追加的 `utm_source=facebook` 覆盖短链已设置 UTM、导致归因错乱的风险。新增内容：① 确立核心原则 **`long_url` 原有参数优先，外部参数只补充不覆盖**；② 三类参数合并策略表——5 个 UTM 参数（含 `utm_term`）以 `long_url` 为准、同名外部参数直接丢弃，`fbclid` / `gclid` / `ttclid` / `msclkid` / `twclid` / `li_fat_id` 等 click ID 在 `long_url` 未设置时透传，其他 query 参数同名保留原值 / 新 key 透传；③ 实现细节 5 条：判定"已设置"以 key 存在为准（空值亦算已设置）、多值参数整体保留不逐值合并、`long_url` 参数排在前、fragment 以 `long_url` 为准、**明确不沿用 Short.io 的 `shortio_nomerge=1`**（属其私有约定，自建短链默认即目标 URL 优先，短链形态保持纯路径）；④ 三个场景示例（FB 追加 UTM+fbclid / IG 仅追加 click ID / 普通业务参数冲突）；⑤ 流程图步骤由 4 步扩为 5 步，跳转前显式插入合并环节；⑥ 异常处理新增 2 条：外部参数超长（阈值 512 字符）或含控制字符则丢弃、URL 总长超 2048 按"UTM → click ID → 其他"从低到高裁剪且 `long_url` 原参数永不裁剪，以及跳转目标只取自 `long_url`、外部参数不得改写 host / path 以防 open redirect。 |
