# Looply 支付渠道技术配置参考 v1.0

> 日期：2026-09-23｜适用：支付服务技术接入配置｜产品后台不维护商户账号或密钥

## 一、配置边界

“收单配置 > 支付方式”只维护支付方式名称、唯一编码、支付通道和启用状态。商户账号、Client ID／Client Secret、API Key、Webhook 密钥、证书与运行环境由技术侧支付接入配置维护，不在运营后台新增、编辑或展示。

创建支付单时，支付服务根据支付方式、Market、币种和运行环境解析实际使用的商户账号与凭证，并把稳定的账号标识写入支付单。后续查单、回调、退款和对账按支付单记录处理，不能重新按当前配置猜测原账号。

## 二、三种支付方式的技术配置参考

| 支付方式 | 支付通道 | 技术侧需要维护 | 运行校验 |
|---|---|---|---|
| PayPal | PayPal | Merchant ID／payer_id、Live REST App Client ID、Client Secret、Webhook ID／签名校验配置、环境、凭证版本 | US／USD 与 HK／HKD 的收款、查单、回调、部分／全额退款与对账均通过联调 |
| Credit Card | Airwallex | Airwallex 账号或内部连接 ID、API Client ID／API Key、Webhook 配置、环境、凭证版本 | US／USD 与 HK／HKD 的卡支付、退款、3DS 和回调通过联调 |
| Apple Pay | Airwallex | Airwallex 账号或内部连接 ID、API 凭证、Apple Pay 能力开关；按接入模式维护域名验证、Merchant ID 与证书状态 | US／USD 与 HK／HKD 均可在受支持设备和浏览器拉起钱包并完成收款退款 |
| Klarna | Airwallex | Airwallex 账号或内部连接 ID、API 凭证、Klarna 支付能力与地区配置 | 仅开放 US／USD；不为 HK Market 建立路由 |

Credit Card、Apple Pay 与 Klarna 可以使用同一个 Airwallex 技术账号，但它们仍是三个独立支付方式；是否能在某个 Market 展示由收单路由决定。

## 三、支付单记录要求

支付单至少记录支付方式、支付通道、渠道订单号、实际账号稳定标识、金额、币种和状态。V1.5 还要求支付单记录原父订单的 Market。敏感凭证只保存引用或版本号，不写入支付单、业务日志或运营后台。

技术侧调整账号或凭证映射后，只影响新支付。历史支付继续按支付单记录的账号标识与凭证版本处理；若旧凭证已轮换，技术侧需保证历史交易仍能查单和退款。

## 四、上线检查

1. 生产与沙箱配置完全隔离。
2. 每个 Market、币种、支付方式组合都有明确的技术路由结果。
3. Webhook 可定位到原支付单，并校验通道、金额和币种。
4. 支付单已保存实际账号稳定标识，退款不依赖产品后台当前配置。
5. 凭证不可用时阻断新支付，并产生技术告警；运营后台不提供修改密钥的入口。
