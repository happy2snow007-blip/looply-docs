## 二、一条贯穿全文的取值规则：一律取下单时冻结的快照

导出和详情页要展示的品牌、商品标题、成色、HBLitemID、渠道商品ID、优惠码码值，**一律取下单成交那一刻冻结下来的值，不在展示或导出时回查商品域和营销域**。

这条与 C 端订单 PRD v1.5 §1.5 的既定原则一致（「一律读下单时冻结的订单快照，不实时回查商品/翻译/字典」）。

## 三、订单导出

线上已有一版导出（9 列：`类型 / 订单号 / 父订单号 / 买家邮箱 / 订单状态 / 币种 / 订单金额 / 商品数 / 下单时间`），本次在其基础上扩充字段并明确规格。

**目标态共 40 列 = 保留现有 9 列 + 新增 31 列**（§3.3 中 ✅ = 现有、★ = 新增）。

**现有列名一律沿用，只改一个**：「商品数」→「**订单商品总数**」。因为改成一行一商品后，「商品数」会被读成"这一行几件"，而它的实际含义是"这一单共几件"。其余 8 列列名不动，减少运营的适应成本。

### 3.1 导出粒度：一行一商品

订单里运营关心的动作几乎全发生在商品行——**发货按件**（支持分批）、**退款按件**（退款状态是商品级的唯一事实源）、**红布林建单按件**（一单一件）、**找货按 HBLitemID 按件**。一行一订单表达不了「两件里退了一件」「第一件发了第二件没发」，而这正是运营每天要看的。

多商品单的金额重复问题用输出规则解掉：

| 金额类型 | 输出规则 |
|---|---|
| **商品级**（优惠分摊、实付小计、本行退款金额） | 每行都是本行真值，可直接求和 |
| **订单级**（订单优惠合计、订单金额） | **只在该订单的第 1 行输出，其余行留空**，这样求和仍然正确 |

另给「订单内序号」（1、2、3…）与「订单商品总数」两列，一眼看出这单几件、当前是第几件。

### 3.2 导出范围

- 导出结果**必须与列表当前筛选条件下看到的数据完全一致**，不能出现「列表 100 条、导出 120 条」
- 列表默认展示子单，导出沿用列表口径；同时输出父订单号列供合并统计
- 弹窗里的「N 条」按**订单**计数（与列表一致），实际行数为这批订单的商品行数之和，弹窗提示需写明，避免运营以为导多了

### 3.4 退款金额与日期的取数规则（**开发重点**）

退款有两个来源，只查一处会漏。2026-09-03 实测 100 个子单：只查订单发起的退款单，会漏掉售后单产生的退款（漏了 2 笔，含一笔 $333）。

**按两段优先级取数，并强制输出来源列：**

| 优先级 | 数据源 | 「退款数据来源」输出 |
|---|---|---|
| 1 | 支付侧退款单（订单发起） | 支付退款单 |
| 2 | 支付侧退款单（售后单发起） | 售后退款单 |
| — | 两处都取不到，但商品退款状态 = 已退款 | **记录缺失**（金额与日期留空） |

**两条硬性要求：**

1. **判定「退了没有」始终以商品的退款状态为准**，不以能否查到退款单为准。
2. **退款状态 = 已退款却取不到金额时，必须输出「记录缺失」，不得静默留空。** 留空会被运营读成「这单没退款」，对账时直接对不上。

> **「记录缺失」不是异常兜底，是本期预期会出现的一类值。** 实测 100 单中有 9 单，操作日志写着「审批通过，退款单 3035…」，但按该号查询返回「退款记录不存在」——本期**不从操作日志取数**（产品 2026-09-09 定），这批单会全部落到「记录缺失」：金额与日期留空、来源列标「记录缺失」。这是有意为之——**让这批坏数据在导出里显形，而不是伪装成「没退款」**。

> **⏳ 待产品拍板：退款金额要不要落到具体商品行。**
> 实测发现退款申请侧记的「退款商品」标识与订单商品行的标识不是同一套编码，当前拿不到「这笔退款退的是哪一件」。
> · **作为本期硬性要求** → 研发先对齐两侧标识，一单多件的退款金额才落在对的那一行。
> · **本期不做** → 退款金额只在订单第 1 行输出订单级合计，「退款数据来源」列标 `订单级合计`。**代价**：一单两件退了其中一件时金额恒落在第 1 行，退的正好是第 1 件才对、退第 2 件就错，而运营从表上看不出这一行是真值还是合计。

### 3.5 优惠码列的取值

营销 v2.4 已定：**一单可以有多个码同时生效**，前提是作用于不同商品行；单个商品行至多生效一条折扣。所以「本行优惠码」至多一个，「订单全部优惠码」是该单全部生效码去重后分号连接、只在第 1 行输出。码值一律**大写**输出（与营销侧存储口径一致）。自动折扣无码，两列留空。

### 3.6 通用规则

| 规则 | 内容 |
|---|---|
| **时区** | **一律按美东时间（US/Eastern）输出，表头注明**（例：`付款时间（美东）`）。含夏令时，按美东当地时间的自然日切分。不这么做的话，导出的日期会和运营在页面上看到的对不上、按天切数据全错 |
| 时间格式 | `YYYY-MM-DD HH:mm:ss`，不导出时间戳 |
| 空值 | 一律留空，不填「无」「未知」「-」——空值在 Excel 里能直接筛选和计数，占位文本不行 |
| 金额 | 数值型，不带货币符号（币种单列输出），便于直接求和。**按币种标准小数位输出，USD 保留 2 位**——现有导出是 4 位（`605.0000`），在 Excel 里既占宽又容易被误读成有零头 |
| 枚举值 | **一律导出中文展示值，与页面保持一致，不导出英文枚举名**。现有导出的订单状态是 `paid` / `cancelled`，运营需要自己对照 |

## 四、订单详情页

### 4.1 优惠信息表格增加「优惠码」列

在现有「优惠类型 / 优惠名称 / 优惠金额 / 分摊明细」之间加一列**优惠码**，展示码值（大写等宽字体，如 `SAVE30`），自动折扣显示 `—`。一单多码时按码分行展示。

C 端不受影响：营销 v2.4 已定码值不透传 C 端，本次只改运营后台。

### 4.2 商品名称前加品牌

**渲染为两行，不拼成一个字符串：**

```
LOUIS VUITTON                ← 品牌，全大写，次级文本样式
Vintage Monogram Speedy 30   ← 商品名称，正文样式
```

与 C 端订单详情的既定形态一致（品牌大写灰色小字在商品名上方）。

### 4.3 收货地址一键复制

在「收货地址」区块标题右侧加「复制地址」按钮，点击把下列**多行文本**复制到剪贴板，并给「已复制收货地址」的成功提示：

```
Sarah Johnson
+1 213-555-0147
1234 Sunset Blvd
Apt 5B
Los Angeles, CA 90028
United States
```

| 规则 | 说明 |
|---|---|
| 格式 | 按美国地址书写规范：姓名 / 电话 / 地址行1 / 地址行2 / `城市, 州 邮编` / 国家 |
| 空字段 | 地址行 2 为空时整行不输出，不产生空行 |
| 国家 | 输出全称 `United States`，不输出 `US`——快递系统识别全称 |
| 账单地址 | 同样加复制按钮，格式一致 |

## 五、订单列表页

### 5.1 新增 5 个查询维度

| 维度 | 匹配方式 | 说明 |
|---|---|---|
| 渠道商品ID | 精确 | — |
| HBLitemID | 精确 | ⚠️ 是商品属性值，不是 `hbl_info_id` |
| 红布林订单号 | 精确 | 一单一件 1:N，命中任一即返回该订单 |
| 物流单号 | 精确 | — |
| 收件人 / 地址 | **模糊** | 同一个关键词同时在收件人姓名与收货地址各字段（地址行 1/2、城市、州/省、邮编）中匹配，任一命中即返回。例：搜 `Sunset` 命中地址 `1234 Sunset Blvd`，搜 `Johnson` 命中收件人 `Sarah Johnson` |

### 5.2 筛选区重构

现有 6 个控件 + 新增 5 个 = 11 个，平铺会占三行、把列表可视区压掉。**把只会单独使用的精确匹配 ID 类收进一个「搜索类型下拉 + 关键词输入框」**，其余保持独立控件：

```
第一行： [搜索类型 ▾][关键词输入框    ]  [买家邮箱]  [收件人 / 地址]  [卖家ID]
第二行： [子单类型 ▾]  [取消原因 ▾]  [开始日期 — 结束日期]   [查询] [重置]
状态 Tab： 全部 | 待付款 | 已付款·待发货 | 已发货 | 已完成 | 已取消
```

**「搜索类型」下拉**（默认「订单号」）：订单号 / 父订单号 / 渠道商品ID / HBLitemID / 红布林订单号 / 物流单号。

**为什么 ID 类可以合并**：这六项都是「手上有一个号，找它属于哪张单」，一次只会用一个，不存在同时按渠道商品ID 和物流单号搜的需求。而买家邮箱、收件人/地址、卖家ID、日期、状态是**筛选**，天然要互相组合，必须独立。

### 5.3 「查看详情」改为新标签页打开

列表的**「订单号」列**与**「查看详情」按钮**均改为在新标签页打开，样式不变，且必须同时满足四条浏览器原生行为（实现方式由技术方案定，但用脚本弹窗的做法满足不了，做之前先确认）：

| 行为 | 为什么运营需要 |
|---|---|
| 直接点击 → 新标签页 | 本需求主诉求 |
| **Cmd/Ctrl + 点击** → 新标签页 | 批量处理时连点多单，一次开一批 |
| **鼠标中键点击** → 新标签页 | 同上，比按修饰键更快 |
| **右键 → 在新标签页打开 / 复制链接地址** | 把某一单发给同事跟进，每天都在做 |

其他跳转（发货、发起退款）保持当前窗口内的弹窗，不变。

**建议一并做**：列表的筛选条件也体现在地址里。做了之后从新窗口切回列表、或刷新列表页，筛选条件不丢，也能把「筛好的这一批」发给同事。不做的代价：运营筛完一批订单，刷新一下就要重筛。

## 六、验收要点

| # | 验收项 | 判定 |
|---|---|---|
| 1 | 一单两件商品的导出 | 输出 2 行；订单金额、订单优惠合计只在第 1 行有值、第 2 行为空；两行的「订单内序号」分别为 1、2 |
| 2 | 一单两件、只退了其中一件 | 退款金额只出现在被退的那一行；另一行退款状态「无退款」、金额空 |
| 3 | 退款状态已退款但退款单查不到 | 「退款数据来源」输出「记录缺失」，不是空 |
| 4 | 非红布林来源商品 | HBLitemID、红布林订单号两列为空，不报错、不填占位符 |
| 5 | 一单多码 | 「订单全部优惠码」列出全部码；每个商品行的「本行优惠码」只有作用于它的那一个 |
| 6 | 导出条数与列表一致 | 列表筛出 N 单，导出文件「订单内序号 = 1」的行数 = N |
| 7 | 导出时间 | 全部美东，与页面展示逐条一致，表头标注「（美东）」；跨夏令时切换日不出现 1 小时偏移 |
| 8 | 导出枚举与金额 | 订单状态是中文（不是 `paid`）；金额是 2 位小数（不是 `605.0000`） |
| 9 | 详情页复制地址 | 粘贴为 5~6 行；地址行 2 为空时不出现空行；国家是 `United States` |
| 10 | 详情页品牌 | 品牌与商品名分两行；历史订单无品牌时不留空行 |
| 11 | HBLitemID 搜索 | 已知 HBLitemID 能命中该订单；拿一个 `hbl_info_id` 搜索应搜不到 |
| 12 | 新标签页打开 | 直接点击、Cmd/Ctrl + 点击、鼠标中键、右键菜单四种方式都能开新标签；刷新不白屏 |
| 13 | 导出留痕 | 操作日志能查到本次导出的操作人、时间、筛选条件、订单数与行数 |
