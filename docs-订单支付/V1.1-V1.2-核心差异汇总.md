## 2. 一句话概括本次改动

本次是一次**订单数据模型层面的改造**，核心是两件事：

1. **支付后拆单**：下单时只创建整体订单 `parent_order`（待付款态），支付到账后才按商家拆出子订单 `order`。待付款态从子订单上移到父订单层。
2. **取消时序修复**：已付款订单取消，改为「退款成功后才置已取消」，退款失败则挂人工、订单保持已付款。

外加待付款超时、同步/异步支付（风控）、库存锁定时机前移等配套变更。

## 4. 新增功能 / 新增内容

### 4.1 待付款态（pending_payment）与支付后拆单

- 下单点击 Buy Now → 只创建 `parent_order`（起始 `parent_status = pending_payment`），**不创建子订单**。
- 支付到账 Webhook → `parent_order` 转 `paid`，**此时才**按商家拆出 N 个 `order`（起始 `order_status = paid`）并生成 `order_item`。
- C 端订单列表：待付款只显示一条整体订单、只需付一次款；支付后按商家展示多条子订单。
- 后台订单列表：新增「待付款」Tab（查 parent_status = pending_payment 的父订单）。

### 4.2 待付款超时机制

- 新增 `payment_deadline` = 下单 + 1 自然日（连续计时、周末不延后）。
- 超时未到账或支付失败 → parent_order 转 cancelled + 关闭支付单（closed）+ 释放锁定库存。此时无子订单、无退款。
- **需要定时/延时任务**扫描超时父订单。

### 4.3 同步 / 异步支付（卡风控审核）

- 同步渠道（卡未命中风控）：数百毫秒到账，C 端等结果跳订单成功页（Order Confirmed）。
- 异步（卡命中风控审核）：支付单停 `processing`、parent_order 停 pending_payment，C 端跳「订单已提交」页（Order Placed / Payment Processing 变体）。
- 需支付回调二次驱动状态流转。

### 4.4 新增页面 / 变体

- **C 端订单成功页待付款变体**（parent_order = pending_payment）：标题 Order Placed，文案 "We're processing your payment. We'll confirm within 1 day."，不显示 "Thank you for your purchase"，CTA View Order。

### 4.5 新增邮件（邮件方案 v1.1，共 5 个模板）

| 模板 | 触发时机 | 本次是否新增 |
|------|---------|------------|
| #1 订单支付成功确认 | 支付到账 → order 转 paid | 既有 |
| #2 订单发货通知 | 运营确认发货 | 既有 |
| #3 退款成功通知 | 退款成功 Webhook | 既有 |
| **#4 订单已接收（仅异步场景）** | 下单创建 parent_order(pending_payment) 且进入风控审核 | **新增** |
| **#5 订单取消通知（待付款失败/超时）** | 待付款订单转 cancelled | **新增** |

- 发送策略（防打扰）：即时到账仅发 #1 一封；异步场景下单先发 #4，到账再发 #1，共 2 封。
- 静默注册「设置密码」链接：异步场景挂在 #4（首封）上。

## 5. 数据模型变化（ER v8.0 → v9.1）

### 5.1 parent_order（父订单）新增 4 字段

| 字段 | 类型/说明 |
|------|----------|
| `parent_status` | 父订单状态：pending_payment / paid / cancelled |
| `payment_deadline` | 待付款超时时间（下单 + 1 自然日） |
| `paid_at` | 付款到账时间 |
| `cancelled_at` | 取消时间（待付款取消） |

> parent_order 从 9 字段变为 13 字段，**需要 DDL 变更 + 迁移脚本**。

### 5.2 order（子订单）无字段增删，语义变化

- `paid_at` 说明改为「付款到账时间（继承父订单）」。
- 表语义：支付到账后才按商家拆分（起始 paid）。
- **注意**：order 表两版都没有 `payment_deadline`，不存在「从 order 迁移」——超时字段是本次**新增**到 parent_order。

### 5.3 枚举变化

| 枚举 | 变化 |
|------|------|
| `parent_order.parent_status`（全新维度） | pending_payment / paid / cancelled |
| `order.order_status` | paid / shipped / completed / cancelled（**起始即 paid，不再含 pending_payment**） |
| `checkout_session.checkout_status` | converted 语义：由「支付成功转化」→「提交支付时转化」 |
| `payment_order.status` | pending / processing / succeeded / failed / closed（processing 在原型 v5 已存在，非本次新增；以 PRD/ER 为权威） |

> 其余表（order_item / order_package / refund_request / refund_order / payment_transaction / order_discount 等）字段与关系两版一致。

## 6. 流程变化（系统流程图 v1.0 → v2.0）

### 6.1 段落结构

| v1.0 | v2.0 |
|------|------|
| ① 结算与**支付** | ① 结算与**下单** |
| ④ 订单取消 + ⑤ 退款处理（两段） | ④ 订单取消**与退款**（合并为一段） |

### 6.2 拆单时机（核心变更）

- v1.0：① 段点 Place Order → ② 段支付成功后「创建父订单 + 按商家拆子订单」（父子订单同时创建）。
- v2.0：① 段「创建 parent_order(待付款)、挂父订单快照、暂不拆单」→ ② 段到账后「parent_order 转已支付 + 按商家拆子订单(起始 paid) + 生成子订单明细」。

### 6.3 库存锁定时机 + 术语（双变）

- v1.0：**支付成功时**预占库存；术语「预占」。
- v2.0：**下单即锁**库存（锁在 parent_order）；术语统一为「锁定」；发货时「锁定转实扣」。
- 需处理：下单锁定后支付失败/超时的释放逻辑。

### 6.4 取消时序（核心变更）

- v1.0：取消 → 立即「订单状态→已取消」→ 再退款。
- v2.0：
  - **未付款分支（新增）**：parent_order→已取消 + 关支付单 closed + 释放库存，**结束不退款**。
  - **已付款分支**：创建退款申请 → 商品退款中（**订单暂不改状态**）→ 通道退款 → Webhook →「**退款成功后才置订单已取消**」；退款失败→「挂人工，订单不置取消」。

### 6.5 弃单边界明确化

- v2.0：弃单 = 进入结算但未提交支付的会话（checkout_status=pending）；**已提交支付的待付款订单不属于弃单，归订单管理**。

## 7. 开发关注重点（按优先级）

1. **【最高】订单创建时机改造**：parent_order 从「支付成功创建」改为「下单创建（待付款）」；子订单拆分 + order_item 生成从下单挪到支付到账回调里。落库时机、事务边界、幂等键都要改。所有依赖「下单即有子订单」的逻辑需按新时序重排。

2. **【高】parent_order DDL 变更**：新增 parent_status / payment_deadline / paid_at / cancelled_at 四字段 + 迁移脚本。待付款态生命周期只在 parent_order 维护，子订单不含待付款态。

3. **【高】取消置位时序**：已付款取消必须等退款成功回调后才置 order 为 cancelled；退款失败要挂人工、订单保持 paid，**不能提前置 cancelled**。任何「取消即完结/即释放库存」的旧实现要改。

4. **【高】待付款超时任务**：基于 payment_deadline（下单+1自然日）的定时/延时任务，超时→关支付单→走未付款取消（释放库存、不退款）。

5. **【中】库存锁定时机前移**：从「支付成功」提前到「下单点 Place Order」，锁定主体是 parent_order；处理下单后支付失败/超时的释放。术语由「预占」统一为「锁定」。

6. **【中】同步/异步支付分岔**：命中风控 → 支付单 processing、parent_order 停待付款、前端跳「订单已提交」页；需支付回调二次驱动状态。

7. **【中】前端页面**：新增「订单已提交」页（异步）；C 端订单列表待付款展示一条父订单；订单成功页两套变体（Order Confirmed / Order Placed）。

8. **【中】邮件**：异步场景多发一封 #4「订单已接收」（下单时），到账再发 #1；同步只发 #1。静默注册设置密码链接在异步场景挂 #4。

9. **【低】checkout_session 转化时机**：由「支付成功」改为「提交支付时（converted）」，弃单判定口径 checkout_status=pending。
