Order Detail - APP v3

All order status states in one prototype · click tabs to switch
1 Fulfillment Groups
Design Pattern
StateItems are grouped by fulfillment package/status, not listed flat. Each group contains: status header + next-step guidance (delivery ETA / ship date / refund details) + items + tracking (if applicable). Driven by order_shipment + order_item.fulfillment_status in ER.
Confirmed State 1
StatePartial refund before shipping: Package 1 (Preparing) with ship date + delivery ETA. Refund group with refund amount, reason, processed date. Shows refund can happen at any stage, not only after delivery.
On its way State 2
StateTwo groups: Package 1 (Shipped) with delivery ETA + mini-tracking + "Track This Package" link. Package 2 (Preparing) with est. ship date + delivery window. Each package shows only its own items.
Completed State 3
StateTwo groups: Package 1 (Delivered) with signed-by info + tracking. Refund group with refund amount, reason, processed date, and refund method. Each group shows only its relevant item.
Cancelled State 4
StateFull cancellation uses refund banner + cancellation details card (reason, refund status). "Refund completed" is tappable → opens bottom sheet with full refund details (ID, items, amounts). Items shown flat with reduced opacity.
2 Next-Step Guidance
Preparing Group
StateBlue guidance block: "Preparing for shipment" + estimated shipping date + delivery window. Tells user when to expect shipment.
Shipped Group
StateBlue guidance: "On the way to you" + delivery ETA. Below items: mini-tracking (latest event + 1-2 previous) + "Track This Package" link. User knows exactly where their package is.
Delivered Group
StateGreen guidance: "Delivered on [date]" + signed-by info. Mini-tracking shows delivery confirmation. "View Tracking History" for full log.
Refunded Group
StateRed guidance: "Refund completed on [date]" + amount + return method. Detail rows: reason, refund method, processed date, refund amount. User sees full refund lifecycle.
3 Information Architecture
Three-Card Split
StateBottom section split into 3 cards by information domain: Shipping & Delivery (logistics: where it goes) → Payment (financial: how you paid + billing address) → Order Summary (amounts: subtotal/tax/total/refund). No mixing of concerns.
Billing Address
StateLives in Payment card (not Shipping). Billing address = credit card verification / invoice address, financial info not logistics. When same as shipping: "Same as shipping address" (italic gray).
4 Actions by Status
No Cancel Order
Edge CaseC-end does not support Cancel Order. Users who need to cancel should contact support.
Confirmed
TapContinue Shopping (purple outline) + Contact Support.
On its way
TapTrack All Packages (primary) + per-group "Track This Package" link + Contact Support.
Completed
TapBuy Again (primary) + Contact Support.
Cancelled
TapContinue Shopping (primary). "Refund completed" → bottom sheet with refund ID, reason, method, refunded items, total amount.
5 Order Summary & Refund
Normal Flow
StateSubtotal + Shipping + Tax = Total. On its way state shows this (no refund in that scenario).
Partial Refund
StateConfirmed & Completed both show partial refund: total remains, green "Refund (1 item) - $X" line, bold "You paid" net amount. Refund can happen at any stage (before shipping, after delivery). Detail lives in Refund fulfillment group.
Full Refund
StateCancelled: total strikethrough, green "+ $X" refund, "Refunded to" replaces "Paid with".
