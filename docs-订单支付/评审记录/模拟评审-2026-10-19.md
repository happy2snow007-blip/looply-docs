# 未支付订单提醒与支付失败续付——模拟评审记录

> 日期：2026-10-19  
> 结论：P0、P1 问题已全部闭环，可进入开发评审。

| 级别 | 评审问题 | 处理结论 |
| --- | --- | --- |
| P0 | 多订单默认目标在“可操作优先”和“最早到期”之间存在歧义 | 统一定义“优先目标订单”：可继续支付优先，同类中最早到期 |
| P0 | 普通支付截止时间与渠道风控审核延期缺少边界 | 明确仅渠道已返回风控审核中时进入最长 72 小时确认期，禁止再次支付 |
| P0 | 取消／库存释放后收到迟到成功的处理不明确 | 取消完成前成功优先；取消完成后不恢复订单和库存，进入现有支付异常人工处理链路 |
| P1 | “本次会话”及关闭后新增订单的规则不明确 | 定义账号会话边界、PC 跨标签一致性及新增父订单可重新提醒 |
| P1 | Me 红点重新点亮事件不完整 | 补齐新增订单、确认转失败、再次明确失败及后台状态修正四类事件 |
| P1 | Me 红点与首页卡片缺少可开发的 PC／APP 设计 | 新增响应式 HTML 原型，覆盖单笔、多笔、确认中、已读及终态 |
| P1 | 订单详情确认中／到期原型仍保留错误动作 | 确认中隐藏支付按钮；到期仅允许查看商品或继续浏览 |
| P2 | Me 首页可能同时出现横幅和卡片 | 将 Me / Account Home 加入横幅排除页面 |
| P2 | 代表商品选择规则未定义 | 固定取父订单冻结商品明细第一件 |
| P2 | “立即更新”不可测试 | 改为动作响应或下一次成功资格刷新后更新，并明确前后台恢复触发 |

## 遗留项

无阻塞开发的遗留问题。本期不修改 ER，不新增支付方式，不扩展邮件、短信或 Push 催付。
