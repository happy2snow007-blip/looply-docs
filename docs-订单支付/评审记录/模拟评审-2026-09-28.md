## 二、问题与闭环结果

| # | 级别 | 问题 | 处理结论 | 落点 |
|---|---|---|---|---|
| 1 | P0 | 商品金额汇总被误当作订单实付，运费税费场景取消阈值错误 | 订单实付、订单累计成功退款、订单剩余应退均读取整单；商品金额单独汇总 | 迭代 PRD §1.4、§3.2；完整 PRD §2.4、§4.1.2；原型 v34 |
| 2 | P0 | 历史部分退款后，按“本次金额等于原实付”无法识别取消退款 | 取消订单退款定义为退回订单当前全部剩余应退；从提交起阻断发货 | 迭代 PRD §1.4、§2.4；完整 PRD §2.4、§4.7 |
| 3 | P0 | 取消退款含运费税费，但商品明细无法承载差额 | 申请总额由商品剩余应退、应退运费和应退税费组成；总额与商品明细差额为订单费用退款金额，只计入订单累计 | 迭代 PRD §2.2–2.3；完整 PRD §2.4、§4.7 |
| 4 | P0 | 同一商品并发退款可能超退 | 同一商品同一时刻只允许一笔未结束申请；终态后允许再次部分退款 | 迭代 PRD §2.2、§6；完整 PRD §2.2.2、§4.7 |
| 5 | P0 | 发货与最后一笔退款成功并发时结果不唯一 | 发货先完成则保留履约事实后取消；取消先完成则后到发货失败 | 迭代 PRD §2.5；完整 PRD §2.4、§4.7 |
| 6 | P0 | 状态机只允许已付款转已取消 | 累计成功退款达到实付时允许已付款、已发货、交易完成转已取消；商品与包裹事实保留 | 完整 PRD §2.2.2–§2.4 |
| 7 | P0 | 退款记录无法覆盖审批和资金全阶段 | 分开显示申请状态与资金状态；未创建退款单时资金状态为“未开始” | 迭代 PRD §3.5；完整 PRD §4.1.2；原型 v34 |
| 8 | P1 | C 端退款展示范围一度被误判为需要改版 | 核实后确认规则未变：只展示订单级累计 Refund，不新增商品退款金额、分组、状态或交互；删除误新增的 C 端 PRD 与 UI 版本 | 迭代 PRD §5.2；完整 PRD“C 端订单详情联动规则” |
| 9 | P1 | 售后可退基准未扣发货前退款 | 售后退款基准改为商品实付减全部历史成功退款，不再写商品单一退款状态 | 售后 PRD v1.2 |
| 10 | P1 | “库存锁定”与库存域人工质量锁定混淆 | 全部改为释放该订单仍预占库存，不解除人工质量锁定 | 两版 PRD |
| 11 | P1 | 必填字段未参与提交条件 | 退款原因、承运商、快递单号纳入按钮校验；失败保留输入 | 两版 PRD；原型 v34 |
| 12 | P1 | 重复提交、重复回调可能重复累计和通知 | 同一业务动作只生效一次，不重复建单、累计、取消、释放库存或发邮件 | 两版 PRD |
| 13 | P1 | 失败重试与一申请一退款单关系不清 | 失败重试创建新申请和退款单，旧失败记录保留 | 两版 PRD |
| 14 | P1 | 金额精度、取消失败、库存释放失败无明确结果 | USD/HKD 按最小货币单位比较；定义“取消处理中”和库存异常任务 | 两版 PRD |
| 15 | P2 | 发货弹窗“单价／实付小计”口径不一致 | 两个入口统一展示商品实付小计 | 两版 PRD；原型 v34 |
