## P0（规则缺失或制品矛盾，阻塞开发）

### 1. [开发] ER 图有 ref_type 和 remark 字段，PRD 完全未提及

- **位置**：PRD §2.3 关联单据规则（第 398-404 行） vs ER v4.0 inventory_ledger（ref_type 第 34 行、remark 第 39 行）
- **问题**：ER v4.0 的 inventory_ledger 表有 `ref_type`（关联单据类型）和 `remark`（备注）两个字段，但 PRD 只定义了 `ref_no`（关联单据号）。开发不知道：
  - `ref_type` 应该填什么值？当关联订单时填 "ORDER"？枚举全集是什么？
  - `remark` 在哪些场景下写入？内容格式是什么？页面上是否展示？
- **建议**：
  - 方案 A：在 PRD §2.3 关联单据规则中补充 ref_type 枚举定义（如 ORDER / IMPORT_BATCH / MANUAL 等），并说明 remark 的写入场景
  - 方案 B：如果本期不使用这两个字段，在 PRD "不做什么"中注明，ER 图标注为"预留字段"

## P1（规则不完整，影响质量）

### 2. [开发] PRD 引用 ER v3.4，但实际交付包是 v4.0

- **位置**：PRD 头部第 7 行
- **问题**：PRD 写"对应 ER 图: 库存系统实体关系图 v3.4"，但 `交付开发 V1.0-20260518/` 目录下交付的是 v4.0.svg。开发拿到的 ER 图版本与 PRD 声明不一致，容易引起困惑。
- **建议**：PRD 头部改为 v4.0

### 3. [开发] 行内增加在库数量一律生成"入库"事件，无法区分真正入库 vs 盘盈调整

- **位置**：PRD §2.4 触发条件（第 462 行）vs §2.3 枚举定义（第 360 行）
- **问题**：§2.4 规定"行内编辑在库数量（增加）→ 事件类型=入库"，但 §2.3 枚举中"调整"的含义包含"盘盈补入"，状态流转表也有"调整（增加）: - → 在库（盘盈补入）"。当运营人员因盘点发现多出 5 件商品而增加在库数量时，系统生成的是"入库"事件而非"调整"事件，流水记录的业务语义不准确。
- **建议**：
  - 方案 A（简单）：本期不区分，所有增加 = 入库，所有减少 = 调整。在 §2.3 枚举中删除"调整（增加）/盘盈补入"这一行，保持一致
  - 方案 B（精确）：行内编辑增加时弹出选择"入库/盘盈调整"，用户明确意图后生成对应事件类型

### 4. [测试] 批量导入对已有库存记录的商品是新建还是累加

- **位置**：PRD §2.2 操作流程（第 256-263 行）
- **问题**：当批量导入的 Excel 中包含一个已有 inventory_item 记录的商品（如 PRD-20056 已在库 350 件），导入 100 件时：
  - 是新建一条 inventory_item 记录（quantity_on_hand = 100），还是在已有记录上累加（350 + 100 = 450）？
  - 如果累加，流水的 from_status 应该是"在库"还是"-"？
  - PRD §2.2 只说"系统批量创建库存记录"，"创建"一词暗示新建，但业务上同一商品不应有多条库存主体记录
- **建议**：明确说明"若商品已有库存记录，则累加在库数量，生成入库流水；若为新商品，则创建库存记录"

### 5. [开发] 搜索框写"支持按商品名称、SKU 模糊搜索"，但无 SKU 字段

- **位置**：PRD §2.1 工具栏（第 119 行）
- **问题**：库存总览工具栏写"支持按商品名称、SKU 模糊搜索"，但：
  - §2.1 数据表格列定义中没有 SKU 列
  - ER v4.0 inventory_item 也没有 SKU 字段
  - ER 中 product 表也没有 SKU 字段（仅 product_id/product_name/product_type/brand_id）
  - 开发不知道 SKU 从哪来
- **建议**：
  - 方案 A：搜索范围改为"商品名称、商品ID"（与表格列一致）
  - 方案 B：如果确实需要 SKU 搜索，需要在商品系统依赖中说明 SKU 字段来源

## P2（描述可更精确）

### 6. [测试] 在库数量和锁定数量无上限定义

- **位置**：PRD §2.1 校验规则（第 165-170 行）
- **问题**：校验规则定义了下限（≥0）和关系约束（在库 ≥ 预占+锁定），但没有上限。当运营人员输入 999999999 时系统如何处理？数据库字段类型的上限是多少？
- **建议**：补充合理上限（如 INT 范围 2,147,483,647 或业务合理值如 9,999,999），或注明"无业务上限，受数据库字段类型约束"

### 7. [设计] 批量导入功能缺"交互说明"子段落

- **位置**：PRD §2.2
- **问题**：按 PRD 写作规范，页面型功能应包含"交互说明"子段落。§2.2 缺少以下交互说明：
  - 上传过程中是否显示进度条
  - 上传完成后是否自动触发校验，还是需要手动点击
  - 弹窗打开后，点遮罩层是否关闭（原型 maskClosable=false，PRD 未说明）
- **建议**：补充"交互说明"段落，至少覆盖以上三点

### 8. [开发] 校验规则与 max(0,...) 兜底的关系

- **位置**：PRD §2.1 校验规则（第 167-168 行）+ 可售库存定义（第 71、129 行）
- **问题**：校验规则禁止用户编辑后可售为负（在库 ≥ 预占+锁定），那 max(0,...) 兜底在用户编辑场景下永远不会触发。max(0,...) 实际上是防御系统操作（如：用户编辑后、保存前，订单系统预占了新库存）导致的瞬时负值。这个关系没有说清楚。
- **建议**：在 §2.1 可售库存说明或交互说明中加一句："校验规则防止用户编辑导致可售为负；max(0,...) 兜底处理系统并发操作导致的瞬时负值场景"
