## 一、概述

### 1.1 背景与目标

looply 是一个二手电商平台，同时支持二手商品（一物一码）和标品（批量库存）的售卖。库存管理模块负责管理所有实物商品的库存数量，记录库存变动流水，为运营人员提供库存查看和操作能力。

**本期目标**：
- 提供库存总览，运营人员可查看所有商品的库存数量
- 支持行内直接修改在库数量和锁定数量
- 支持批量导入入库
- 提供完整的库存流水记录，支持追溯和对账

### 1.2 不做什么

本期明确不做的功能：
- **渠道库存分配**：多渠道分配、渠道可售上限设置（ER 图已预留，后续迭代）
- **批次管理界面**：标品的批次查看、FIFO 扣减展示（ER 图已预留，后续迭代）
- **仓库管理**：仓库的增删改查（归属仓储模块）
- **在途库存管理**：采购在途、调拨在途的流程（ER 图已预留字段，后续迭代）
- **库存预警**：安全库存、缺货预警
- **库存盘点**：盘点任务、盘点差异处理

### 1.3 用户角色

| 角色 | 说明 | 权限范围 |
|------|------|----------|
| 运营人员 | 库存管理后台的操作者 | 查看库存、修改数量、批量导入、查看流水 |
| 系统 | 订单系统等自动触发 | 预占库存、释放库存、出库扣减 |

### 1.4 核心场景

1. **查看库存**：运营人员查看所有商品的库存数量（在库、预占、锁定、可售）
2. **入库操作**：运营人员通过行内编辑增加在库数量，或通过批量导入批量入库
3. **锁定/解锁**：运营人员通过行内编辑修改锁定数量（因质量问题、合规审查等）
4. **库存调整**：运营人员通过行内编辑修正在库数量（盘点差异、损坏报废）
5. **查看流水**：运营人员查看库存变动历史，支持按事件类型、时间范围筛选

### 1.5 全局页面流转

```
库存总览（列表页）──「查看库存流水」按钮──→ 库存流水（列表页）
库存总览（列表页）──「批量导入」按钮──→ 批量导入弹窗
```

页面共 2 个列表页 + 1 个弹窗，结构简单，无深层嵌套。

### 1.6 术语说明

| 术语 | 含义 |
|------|------|
| 在库数量（quantity_on_hand） | 实物在仓库中的总数量 |
| 预占数量（quantity_reserved） | 买家下单未付款时冻结的数量，由订单系统自动管理 |
| 锁定数量（quantity_locked） | 因质量问题、合规审查等原因人工锁定的数量 |
| 可售库存 | 实时计算：max(0, 在库 - 预占 - 锁定)，不展示负值 |
| 库存主体（inventory_item） | 库存管理最小单元，二手商品一物一码（在库数量=1），标品按商品×仓库维度汇总（在库数量≥1） |
| 库存流水（inventory_ledger） | 每次库存变动产生的不可变记录 |

### 1.7 多语言 / 多国家策略

本期库存管理后台仅面向内部运营人员，界面语言为中文，不涉及多语言。库存数据本身不区分国家（通过仓库所在国家间接区分）。

## 二、需求详细描述

### 2.1 库存总览

**功能类型**：页面型

#### 功能描述

库存总览是库存管理的核心页面，展示所有商品的库存数量汇总，支持运营人员直接在表格行内修改在库数量和锁定数量。

#### 前置条件

- 用户已登录库存管理后台
- 用户具有库存管理权限

#### 页面布局

页面结构（PC 端，无 APP 端）：
- 顶部：页面标题 + 操作按钮（批量导入）
- 统计卡片区：商品总库存、预占中、锁定中
- 工具栏：搜索框 + 查询/重置按钮
- 数据表格：库存列表
- 底部：分页器（每页 20/50/100 条，默认 20）

#### 页面元素

**统计卡片**（3 列）：

| 卡片 | 数据来源 | 说明 |
|------|----------|------|
| 商品总库存 | SUM(所有 inventory_item.quantity_on_hand) | 所有商品在库数量总和 |
| 预占中 | SUM(所有 inventory_item.quantity_reserved) | 所有商品预占数量总和 |
| 锁定中 | SUM(所有 inventory_item.quantity_locked) | 所有商品锁定数量总和 |

**工具栏**：

| 元素 | 类型 | 说明 |
|------|------|------|
| 搜索框 | 文本输入 | 支持按商品名称、商品ID 模糊搜索 |
| 查询按钮 | 主按钮 | 触发搜索 |
| 重置按钮 | 普通按钮 | 清空搜索条件，恢复默认列表 |

**数据表格列定义**：

| 列名 | 字段 | 对齐 | 可编辑 | 说明 |
|------|------|------|--------|------|
| 商品ID | product_id | 左 | 否 | 商品系统的商品ID |
| 商品名称 | product_name | 左 | 否 | 商品系统的商品名称 |
| 可售库存 | 计算值 | 右 | 否 | = max(0, 在库 - 预占 - 锁定)，不展示负值 |
| 在库 | quantity_on_hand | 右 | 是 | 点击数字可直接修改 |
| 预占 | quantity_reserved | 右 | 否 | 由订单系统自动管理 |
| 锁定 | quantity_locked | 右 | 是 | 点击数字可直接修改 |
| 入库时间 | entered_at | 左 | 否 | 首次入库时间 |
| 最近变动时间 | last_moved_at | 左 | 否 | 最近一次库存变动时间 |
| 操作 | - | 左 | - | 「查看库存流水」按钮 |

#### 操作流程

**主流程 — 查看库存**：
1. 进入库存总览页面，系统加载库存列表（默认按入库时间倒序）
2. 统计卡片显示汇总数据
3. 可通过搜索框筛选商品

**分支流程 — 行内编辑在库数量**：
1. 运营人员点击「在库」列的数字
2. 数字变为输入框，显示当前值，自动选中
3. 运营人员输入新数量
4. 按回车或点击输入框外部确认
5. 系统更新在库数量，同时生成一条库存流水记录
6. 数字短暂变绿色表示修改成功，然后恢复正常颜色
7. 可售库存列自动重新计算

**分支流程 — 行内编辑锁定数量**：
1. 操作方式与编辑在库数量相同
2. 修改锁定数量后，系统生成一条锁定/解锁流水记录
3. 可售库存列自动重新计算

**分支流程 — 查看库存流水**：
1. 运营人员点击某行的「查看库存流水」按钮
2. 跳转到库存流水页面，自动按该商品ID过滤流水列表
3. 搜索框显示该商品ID，列表仅展示该商品的流水记录

#### 校验规则

| 字段 | 规则 | 校验时机 |
|------|------|----------|
| 在库数量 | 必须为非负整数（≥0） | 输入框失焦时 |
| 在库数量 | 不能小于当前预占数量 + 锁定数量（否则可售为负） | 输入框失焦时 |
| 锁定数量 | 必须为非负整数（≥0） | 输入框失焦时 |
| 锁定数量 | 不能大于在库数量 - 预占数量（否则可售为负） | 输入框失焦时 |

#### 交互说明

- 可编辑字段（在库、锁定）hover 时出现浅紫色边框和背景，提示可点击
- 点击后原地变为数字输入框，紫色边框，背景浅紫
- 按 Enter 或失焦确认修改
- 修改成功后数字短暂变绿（1 秒），然后恢复
- 预占列不可编辑（由订单系统管理），无 hover 效果
- 「可售库存」列 tooltip 提示计算公式：可售库存 = 在库 - 预占 - 锁定
- 「在库」列 tooltip 提示：点击数字可直接修改（入库/调整）
- 「锁定」列 tooltip 提示：点击数字可直接修改，锁定后不参与可售计算
- 「预占」列 tooltip 提示：买家下单未付款时冻结的数量，由订单系统自动管理

#### 异常处理

| 场景 | 处理方式 |
|------|----------|
| 网络异常 | 修改失败时提示"操作失败，请重试"，恢复原值 |
| 输入非法值（负数、非整数） | 输入框失焦时校验不通过，提示错误信息，不提交 |
| 可售为负 | 校验不通过，提示"修改后可售库存将为负数，请检查" |
| 并发冲突 | 提交时后端检查版本号，冲突时提示"数据已被其他人修改，请刷新后重试" |

#### UI 关联

- PC 端原型：库存管理后台原型 V7 —「库存总览」页面（page-inventory-overview-list）

### 2.2 批量导入

**功能类型**：页面型（弹窗）

#### 功能描述

运营人员通过上传 Excel/CSV 文件批量入库，系统校验数据后预览结果，确认后批量创建库存记录。

#### 前置条件

- 用户在库存总览页面
- 用户点击「批量导入」按钮

#### 页面布局

弹窗结构：
- 操作步骤说明（蓝紫色提示框）
- 第 1 步：下载模板
- 第 2 步：上传文件（拖拽区域）
- 第 3 步：导入预览（校验结果表格 + 统计）
- 底部：取消 / 确认导入按钮

#### 页面元素

**操作步骤说明**：
1. 下载导入模板，按格式填写商品入库信息
2. 上传填写好的文件（支持 .xlsx / .csv）
3. 系统校验数据，预览导入结果后确认执行

**下载模板**：
- 提供「下载入库模板（.xlsx）」按钮
- 模板包含列：商品ID、商品名称（自动填充）、入库数量

**上传文件**：
- 支持拖拽上传或点击选择文件
- 支持格式：.xlsx、.csv
- 单次上传上限：500 条

**导入预览表格**：

| 列名 | 说明 |
|------|------|
| 行号 | 文件中的行号 |
| 商品名称 | 从商品系统匹配的名称 |
| 数量 | 入库数量 |
| 校验结果 | 通过（绿色标签）/ 失败（红色标签 + 失败原因） |

**统计信息**：
- 总条数、通过条数（绿色加粗）、失败条数（红色加粗）
- 说明"失败项将跳过"

**底部按钮**：
- 「取消」：关闭弹窗
- 「确认导入（N 条）」：N = 通过条数，执行导入

#### 操作流程

**主流程**：
1. 运营人员点击「批量导入」按钮，弹窗打开
2. 下载模板文件，按模板格式填写入库数据
3. 拖拽或选择文件上传
4. 系统解析文件，校验每行数据，展示预览结果
5. 运营人员确认无误，点击「确认导入」
6. 系统批量处理：若商品已有库存记录则累加在库数量，若为新商品则创建库存记录；每条记录生成一条入库流水
7. 弹窗关闭，库存总览刷新

#### 校验规则

| 校验项 | 规则 | 失败提示 |
|--------|------|----------|
| 商品ID | 必须在商品系统中存在 | "商品ID无效" |
| 入库数量 | 必须为正整数（≥1） | "数量无效" |
| 二手商品数量 | 二手商品入库数量必须为 1 | "二手商品数量必须为1" |
| 文件格式 | 必须为 .xlsx 或 .csv | "不支持的文件格式" |
| 文件大小 | 单次最多 500 条 | "超过单次导入上限500条" |
| 重复行 | 同一商品ID不能重复出现 | "商品ID重复" |

#### 异常处理

| 场景 | 处理方式 |
|------|----------|
| 文件格式不支持 | 上传区提示"不支持的文件格式，请上传 .xlsx 或 .csv" |
| 文件为空 | 提示"文件为空，请检查" |
| 全部校验失败 | 「确认导入」按钮置灰，提示"没有可导入的数据" |
| 导入过程中部分失败 | 成功的正常入库，失败的跳过，导入完成后提示结果 |
| 网络异常 | 提示"导入失败，请重试" |

#### UI 关联

- PC 端原型：库存管理后台原型 V7 — 批量导入弹窗（batch-import-dialog）

### 2.3 库存流水

**功能类型**：页面型

#### 功能描述

库存流水记录所有库存变动的历史，每次在库数量或锁定数量发生变化时自动生成一条不可变的流水记录。支持运营人员按多维度筛选查看。

#### 前置条件

- 用户已登录库存管理后台
- 用户具有库存管理权限

#### 页面布局

页面结构（PC 端，无 APP 端）：
- 顶部：页面标题
- 统计卡片区：流水总数、入库记录、出库记录、其他变动（4 列）
- 工具栏：搜索框 + 事件类型筛选 + 操作人类型筛选 + 日期范围 + 查询/重置
- 数据表格：流水列表
- 底部：分页器（每页 20/50/100 条，默认 20）

#### 页面元素

**统计卡片**（4 列）：

| 卡片 | 说明 |
|------|------|
| 流水总数 | 所有流水记录数 |
| 入库记录 | event_type = 入库的记录数 |
| 出库记录 | event_type = 出库的记录数 |
| 其他变动 | 调整 + 预占 + 释放 + 锁定 + 解锁的记录数 |

**工具栏**：

| 元素 | 类型 | 说明 |
|------|------|------|
| 搜索框 | 文本输入 | 支持按商品ID、商品名称、关联单号搜索 |
| 事件类型 | 下拉选择 | 全部 / 入库 / 出库 / 调整 / 预占 / 释放 / 锁定 / 解锁 |
| 操作人类型 | 下拉选择 | 全部 / 运营人员 / 系统自动 |
| 开始日期 | 日期选择 | 时间范围筛选 |
| 结束日期 | 日期选择 | 时间范围筛选 |
| 查询按钮 | 主按钮 | 触发筛选 |
| 重置按钮 | 普通按钮 | 清空筛选条件 |

**数据表格列定义**：

| 列名 | 字段 | 说明 |
|------|------|------|
| 流水ID | ledger_id | 流水唯一标识 |
| 商品ID | inventory_item → product_id | 关联商品ID |
| 商品名称 | inventory_item → product_name | 关联商品名称 |
| 事件类型 | event_type | 彩色标签显示，见枚举定义 |
| 数量变化 | quantity_change | 正数绿色，负数红色，加粗显示 |
| 变动前状态 | from_status | 变动前的库存物理状态 |
| 变动后状态 | to_status | 变动后的库存物理状态 |
| 关联单据 | ref_no | 触发变动的业务单据号，无则显示"-" |
| 操作人 | operator_id + operator_type | 运营人员姓名 或 "系统" |
| 操作时间 | occurred_at | 变动发生时间 |

#### 枚举定义

**事件类型（event_type）**：

| 枚举值 | 含义 | 触发时机 | 数量变化 | 标签颜色 |
|--------|------|----------|----------|----------|
| 入库 | 商品入库 | 运营人员行内编辑增加在库数量，或批量导入 | +N | 绿色（.tag.on）— 增加类 |
| 出库 | 订单发货 | 订单系统确认发货，扣减库存 | -N | 红色（.tag.req）— 减少类 |
| 调整 | 数量修正 | 运营人员行内编辑减少在库数量（盘点差异/报废） | -N | 蓝色（.tag.sale）— 中性 |
| 预占 | 下单冻结 | 买家下单，订单系统冻结库存 | -N | 红色（.tag.req）— 减少类 |
| 释放 | 取消/超时释放 | 订单取消或预占超时，系统释放库存 | +N | 绿色（.tag.on）— 增加类 |
| 锁定 | 人工锁定 | 运营人员行内编辑增加锁定数量 | -N | 红色（.tag.req）— 减少类 |
| 解锁 | 解除锁定 | 运营人员行内编辑减少锁定数量 | +N | 绿色（.tag.on）— 增加类 |

**from_status / to_status 枚举值**：

| 枚举值 | 含义 | 使用场景 |
|--------|------|----------|
| 在库 | 正常在库可用 | 入库后、释放后、解锁后的目标状态 |
| 预占 | 被订单冻结 | 预占操作的目标状态 |
| 锁定 | 人工锁定不可售 | 锁定操作的目标状态 |
| 已出库 | 已发货离开仓库 | 出库操作的目标状态 |
| 已损 | 损坏/报废 | 调整（报废）操作的目标状态 |
| - | 无（首次入库前） | 入库操作的来源状态 |

**各事件类型的状态流转**：

| 事件类型 | from_status | to_status | 说明 |
|----------|-------------|-----------|------|
| 入库 | - | 在库 | 新增库存（含行内增加、批量导入） |
| 出库 | 预占 | 已出库 | 预占的库存发货出库 |
| 调整（减少） | 在库 | 在库 | 盘亏扣减（仍在库但数量减少） |
| 调整（报废） | 在库 | 已损 | 损坏报废 |
| 预占 | 在库 | 预占 | 在库数量转为预占 |
| 释放 | 预占 | 在库 | 预占数量恢复为在库 |
| 锁定 | 在库 | 锁定 | 在库数量转为锁定 |
| 解锁 | 锁定 | 在库 | 锁定数量恢复为在库 |

**操作人类型（operator_type）**：

| 枚举值 | 含义 | 对应操作 |
|--------|------|----------|
| 运营人员 | 人工操作 | 入库、调整、锁定、解锁、批量导入 |
| 系统自动 | 系统触发 | 预占、释放、出库 |

**关联单据规则**：

| 事件类型 | 关联单据 | 说明 |
|----------|----------|------|
| 预占 | ORD-XXXX | 订单号 |
| 释放 | ORD-XXXX | 触发释放的原订单号 |
| 出库 | ORD-XXXX | 订单号 |
| 其他（入库/调整/锁定/解锁） | - | 无关联单据 |

#### 操作流程

**主流程 — 查看流水**：
1. 进入库存流水页面，系统加载全量流水（默认按操作时间倒序）
2. 统计卡片显示各类型记录数

**分支流程 — 从库存总览跳转**：
1. 在库存总览点击某行的「查看库存流水」按钮
2. 跳转到流水页面，搜索框自动填充商品ID
3. 列表按该商品ID过滤，仅展示该商品的流水记录
4. 清空搜索框可恢复全量列表

**分支流程 — 条件筛选**：
1. 运营人员选择事件类型、操作人类型、日期范围
2. 点击查询，列表按条件过滤
3. 点击重置，清空所有条件恢复默认

#### 交互说明

- 事件类型以彩色标签展示，不同类型不同颜色（见枚举定义）
- 数量变化：正数显示为绿色加粗（如 +200），负数显示为红色加粗（如 -50）
- 流水记录不可编辑、不可删除（append-only）
- 列表默认按操作时间倒序排列
- 事件类型表头有 tooltip，解释每种事件类型的含义
- 数量变化表头有 tooltip，解释正负数含义
- 变动前/后状态表头有 tooltip
- 关联单据表头有 tooltip，说明 ORD- 前缀含义和"-"的含义

### 2.4 流水自动生成规则

**功能类型**：机制型

#### 功能描述

每次库存数量发生变化时，系统自动生成一条库存流水记录。流水记录不可修改、不可删除，作为库存变动的完整审计轨迹。

#### 触发条件

以下操作触发流水生成：

| 触发操作 | 来源 | 流水内容 |
|----------|------|----------|
| 行内编辑在库数量（增加） | 运营人员 | 事件类型=入库，数量变化=增加量 |
| 行内编辑在库数量（减少） | 运营人员 | 事件类型=调整，数量变化=减少量 |
| 行内编辑锁定数量（增加） | 运营人员 | 事件类型=锁定，数量变化=锁定增加量 |
| 行内编辑锁定数量（减少） | 运营人员 | 事件类型=解锁，数量变化=解锁量 |
| 批量导入入库 | 运营人员 | 事件类型=入库，每行一条流水 |
| 买家下单 | 订单系统 | 事件类型=预占，数量变化=订单数量 |
| 订单取消/超时 | 订单系统 | 事件类型=释放，数量变化=释放数量 |
| 订单发货 | 订单系统 | 事件类型=出库，数量变化=出库数量 |

#### 处理流程

1. 业务操作触发库存变动
2. 更新 inventory_item 对应数量字段
3. 同步生成 inventory_ledger 记录，包含：
   - 事件类型
   - 数量变化（正数/负数）
   - 变动前状态和变动后状态
   - 关联单据号（仅预占/出库有）
   - 操作人和操作人类型
   - 操作时间
4. 库存变动和流水记录在同一事务中完成，保证数据一致性

#### 规则说明

- 流水记录一旦写入不可修改、不可删除
- 每次操作只生成一条流水（批量导入中每行商品各生成一条）
- 操作时间取服务端时间，非客户端时间
- 数量变化的正负方向从"可售库存"视角定义：增加可售为正（入库/释放/解锁），减少可售为负（出库/预占/锁定/调整减少）

#### 异常处理

| 场景 | 处理方式 |
|------|----------|
| 流水写入失败 | 整个事务回滚，库存数量不变，提示操作失败 |

## 三、依赖与风险

### 上下游系统依赖

| 依赖系统 | 依赖内容 | 影响范围 |
|----------|----------|----------|
| 商品系统 | 商品ID、商品名称、商品类型 | 库存总览展示、批量导入校验 |
| 订单系统 | 下单预占、取消释放、发货出库 | 预占/释放/出库流水 |

### 风险项

| 风险 | 影响 | 应对 |
|------|------|------|
| 行内编辑无二次确认 | 运营人员误操作直接生效 | 所有操作记录流水，可追溯；后续可增加操作确认弹窗 |
| 并发编辑冲突 | 多人同时修改同一商品库存 | 后端乐观锁机制，冲突时提示刷新 |
| 批量导入数据质量 | 上传错误数据导致库存不准 | 导入前校验 + 预览确认，失败项自动跳过 |
