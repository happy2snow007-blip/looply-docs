# Looply GA4 五个埋点开发确认结论

> 版本：v1.0  
> 日期：2026-08-18  
> 状态：可交付 GA4 开发  
> 适用范围：回答《Looply GA4 五个埋点调整·需求分析报告》中的待确认项，不新增事件范围。

本文件用于回答开发分析报告中的问题；最终开发口径已合并进入《Looply GA4 埋点变更清单 v1.2》，实施时以v1.2为准。

## 一、开发确认结论

| 对应事件 | 开发提出的问题 | 确认结论 | 开发处理 |
|---|---|---|---|
| `view_search_results` | 是否保留主动上报，以及如何避免与 GA4 自动网站搜索重复 | 保留主动上报。GA4 后台关闭增强型衡量中的“网站搜索”，其他增强型衡量选项不变 | 继续发送 `looply_ga4_view_search_results`，最终进入 GA4 的事件名为 `view_search_results`；发布时同步关闭对应 Web 数据流的“网站搜索”自动采集 |
| `view_search_results` | `search_version`、`index_version` 从哪里取得 | 两个字段不属于本期 GA4 必要信息 | 从 GA4 必填字段和开发阻塞项中删除；不得使用前端常量或占位值 |
| `view_cart`、`remove_from_cart` | `cart_id` 是否需要由购物车接口新增返回 | `cart_id` 不属于本期 GA4 必要信息 | 从 GA4 必填字段和开发阻塞项中删除；不为 GA4 单独修改 CartView 或购物车后端契约 |
| `view_cart` | 非空、`items[]`和`value`统计哪些商品 | 只包含当前可购商品；不可购商品不进入事件 | `items[]`记录页面内全部可购商品，`value`为这些商品的金额合计；不受购物车勾选状态影响，实际勾选结算商品由`begin_checkout`记录；只有不可购商品时不发送`view_cart` |
| `search` | 输入联想是否必须提供稳定业务对象ID | 普通搜索词联想不要求稳定业务对象ID | 必填`search_id`、`search_term`、`trigger_type=suggestion_select`和建议位置；有稳定实体ID时可选传`suggestion_object_id`，没有时不得伪造 |
| `search` | 热门品牌、热门Collection是否作为搜索 | 不作为搜索 | 不发送`search`；按入口点击和目标Collection页面`page_view`处理 |
| `remove_from_cart` | 当前购物车商品数量固定为1，是否同时建设数量修改能力 | 本期只覆盖现有成功删除，不新增数量修改能力 | 成功删除后发送一次，实际减少数量为1；删除失败、无变化或只露出删除操作不发送 |

## 二、搜索提交与结果关联

### 2.1 需要取消的旧限制

取消“所有`view_search_results`都必须存在前序`search`”的限制。

调整后两个事件分别成立：

- `search`记录用户通过站内搜索入口主动提交搜索；
- `view_search_results`记录搜索结果实际展示及该次结果的终态。

站内主动提交产生的两个事件需要关联；直达搜索URL、刷新或页面恢复没有新的用户提交动作，因此允许只有`view_search_results`。

### 2.2 开发发送矩阵

| 场景 | 是否发送`search` | 是否发送`view_search_results` | `search_id`处理 |
|---|---:|---:|---|
| 点击搜索轮播词 | 是 | 结果实际展示后发送 | 提交时生成；结果事件复用同一值 |
| 手动输入后按回车 | 是 | 结果实际展示后发送 | 提交时生成；结果事件复用同一值 |
| 手动输入后点击搜索按钮 | 是 | 结果实际展示后发送 | 提交时生成；结果事件复用同一值 |
| 点击输入联想 | 是 | 结果实际展示后发送 | 提交时生成；结果事件复用同一值 |
| 点击搜索历史 | 是 | 结果实际展示后发送 | 提交时生成；结果事件复用同一值 |
| 点击热门搜索词 | 是 | 结果实际展示后发送 | 提交时生成；结果事件复用同一值 |
| 首次直达带有效搜索词的结果URL | 否 | 结果实际展示后发送 | 如果没有前序提交传入的`search_id`，为本次结果展示生成新值，仅供结果事件使用 |
| 刷新搜索结果页 | 否 | 结果重新展示后发送 | 为本次结果展示生成新值，仅供结果事件使用 |
| 前进、后退或页面恢复后重新展示结果 | 否 | 结果重新展示后发送 | 如果没有可复用的本次结果上下文，为本次结果展示生成新值，仅供结果事件使用 |
| URL有搜索参数但未执行搜索或未形成结果终态 | 否 | 否 | 不生成 |

### 2.3 具体实现规则

1. 站内主动提交时，先生成唯一`search_id`并发送`search`，再将该`search_id`传入本次搜索请求或结果上下文。
2. 结果进入最终状态时发送`view_search_results`：
   - 能取得前序主动提交的`search_id`：直接复用；
   - 不能取得前序主动提交的`search_id`：新生成一个`search_id`，但不得反向补发`search`。
3. 每个结果展示实例只能发送一次`view_search_results`，终态只能是`success`、`no_results`、`failed`或`cancelled`之一。
4. 重新渲染同一个结果状态不得重复发送；只有直达、刷新或页面恢复形成新的结果展示实例时才重新发送。
5. 本期GA4调整不把筛选、排序和翻页重新定义为新的首次搜索提交。
6. 分析时：
   - 有相同`search_id`的`search`与`view_search_results`，表示站内主动提交及其结果；
   - 只有`view_search_results`而没有同ID的`search`，表示无前序主动提交的结果展示，不得计入“站内主动搜索次数”，但可计入“搜索结果页展示次数”。

## 三、GA4后台设置与上线验收

### 3.1 设置调整

路径：GA4管理 → 数据收集和修改 → 数据流 → Looply Web数据流 → 增强型衡量功能 → 设置。

- 关闭“网站搜索”；
- 不关闭增强型衡量功能总开关；
- 网页浏览量、滚动次数、出站点击等其他选项保持当前设置。

### 3.2 验收要求

1. 在测试环境确认主动`view_search_results`已正常进入GA4后，再调整正式数据流设置。
2. 分别验证搜索成功、零结果、失败和取消场景。
3. 同一次站内正式搜索在GA4中只能出现一条`search`和一条使用相同`search_id`的`view_search_results`；直达URL、刷新和页面恢复允许只有`view_search_results`。
4. 关闭“网站搜索”后，确认带`keyword`等查询参数的结果页不会再额外生成第二条自动`view_search_results`。
5. 验证`view_cart`只包含可购商品；`remove_from_cart`只在购物车实际减少后产生。

## 四、不需要扩大的开发范围

- 不为GA4新增或改造搜推版本字段接口；
- 不为GA4新增购物车主体ID接口；
- 不为GA4新增购物车数量修改能力；
- 不要求普通搜索词联想新增稳定业务对象ID；
- 不修改本次五个事件以外的GA4事件。
