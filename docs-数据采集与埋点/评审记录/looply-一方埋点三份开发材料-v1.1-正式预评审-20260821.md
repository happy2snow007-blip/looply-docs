## 一、结论摘要

三份 v1.1 材料已经修复上一轮多数结构性缺口：17 个客户端统一事件、22 个新增公共字段、5 类服务端权威事实、稳定页面／模块／展示位字典及 v1.7 的 81 项页面操作均已迁入；`anonymous_id`与`domain_userid`同时上传、删除`identity_state`字段、冻结`source_type`八枚举、参数缺失不抑制事件、服务端五类事实不由 Web 生成等最新确认也已落地。

但开发仅拿三份材料仍不能唯一实施。当前存在 1 个 P0、6 个 P1、2 个 P2：客户端事件参数中仍保留“来源／发生页面／商品快照／移除前后状态”等未形成稳定业务字段清单的概念占位；`source_type`虽冻结八个值，却未定义每个值的业务含义和场景映射；来源事件链、站外触点携带生命周期、失败分类、稳定模块示例及现有公共字段基线的复用关系仍未闭合。2026-08-21 对飞书现有公共字段页的一次性读取确认 22 个新字段名均未原名出现，但`module_id/placement_id/source_type/source_page_id/source_module_id/landing_page_clean/touchpoint_at`等与现有`placement_* / page_url / referrer_url / event_time_*`存在潜在语义重叠；“字段名不同”不能直接证明应新建第二套字段。

| 等级 | 数量 | 门禁含义 |
|---|---:|---|
| P0 | 1 | 开发无法唯一形成事件业务参数契约，阻塞实施与冻结 |
| P1 | 6 | 关键归因、上下文或质量边界不完整，阻塞冻结 |
| P2 | 2 | 当前主语义可判断，但唯一权威位置和正文减法未通过 |
| P3 | 0 | 未发现需要单列的非阻塞优化项 |

最终判断：**仍需产品决策。** 需要先由产品确认 P0 和 P1 中的业务字段、值义、携带条件及场景映射；确认后修正三份材料，再按本报告的全量范围复检。不能把这些缺口下放给技术团队自行选择，也不能用后续`tracking-plan.yaml`技术设计替代产品定义。

### 5.4 22 个新增字段与现有公共字段基线核对

2026-08-21 一次性读取的飞书现有基线共见到 53 个字段。22 个 v1.1 字段名均未原名出现；`anonymous_id`、`canonical_person_id`、`session_id`、`page_instance_id`、`source_type`和`identity_state`均不在现有表，其中`identity_state`本期明确不新增。精确字段名缺失只能证明“没有同名字段”，不能证明没有同义或可复用字段。

| v1.1 字段／字段组 | 现有相近字段 | 核对结论 |
|---|---|---|
| `anonymous_id` | `domain_userid`、`user_id` | 业务语义明确不同；应与`domain_userid`同时上传，不得复用或替代 |
| `market` | `geo_country` | 业务市场与地理国家不同；应保留独立语义，不得由 IP 国家代替 |
| `module_id` | `placement_module_name` | 可能分别表达通用页面模块与商品展示模块；三份材料未定义何时复用、何时双字段并存 |
| `placement_id` | `placement_scene`、`placement_module_name`、`placement_list_id` | 新封闭展示位可能与现有 placement 实体多列重叠；字段表只写“不得用`placement_list_id`冒充”，未给迁移／复用关系 |
| `source_type` | `placement_scene`、`placement_source` | 原始站内来源与现有场景／推荐来源可能同事件并存；需明确语义边界和是否保留两套字段 |
| `source_page_id` | `page_id`、`referrer_url` | 当前页、来源页和 Referrer 可共存，但来源页面的生成／复用规则未与现有字段闭合 |
| `source_module_id` | `placement_module_name` | 可能引用前序模块，也可能与当前 placement 模块重叠；需定义唯一取值关系 |
| `landing_page_clean` | `page_url`、`referrer_url` | 清洗后首次落地页与当前页 URL／Referrer 不同，但携带和继承生命周期未定义 |
| `touchpoint_at` | `event_time_ms`、`event_time_utc` | 若只随触点事件携带可复用事件时间；若在后续事件继承则需要独立字段。当前材料未作选择 |
| `result_state`、`failure_type` | 无直接同名或明显同义字段 | 字段方向可新增；`failure_type`值域仍需产品闭合 |

事件专属字段还存在额外复用风险：现有基线已有`search_query`和`method`，而事件表使用`search_term`、`sign_up_method`、`login_method`；现有表也已有`quantity/order_id/amount/currency`及多项`placement_*`。三份材料没有说明沿用、改名、停止还是并存，因此不能只按文字新建同义字段。
