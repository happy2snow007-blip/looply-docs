## 二、逐文档差异与开发动作

### 1. 详细埋点需求定稿：v1.1 → v1.2

| 变化范围 | 当前要求 | 开发动作 |
|---|---|---|
| Search／Collection动态筛选 | 筛选维度和选项来自后台动态配置；使用稳定`dimension_code`和`option_code`，不维护前端固定维度白名单 | 建立Search／Collection共用的最终已Apply筛选事实；后台／数据平台维护Code到展示名称的可追溯映射 |
| 一方`filter_ids[]` | 每项使用`dimension_code:option_code`；去重并按Code稳定排序；未Apply、选择后取消或关闭的值不进入最终集合，Reset后为空 | Search／Collection的Apply、商品曝光和商品点击使用同一最终集合 |
| 筛选交互 | 筛选组展开／收起／查看全部使用`dimension_code`；选项select使用`dimension_code:option_code`；Apply携带最终`filter_ids[]` | 修改Search和Collection对应`ui_interaction`参数 |
| 受影响事件 | `item_impression`、`item_click`、`search`、`view_search_results`及Search／Collection筛选操作；Collection商品曝光和点击增加最终`filter_ids[] / sort_type` | 不得只改URL；需同步修改对应一方事件载荷 |
| 权威交易事实 | `order_created`、`payment_started`、`payment_failed`、`purchase`、`refund`在本工作簿中只保留事实名和客户端边界；完整定义迁入《Looply 订单与交易数据接入需求 v1.0》 | Web／SDK不生成这五类事实；数据接入／数仓按独立权威文档实施 |

未变化：工作簿仍为4个Sheet、250个点位（客户端245、权威业务表事实5）；“停止项”Sheet无变化；没有因本次更新新增第六类权威事实或改变一方客户端事件集合。

### 2. 公共基础字段需求定稿：v1.1 → v1.1（2026-08-26修订稿）

| 变化范围 | 当前要求 | 开发动作 |
|---|---|---|
| 公共字段总表 | 实际0处变化；没有新增、删除、改名或改枚举 | 不因本文件修订新增Web／SDK公共字段或Schema |
| 交易事实引用 | “公共规则”和“兼容边界”中的订单／支付／退款事实，改为统一引用《Looply 订单与交易数据接入需求 v1.0》 | 交易事实不进入Web／SDK YAML Schema；不要求前端生成 |
| 文档职责 | 客户端公共字段文档只保留Web边界，不平行维护交易字段定义 | 订单、支付、成交、退款和售后实施时读独立交易数据文档 |

版本说明：本文件仍为v1.1，是因为公共字段集合没有变化；但文档中心当前v1.1已更新了交易事实引用和兼容边界，应使用2026-08-26当前文件，不得使用今日以前的同名v1.1副本。

### 3. 一方埋点公共实施规则：v1.6 → v1.7

| 变化范围 | 当前要求 | 开发动作 |
|---|---|---|
| 开发基线边界 | 三份文档只构成客户端埋点基线；交易事实完整定义改由《Looply 订单与交易数据接入需求 v1.0》维护 | 不要从旧v1.6复制交易事实字段定义 |
| 身份 | 分别上传并保存`domain_userid`和`anonymous_id`；已登录事件增加当前`user_id`；三者不互相代填，不因ID相同自动合并不同`user_id` | 保留事件发生时实际取得的ID；不新增`identity_state`、`canonical_person_id`或`visitor_id` |
| `origin_session_id` | 正常Web Checkout下单时必传必存：Web／埋点SDK传入当时Snowplow `session_id`，订单服务随订单或归因上下文保存，后续支付和成交按`order_id`沿用 | 不再把正常Web下单的该字段当作可选；只有明确不经过Web Checkout且能识别来源的订单可为空 |
| Search／Collection动态筛选 | 增加共用最终已Apply筛选事实；一方`filter_ids[]`使用`dimension_code:option_code`；Collection与Search使用同一规则 | 按v1.7第5.2节和详细点位v1.2同步实施 |
| 权威交易事实 | 公共规则只保留五个事实名、Web禁止伪造的边界和独立文档引用 | 数据接入、唯一键、交易字段、订单行／退款行及售后过程全部按《Looply 订单与交易数据接入需求 v1.0》实施 |

未变化：页面实例、商品曝光、事件参数缺失不抑制事件、数据内容边界、本期不实施场景和技术实施边界等原有原则继续有效。
