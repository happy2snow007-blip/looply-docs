# Looply 数据采集与埋点 v1.5 → v1.6 核心差异

> 日期：2026-08-18  
> 版本关系：v1.5保留为历史版本；v1.6为后续开发实施基线。

## 一、总体变化

v1.6不是在v1.5上增加第二套埋点，而是把原有方案按当前代码和业务范围重新收口。统一事实总数仍为22项，拆分为17个客户端统一事件和5类权威业务事实。

## 二、开发需要关注的核心差异

| 方向 | v1.5 | v1.6 |
|---|---|---|
| 数据来源 | 22项统一事件放在同一事件体系中描述 | 17个客户端事件由Web／SDK采集；5类订单、支付和退款事实由服务端或权威业务表接入 |
| 事件名称 | 统一事件名与旧物理名称存在混用 | 一方平台最终`event_type`等于统一事件名；旧名称只在专项兼容层保留，不得双发双计 |
| 搜索 | 对提交和结果的现有`search`语义描述不准确 | 提交调用点为`search`，结果调用点迁移为`view_search_results`，使用同一`search_id`；筛选、排序和重置形成新的搜索上下文 |
| 商品标识 | 客户端要求同时取得内部`product_id`、内部`listing_id`和`listing_public_code` | 客户端只强制`listing_public_code`；内部ID由一方数据平台关联补充 |
| 当前不可得字段 | `cart_id`、`wishlist_id`、`search_version`、`index_version`仍在首期要求中 | 四个字段从首期方案完全删除；同时删除`checkout_start_event_id`依赖 |
| 身份与Session | 依赖外部身份PRD，登出／换号的Session规则存在冲突 | 直接使用`looply_anonymous_id`作为`anonymous_id`；身份切换不强制切Session，事件按发生时身份归属；连续30分钟无有效事件结束Session |
| 当前页面范围 | 包含部分当前不存在或未实施场景 | 删除购物车数量增减、Cart优惠码、Move to Wishlist、已保存支付工具复用／修改；PC不实施独立Shop和Favorites，Tablet和App不在本期 |
| 页面操作 | 页面、节点和稳定命名分散在多张表中 | 第8.4节作为页面有意义操作的唯一映射，统一页面、模块、操作、控件和目标ID |
| Checkout | 使用前序事件ID作为就绪事件边界 | `add_shipping_info`和`add_payment_info`按Checkout的`page_instance_id`判断首次就绪 |
| 存量Share | 缺少明确迁移目标 | 统一迁移为`ui_interaction/product_share`；真实旧名称和调用点由开发登记在技术迁移清单 |

## 三、从产品PRD移出的内容

- 数据架构图、产品／技术职责说明和重复治理原则，删除后不改变实施要求。
- 返回次数、按Session购买转化率等报表计算公式，改由数据分析报表需求维护。
- 库存、履约、售后和归因等重复业务节点矩阵；相关结果继续读取权威业务表或依据原始事实计算。
- 重复的逐事件验收表和平台公共数据章节；开发要求已合并到事件字典、存量迁移表和页面操作唯一映射。
- UTC存储格式等技术实现细节；产品只要求保留事实真实发生时间，技术格式由实施方案确定。

## 四、开发阅读方式

开发直接以v1.6为准，不需要同时合并v1.5正文。实施重点为：

1. 第五章：17个客户端统一事件；
2. 第六章：5类权威业务事实及服务端／数据平台接入边界；
3. 第七章：存量事件迁移；
4. 第八章：页面、模块及所有有意义操作的唯一映射；
5. 第九章：统一枚举。
