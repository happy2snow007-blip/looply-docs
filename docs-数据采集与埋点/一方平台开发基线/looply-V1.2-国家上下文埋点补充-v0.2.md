# Looply V1.2 国家上下文埋点补充

> 版本：v0.2
> 日期：2026-11-06
> 状态：工作稿
> 范围：V1.2 按国家展示涉及的客户端公共上下文；本文件统一定义该增量的字段语义与验收要求。

## 1. 公共业务信息

| 信息 | 含义与来源 | 与现有信息的边界 |
|---|---|---|
| 当前生效国家 | 新增公共参数 `site_country`；表示事件发生时页面实际使用的国家配置，从全站已生效国家上下文读取，使用 ISO 3166-1 alpha-2 国家代码 | 不使用 IP GEO、账号资料国家、收货国家、浏览器语言或渠道推断 |
| IP 定位国家 | 沿用现有 `geo_country`；表示事件来源 IP 的 GEO 国家 | 只回答流量从哪里访问，不能代替 `site_country` |
| 当前业务市场 | 沿用现有 `market`；表示 Looply 业务市场 | 一个 Market 可以包含多个国家，不能代替 `site_country` |

`site_country` 作为一方埋点公共参数，由统一客户端采集层附加到 C1、C2 已接入的适用客户端事件。`market` 和 `geo_country` 保持现有语义与取值方式，不因本次需求改写。GA4 已存在同语义参数时应与 `site_country` 使用同一来源和同一国家代码，不得在一方平台并行新增其他同义字段。国家代码不翻译。

## 2. 采集与状态规则

1. 覆盖 C1、C2 已接入统一采集的适用客户端事件，包括首页 Banner、PC 导航及推荐位、Collection 入口、Mobile Shop、Footer、Contact Us 和 Sell；各终端沿用已有事件接入范围。
2. 国家值在事件成立时取快照。国家切换成功且页面新上下文生效后，后续事件使用新国家；仅打开选择器、选中但未生效或切换失败时不提前改值。
3. 延迟发送及同一事件重试保留原事件国家。新标签页、刷新、返回、登录或跨设备访问均读取该页面实际生效的国家，不以另一页面或账号资料覆盖。
4. 国家上下文尚未取得时省略国家参数，已成立事件继续发送；不得填默认 US、IP 国家或旧国家，不回填历史事件。上下文已生效仍缺值属于采集缺口。
5. 复用现有事件名称、业务对象标识及曝光成立规则。按国家配置本身不新增曝光、点击或国家切换专属事件；切换操作沿用已有偏好操作事件。
6. 未开放 Sell 国家中，已经隐藏的 Sell 入口及相关信息不触发曝光；直接访问未开放页面不构成 Sell 申请成功事实。

## 3. 平台接入边界

- 一方：`site_country` 从公共事件上下文进入请求、落库和查询层，并可用于按页面生效国家筛选；逐点位表继续定义事件，无需为每行重复增加该参数。
- GA4：现有由 Looply 主动发送且允许发送的客户端事件携带同语义事件参数，经 dataLayer、GTM 传递至 GA4，并登记事件级自定义维度。GA4 自带地理国家保持原义。GA4 自动事件不宣称已经覆盖，不为补参数恢复主动 `page_view` 或重复发送事件。
- 事件发送地区策略继续读取既有可信地区策略，不能以用户选择的站点国家覆盖。此次不调整服务端 Purchase、Refund 或订单国家口径。

## 4. 验收要求

| 场景 | 预期 |
|---|---|
| IP 国家与页面生效国家不同 | `site_country` 等于页面国家，`geo_country` 仍等于 IP GEO 国家；例如加拿大 IP 访问美国站时分别为 `US` 和加拿大 GEO 值 |
| 同一 Market 下两个国家使用相同语言 | 两国事件可分别筛选，国家不能从市场或语言代填 |
| 国家选择未生效、失败、成功 | 前两者保留当前国家；成功后新事件使用新国家 |
| 切换前事件延迟发送或重试 | 仍携带事件成立时的国家与原事件标识 |
| 游客与登录用户、PC 与 Mobile、刷新与返回 | 事件与该页面当时实际生效的国家一致 |
| 国家上下文缺失 | 事件继续发送、`site_country` 省略，不伪造值 |
| Sell 未开放 | 隐藏内容无曝光，不生成申请成功事实 |
| 传输与落库 | 一方请求、落库和查询结果中的 `site_country` 一致；GA4 适用主动事件使用同一来源与同一国家代码，无同义参数重复上报 |
