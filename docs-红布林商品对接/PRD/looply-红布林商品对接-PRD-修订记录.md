**`url_slug` 一经生成永不变更**（对外契约，C 端收藏链接/外链/SEO 依赖；这是重算可全自动的前提，否则每次重算都需人工评估 SEO 影响），§2.5.4、§2.7 同步回指；② 变更分补齐/修订/删除三类，各自定义处理；③ 修订场景给出**重算范围规则**（未创建 product、已创建未上架、已上架均自动重算内部字段；已排除、已售出/已失效不重算，历史保真）；④ **术语英文变更自动联动更新映射 `source_value_en`**（新值不存在则就地改 key 保留 `target_id`，已存在则合并到已有行、原行标记失效），消除失配与孤儿行；⑤ 删除的影响面提示区分「未创建 product（回异常态）」与「已创建 product（不回滚）」；⑥ 重算异步批量、复用失败阈值、不改 `product_status`、需支持断点续跑。§1.4 场景5、§2.9、§2.10 同步改写。<br><br>**★§2.7 实体归属变更改为 product 重建（全自动）**：品牌/系列/类目挂在 SPU 上，product 只挂 `standard_sku_id` 经 `standard_sku→spu` 继承，故三者任一变更等价于**该实物商品需重新对齐到另一个标品SKU**（必要时新建 SPU + 标品SKU），性质是换了标品归属而非改几个字段。原设计「重新翻译+重新映射→**更新** product（需人工确认）」改为 **重建 product、全自动无人工确认**：新 product 挂新 `standard_sku_id` 并继承一物一码字段；旧 product 置「已失效」、旧 listing 下架、旧库存清零，**均不删除**保留追溯；快照层 `product_id` 回写指向新 product；新 listing 生成**新 url_slug**；ITEM 级属性值**不迁移**（新类目/品牌的 `attribute_scope_config` 作用域不同，按新作用域重新落值）。**只变类目也重建**（作用域按 `category_id` slug 属预期行为。两处均已补「适用边界」说明。<br><br>**下游同步**：系统流程图 **V12.2 → V12.3**（⑤段分支节点由 1 个扩为 3 个，描述重建全过程；注释补 SPU 归属/只变类目也重建/已售出不重建/slug 边界四条；「人工确认」表述清除）；PRD 内流程图引用同步 V12.3。<br><br>**★开发评审 ToDo 落实（2026-07-20）**：<br>**① TOP 系列数据来源**（原 PRD 全文无"爬虫"字样，只定义了页面维护）：§2.11 补「数据来源」段，明确 V1.0 链路为「**爬虫抓取 → 产出 Excel → 运营导入**」，**爬虫不直连写库**（爬虫依赖三方站点结构、稳定性不可控，直连一旦抓错会直接污染定价且因"算得出结果"而不易察觉；走导入保留人工确认与导入历史，可定位可回滚）。TOP 系列的使用位置与路由逻辑原已齐全（②定价：Top+C → 公式3/1/2/4/5/7，非Top/无C/宝格丽 → 公式6），本次未改。<br>**② TRR 导入改为按品牌全量覆盖**：原 PRD 等）维持原样，**未引入基于数据日期的自动降级**。§2.11 补充的 `样本数 / 数据日期` 两列仅同步原型既有字段、供运营判断可信度，**不参与定价逻辑**，文中已显式声明。<br>**⑤ 标品SKU 规格要求 — 按决策暂不处理**：与 R5「属性作用域配置覆盖不足」合并，待与商品模块对齐 `attribute_scope_config` 的 SPU/SKU/ITEM 三档归属后再补
