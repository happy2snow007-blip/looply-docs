# Looply 物流信息服务 — API 错误处理规范（快递100）

> 版本：v1.2  
> 日期：2026-06-10  
> 范围：快递100平台对接的运单注册（订阅）及推送处理
> 
> **v1.2 变更**：§3.3、§4.1 两表的 internal_status 列由中文（待揽收/运输中/派送中/已签收/物流异常）统一改为 AfterShip 英文 tag（Pending/InTransit/OutForDelivery/Delivered/Exception），对齐 PRD 1.7「快递100状态统一映射成 AfterShip tag 后展示」及 PRD v1.4 的 8 值状态空间。
> 
> **v1.1 变更**：新增 Looply 自定义错误码 `LOW_QUOTA_WARNING`（订阅额度预警）和 `QUOTA_EXHAUSTED`（额度耗尽），用于快递100每月4次订阅限制的产品化处理。

## 一、校验层级

```
业务系统请求
    ↓
【第一层】Looply 基础校验（本地，毫秒级）
    ↓ 通过
【第二层】快递100平台校验（远程，秒级）
    ↓ 通过
创建 shipment 记录，返回成功
```

## 二、Looply 基础校验规则

### 2.1 tracking_no（运单号）

| 规则 | 校验条件 | 错误码 | 提示语 |
|------|----------|--------|--------|
| 必填 | 不能为空/全空格 | `MISSING_TRACKING_NO` | 运单号不能为空 |
| 去空格 | 前后空格自动 trim | — | 静默处理，不报错 |

> 说明：运单号的格式由承运商定义，Looply 不做本地格式校验。快递100接受 6-32 位运单号，格式不正确时快递100会返回错误，Looply 映射为统一错误码返回给调用方。

### 2.2 carrier_id（承运商ID）

| 规则 | 校验条件 | 错误码 | 提示语 |
|------|----------|--------|--------|
| 必填 | 不能为空 | `MISSING_CARRIER` | 承运商不能为空 |
| 存在性 | 必须在 carriers 表中存在 | `CARRIER_NOT_FOUND` | 承运商不存在，请确认承运商ID是否正确 |
| 状态 | 承运商状态必须为启用 | `CARRIER_DISABLED` | 该承运商已停用，请联系管理员 |
| 平台映射 | 必须有对应的追踪平台映射 | `CARRIER_NO_PLATFORM` | 该承运商未配置追踪平台，请联系管理员 |

### 2.3 business_order_no（业务单号）

| 规则 | 校验条件 | 错误码 | 提示语 |
|------|----------|--------|--------|
| 必填 | 不能为空/全空格 | `MISSING_BUSINESS_ORDER_NO` | 业务单号不能为空 |

> 说明：业务单号的具体格式由调用方业务系统自行定义，Looply 仅做非空校验。

### 2.4 phone（手机号 — 顺丰专用）

| 规则 | 校验条件 | 错误码 | 提示语 |
|------|----------|--------|--------|
| 条件必填 | 承运商为顺丰速运/顺丰快运时必填 | `CARRIER_FIELD_REQUIRED` | 该承运商需要提供手机号（后4位即可） |
| 可选 | 其他承运商不需要 | — | — |

> 说明：快递100要求顺丰运单必须提供寄件人或收件人手机号（完整号码或后4位均可）。该手机号是国内转仓下单人的，由调用方业务系统传入。

### 2.5 source（来源系统）

| 规则 | 校验条件 | 错误码 | 提示语 |
|------|----------|--------|--------|
| 必填 | 不能为空 | `MISSING_SOURCE` | 来源系统标识不能为空 |
| 白名单 | 必须在已注册的系统标识中 | `INVALID_SOURCE` | 来源系统标识无效，请确认是否已注册 |

### 2.6 状态通知（产品要求）

> 物流状态变更时，Looply 须主动通知调用方。通知内容包含业务单号、运单号、承运商、当前状态及最新轨迹事件。通知失败须自动重试（最多 3 次，间隔递增）。
>
> 具体通知通道（HTTP 回调 / 消息队列 / 其他）由技术侧根据系统对接方式决定，产品层面不约束实现方式。
>
> 调用方可随时通过查询接口获取最新状态作为兜底。

## 三、快递100错误码映射表

### 3.1 订阅接口错误（同步返回）

#### 3.1.1 参数错误类（调用方修正后可重试）

| 快递100 code | 快递100含义 | Looply 错误码 | 提示语 | 操作指引 |
|-------------|-------------|---------------|--------|----------|
| 700 | 不支持的快递公司编码 | `CARRIER_SLUG_INVALID` | 承运商在追踪平台中不可用 | 请确认该承运商已在追踪平台正确配置，或联系管理员 |
| 701 | 订阅参数异常或回调地址错误 | `PLATFORM_BAD_REQUEST` | 追踪平台拒绝了请求 | 系统内部异常，请联系管理员 |
| 702 | 运单号无法识别快递公司 | `CARRIER_UNRECOGNIZED` | 无法从运单号自动识别承运商 | 请在请求中明确指定承运商编码（carrier_id） |
| 408 | 顺丰验证码错误（phone缺失或错误） | `CARRIER_FIELD_REQUIRED` | 该承运商需要提供手机号 | 顺丰运单需要寄/收件人手机号（后4位即可），请补充后重新提交 |

#### 3.1.2 业务冲突类（需要调整业务逻辑）

| 快递100 code | 快递100含义 | Looply 错误码 | 提示语 | 操作指引 |
|-------------|-------------|---------------|--------|----------|
| 501 | 重复订阅（已在监控中） | `TRACKING_EXISTS` | 该运单号已注册追踪 | 无需重复注册。查询请调用 GET /trackings/{tracking_no}；如需重新注册请先调用 DELETE 取消 |

> 注意：快递100同一运单号每月最多订阅 4 次。超出后即使 DELETE 再 POST 也会失败，需等次月重置。

#### 3.1.3 额度管理类（Looply 自定义，非快递100返回）

| Looply 错误码 | 触发条件 | 提示语 | 操作指引 |
|---------------|----------|--------|----------|
| `LOW_QUOTA_WARNING` | 当月剩余订阅次数 ≤ 1 | 该承运商本月订阅额度即将用尽（剩余 X 次），请谨慎使用 | 建议优先使用查询接口确认运单状态，避免不必要的重复注册 |
| `QUOTA_EXHAUSTED` | 当月订阅次数已达 4 次上限 | 该承运商本月订阅额度已用尽，将于 {reset_at} 重置 | 请等待次月 1 日额度重置后再注册新运单，或使用查询接口获取已注册运单状态 |

> **说明**：
> - 快递100平台仅在额度耗尽时返回 returnCode 702，Looply 在此基础上增加了"剩余 ≤ 1 时预警"的产品逻辑
> - `LOW_QUOTA_WARNING` 在 PATCH /trackings/{shipment_id} 接口返回（修改运单信息时触发）
> - `QUOTA_EXHAUSTED` 对应快递100 returnCode 702，在 POST /trackings 接口返回
> - GET /carriers 接口返回的快递100承运商附加 `subscription_quota` 字段：`{used: 2, limit: 4, reset_at: '2026-06-01'}`
> - POST /trackings 注册成功后，响应体附加 `quota_remaining` 字段提示当月剩余次数

#### 3.1.4 认证/权限类（系统配置问题，需管理员介入）

| 快递100 code | 快递100含义 | Looply 错误码 | 提示语 | 操作指引 |
|-------------|-------------|---------------|--------|----------|
| 600 | key 无效或无可用订阅量 | `PLATFORM_AUTH_FAILED` | 追踪平台认证失败 | 系统配置异常，请联系管理员检查追踪平台 API Key 或充值订阅量 |
| 601 | key 已过期 | `PLATFORM_AUTH_FAILED` | 追踪平台认证已过期 | 系统配置异常，请联系管理员续费追踪平台服务 |

#### 3.1.5 服务器错误类（平台故障，等待恢复）

| 快递100 code | 快递100含义 | Looply 错误码 | 提示语 | 操作指引 |
|-------------|-------------|---------------|--------|----------|
| 500 | 服务器错误 | `PLATFORM_UNAVAILABLE` | 追踪平台暂时不可用 | 请稍后重试（建议30秒后），如持续失败请联系管理员 |

#### 3.1.6 内容安全类

| 快递100 code | 快递100含义 | Looply 错误码 | 提示语 | 操作指引 |
|-------------|-------------|---------------|--------|----------|
| 502 | 回调地址敏感内容拦截 | `PLATFORM_BAD_REQUEST` | 追踪平台拒绝了请求 | 系统内部异常，请联系管理员 |

### 3.2 推送回调中的异步异常

快递100通过 Webhook 推送的 `status` 字段标识异步异常：

#### 3.2.1 abort 状态（追踪终止）

| 场景 | 触发条件 | tracking_health | 通知调用方 | 操作建议 |
|------|---------|-----------------|-----------|----------|
| 3天无记录 | 订阅后连续3天承运商无任何轨迹信息 | abnormal | 是 | 建议确认运单号与承运商是否匹配，或联系承运商确认是否已揽收 |
| 60天无变化 | 有轨迹但60天未更新 | abnormal | 是 | 该运单长时间无物流更新，建议联系承运商确认包裹状态，必要时申请理赔 |

> 注意：快递100 abort 后自动停止监控，不再推送。如需继续追踪，需重新订阅（受每月4次限制）。

#### 3.2.2 autoCheck 自动纠错

| 场景 | 触发条件 | Looply 处理 | 通知调用方 | 操作建议 |
|------|---------|-------------|-----------|----------|
| 承运商自动修正 | 快递100检测到原始承运商代码错误，自动更换为正确的 | 更新本地 carrier_id + 记录变更日志 | 是 | 承运商已由系统自动修正为{comNew}，如有疑问请确认 |

> 当 `autoCheck=1` 时，推送中 `comOld` 为原始代码，`comNew` 为修正后代码。Looply 自动更新映射关系。

| 0 | 在途 | InTransit | normal |
| 5 | 派件 | OutForDelivery | normal |
| 3 | 签收 | Delivered | normal |
| 7 | 转投 | InTransit | normal |
| 8 | 清关 | InTransit | normal |
| 10 | 待清关 | InTransit | normal |
| 11 | 清关中 | InTransit | normal |

| 2 | 疑难 | Exception | normal |

| 13 | 清关异常 | Exception | normal |
| 14 | 拒签 | Exception | normal |

| abort | "3天无记录" / 类似表述 | tracking_health = abnormal |
| abort | "60天无变化" / 类似表述 | tracking_health = abnormal |
| shutdown | — | 正常结束追踪（已签收），不影响 tracking_health |

## 五、兜底策略

### 5.1 未知快递100错误码

当收到未在上述映射表中的返回码时：

```json
{
  "success": false,
  "error": {
    "code": "UNKNOWN_PLATFORM_ERROR",
    "message": "追踪平台返回了未知错误",
    "action": "请稍后重试，如持续失败请联系管理员并提供追踪编号",
    "trace_id": "lpy_20260525_x7k9m2",
    "debug": {
      "platform": "kuaidi100",
      "platform_code": 999,
      "platform_message": "原始错误信息..."
    }
  }
}
```

### 5.2 网络层错误（无法到达快递100）

| 场景 | Looply 错误码 | 提示语 | 操作指引 |
|------|---------------|--------|----------|
| 连接超时 | `PLATFORM_TIMEOUT` | 追踪平台连接超时 | 请稍后重试，系统将自动恢复 |
| DNS 解析失败 | `PLATFORM_UNREACHABLE` | 追踪平台无法连接 | 系统网络异常，请联系管理员 |
| SSL/TLS 错误 | `PLATFORM_UNREACHABLE` | 追踪平台连接异常 | 系统网络异常，请联系管理员 |

### 5.3 兜底优先级

```python
def map_kuaidi100_error(response):
    code = response.get('returnCode')
    
    # 优先级 1：精确匹配返回码
    if code in EXACT_MAP:
        return EXACT_MAP[code]
    
    # 优先级 2：认证类错误
    if code in ('600', '601'):
        return PLATFORM_AUTH_ERROR
    
    # 优先级 3：服务器错误
    if code == '500':
        return PLATFORM_UNAVAILABLE_ERROR
    
    # 优先级 4：终极兜底
    return UNKNOWN_PLATFORM_ERROR
```

## 七、快递100特有机制

### 7.1 每月订阅次数限制

快递100对同一快递公司+运单号组合，每月最多允许订阅 4 次。

**影响场景：**
- 承运商修改（PATCH carrier_id）需要 DELETE 旧订阅 + 重新订阅 = 消耗 2 次
- 运单号录错（DELETE + 新 POST）= 消耗 2 次（旧单号 1 次 + 新单号 1 次）

**Looply 处理：**
- 记录每个运单号的订阅次数
- 当剩余次数不足时，在错误响应中提醒调用方

### 7.2 自动承运商纠错

快递100在订阅后 3 天无结果时，会尝试自动识别正确的承运商并重新订阅。

**Looply 处理：**
- 收到 `autoCheck=1` 的推送时，自动更新本地承运商映射
- 通知调用方承运商已被自动修正
- 记录变更到 message_logs

### 7.3 abort 自动停止

快递100在以下条件自动停止监控并推送 `status=abort`：
- 订阅后连续 3 天无任何轨迹记录
- 有轨迹但连续 60 天无变化

**Looply 处理：**
- 标记 tracking_health = abnormal
- 通知调用方（附操作建议）
- 如需继续追踪需重新订阅（受每月4次限制）

### 7.4 顺丰手机号验证

顺丰速运/顺丰快运因隐私保护机制（2019年起），查询轨迹必须验证关联手机号。

**规则：**
- 必须提供寄件人或收件人手机号（任选其一）
- 完整号码或后4位均可
- 不提供或提供错误 → 返回 408 错误

**Looply 产品处理：**
- GET /carriers 接口中标注顺丰的 `required_fields: ["phone"]`
- 调用方选择顺丰后即知道需要补充手机号
- POST /trackings 时通过 `carrier_extra.phone` 传入

## 八、调用方重试建议

| 错误分类 | 是否可重试 | 重试策略 |
|----------|-----------|----------|
| 参数错误（700/701/702/408） | 修正后可重试 | 修正参数后立即重试 |
| 重复订阅（501） | 调整逻辑后可重试 | 根据指引调整后重试 |
| 额度预警（LOW_QUOTA_WARNING） | 可继续操作 | 警告性提示，不阻断操作；建议优先使用查询接口 |
| 额度耗尽（QUOTA_EXHAUSTED） | 次月重置后可重试 | 等待次月 1 日额度重置，或使用查询接口获取已注册运单状态 |
| 认证错误（600/601） | 修复后可重试 | 联系管理员修复后重试 |
| 平台不可用（500） | 可自动重试 | 30s / 60s / 120s 退避，最大重试 3 次 |
| 网络层错误 | 可自动重试 | 30s / 60s / 120s 退避，最大重试 3 次 |
| 未知错误 | 可尝试重试 | 30s 后重试 1 次，失败则人工介入 |

## 九、与 AfterShip 规范的差异速查

| 维度 | AfterShip | 快递100 |
|------|-----------|---------|
| 错误码粒度 | 精细（20+ 个错误码） | 粗（8 个错误码） |
| 重复注册 | 无次数限制，返回 4003 | 每月最多 4 次，返回 501 |
| 承运商纠错 | 返回错误，调用方自行修正 | 自动纠正并继续追踪 |
| 追踪终止 | Pending_005 / Expired（异步推送） | abort（3天/60天后自动停止） |
| 停止追踪 | 需主动调 DELETE API | 签收/abort 后自动停止 |
| 特殊字段 | 无 | 顺丰必须传 phone |
| 追踪 URL | 首次获取轨迹后返回 courier_tracking_link | 不返回，需自行通过模板拼接 |
| 推送格式 | JSON body | form-urlencoded（param 为 JSON 字符串） |
| 签名 | HMAC-SHA256 | MD5(param + salt) |
| 推送重试 | 未公开 | 30分钟间隔，最多3次 |
