## P0（规则缺失或制品矛盾，阻塞开发）

### 1. [开发] Bags 成色详细信息示例数据违反数据源互斥规则

- **位置**：PRD 2.10 节（"同一类目规则内每个数据源字段最多选一次"）vs 原型 COND_DETAIL_RULES（第 278-283 行）
- **问题**：原型中 Bags 类目的成色详细信息配置有 5 个字段行，其中 cf2（Exterior）和 cf3（Interior）**都绑定了 `appearance_desc`** 数据源。这违反了 PRD 明确规定的互斥规则。
  - 原型数据（第 280-281 行）：
    - `cf2: name='Exterior', source='appearance_desc'`
    - `cf3: name='Interior', source='appearance_desc'`
  - 开发如果按互斥规则实现 Select 禁用逻辑，这条示例数据本身就是非法状态；如果按示例数据理解规则，又与 PRD 互斥规则矛盾。
- **建议**：修正 Bags 示例数据——cf3 的数据源应改为其他字段（如 `supplement_notes`），或重新评估互斥规则是否需要放宽（允许同一数据源多次使用、用不同展示名区分前台展示）。

### 2. [开发] APP 端 Add to Cart 飞入动效目标与页面结构矛盾

- **位置**：PRD 5.2 节差异对照表（第 971 行）vs PRD 2.8 节（第 501 行）
- **问题**：PRD 内部对 APP 端 Add to Cart 飞入动效的描述自相矛盾：
  - 5.2 差异表写道："商品图飞向**底部 Tab 购物车图标** + 角标 +1"
  - 2.8 节明确说："APP 端商详页**隐藏底部 TabBar**，由 Sticky 底部购买栏替代"
  - 底部 TabBar 在商详页已被隐藏，飞入动效不可能飞向一个不存在的目标。开发无法实现此动效。
- **建议**：修正 5.2 APP 端飞入动效描述——目标应改为 **Header 右上角购物车图标**（与 PC 端一致），或确认其他目标位置。

### 3. [测试] listing_status=off_shelf 时页面级行为未定义

- **位置**：PRD 2.8 节（商品可售性判断表格，第 485 行）
- **问题**：PRD 写 off_shelf 时"页面显示'商品已下架'提示"，但未定义页面**整体**行为：
  - 场景：用户通过收藏记录中的链接访问一件已下架商品。页面打开后看到的是什么？
  - 方案 A：整页替换为"商品已下架"提示页（类似 404），其他模块不渲染
  - 方案 B：保留完整商品信息（Gallery、价格、Condition 等），仅在 CTA 区域显示"已下架"并禁用按钮
  - 两种方案的前端实现和用户体验完全不同，测试无法写验收用例
- **建议**：明确 off_shelf 的页面级行为。如果选方案 A，需确认推荐区 / 浏览历史是否仍展示（引导用户发现其他商品）；如果选方案 B，需确认价格是否仍展示（下架商品展示价格可能误导用户）。

## P1（规则不完整，影响质量）

### 4. [开发] Condition 等级数量限制：PRD "无上下限" vs 原型最少 2 个

- **位置**：PRD 2.10 节（第 628 行："等级数量灵活……无上下限约束"）vs 原型 ConditionEditModal（第 494 行：`grades.length > 2` 控制删除按钮）
- **问题**：PRD 明确写"无上下限约束"，但原型通过 `grades.length > 2` 条件强制最少保留 2 个等级。V1.5 评审时已将 PRD 从"3-6"改为"不限制"，但**原型未同步更新**——删除条件仍是 `> 2`（即最少 2 个）。
  - 业务上，进度条只有 1 段时失去了"对比"含义，最少 2 个可能是合理的
  - 但 PRD 和原型的规则不一致，测试无法判断边界值
- **建议**：对齐为"最少 2 个等级"，PRD 补充下限约束，或原型去掉限制。从业务角度看建议保留最少 2 个。

### 5. [开发] 模板新建弹窗有「描述」字段，PRD 未定义

- **位置**：PRD 2.3 节（模板属性表，第 194-199 行）vs 原型 NewTemplateModal（新建弹窗包含"模板名称"+"描述"+"关联类目"三个字段）
- **问题**：PRD 模板属性只列了「模板名称」和「关联类目」两个属性，但原型新建/编辑弹窗都有一个「描述」TextArea 字段。开发不确定模板数据模型是否需要 description 字段。
- **建议**：确认「描述」是否为正式属性。如果是，PRD 2.3 模板属性表补充；如果不是，原型需删除。

### 6. [开发] Size Guide 默认展示名不一致

- **位置**：PRD 2.11 节（第 703 行："运营可编辑前台展示名（默认'Size'）"）vs 原型 DescAttrNewModal（新增规则时 Size Guide 展示名初始值为 "Size Guide"）
- **问题**：前台默认 label 是 "Size" 还是 "Size Guide"？翻译入队时的源文本也会不同，影响多语言翻译。
- **建议**：对齐确定默认值。"Size Guide" 比 "Size" 更准确地传达功能含义，建议 PRD 改为 "Size Guide"。

### 7. [开发] Condition 边界情况"三个选填字段"与 4 字段配置模型不匹配

- **位置**：PRD 2.10 节（第 652 行："三个选填字段全部为空时：仅展示等级进度条 + 徽章 + 成色描述"）
- **问题**：2.10 节定义的可配置数据源字段有 4 个（condition_summary、appearance_desc、accessories_info、supplement_notes），不是 3 个。而且这条边界情况说"仍展示成色描述"——成色描述就是 condition_summary 字段。这暗示 condition_summary 有特殊的"必展示"地位，但上方通用规则写的是"有值时展示，为空时该行隐藏"，两者矛盾。
  - 如果 condition_summary 总是展示（即使 CMS 未配置），则它不应由 CMS 类目级配置控制
  - 如果它也受 CMS 配置控制，则边界情况应改为"CMS 配置的所有字段均为空时：成色详细信息区域整体隐藏"
- **建议**：明确 condition_summary 是否有特殊地位。如果没有（与其他 3 个字段同等），修正边界情况为"**四个**字段全部为空时：成色详细信息区域整体隐藏，仅保留进度条 + Condition Guide + 徽章"。

### 8. [开发] 模板删除 + 类目跨模板迁移的影响规则缺失

- **位置**：PRD 2.3 节（第 192-206 行）
- **问题**：PRD 定义了模板的创建、配置、开关、变更记录，操作类型枚举也包含"删除模板"，但缺少两个关键场景的规则：

  **场景 A：模板删除**
  - 运营删除 Luxury PDP 模板，该模板关联了 Jewelry / Bags / Watches 三个类目，这些类目下有数百件在售商品
  - 删除后这些类目变为"未关联模板"，按 2.3 规则：Certified Authentic 不展示、Condition 仅展示基本信息、Description 不展示——大量商品页面突然缺失多个模块
  - 是否允许删除已有关联类目的模板？

  **场景 B：类目迁移**
  - 运营将 Necklace 类目从 Luxury 模板迁移到 Fine Jewelry 模板
  - 旧模板中的类目级配置（Condition 详细信息、Description 属性）是否跟随迁移到新模板？还是清空需重新配置？
  - 新模板的等级体系可能不包含某些商品的 grade（如旧模板有 Fair，新模板无 Fair），导致进度条静默隐藏

- **建议**：
  - 模板删除：增加前置校验——已关联类目的模板需先解绑所有类目（或阻止删除），防止误操作
  - 类目迁移：明确类目级配置是否随迁移清空，并在迁移操作时给出影响提示

### 9. [测试] 浏览历史已下架商品处理规则"或"字二选一

- **位置**：PRD 2.14 节（第 820 行）
- **问题**：边界情况写"浏览记录中的商品已下架：标记 'Sold' 标签**或**从列表移除"，用"或"连接了两个互斥方案。测试无法判断验收标准。
  - 如果选"标记 Sold 标签"：Sold 标签是否可点击？点击后跳转到什么？（已下架页面）
  - 如果选"从列表移除"：列表会不会因为移除过多而变空？
  - 另外 "Sold" 不等于"下架"——售罄和下架是不同状态，标记"Sold"可能误导用户
- **建议**：选定一种方案。建议：售罄（active + 无库存）→ 标记 "Sold Out" 标签 + 卡片置灰不可点击；主动/违规下架（off_shelf）→ 从列表移除。

### 10. [测试] 汇率查询失败时价格降级策略未定义

- **位置**：PRD 2.7 节（币种转换流程，第 436 行）
- **问题**：PRD 详细定义了正常的币种转换流程（调用汇率管理模块查询接口），但未定义接口不可用时的降级行为。
  - 场景：用户选择展示货币 EUR，listing 定价 USD，但汇率查询接口超时。价格区域展示什么？
  - 可能方案：回退展示定价货币原价 / 展示"价格暂不可用"/ 使用缓存汇率
  - 价格是用户购买决策的核心信息，异常场景必须有明确定义
- **建议**：补充汇率查询失败的降级策略。建议回退到定价货币原价展示，并给出提示"Price shown in [定价货币]"。

### 11. [开发] 4 个外部依赖未在第三章声明

- **位置**：PRD 第三章（第 888-916 行）
- **问题**：PRD 正文中引用了以下外部模块，但第三章依赖表中未列出：

  | 被引用模块 | 引用位置 | 引用方式 |
  |-----------|---------|---------|
  | 购物车/订单域 | 2.4 Header Cart 角标（第 309 行）、2.8 Add to Cart/Buy Now | 提供加购接口和购物车角标数量 |
  | 配送模块 | 2.12（第 737 行）、后续迭代（第 936 行） | "后续配送模块就绪" |
  | 营销模块 | 2.15 Footer Newsletter（第 840 行） | 数据来源标注"营销模块" |
  | Share To | 2.4（第 321 行）、5.2（第 969 行） | "详见 Share To PRD" |

  其中 Share To PRD 被两次引用但实际不存在。如果是后续设计的模块，应声明为"待设计"依赖。

- **建议**：第三章依赖表补充这 4 个模块，标注当前状态。Share To 如未设计，正文改为"后续设计"而非"详见 Share To PRD"。

### 12. [测试] Sold Out 时收藏按钮和收藏人数行为未定义

- **位置**：PRD 2.6 节 + 2.8 节
- **问题**：2.8 节定义了 Sold Out 时 CTA 按钮禁用，但 Gallery 区域的收藏按钮和收藏人数在售罄状态下的行为未说明。
  - 场景：一件已售罄商品（active + 库存 0），用户访问商详页。Gallery 区的收藏按钮是否仍可点击？收藏人数是否仍展示？
  - 二手电商中允许收藏售罄商品是常见做法（用于到货提醒），但需明确定义
- **建议**：明确 Sold Out 时收藏功能是否可用，以及是否展示收藏人数。

- **问题**：表格三行场景（有促销 / 无促销有 compare_at_price / 均无）表面看是互斥的，但实际数据中"有促销价"和"有 compare_at_price"可以同时存在。场景：listing_price=200，compare_at_price=300，promotion_price=150。
  - 按表格第一行：划线价=listing_price(200)，Save=50
  - 但用户视角 300→150（Save 150）更有吸引力
  - 虽然当前促销模块未设计，但 compare_at_price 已在 V1.6 引入，需提前定义组合行为
- **建议**：补充"促销价 + compare_at_price 同时存在"时的划线价取值规则（建议：有促销时划线价=max(listing_price, compare_at_price)，让用户看到最大折扣）。
