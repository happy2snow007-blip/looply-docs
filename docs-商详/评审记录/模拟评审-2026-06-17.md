## P0（规则缺失或制品矛盾，阻塞开发）

### 1. [开发] Condition 模块开关行为定义矛盾

- **位置**：PRD 2.3 节（模块开关段落） vs PRD 2.10 节（CMS 配置段落）
- **问题**：同一 PRD 内对 Condition 模块开关关闭后的前台行为定义矛盾。
  - 2.3 节通用规则写道："模块开关关闭后，前台商详页不展示该模块（完全隐藏，无默认内容）"
  - 2.10 节 Condition 专属规则写道："模块开关：关闭后前台不展示 Condition 折叠区的进度条和 Condition Guide（但成色描述等质检信息仍展示）"
  - 当运营关闭 Condition 模块开关后，开发按 2.3 实现"整个 Condition 折叠区消失"，还是按 2.10 实现"进度条/Guide 消失但成色描述保留"？两种实现差异巨大。
- **建议**：明确 Condition 开关的唯一行为。考虑到成色描述（condition_summary、appearance_desc 等）来自 product_inspection 而非 CMS 配置，Condition 开关可能只应控制 CMS 配置的部分（进度条 + Condition Guide），质检信息作为商品固有属性始终展示。如果选择"完全隐藏"方案，需更新 2.10；如果选择"部分隐藏"方案，需在 2.3 增加 Condition 的例外说明。

### 2. [开发] Description 删除确认弹窗文案引用已废弃的继承机制

- **位置**：PRD 2.3 节 vs 原型 DeleteConfirmModal（约第 396 行）
- **问题**：PRD 1.2 节声明"CMS 后台页面交互由 CMS 后台原型文档维护"，因此原型弹窗文案也属于规格的一部分。当前两边定义矛盾：
  - PRD 2.3 节："删除某类目的规则后，该类目商品的 Description 区域整体隐藏"（V1.5 已简化为仅按类目配置，无品牌/系列继承）
  - 原型弹窗文案："删除后，该作用域下的商品将回退到上级规则（如品牌级删除后回退到类目级）"
  - 开发如果按弹窗文案实现"回退到上级规则"逻辑，会找不到任何上级规则（因为 V1.5 已取消继承），导致行为不确定。
- **建议**：更新原型弹窗文案为"删除后，该类目下的商品将不展示 Description 区域"，与 PRD 2.3 的"整体隐藏"行为对齐。

## P1（规则不完整，影响质量）

### 3. [开发] 成色进度条高亮颜色值与品牌色不一致

- **位置**：PRD 2.10 节（分段进度条段落）
- **问题**：PRD 写道"当前商品等级对应的段高亮为品牌色（紫色 #5212FF）"，但全系统品牌色为 **#7C3AED**（looplyTheme.colorPrimary、原型组件、Figma 设计稿统一使用）。#5212FF 不在品牌色卡中，也未在任何其他制品中出现。
  - 前端按 PRD 的 #5212FF 实现，进度条颜色会与页面其他品牌色元素（按钮、选中标签、链接等 #7C3AED）产生视觉割裂。
- **建议**：将 PRD 中的 #5212FF 更正为 #7C3AED，与品牌色体系保持一致。

### 4. [测试] Condition 等级数量范围校验不一致

- **位置**：PRD 2.10 节 vs 原型 ConditionEditModal（约第 508 行）
- **问题**：PRD 说"不同模板可定义 3-6 个等级"，但原型实现与之不符：
  - 删除：原型用 `grades.length > 2` 控制删除按钮显示，即最少可保留 2 个等级（PRD 要求最少 3 个）
  - 添加：原型 addGrade 无上限检查（PRD 要求最多 6 个）
  - 测试无法确定边界：最小等级数是 2 还是 3？最大等级数是 6 还是无上限？
- **建议**：统一为 PRD 定义的 3-6 范围。原型删除条件改为 `grades.length > 3`，添加按钮在 `grades.length >= 6` 时禁用或隐藏。

### 5. [开发] 新建模板字段定义不一致

- **位置**：PRD 2.3 节 vs 原型 NewTemplateModal（约第 686 行）vs EditTemplateModal（约第 731 行）
- **问题**：三处对"模板名称"的定义各不相同：
  - PRD 2.3："模板名称: 运营自定义"（单字段）
  - 原型新建弹窗：两个必填字段"模板英文名"和"模板中文名"
  - 原型编辑弹窗：单字段"模板名称"
  - 开发做数据模型时，是一个 name 字段还是 name_en + name_cn 两个字段？编辑时怎么对应？
- **建议**：确认是单名还是双语名，统一 PRD 和两个弹窗的定义。如果是双语名，PRD 2.3 需补充说明模板有英文名和中文名两个字段；如果是单名，原型新建弹窗需简化。

### 6. [测试] Size Guide 默认值策略未在原型中体现

- **位置**：PRD 2.3 节（Size Guide 默认值策略）vs 原型 DescAttrNewModal（约第 604 行）
- **问题**：PRD 明确按类目区分 Size Guide 默认值：
  - "有尺码概念的类目（Jewelry / Bags / Clothing 等）：Size Guide 默认开启"
  - "无尺码概念的类目（Electronics 等）：Size Guide 默认关闭"
  - 但原型新增规则时，无论选择哪个类目，Size Guide 始终初始化为 `enabled: true`
  - 当运营新增 Phones 类目规则时，Size Guide 应该默认关还是默认开？实际行为与 PRD 不一致。
- **建议**：原型根据所选类目判断默认值：Jewelry & Accessories / Bags / Watches / Shoes / Clothing 等类目默认开启，Phones / Laptops / Tablets 等类目默认关闭。或者在 PRD 中维护一份"有尺码概念的类目"清单，而不是用"等"字模糊处理。

### 7. [开发] 变更日志示例数据引用已废弃的品牌级配置

- **位置**：原型 OPLOG_DATA 第 5 条（约第 298 行）
- **问题**：该条记录内容为"修改「Jewelry > LV」品牌级配置：新增 Length 属性"。V1.5 已将 Description 配置从「类目 > 品牌 > 系列」三级继承简化为仅按类目配置，不再存在"品牌级配置"概念。
  - 运营看到此示例会误以为存在品牌级配置功能。
  - 虽然只是示例数据，但作为原型交付物，示例应反映当前业务模型。
- **建议**：将该条记录改为类目级操作，如"修改「Jewelry & Accessories」类目级配置：新增 Length 属性"。

### 8. [开发] CMS 等级删除后已关联商品的处理规则缺失

- **位置**：PRD 2.10 节（CMS 配置段落）
- **问题**：PRD 定义了 Condition 等级可增删改排序，但未说明删除等级后对存量商品的影响：
  - 场景：Luxury 模板原有 5 个等级（Like New / Excellent / Very Good / Good / Fair），运营删除"Fair"等级。此时已有 30 件商品的 `product_inspection.grade` 被标记为 Fair。
  - 这些商品在商详页的进度条如何渲染？等级文字展示什么？Condition Guide 中是否还列出 Fair？
  - 可能方案：禁止删除已被使用的等级（需前端校验）、删除后存量商品降级/升级到相邻等级、删除后存量商品等级标记为"已弃用"仍展示旧文案但进度条不渲染。
- **建议**：在 PRD 2.10 CMS 配置段落补充"等级被使用时的删除约束"规则（如：已有商品使用该等级时，禁止删除并给出提示）。

## P2（描述可更精确）

### 9. [测试] 变更记录筛选维度不完整

- **位置**：PRD 2.3 节 vs 原型变更记录 Drawer（约第 1012-1019 行）
- **问题**：PRD 要求"支持按操作人、所属模板、所属模块和操作类型筛选"（4 个维度），原型仅实现了"所属模板"和"所属模块"两个筛选器，缺少"操作人"和"操作类型"。
  - 原型作为交付规格，测试按原型写用例只有 2 个筛选项，与 PRD 不符。
- **建议**：确认 MVP 是否需要 4 个筛选维度。如果 4 个都做，原型补充两个筛选器；如果本期只做 2 个，PRD 2.3 调整表述或标注后续迭代。

### 10. [测试] Trust Statement 标题/描述必填的保存校验未定义

- **位置**：PRD 2.9 节
- **问题**：PRD 说"标题或描述为空：不展示（三个字段中标题和描述为必填）"，但"必填"的校验时机不清楚：
  - 是后台保存时做非空校验（不允许保存空标题）？
  - 还是允许保存空标题，只是前台渲染时不展示？
  - 原型 TrustEditModal 无任何保存校验逻辑，保存按钮始终可点击。
  - 测试写"清空标题后点保存"的用例时，预期结果是"保存失败给提示"还是"保存成功但前台不展示"？
- **建议**：明确保存时的校验规则——建议后台保存时校验标题和描述非空，给出明确错误提示"标题不能为空"。

### 11. [设计] 进度条非激活段颜色值可能有误

- **位置**：PRD 2.10 节（分段进度条段落）
- **问题**：PRD 写道非激活段为"浅色（#F3F0FF）"，但 #F3F0FF 不在品牌色卡中。品牌色体系的标准浅紫为 #F3EEFF（itemSelectedBg）或 #EDE9FE（原型 ConditionBarPreview 实际使用值）。
  - #F3F0FF 与 #F3EEFF 视觉差异极小（肉眼几乎不可辨），但色值不一致会导致代码实现时产生歧义。
- **建议**：更正为品牌色体系中的标准值（#EDE9FE 或 #F3EEFF），与原型和设计稿对齐。

## P3（锦上添花）

### 12. [设计] Description CMS 预览未包含商品描述文案占位提示

- **位置**：原型 DescPreviewCard（约第 355-386 行）
- **问题**：PRD 2.11 说"商品描述文案：展示在属性表下方，作为描述折叠区的一部分"。但 CMS 的 Description 预览卡只展示了属性行和 item #，未提示运营"属性下方还会展示商品描述文案（来自 listing.listing_description）"。
  - 运营可能以为前台 Description 区域只展示自己配置的属性列表，不知道下方还有一段商品描述文案。
- **建议**：在预览卡底部增加一行灰色提示文字，如"属性下方将自动展示商品描述文案（来自渠道描述）"，让运营了解完整前台效果。
