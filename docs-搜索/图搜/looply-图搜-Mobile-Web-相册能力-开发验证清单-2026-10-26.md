# Looply 图搜 Mobile Web 相册能力开发验证清单

日期：2026-10-26<br>
依据：[图搜 PRD v0.1](looply-图搜-PRD-v0.1.md) §2.1、§4、§6。此清单用于技术可行性验证，不把 Demo 的模拟授权或示例照片当作浏览器能力。

## 目标体验

相册面板初始显示 `Enable photo access to find products faster.` 与 `Enable`。用户点击 `Enable` 后请求照片访问；允许则在面板内展示用户设备的最近照片缩略图，点击照片提交整图搜索；拒绝则仍显示开启状态。`All photos` 打开系统选图器，取消选择后原页面和结果不变。

## 开发实测项目

| 项目 | 需要记录的证据与结论 |
|---|---|
| 目标环境 | 列出本期实际支持的 iOS Safari、Android Chrome 及其他目标浏览器／版本和设备；不要仅凭桌面模拟器结论覆盖手机。 |
| 权限触发 | 在首次进入、点击 `Enable`、已允许、已拒绝、浏览器记住拒绝、撤销授权后分别观察系统或浏览器提示是否出现，记录真实触发时机。 |
| 最近照片读取 | 验证网页能否在用户授权后列出设备最近照片的缩略图、可读取范围、排序、数量、加载耗时，以及是否需用户逐张主动选择；按浏览器分别给出可／不可实现结论。 |
| 系统选图器 | 验证 `All photos` 能否打开、选择一张照片能否读取和搜索、取消选择是否保持原状态；与面板内最近照片能力分别判断。 |
| 拒绝与恢复 | 验证拒绝后保持 `Enable` 状态；再次点击与下次进入能否重新请求、是否须转浏览器设置，记录可向用户提供的真实操作路径。 |
| 摄像头独立性 | 相机拒绝、相册允许；相机允许、相册拒绝；两者均拒绝时，核对相册面板和拍照入口状态，避免将两类权限误合并。 |
| 图片输入 | 对最近照片、系统选图及拍照输入分别验证支持格式、大小上限、无法解码和超时；实际限制由开发方案统一确定，错误提示须与 PRD §2.4 对应。 |
| 隐私与数据 | 明确照片获取、暂存、上传、删除和日志范围；埋点及 URL 不记录图片像素、base64、文件名、EXIF、完整图片地址或剪贴板内容。 |

每个目标浏览器至少提交：设备与版本、操作步骤、截图或录屏、权限结果、最近照片可否直接展示、失败原因及可复现性。技术结论若为不能实现目标体验，回到产品评审决定替代交互，再更新 UI、PRD 和 Demo；不得将 Demo 模拟状态视为验收通过。
