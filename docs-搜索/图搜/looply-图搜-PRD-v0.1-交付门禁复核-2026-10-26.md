- Mobile section 可见首页入口、拍照／相册、搜索中、结果、无结果、相机／相册未授权及其西语画板。搜索中画板有 `Cancel`；无结果画板显示图片缩略图、`No results found for this image`、`Try searching for a different brand or item.` 与 `More to Explore`，与 PRD §2.3–2.4 的主文案一致。未授权画板显示 `Enable photo access to find products faster.` 和 `Enable`，与 PRD §2.1 一致。画板仅说明期望状态，不证明浏览器能取得最近照片。
- PC section 可见首页入口、上传、图片链接及错误示例、结果和无结果画板。无结果画板有本次图片缩略图及 `More to Explore`；结果画板显示缩略图、结果数、原搜索页筛选排序与商品网格，和 PRD 主结构一致。

先读[当前 PRD](looply-图搜-PRD-v0.1.md)的本期规则，再看其中 §5 指向的双端 UI 稿与 Demo；[Checklist](looply-图搜-Checklist-v0.1.md)用于追踪待验证能力和历史取舍。Demo 只说明交互期望，不能替代技术验证或已确认 UI。开发需提供图片接收、Mobile Web 相册、结果恢复及结果链路埋点方案；这些方案评审通过后，才可将 PRD 与 UI 冻结为实施和验收基线。

## 结果恢复决策记录

已确认的[文字搜索 PRD v0.2](../PRD/looply-Web全局搜索-PRD-v0.2.md) §6.7 支持可分享结果 URL、刷新及前后退恢复；图搜尚无安全的图片状态标识，不能直接沿用文字词条写入 URL 的方式。现有 eBay 图搜截图能看到结果 URL，但没有刷新或跨设备实测证据，因此此处不把竞品行为写成事实。

| 选项 | 用户可见行为 | 主要代价 |
|---|---|---|
| A（2026-10-26 用户已确认） | 同设备刷新及浏览器前后退可恢复当前图搜结果；本期不提供图搜结果分享与跨设备恢复。 | 需开发设计短期、受控的结果状态保存；与文字搜索的可分享 URL 体验不同。 |
| B | 刷新、分享及跨设备打开都恢复同一图搜结果。 | 需可跨设备读取的安全图片／结果标识和访问、留存、过期规则，范围更大。 |
| C | 刷新后返回首页；本期不提供分享及跨设备恢复。 | 实现边界较窄，但误刷新会丢失当前结果，与现有文字搜索的结果恢复规则差异更大。 |

用户选择 A，理由是保留同设备误刷新后的连续性，并将跨设备图片保存与分享能力留待后续。该用户可见规则已进入 PRD；具体状态保存、有效期与隐私边界仍需开发方案评审。
