# Looply 图搜 PRD v0.1（工作稿）

> 日期：2026-10-23<br>
> 范围：买家侧 PC Web、Mobile Web 的整图搜索。本文是产品工作稿；双端图搜 UI 的定稿状态与缺失状态视觉核对、Mobile Web 相册能力及结果恢复技术方案尚未完成，不作为冻结的开发交付基线。图片接收能力与结果链路埋点由开发按本文边界设计并评审。

## 一、概述

### 1.1 目标与范围

用户从站内图搜入口提交一张图片，系统按整张图片查找相似在售商品，并使用现有搜索结果商品卡、筛选、排序及无结果推荐能力。游客与登录用户均可使用；商品展示、收藏及进入商详沿用当前搜索结果页和商品模块的有效规则。

当前搜索请求只有图片输入。商品匹配质量、相似度排序、索引范围及召回策略由搜推方案定义；本 PRD 定义用户可见流程、状态及埋点业务语义。

### 1.2 页面流转

| 终端 | 页面流转 |
|---|---|
| PC Web | 来源页 → 图片上传弹窗 → 搜索结果页 → 商品详情。 |
| Mobile Web | 来源页 → 拍照及相册界面 → 图片预览与结果面板 → 商品详情；顶部返回退出图搜。 |

## 二、需求详细描述

### 2.1 图片输入与搜索提交

| 终端 | 入口和输入方式 | 提交时机 |
|---|---|---|
| PC Web | Header 搜索框的相机图标打开图片上传弹窗。用户可选择本地图片、拖入图片、直接粘贴剪贴板图片，或填写可读取的直接图片链接。图搜结果页还可在搜索框直接粘贴新图片。 | 从上传弹窗取得有效图片后，直接按整图发起搜索；图片链接由用户点击 `Search` 提交。结果页搜索框粘贴新图片后，须点击搜索按钮或按回车才提交。 |
| Mobile Web | 首页搜索框内的相机入口打开拍照界面。底部相册面板可上滑展开；未取得照片访问能力时展示开启入口，取得后展示最近照片与 `All photos`。拍照按钮取得图片后发起搜索。 | 用户点击最近照片、在 `All photos` 中选定可读取图片，或成功拍照并通过输入校验后，直接按整图发起搜索。 |

Mobile Web 用户每次主动进入拍照界面时，页面均尝试启动相机；浏览器需要授权时由浏览器发起权限请求。授权成功后展示实时预览并允许拍照。用户拒绝或相机不可用时，在拍照界面显示对应提示，不发起搜索；选图入口仍保留在底部相册面板。用户下次进入拍照界面时再次尝试启动相机；浏览器若已记住拒绝状态，可能直接返回拒绝而不再弹出系统权限框，此时提示用户到浏览器设置中开启。

相册面板在未取得照片访问能力时展示 `Enable photo access to find products faster.` 和 `Enable`。点击 `Enable` 请求照片访问；用户允许后，在面板内展示最近照片缩略图，点击具体照片直接提交整图搜索，`All photos` 打开系统选图器；用户拒绝后，仍停留在相册开启状态，`Enable` 保持可见，不展示最近照片。此为产品期望交互；Mobile Web 是否能在目标浏览器取得相应照片访问能力、授权范围及拒绝后的恢复方式，须由开发验证。当前 Demo 用模拟授权选择及示例照片展示成功、拒绝两条路径，不代表真实系统权限或设备照片。取消系统选图后保持原界面与结果状态，不报错、不发起搜索。

打开入口或关闭 PC 上传弹窗均不产生搜索。输入无效时留在当前界面反馈，允许重新输入。图片与文字关键词不组合为一次搜索；PC 图搜结果页搜索框显示图片状态，用户清除图片后可继续输入文字关键词。

同一次选择产生的重复回调只发起一次搜索。用户连续选择不同图片时，结果只采用最后一次有效提交；旧请求迟到时不能覆盖新图片及其结果。

PC 与 Mobile Web 正式提交新图片时，清除上一张图片结果的筛选，并将排序恢复为线上搜索结果页的默认设置；仅更换待提交输入时，原结果和设置保持不变。

### 2.2 PC 结果页

图片提交后进入现有搜索结果页，加载期间在结果区域展示骨架，搜索框显示图片缩略图，结果标题区域显示本次图片缩略图。成功时显示结果数、统一商品列表、筛选和排序；筛选与排序使用线上搜索结果页的现行规则。

搜索框图片缩略图上的 `×` 只清除当前输入，恢复空文字搜索框；**当前结果、结果数、筛选、排序和滚动位置保持为原图搜结果快照**，直到用户正式提交下一次搜索。清除后当前列表的商品曝光和点击仍归属于原图搜结果。

在结果页搜索框粘贴有效的新图片后，搜索框缩略图先替换为新图，形成 §2.1 所述待提交输入；原结果、结果数、筛选、排序和滚动位置保持不变。提交前再次粘贴图片，以最后一张有效图片作为待提交输入；点击缩略图 `×` 仅清除待提交输入，仍保留原结果快照。正式提交时按 §2.1 重置旧筛选与排序。

### 2.3 Mobile 结果页

取得图片后先展示用户选择的整张图片，并在该页面上呈现搜索中的轻量动效与 `Cancel`（静态文案 key：`image_search.cancel`）。搜索成功返回后，底部结果面板默认展开到顶部。成功结果沿用移动搜索结果的筛选栏、双列商品卡及排序组件。

搜索中点击 `Cancel`，结束本次搜索等待并返回拍照／相册页面，用户可重新拍照或选图。取消后不自动重新提交原图；已取消请求即使随后返回，也不展示其结果、不跳转结果页。取消作为独立终态处理，不显示失败或无结果提示。

用户向下滑动结果面板时，面板收到底部，保留当前图片和结果状态；点击底部把手或向上滑动可重新展开，展开不会重新搜索。点击结果面板右侧 `×` 时，关闭当前结果页并返回拍照／相册界面；不自动重新提交原图。顶部返回按钮退出图搜。结果页顶部只保留返回按钮和标题 `Search by image`。

### 2.4 结果状态与异常

PC 与 Mobile Web 在同一设备、同一浏览器刷新图搜结果页时，恢复刷新前正在展示的已提交图片结果、筛选和排序；浏览器前进／后退回到仍可恢复的图搜结果时亦沿用该规则。刷新或历史导航不构成新的图片提交，也不重复计入入口或提交埋点。滚动位置和已加载批次沿用线上搜索结果页的现行恢复规则。本期不提供图搜结果分享和跨设备恢复；图搜页面不生成可跨设备恢复图片结果的分享链接。浏览器本地结果状态不存在或已失效时，进入首页初始状态。开发需设计同设备结果状态的安全保存、有效期与失效机制；原图、图片链接原文和 EXIF 不写入明文 URL 或埋点。

| 状态 | 成立条件 | 页面结果 |
|---|---|---|
| 搜索中 | 已提交有效图片、当前请求尚未结束 | 保留所选图片，显示轻量识别动效；商品区域处于加载态。 |
| 已取消（Mobile） | 用户在搜索中点击 `Cancel` | 按 §2.3 返回拍照／相册页面。 |
| 有结果 | 当前请求成功且有商品 | 展示结果数量、统一商品卡、筛选与排序。 |
| 无结果 | 首次整图搜索、正式提交新图或同图重试成功，且未应用筛选的结果数为 0 | 展示本次搜索图片缩略图、`No results found for this image`、`Try searching for a different brand or item.` 和 `More to Explore` 推荐商品区；推荐商品复用现有文字搜索无结果推荐数据与商品卡规则。 |
| 搜索失败 | 首次整图搜索、正式提交新图或同图重试的结果请求失败或超时 | 保留图片和当前输入，展示失败提示及 `Try again`；点击后重试同一张整图。 |
| 输入失败 | 当前实现无法接收或读取图片，包括格式、大小、解码或 PC 图片链接读取失败 | 在输入位置显示对应错误，允许重新选图或修正链接；不进入搜索结果页。 |

无结果与失败使用不同状态。无结果页没有额外操作按钮；推荐商品的曝光和点击按推荐展示位归因。开发确定的图片接收能力及链接校验边界需进入技术方案与验收说明。

已有图搜结果上的筛选后 0 件、追加下一批失败，沿用[《Web 全局搜索 PRD v0.2》§6.6](looply-Web全局搜索-PRD-v0.2.md)的结果状态：前者保留筛选并提供 `Clear filters`，后者保留已加载商品并在列表底部或 `View More` 区域重试；均不替换为本节的整图搜索无结果或整块失败页面。

输入异常在当前界面就近提示；文件选择器取消或关闭上传弹窗不报错。文件格式、大小、解码及链接读取问题在搜索请求前拦截；请求发出后的失败使用搜索失败状态。零结果属于搜索成功。一个异常只显示最具体的一条提示；无法确定原因时，显示当前阶段的通用失败提示。

| 静态 UI key | 触发条件 | 英文文案 | 反馈与后续操作 | 适用端 |
|---|---|---|---|---|
| `image_search.file_type_unsupported` | 所选、拖入或粘贴的文件不属于实际支持格式 | This image format isn't supported. Choose another image. | 输入位置提示，可重新选图。 | PC、Mobile |
| `image_search.file_too_large` | 图片超过实现设定的大小限制 | This image is too large. Choose an image under {limit}. | 输入位置提示，可重新选图；`{limit}` 使用开发确定的实际限制。 | PC、Mobile |
| `image_search.image_unreadable` | 文件可接收，但图片损坏或无法解码 | We couldn't open this image. Try another photo. | 输入位置提示，可重新选图。 | PC、Mobile |
| `image_search.url_invalid` | 图片链接为空、无效或并非直接图片地址 | Enter a direct link to an image. | 链接输入框下方提示，保留输入内容供修改。 | PC |
| `image_search.url_unavailable` | 链接有效，但图片无法取得或读取 | We couldn't open this image link. Check the link or upload a photo. | 链接输入框下方提示，可修改链接或上传文件。 | PC |
| `image_search.camera_permission` | 相机权限被拒绝或禁用 | Camera access is off. Allow it in your browser settings. | 拍照界面提示；底部相册面板仍可使用。下次进入时重新尝试启动相机，由浏览器决定是否再次弹出授权框。 | Mobile |
| `image_search.camera_unavailable` | 无可用相机或相机无法启动 | Camera unavailable. | 拍照界面提示；底部相册面板仍可使用。 | Mobile |
| `image_search.album_access` | 相册面板尚未取得照片访问能力，或用户拒绝照片访问 | Enable photo access to find products faster. | 面板展示 `Enable`；点击后请求访问，允许则显示最近照片，拒绝则保留开启状态。 | Mobile |
| `image_search.search_failed_pc`、`image_search.search_failed_mobile` | 图片识别或结果请求失败，包括网络中断与超时 | **Title:** Let's try that again  **Body:** We couldn't load your results. Your photo is saved.  **Action:** Try again | 结果区显示错误态，保留原图，点击后重试同一张整图。 | PC、Mobile |
| `image_search.no_results_pc`、`image_search.no_results_mobile` | 搜索成功，返回 0 件商品 | **Title:** No results found for this image  **Body:** Try searching for a different brand or item.  **Section:** More to Explore | 结果区展示搜索图片缩略图，复用文字搜索无结果推荐商品区。 | PC、Mobile |

### 2.5 多语言与数据来源

本模块新增的标题、按钮、错误及状态文案属于静态 UI 文案，使用稳定 key 接入 Web i18n；上表 key 与双端图搜 UI 逐态核对。商品、品牌、价格及筛选项沿用现有搜索结果页的数据与当前 locale 展示规则。图片本身、用户粘贴的图片链接和文件名不做翻译。

结果数和有序商品来自图搜结果服务；商品卡字段来自现有商品数据；可用筛选及排序条件由搜索结果组件与服务共同提供；无结果推荐来自现有搜索无结果推荐模块。页面不得以 Demo 中的固定数量、商品图或价格作为正式数据。

## 三、数据与埋点规划

### 3.1 双端入口与关键交互（本期产品埋点需求）

本期产品埋点覆盖用户从何处进入图搜、如何提供图片、何时正式提交，以及权限、输入失败、取消和重试等关键交互。PC 与 Mobile Web 的入口页面和后续操作不同，须分端识别；不把打开入口、选中图片与正式提交混为一次动作。入口与交互所用事件名、字段名及一方／GA4 去向由开发按现有埋点规范设计，产品验收以下业务事实与去重口径。

| 终端 | 需覆盖的入口或交互 | 成立与区分规则 |
|---|---|---|
| PC Web | Header 相机图标打开上传弹窗 | 弹窗实际打开记一次图搜入口；保留真实来源页／模块。首页与结果页若使用同一图标，仍通过来源页区分；粘贴新图不算重新打开入口。 |
| Mobile Web | 首页相机入口进入拍照／相册界面 | 界面实际进入记一次图搜入口；即使随后相机权限被拒绝，入口仍成立。返回后重新进入形成新一次入口。 |
| PC Web | 选择文件、拖入图片、粘贴剪贴板图片、提交图片链接；结果页粘贴新图、清除待提交图片 | 区分输入方式和发生位置；仅取得有效图片后形成可提交输入，结果页粘贴只暂存，清除只移除输入。取消文件选择不形成图片输入。 |
| Mobile Web | 拍照、点击最近照片、从 `All photos` 选择照片；点击相册 `Enable` 及授权允许／拒绝 | 区分相机与相册输入，以及相册开启交互和授权结果；取消系统选图不形成图片输入。相册授权态在真实能力验证后落点。 |
| PC、Mobile | 有效图片正式提交、输入校验失败、同图重试；Mobile 搜索中点击 `Cancel` | 提交时点沿用 §2.1；一次有效提交只记录一次。输入拦截记录低基数原因，不计有效提交；重试同图与新图提交区分；`Cancel` 记录用户取消动作。相机权限拒绝／不可用属于相机启动失败交互，不计图片提交。 |

同一用户动作若已由搜索专属事件记录，不再追加同义 `ui_interaction`。入口打开与有效提交可关联，以计算图搜入口提交率；埋点不记录图片像素、base64、文件名、EXIF、完整图片 URL 或剪贴板内容。具体点位清单由开发设计并与产品核对。

入口来源沿用当前事件的 `source_page_id`、`source_module_id` 等已存在来源信息，只在真实可识别时携带。**图搜入口提交率**＝发生过至少一次有效图片提交的图搜入口打开次数 ÷ 图搜入口实际打开次数；一次打开内连续提交多张图片，分子仍只计一次。PC 从首页或结果页打开上传弹窗、Mobile 进入拍照界面各形成一次入口打开；在已有结果页仅替换图片并再次提交属于当前入口会话，不新增入口打开。关闭后重新打开形成新一次入口。开发方案须提供入口与有效提交的关联方式，才能计算该指标。

### 3.2 结果链路埋点参考（开发设计为准）

现行一方事件语义与商品展示位以[《一方埋点公共实施规则 v1.10》](../../looply-docs/docs-数据采集与埋点/一方平台开发基线/looply-一方埋点公共实施规则-v1.10.md)及[详细点位表 v1.5](../../looply-docs/docs-数据采集与埋点/一方平台开发基线/Looply-v1.4-详细埋点需求定稿-v1.5.xlsx)为基线；GA4 以[剩余问题收口开发包 v1.4](../../looply-docs/docs-数据采集与埋点/GA4开发基线/looply-GA4剩余问题收口开发包-v1.4.md)核对。以下保留原结果链路草案供参考，**不是本 PRD 指定的结果事件、字段、枚举或触发契约**。开发须参照既有文字搜索链路，设计图搜的提交、结果状态、商品及无结果推荐曝光／点击、重试、归因与平台去向，形成可评审的点位方案和测试用例；具体实施以评审通过的开发方案及统一埋点基线为准。

| 原草案业务动作或结果 | 原草案一方事件 | 原草案成立与防重复思路 |
|---|---|---|
| 打开图搜入口 | `ui_interaction` | 入口实际打开一次记一次；只打开不记 `search`。实际 PC／Mobile 入口以 §3.1 为准。 |
| 图片输入校验失败 | `ui_interaction` | 用户选取、拖入、粘贴或提交的图片／链接被拦截时记录低基数失败类别；取消选择不记录。 |
| 相机启动失败（Mobile） | `ui_interaction` | 相机权限被拒绝或设备不可用时区分失败原因，不计图片输入失败或有效提交。 |
| 有效图片提交 | `search` | 有效图片真正发起整图请求时记录；PC 结果页仅粘贴或替换图片尚未提交。 |
| 搜索中点击 Cancel（Mobile） | `view_search_results` 的 `cancelled` 终态 | 保留原提交事实；迟到响应不再重复形成终态。用户点击动作本身按 §3.1 覆盖。 |
| 搜索结果终态 | `view_search_results` | 区分 `success`、`no_results`、`failed`、`cancelled`；每次请求避免重复终态。 |
| 结果商品有效曝光、点击 | `item_impression`、`item_click` | 参考现有阈值、去重、商品标识和 `module_id=search_results_list`。 |
| 无结果推荐商品有效曝光、点击 | `item_impression`、`item_click` | 参考现有 `module_id=search_no_results_recommendations`，与真实图搜结果分开。 |
| 失败后点击重试 | `ui_interaction` ＋新一次 `view_search_results` | 区分用户重试动作与结果请求；同图重试不重复计为用户提交新图。 |

PC 清除搜索框图片、粘贴但未提交新图片、Mobile 下滑收起／重新展开结果面板均不改变当前结果快照。Mobile 点击结果面板 `×` 则关闭结果页并返回拍照／相册界面。筛选、排序沿用现有结果页操作规则；结果链路如何继承图搜上下文由开发方案确定。

**原草案字段参考（待埋点评审确认）**

| 字段建议 | 完整枚举或取值 | 使用范围与业务含义 |
|---|---|---|
| `search_mode` | `text`、`image` | 区分文字与整图搜索；本功能固定 `image`。 |
| `image_input_source` | `file_picker`、`drag_drop`、`clipboard`、`image_url`、`camera`、`album` | 图片从何处进入；终端公共字段另行区分 PC/Mobile。 |
| `trigger_type` 扩展 | `image_submit` | 表示用户提交有效图片。原文字搜索取值保持不变；具体是否沿用该字段及与 `image_input_source` 的关系，由统一埋点基线收口。 |
| `result_status` | 复用 `success`、`no_results`、`failed`、`cancelled` | 结果终态，不用 0 结果冒充请求失败。 |
| `input_failure_type` | 见下表 | 输入校验或相机启动失败的低基数原因；前者与后者由 §3.1 的交互动作区分。 |

| `input_failure_type` 取值 | 含义 | 触发时机 |
|---|---|---|
| `unsupported_type` | 文件类型不受支持 | 选取、拖入或粘贴文件后校验失败。 |
| `too_large` | 文件超过实现设定的大小上限 | 文件大小校验失败。 |
| `unreadable` | 文件损坏或无法解码 | 文件格式可接收，但图片内容无法读取。 |
| `invalid_url` | 不是可提交的直接图片链接 | PC 链接提交时校验失败。 |
| `url_unavailable` | 链接无法获取或无法读取图片 | PC 链接提交后读取失败。 |
| `camera_permission` | 相机权限被拒绝或禁用 | Mobile 用户尝试打开相机后无法取得权限。 |
| `camera_unavailable` | 设备没有可用相机或相机启动失败 | Mobile 用户尝试打开相机后无法取得画面。 |

图搜埋点的数据保护要求同样适用于结果链路：不记录图片像素、base64、文件名、EXIF、完整图片 URL 或剪贴板内容，也不将这些内容填入一方 `query` 或 GA4 `search_term`。现有文字搜索从 URL 解析 `query` 的方式不能直接用于图片。原草案建议结果、曝光与点击继承当前**有效结果快照**的图搜上下文，PC 清除输入后亦然；具体关联字段、结果恢复与新旧事件迁移由开发方案设计并对照一方详细点位表评审。

原草案关于无结果率、失败率及结果更新的分析口径，仅供开发设计结果链路时参考。

原草案建议 GA4 结果终态参考 `view_search_results`、商品曝光与点击参考 `view_item_list` 和 `select_item`。GA4 现有文字搜索依赖 `search_term`，图搜不得填入虚构的文字搜索词；图搜提交与结果事件是否复用这些事件及其字段、平台去向，由开发提出方案并在统一埋点基线评审后生效。

## 六、行为验收要点

1. PC 四种输入途径与 Mobile 拍照、相册选图各完成一次有效整图搜索；Mobile 每次主动进入拍照界面时尝试启动相机，浏览器需要授权时请求权限。拒绝或相机不可用时显示对应提示，底部相册面板仍可使用；退出后再次进入会重试相机，已被浏览器记住的拒绝状态无需承诺重弹系统框。相册面板未授权态展示 `Enable`；点击后请求照片访问，允许则展示最近照片并可点击搜索，拒绝则留在开启状态，`All photos` 可打开系统选图器。取消选图不改变页面或结果，也不构成有效图片提交。真实照片访问能力及拒绝恢复方式需先完成目标浏览器验证；格式或读取失败不构成有效图片提交。
2. 搜索中显示原图与加载状态；成功、无结果、失败分别进入唯一正确的页面状态，旧请求迟到不覆盖新结果。Mobile 搜索中点击 `Cancel` 后返回拍照／相册页面，不自动重新提交原图；迟到响应不跳转、不展示结果，取消交互可与有效结果区分。
3. PC 结果页粘贴新图片后只更新搜索框缩略图，原结果及其商品归因不变；点击搜索或按回车才发起新搜索。双端正式提交新图片时按 §2.1 重置旧筛选与排序；PC 再次粘贴以最后一张有效图片为准，点击缩略图 `×` 只清除输入，不改变当前结果。Mobile 面板 `×` 收起结果后，图片保留且可重新展开，展开不重复请求。
4. 双端无结果展示本次搜索图片缩略图、图搜标题、`Try searching for a different brand or item.` 和现有推荐商品；请求失败保留原图并可重试，重试不重复计入主动搜索提交。
5. PC 上传弹窗与 Mobile 拍照界面分别形成可识别的图搜入口；关键输入、提交、权限、失败、取消和重试交互按 §3.1 覆盖，入口打开与有效提交可关联且不重复计数。开发提交图搜结果链路埋点方案，经统一基线评审后按该方案验收。
6. 双端刷新及浏览器历史导航能在同设备、同浏览器恢复当前有效的图搜结果、筛选和排序，且不重复计入入口或提交；无有效本地结果状态时回首页。图搜结果不提供分享或跨设备恢复。抽查地址与埋点，不包含原图、图片链接原文、文件名、EXIF、base64 或虚构的文字搜索词。
