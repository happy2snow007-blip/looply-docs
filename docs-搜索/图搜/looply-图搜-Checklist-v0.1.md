# Looply 图搜 Checklist v0.1

> 2026-10-23。记录 PRD v0.1 定稿前的输入差异与待确认项；不作为开发实现规则。

## 输入源差异

| 输入源 | 观察到的差异 | 处理状态 |
|---|---|---|
| 最新文字搜索 Web PRD v0.2 与本次图搜讨论 | Web 搜索 v0.2 排除 App，原有范围没有图搜；本次已讨论 PC 与 Mobile 图搜。 | 本期范围已确认是 PC Web＋Mobile Web；图搜另立工作稿。 |
| 双端图搜 UI 与此前无结果讨论 | 新双端图搜 UI 均展示搜索图片缩略图、`No results found for this image`、`Try searching for a different brand or item.` 和 `More to Explore`。 | 用户确认无结果以本版 UI 为准；PRD 与 Demo 同步该文案和结构。 |
| Mobile Demo 与已确认算法范围 | Demo 保留候选物品、框选和拖动；当前仅支持整图搜索。 | 本期 PRD 只描述整图；保留 Demo 探索。 |
| PC Demo 与已确认算法范围 | 点击搜索框图片会打开选区编辑弹窗；当前仅支持整图搜索。 | 本期 PRD 不含图片编辑；Demo 保留探索。 |
| PC / Mobile Demo 输入校验 | PC Demo 限 JPG/PNG/WebP、10 MB；Mobile Demo 接收 `image/*`、25 MB。 | Demo 数值和格式不是需求；开发确定实际支持范围，并在技术方案与验收说明中写明。 |
| Mobile 图搜 UI 与相册方案 | 图搜 UI 展示最近照片；用户补充参考截图，要求未授权时在相册面板显示开启入口，授权后展示最近照片。 | Demo 与 PRD 已覆盖点击 `Enable` 后请求照片访问、允许显示最近照片、拒绝留在开启状态；真实能力尚待开发在目标浏览器验证。 |
| 文字搜索埋点基线与图搜 | 现有 `trigger_type`、一方 `query` 和结果 URL 上下文只覆盖文字搜索。 | 产品明确 PC／Mobile 不同入口与关键交互；结果链路沿用文字搜索的设计方法，由开发出点位方案，PRD 原草案仅供参考。 |

## 待设计与技术收口

1. 设计按用户参考截图核对 Mobile 相册未授权态及折叠、展开两态；开发按[相册能力验证清单](looply-图搜-Mobile-Web-相册能力-开发验证清单-2026-10-26.md)实测 Mobile Web 是否可经用户授权获取最近照片。若无法实现，返回产品评审调整相册方案。Demo 中 `Enable` 和最近照片仅为交互模拟。
2. 已在浏览器核对双端图搜 section 的可见画板与无结果文案，并看到文件级 2026-10-26 18:26 自动保存；仍须设计确认图搜 section 的定稿状态，补核搜索失败、输入异常、相机权限及系统选图等未完整覆盖状态。
3. 开发在技术方案中明确实际图片格式、大小上限、HEIC/HEIF 与动图处理，以及 PC 直接图片链接的协议、访问失败与解码边界；产品不预设格式枚举或大小数值。
4. 已确认本期同设备、同浏览器刷新及历史导航恢复当前图搜结果，暂不支持分享与跨设备恢复；开发需给出安全的结果状态保存、有效期、失效及无状态回首页方案，并验证不把原图、图片链接原文或 EXIF 放进埋点或明文 URL。
5. 搜推的整图检索接口、召回范围、结果总数、筛选与排序支持、重复请求及取消终态。图搜沿用线上搜索结果页的现行排序规则；新图片正式提交时清除旧筛选并恢复线上默认排序，无需新增图搜专属默认排序。
6. 开发给出 PC／Mobile 入口与交互点位及一方、GA4 的字段映射，并参照文字搜索链路设计图搜结果状态、商品行为、推荐位和归因点位；页面字典、详细点位表与 GA4 基线同批评审。PRD 第 3.2 节的结果事件和字段仅供参考，不是现行埋点契约。
7. 图片处理的保存期限、删除机制、第三方访问与隐私告知，由产品、技术和隐私负责人确认。
