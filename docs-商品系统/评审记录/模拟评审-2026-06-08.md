## P0（规则缺失或制品矛盾，阻塞开发）

### 1. [跨制品] ER 图包含"属性分组"实体但 PRD 已删除

- **位置**：ER 图 v1.9 `attribute_group` 表（group_id PK + category_id FK + group_name + sort_order + status）+ `attribute_def.group_id` FK；PRD 版本历史 V0.6 明确记录"删除属性分组"
- **问题**：PRD V0.6 已删除属性分组功能，V1.0 全文无任何属性分组描述、无属性分组页面、无属性分组校验规则。但 ER v1.9 仍保留 `attribute_group` 表且 `attribute_def` 仍有 `group_id` FK 指向它。开发参考 ER 建表时会多建一张不该存在的表，且会在 attribute_def 表中保留一个无业务意义的外键字段。
- **建议**：ER 图下轮迭代中删除 `attribute_group` 实体，`attribute_def` 删除 `group_id` 字段及对应关系线。

### 2. [跨制品] ER 图 product 表缺少多个 PRD 定义的核心字段

- **位置**：ER 图 v1.9 `product` 表（仅含 product_id / standard_sku_id / warehouse_id / title / base_price / source / serial_number / images 共 8 字段）；PRD 2.12 实物商品管理
- **问题**：PRD 定义了实物商品的完整数据模型，包含：
  - `item_status`（7 状态枚举：待核验/核验中/待销售/销售中/已售出/已停售/已失效）——状态机是 PRD 的核心规则
  - `cost_price`（采购价）——商品列表和编辑页均有此字段
  - `grade`（成色等级 A/B/C）——创建和编辑流程 Step 3 必填
  - `stock_mode`（商品类型：二手商品 single / 标准配件 bulk）——决定是否质检、是否一物一码
  - `description`（商品描述）
  
  但 ER `product` 表只有 `base_price`（基准售价），以上字段全部缺失。开发按 ER 建表后会发现缺少核心业务字段。
- **建议**：ER `product` 表补充 item_status / cost_price / grade / stock_mode / description 等字段。同时确认 `warehouse_id` 的处理——PRD 将仓库视为外部模块引用（行 128），ER 却有 `warehouse` 表和 FK，需统一口径。

### 3. [跨制品] ER 图缺少质检模板、标签、尾差规则、下载中心数据模型

- **位置**：PRD 2.11 质检报告模板、2.15 标签管理、2.16 尾差规则、2.17 下载中心；ER 图 v1.9 无对应实体
- **问题**：以下 PRD 已完整定义（含页面元素、校验规则、操作流程）的功能在 ER 中完全没有对应实体：

  | PRD 模块 | 预估需要的实体 | 影响 |
  |----------|---------------|------|
  | 2.11 质检报告模板 | qc_template + qc_template_dimension + qc_template_item + qc_template_option（4 表） | 商品创建 Step 3 动态质检表单无法实现 |
  | 2.15 标签管理 | tag + product_tag + listing_tag（3 表） | 标签筛选和标签关联无法实现 |
  | 2.16 尾差规则 | price_rounding_rule（1 表） | 三层定价规则无法落地 |
  | 2.17 下载中心 | download_task（1 表） | 批量导入导出结果管理无法实现 |

  合计至少 9 张表在 ER 中缺失。
- **建议**：在 ER 图下轮迭代（v2.0）中一次性补齐以上实体，确保 PRD 已定义的每个数据模型在 ER 中均有对应。

## P1（规则不完整，影响质量）

### 4. [开发] "展示价"与"挂牌价"的关系未明确

- **位置**：PRD 2.16 尾差规则（"仅影响展示价，结算价不受影响"）；PRD 2.13.2 渠道商品编辑（listing_price = 挂牌价）
- **问题**：PRD 2.16 说尾差规则"仅影响展示价"，但 listing 表只有 `listing_price`（挂牌价），没有 `display_price`（展示价）。场景：运营设置挂牌价 $300，尾差规则调整尾数后，前台展示 $299.99。此时有三个问题未回答：
  1. 展示价是实时计算值还是落库字段？
  2. 结算用挂牌价（$300）还是展示价（$299.99）？
  3. 运营在后台看到的"挂牌价"是调整前还是调整后的？
- **建议**：在 2.16 中补充"展示价定义"段落，明确：展示价 = 挂牌价经尾差规则调整后的值；是否落库；结算取价逻辑；后台展示逻辑。

### 5. [测试] 快捷上架"统一挂牌价"跨币种场景未定义

- **位置**：PRD 2.12.1 快捷上架弹窗 → 快捷模式（行 2101）
- **问题**：快捷模式下运营输入"统一挂牌价"应用到所有选中渠道，PRD 说"币种跟随各渠道所属 Market 默认货币"。当运营同时选了 3 个渠道——美国线上（USD）、日本三方（JPY）、英国门店（GBP），输入统一价格 299，这个 299 是哪个币种？是 299 USD、299 JPY、299 GBP 同时生效？还是系统禁止跨币种使用统一模式？
- **建议**：补充以下任一规则：(a) 统一模式要求所有选中渠道属于同一 Market/同一币种，否则自动切换自定义模式；(b) 统一模式按各渠道币种分别创建 299 的记录（即 299 USD + 299 JPY + 299 GBP）；(c) 明确不会出现跨币种场景的原因。

### 6. [开发] 实物商品编辑"库存状态"字段与 item_status 关系不清

- **位置**：PRD 2.12.3 实物商品编辑 Step 4（行 2347："库存状态 | 下拉选择 | 在库/在途/在售/已售"）；PRD 2.12.1 item_status 定义（7 状态）
- **问题**：PRD 定义了两套状态体系：
  - `item_status`：待核验/核验中/待销售/销售中/已售出/已停售/已失效（7 个，管理实物生命周期）
  - "库存状态"：在库/在途/在售/已售（4 个，出现在商品编辑 Step 4）
  
  它们是同一字段还是不同维度？如果是同一字段的简化展示，映射关系是什么（"在库"对应 item_status 哪个值？）？如果是独立维度（物理位置 vs 业务生命周期），PRD 需要补充 `inventory_status` 字段定义和与 item_status 的联动规则。
  
  另外，行 2362 写"将库存状态改为'已售'时，系统自动下架所有渠道"，但 item_status 的"已售出"也有同样的联动规则（行 2034），如果是两个字段，哪个触发下架？如果是同一字段，为什么枚举值不同？
- **建议**：明确库存状态与 item_status 的关系——如果是同一字段，统一枚举值和名称；如果是两个独立维度，补充字段定义、枚举、联动规则。

### 7. [测试] 允许创建渠道商品（上架）的 item_status 未正向定义

- **位置**：PRD 2.13.1 异常处理 + 2.12.1 item_status 联动规则表
- **问题**：PRD 列出了不能上架的 item_status 异常处理（已售出、已停售、已失效提示不可上架；待核验、核验中不在列表中显示上架按钮），但未正向声明"哪些 item_status 允许创建渠道商品"。按排除法推断只剩"待销售"和"销售中"可以上架，但测试写用例时需要明确的正向规则，不能靠排除法。特别是"销售中"——一件已经在 A 渠道上架的商品，能否再上架到 B 渠道？
- **建议**：在 2.12.1 联动规则表中添加一行正向规则："允许创建渠道商品的 item_status：待销售、销售中"，并确认"销售中"时可多渠道上架。

### 8. [跨制品] ER 图 brand/series/channel 表字段与 PRD 存在差异

- **位置**：PRD 2.2.2 品牌新建 / 2.3.2 系列新建 / 2.14 渠道管理；ER 图 v1.9 对应表
- **问题**：三处字段不对齐：
  
  **brand 表**（ER 仅 5 字段，PRD 定义 10+ 字段）：
  - ER 缺少：所属国家(country)、成立年份(established_year)、创始人(founder)、品牌介绍(introduction)、品牌描述(description)
  - 这 5 个字段在 PRD 品牌新建/编辑页有完整的页面元素定义和校验规则

  **series 表**（ER 缺 2 字段）：
  - ER 缺少：别名(alias)、问世年份(established_year)
  
  **channel 表**（ER 多 1 个、缺多个）：
  - ER 多余：`commission_rate`（佣金率）——PRD 明确说佣金归支付结算系统
  - ER 缺少：站点信息（国家/地区）、渠道自定义内容、同步策略、market_id
- **建议**：ER 下轮迭代同步更新这三张表，与 PRD 页面元素对齐。

### 9. [跨制品] 系统流程图状态命名与 PRD 不一致

- **位置**：流程图 V2.0 ④⑤⑥⑦⑧⑨⑩⑪ 各段涉及的状态值；PRD 2.12.1 item_status 定义
- **问题**：流程图和 PRD 的商品状态命名完全不同：

  | 流程图 | PRD item_status | 是否对应 |
  |--------|----------------|----------|
  | 草稿 | （无） | 流程图多出 |
  | 待质检 | 待核验 | 命名不同 |
  | （无） | 核验中 | PRD 多出 |
  | 待上架 | 待销售 | 命名不同 |
  | 待分发 | （无） | 流程图多出 |
  | 在售 | 销售中 | 命名不同 |
  | 已售出 | 已售出 | 一致 |
  | 已下架 | 已停售 | 命名不同 |
  | 已关闭 | 已失效 | 命名不同 |

  流程图 8 个状态 vs PRD 7 个状态，且只有"已售出"命名一致。开发同时参考两份文档时会困惑"待上架"和"待销售"是否同一个状态。
- **建议**：以 PRD 为权威定义，流程图下轮迭代更新状态命名，与 PRD item_status 枚举对齐。

### 10. [开发] 品牌尺码体系"品牌名称"输入方式与 ER 矛盾

- **位置**：PRD 2.7.3.2 品牌尺码体系新建（"品牌名称 | 文本输入 | 是 | 品牌名称"）；ER `brand_size_system.brand_id`（FK → brand）
- **问题**：PRD 页面元素定义"品牌名称"为文本输入（自由文本），ER 为 `brand_id` FK（引用品牌库）。如果按 PRD 实现文本输入，同品牌会出现多种拼写（"LOUIS VUITTON" / "Louis Vuitton" / "LV"），无法与品牌库关联。如果按 ER 实现 FK，PRD 页面元素描述不准确。
- **建议**：改为下拉选择（从品牌库选择），与 ER 的 `brand_id` FK 对齐。PRD 页面元素更新为"品牌名称 | 下拉选择 | 是 | 从已有品牌中选择"。

### 11. [跨制品] PRD 内部版本历史引用旧章节编号

- **位置**：PRD 版本历史 V1.0（行 3194-3196）+ 版本规划 V1.0（行 3095）
- **问题**：V1.0 版本历史写"2.13.5 批量上架导入""2.13.6 批量导出""2.18 下载中心"，版本规划写"下载中心（→ 2.18）"。但 V1.0 自检时已将章节重排为 2.12.5、2.12.6、2.17，版本历史和规划中的旧编号未同步更新。开发按版本历史定位章节时会找不到对应内容。
- **建议**：统一更新：版本历史中 2.13.5→2.12.5、2.13.6→2.12.6、2.18→2.17；版本规划中 2.18→2.17。

### 12. [跨制品] 商品 PRD 未声明对 Market 模块的依赖 + 商品 ER channel 表缺 market_id

- **位置**：PRD 第三章"依赖与风险"（无 Market 条目）；PRD 全文 20+ 处引用"渠道所属 Market 默认货币"；ER 图 v1.9 channel 表（无 market_id 字段）
- **问题**：Market 是独立模块，已有 PRD v1.2 + ER v5.0 + 原型 v21 且已交付开发 V1.0。Market 模块定义了销售市场实体、Market-Country 关系、每个 Market 的默认货币，且明确 Channel 归属 Market（channel → market_id）。商品 PRD 大量引用 Market 概念（尾差规则三层优先级、渠道定价货币、快捷上架统一价格等），但存在两个问题：
  1. PRD 第三章"依赖与风险"未将 Market 模块列为上游依赖
  2. 商品 ER v1.9 的 channel 表没有 market_id FK（Market ER v5.0 已定义此关联，但商品 ER 未同步）
- **建议**：(a) PRD 第三章补充"Market 主数据模块"为上游依赖，说明商品系统从 Market 获取渠道归属、默认货币等数据；(b) 商品 ER channel 表补充 market_id FK。

## P2（描述可更精确）

### 13. [测试] 成色等级 3 级 vs 调研报告建议 4 级

- **位置**：PRD 1.6 术语说明（"A 几乎全新 / B 轻微使用痕迹 / C 明显使用痕迹"）；模块启动报告竞品发现 #1（"前期统一用 4 级通用分级"）
- **问题**：PRD 定义 A/B/C 共 3 级成色。模块启动报告竞品分析结论为"前期统一用 4 级通用分级，V2 再按品类细分"，4 级参考 NWT / Excellent / Good / Fair。PRD 实现为 3 级，与调研结论不一致。如果是有意简化，建议在 PRD 中注明决策依据以免开发质疑。
- **建议**：确认 3 级是最终决策并在 PRD 术语说明中补充"参考竞品 4 级分级后简化为 3 级，V2 按品类细化"，或调整为 4 级。

### 14. [设计] 附录设计稿索引缺少质检报告模板页面

- **位置**：PRD 附录设计稿索引（行 3116-3175）；PRD 2.11.1（引用 page-qc-template-list）、2.11.2（引用 page-qc-template-form）
- **问题**：PRD 正文 2.11 引用了 `page-qc-template-list` 和 `page-qc-template-form` 两个原型页面，但附录设计稿索引中没有这两个页面的条目。索引与正文不一一对应。
- **建议**：在附录设计稿索引中补充"质检报告模板列表"和"质检报告模板新建/编辑"两行。

### 15. [测试] SPU 名称无唯一性约束

- **位置**：PRD 2.9.2 SPU 新建 → 校验规则（仅"不能为空"）
- **问题**：删除 SPU 编码后，SPU 的唯一标识只剩系统生成的 SPU ID。两个不同 SPU 可以完全同名（如两个"iPhone 15 Pro Max"），在搜索和关联选择场景中容易混淆。是否需要"全局唯一"或"同类目+品牌+系列下唯一"的约束？
- **建议**：确认是否需要唯一性约束。如果不需要（靠类目+品牌+系列天然区分），在 PRD 中补充说明"允许同名，靠类目/品牌/系列区分"。
