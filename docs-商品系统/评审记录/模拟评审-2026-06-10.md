## P0（规则缺失或制品矛盾，阻塞开发）

### 1. [跨制品·PRD vs 原型] 属性定义列表/表单字段与原型概念模型大幅偏差

- **位置**：PRD 2.4.1.1 属性定义列表 + 2.4.1.2 新建
- **问题**：PRD 和原型对属性定义采用了不同的概念模型，不是简单的字段缺失而是底层设计分歧：

  | 维度 | PRD 定义 | 原型实际 |
  |------|---------|---------|
  | 列表列数 | 7 个数据列（属性类型、录入方式、是否必填、是否支持单位、关联维度、状态） | 5 个数据列（属性类型、输入控件、值约束、选项数） |
  | 核心概念 | "值类型"（文本/数值/枚举单选/枚举多选）+ "录入方式"（手动输入/下拉选择/多选标签） | "值约束"（free/enum/size）+ "输入控件"（single_select/multi_select/text_input/number_input/image_upload/size_select） |
  | 状态列 | 有 | 无 |
  | 尺码体系 | 不在属性定义中配置（在属性作用域中） | 值约束=size 时展开尺码体系配置区域 |
  | 图片上传 | 录入方式无此选项 | 输入控件有 image_upload，含图片配置 |
  | 排序字段 | 有 | 无 |

- **建议**：需对齐到统一模型。建议以 PRD 的"值类型+录入方式"为基准（语义更清晰），原型按 PRD 调整。image_upload 和 size_select 需明确是否纳入当前版本——如纳入则 PRD 补充，如不纳入则原型移除。

### 2. [跨制品·PRD vs ER] ER 图缺少标签实体和关联表

- **位置**：PRD 2.9 标签管理（标签列表/新建/编辑）；PRD 全局约定·停用与删除规范（标签→商品标签关联）
- **问题**：PRD 定义了完整的标签管理模块（3 个页面），并在实物商品编辑（步骤 4）和渠道商品编辑中引用了标签多选功能，停用与删除规范也声明了"标签→商品标签关联"引用关系。但 ER v2.6 中完全没有 tag 表、product_tag 关联表和 listing_tag 关联表。
- **建议**：ER 图补充 tag 表（tag_id, tag_name, applicable_type, description, status）和关联表（product_tag、listing_tag）。

### 3. [跨制品·PRD vs ER] ER 属性定义表缺少 status 字段

- **位置**：PRD 2.4.1.1 属性定义列表（按状态筛选）、全局约定·停用影响汇总表（属性定义行）、编辑限制汇总表（属性定义行）
- **问题**：PRD 多处依赖属性定义的启用/停用功能——列表筛选按状态、停用影响汇总表明确列出停用处理策略、编辑限制汇总表列出锁定规则。但 ER v2.6 的 `attribute_def` 表没有 `status` 字段，开发无法实现停用功能。
- **建议**：ER 的 attribute_def 表补充 `status` 字段（ENUM: active/inactive）。

### 4. [跨制品·PRD vs ER] ER listing 表缺 off_shelf_reason / off_shelf_remark / is_deleted

- **位置**：PRD 2.7.2 渠道商品管理·扩展字段（第 2298-2302 行）
- **问题**：PRD 明确定义了渠道商品的 3 个扩展字段——off_shelf_reason（4 值枚举：manual/out_of_stock/blocked/item_invalid）、off_shelf_remark（VARCHAR）、is_deleted（BOOLEAN），但 ER v2.6 的 listing 表均不包含这 3 个字段。
- **建议**：ER 的 listing 表补充这 3 个字段。

### 5. [跨模块·依赖] 汇率服务声称"已独立设计"但实际不存在

- **位置**：PRD 三·上下游系统依赖（第 2873 行）："汇率服务为独立模块，已独立设计"
- **问题**：PRD 依赖表中明确写"已独立设计"，但 `~/Desktop/海外业务/` 下不存在任何汇率相关目录或文件。尾差规则场景（2.8.1）强依赖汇率服务进行前台跨币种换算，描述与事实不符。
- **建议**：修正依赖描述为"汇率服务模块尚未启动设计"，并在风险项中补充"汇率服务未设计，前台跨币种展示阻塞"及应对方案。

### 6. [跨制品·PRD vs 原型] 尺码体系列表承载结构矛盾

- **位置**：PRD 2.4.4.1 尺码体系列表
- **问题**：PRD 设计为"标准体系 / 品牌体系"双 Tab 切换，两个 Tab 各有独立的列表字段定义、搜索范围和 KPI 统计。原型实际为单表混合展示，通过"体系类型"列区分，统一搜索框。这不是简单的字段差异，是页面结构设计分歧。
- **建议**：确认采用哪种方案。双 Tab 方案信息密度更低但操作更聚焦，单表方案一览全局但混合了不同数据结构。

### 7. [跨制品·PRD vs 原型/ER] 品牌"英文名"字段缺失

- **位置**：PRD 2.2.2 品牌新建（页面元素表）、PRD 2.2.1 品牌列表（列表字段）
- **问题**：原型品牌列表有"英文名"列，品牌新建有"英文名"FormRow，品牌搜索范围含"英文名"。ER 也有 `brand_name_en` 字段。但 PRD 品牌新建表、品牌列表字段均无"英文名"。同样，系列也存在此问题（ER 有 `series_name_en`，PRD 无）。
- **建议**：PRD 补充品牌英文名、系列英文名字段。这是产品名称的原始录入值（奢侈品品牌本身就是外文名），与多语言翻译不矛盾。

## P1（规则不完整，影响质量）

### 8. [跨制品·PRD vs 原型] 尾差规则编辑页锁定逻辑未实现

- **位置**：PRD 2.8.1.3 尾差规则编辑·交互说明
- **问题**：PRD 明确要求"规则层级和适用范围（Market/货币）创建后不可修改，编辑页以只读方式展示"。但原型编辑页中，规则层级和适用 Market 仍为可编辑的 Select 控件。另外 PRD 新建页要求适用 Market/适用货币按层级动态显隐，原型始终展示。
- **建议**：原型调整——编辑页锁定规则层级和适用范围为只读；新建页按层级动态显隐适用范围字段。

### 9. [跨制品·PRD vs ER] 属性类型分类不一致

- **位置**：PRD 2.4.1.2 属性定义新建·属性类型；ER attribute_scope_config.attribute_type
- **问题**：PRD 使用"销售属性/描述属性"二分法（sale/description），ER 的 `attribute_scope_config.attribute_type` 使用 key/sale/non_key 三分法。PRD 从未定义"key 属性"概念。ER design_rules 提到"key 属性→必须 SPU 级"但 PRD 无对应说明，开发会困惑 key 和 sale 的区别。
- **建议**：对齐分类方案。如果"key"指品类核心属性（如手袋的材质），需在 PRD 术语说明中定义，并在属性配置规则矩阵中补充 key 类型的行为。如不需要 key 类型，ER 调整为二分法。

### 10. [跨制品·PRD vs ER] 录入方式枚举不一致

- **位置**：PRD 2.4.1.2 属性定义新建·属性配置规则矩阵（录入方式列）
- **问题**：PRD 列出 3 种录入方式（手动输入/下拉选择/多选标签），ER 列出 6 种（input/select/multi_select/text_input/number_input/image_upload）。特别是 `image_upload`（图片上传）在 ER design_rules 中有完整场景说明（实物图片、质检图片等），原型也有图片上传配置区域，但 PRD 属性配置规则矩阵完全未覆盖。
- **建议**：确认 image_upload 是否属于属性定义的录入方式。如属于，PRD 补充到配置规则矩阵；如不属于（图片上传不走属性体系），ER 和原型调整。

### 11. [跨制品·PRD vs 原型] 实物商品详情页缺字段

- **位置**：PRD 2.7.1.2 商品详情
- **问题**：PRD 定义了商品详情页的"成色与质检区域"包含成色等级、成色描述、外观描述、补充描述、配件信息，以及"实物状态""实物图片"区域。原型详情页的 ReadGrid 缺少"外观描述"字段、无"实物状态"字段、无图片展示区域。
- **建议**：原型补充缺失字段。详情页是运营快速查看商品全貌的入口，字段不全会导致运营必须进编辑页才能看到完整信息。

### 12. [跨制品·PRD vs 原型] 标签管理 KPI 口径不一致

- **位置**：PRD 2.9.1 标签列表·统计卡片
- **问题**：PRD 定义 KPI 为"总标签数、实物商品标签数、渠道商品标签数、通用标签数"（按适用对象分），原型实际为"启用标签、停用标签、总使用次数、今日新增"（按状态和使用量分）。两种口径关注点完全不同。此外原型标签列表多了批量停用/批量清理按钮，PRD 未定义。
- **建议**：确认 KPI 口径。按适用对象分更有助于运营理解标签体系结构，按状态分更有助于日常运维。可考虑保留 PRD 方案（适用对象维度），批量操作如需保留则 PRD 补充功能描述。

### 13. [跨模块·依赖] 商家系统依赖无设计产物

- **位置**：PRD 三·上下游系统依赖（商家系统行）
- **问题**：实物商品列表和渠道商品列表展示"卖家 ID、卖家昵称"，PRD 声明依赖商家系统。但 `~/Desktop/海外业务/` 下无"商家"模块目录，用户管理模块（PRD v1.5）仅覆盖 C 端用户后台，不含商家体系。风险项虽提及（第 2889 行）但未给出降级方案。
- **建议**：在风险项中补充 MVP 降级方案（如：卖家信息暂由实物商品表 seller_id 字段关联，卖家昵称由运营手动录入或读取登录注册模块的用户名）。

### 14. [跨模块·依赖] 多项上游依赖漏声明

- **位置**：PRD 三·上下游系统依赖表
- **问题**：以下依赖在 PRD 正文或模块启动报告中明确引用，但三.1 依赖表未列出：
  - **国家主数据模块**：PRD 1.7 和 2.2.2 提到"后续由独立国家主数据模块提供接口支持"，主数据模块已有 ER v1.7，但依赖表未声明
  - **风控系统**：模块启动报告的"对外接口约定"明确列出"风控系统：商品审核规则校验"，PRD 的商品状态机有 pending_check→checking 环节隐含审核链路
  - **鉴定服务商**：PRD 已有完整鉴定表单字段（鉴定状态/机构/证书编号/日期），启动报告也列出鉴定服务商依赖
- **建议**：依赖表补充这 3 项。当前版本不对接的标注为"预留依赖，当前版本降级为手动录入"。

### 15. [开发] 属性作用域删除操作未定义

- **位置**：PRD 2.5.1 属性作用域列表、2.5.3 编辑
- **问题**：当运营人员误建了一条属性作用域规则（如错选了类目+品牌组合），PRD 只定义了"编辑"操作，没有"删除"操作。编辑页的作用域定位（类目/品牌/系列）创建后不可修改，意味着无法通过编辑修正错误的组合。PRD 2.5.3 也只提到"如需变更需删除后重建"，但没有定义删除的入口和规则。
- **建议**：在属性作用域列表的操作列补充"删除"按钮，定义删除前置校验（如该作用域已被 SPU 引用则提示确认或禁止删除）。

### 16. [开发] SPU 停用的级联死锁

- **位置**：PRD 2.6.1.3 SPU 编辑·SPU 停用约束 + 2.6.2.3 SKU 编辑·实物引用保护
- **问题**：当运营需要停用一个 SPU 时，PRD 要求"先停用所有 SKU"。但 SKU 编辑的实物引用保护规定"SKU 已被实物商品引用时禁止停用"。如果 SPU 下所有 SKU 都被实物引用（正常业务情况），则 SKU 无法停用→SPU 也永远无法停用。形成停用死锁。
- **建议**：重新设计停用链路。方案一：SPU 停用不依赖 SKU 全部停用，而是 SPU 停用后 SKU 跟随标记为不可用（但存量实物不受影响）。方案二：定义"实物关联解除"流程作为前置步骤。

### 17. [测试] 系统默认尾差规则设为"继承上级"的兜底逻辑

- **位置**：PRD 2.8.1.2 尾差规则新建·尾数策略枚举
- **问题**：尾数策略包含"继承上级"选项。取数算法定义了"继承上级等同于该层无规则，继续向上级查找"。但如果系统默认规则（最高层）本身也被设置为"继承上级"，则没有任何层级生效，系统无兜底规则。PRD 未定义此场景的处理方式。
- **建议**：方案一：系统默认规则不允许选择"继承上级"策略（因为没有上级可继承）；方案二：所有层级都为"继承上级"时，等同于"不启用"（不做尾数调整）。建议方案一更明确。

### 18. [跨制品·PRD vs 原型] 实物商品列表字段差异

- **位置**：PRD 2.7.1.1 商品列表
- **问题**：
  - PRD 列表字段无"标签"列，原型有
  - PRD 筛选无"按标签筛选"，原型有
  - PRD 搜索范围"按商品 ID/标题"，原型多了"标品 SKU ID"
  - PRD "卖家昵称"→原型"卖家信息"命名不同
- **建议**：对齐。标签列和标签筛选在 V1.6 新增了渠道商品列表的标签功能，但遗漏了实物商品列表。建议 PRD 补充。搜索范围扩展到标品 SKU ID 是合理的产品改进。

## P2（描述可更精确）

### 19. [跨制品·PRD vs ER] 多项唯一性约束未在 ER 中标注

- **位置**：PRD 全局约定·停用与删除规范（唯一性约束包含停用项）
- **问题**：PRD 定义了多个实体的名称唯一性约束（品牌名称全局唯一、类目名称同级唯一、属性名称全局唯一、系列名称同品牌唯一、渠道名称全局唯一），但 ER v2.6 中除 system_code、dimension_code 外，其余均未标注 UK（Unique Key）约束。
- **建议**：ER 图补充 UK 标注。虽然唯一性约束可以在 PRD 中定义、开发代码层实现，但 ER 作为技术参考应体现数据库级约束。

### 20. [跨制品·PRD vs ER] listing_description 有 ER 字段但 PRD 无编辑入口

- **位置**：PRD 2.7.2.2 渠道商品编辑
- **问题**：ER listing 表有 `listing_description` 字段且 design_rules 定义了兜底规则（优先 listing 级 → 兜底到 product.description），但 PRD 渠道商品编辑页面未提供此字段的编辑入口。
- **建议**：确认是否需要。如需渠道差异化描述（与展示标题类似），PRD 补充字段；如不需要（描述统一使用商品原始描述），ER 移除或标记为"预留字段"。

### 21. [跨制品·PRD vs ER] barcode vs 货号命名混淆

- **位置**：PRD 2.6.2.2 SKU 新建·SKU 信息区域
- **问题**：PRD 称该字段为"货号"（品牌货号），校验规则写"自由文本，品牌货号格式各异"。ER 标品 SKU 的对应字段名为 `barcode`，注释为"国际条码"。两者语义不同：货号是品牌内部编码（如 H0123456），barcode 是 UPC/EAN 国际条码。
- **建议**：明确是一个字段还是两个字段。如果只保留一个，PRD 和 ER 统一命名和语义说明。

### 22. [跨制品·PRD vs ER] 单位编码 unit_code 未在 PRD 中定义

- **位置**：PRD 2.4.3.2 维度新建·下属单位区域
- **问题**：ER `unit_of_measure` 表有 `unit_code`（UK 唯一约束）字段，PRD 维度新建/编辑页的单位表格未包含"单位编码"列，仅有单位名称和符号。
- **建议**：确认 unit_code 的用途。如果用于系统间集成（如接口传参用编码不用名称），PRD 应补充此字段。

### 23. [跨制品·PRD vs 原型] SPU 管理字段差异

- **位置**：PRD 2.6.1.1 SPU 列表 + 2.6.1.2 SPU 新建
- **问题**：
  - SPU 列表：原型多了"所属品牌"列，PRD 只有"所属类目、所属系列"
  - SPU 新建·描述属性表：原型多了"值归属"列，PRD 无
  - SPU 新建·SKU 批量生成表：原型多了"尺码"和"重量(g)"列，PRD 只有颜色/材质/货号/参考价/状态
  - SPU 编辑·已关联 SKU 表：原型多了"重量(g)"列
- **建议**：SPU 列表补充"所属品牌"列（方便快速识别）。描述属性表的"值归属"列已在属性作用域中定义为属性配置的一部分，建议 PRD 补充。SKU 表的尺码/重量是动态销售属性列，PRD 用"颜色/材质"作为示例是合理的，但建议注明"动态列根据实际销售属性生成"。

### 24. [测试] 渠道商品重新上架是否需重新校验上架就绪条件

- **位置**：PRD 2.7.1 上架就绪校验 + 2.7.2.1 渠道商品列表（上架操作）
- **问题**：PRD 定义了上架就绪校验（商品标题/成色等级/成色描述/实物主图/商品状态/渠道状态 6 项），适用于"快捷上架或批量上架"。但渠道商品列表的"上架"操作（已下架→在售）只检查了实物状态和渠道状态，未提及是否需要重新校验信息完整性（如下架期间图片被删除、成色描述被清空）。
- **建议**：明确重新上架时是否执行完整上架就绪校验。如执行，需在 2.7.2.1 的上架交互中补充说明。

### 25. [测试] 批量导出行数上限未定义

- **位置**：PRD 2.7.1.6 批量导出
- **问题**：批量导入有明确的行数上限（≤ 10,000 行），但批量导出没有定义上限。如果筛选结果包含大量商品（如 50,000 件），直接导出可能导致超时或内存溢出。
- **建议**：定义导出上限（如 50,000 行），超出时提示"数据量过大，请缩小筛选范围"或分批导出。

## P3（锦上添花）

### 26. [设计] 多个模块列表列序差异

- **位置**：类目列表、品牌列表、渠道商品列表等
- **问题**：PRD 和原型的列表列顺序不完全一致（如类目列表 PRD 先列类目 ID，原型先列类目名称）。不影响功能但影响交付一致性。
- **建议**：统一以原型为准（原型是开发的直接参考），PRD 按原型调整列序。

### 27. [设计] 多处 KPI 统计卡片 PRD 未定义

- **位置**：SKU 列表、属性作用域列表、属性定义列表、渠道列表
- **问题**：原型中这些列表页都有 KPI 统计卡片（如 SKU 总数/待补货号/待补图片/今日新增），但 PRD 的页面元素表中未定义 KPI 内容。不影响开发但会导致测试用例无标准参考。
- **建议**：PRD 补充各列表页的 KPI 统计卡片定义，或统一注明"KPI 卡片以原型为准"。
