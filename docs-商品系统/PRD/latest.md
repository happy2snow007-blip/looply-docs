# looply 商品系统 PRD V1.7

> 版本：V1.7 | 日期：2026-06-10 | 范围：基础数据关系 + 属性管理 + 属性作用域 + 标品管理（SPU/SKU）+ 尺寸测量方法模板 + 实物商品 + 渠道管理 + 渠道商品 + 标签管理 + 尺码体系 + 商品定价（尾差规则）+ 批量上架导入 + 下载中心

## 一、概述

### 1.1 背景与目标

looply 是一个面向海外市场的二手电商平台，采用 B2C 模式（三方商家 + 自营），前期主攻美国市场，品类以奢侈品为主（占比 ≥80%），消费电子约 20%。

商品系统是平台的商品生命周期管理中枢，负责商品从发布到可售的全流程。本 PRD 当前版本覆盖商品系统的基础数据层，包括：

- 基础数据关系：类目、品牌、系列及其关联关系的管理
- 属性管理：属性定义、属性选项、度量单位的管理
- 属性作用域：按类目/品牌/系列三层维度控制属性的启用、必填、可选值
- 标品管理：SPU（标准产品单元）和标品 SKU 的创建与维护
- 尺寸测量方法模板：品类级 SVG 尺寸示意图模板配置，前端根据模板槽位自动渲染尺寸标注
- 实物商品管理：一物一码的实物商品录入、质检、鉴定管理
- 渠道管理：销售渠道的创建与配置
- 渠道商品：实物商品在各渠道的上架管理
- 标签管理：商品标签的创建与分类管理
- 尺码体系：标准尺码体系管理、尺码换算、品牌尺码体系及品牌尺码换算

### 1.2 不做什么

- 前台类目管理（前台展示类目树及前后台类目映射，后续版本覆盖）
- 成色质检、鉴定安全、合规字段等独立模块（当前版本中质检和鉴定作为二手商品录入的子流程内嵌）
- 质检报告模板管理（按类目配置质检模板系统，移至后续版本独立模块化；当前版本采用 4 个固定文本字段：成色描述、外观描述、补充描述、配件信息）
- 高级定价能力（促销价、折扣策略、自动调价等，已从原型中移除；基础挂牌价在渠道商品中支持，心理定价尾差规则在 2.8.1 中定义）
- 商品发布流程、商品审核流程（已从原型中移除）

### 1.3 用户角色

| 角色 | 说明 |
|------|------|
| 运营人员 | 管理类目、品牌、系列、属性体系，配置属性作用域规则 |

> 当前版本仅覆盖运营后台，商家端、质检端后续版本覆盖。

### 1.4 核心场景

1. 运营人员搭建品类体系：创建多层级类目树，建立品牌库和系列库，配置类目-品牌-系列的关联关系
2. 运营人员定义属性体系：定义属性及其选项，配置度量单位
3. 运营人员管理尺码体系：创建标准尺码体系（如 IT、FR、US），维护尺码值和跨体系换算关系
4. 运营人员管理品牌尺码体系：创建品牌专属尺码体系（如 Moncler 0-6 码），建立品牌尺码到标准尺码的映射
5. 运营人员配置属性作用域：针对不同类目/品牌/系列组合，控制哪些属性启用、是否必填、可选哪些值
6. 运营人员创建标品 SPU：选择类目/品牌/系列，填写 SPU 信息和属性值，上传标品图片
7. 运营人员创建标品 SKU：基于 SPU 的销售属性组合生成 SKU 矩阵，维护货号和参考价
8. 运营人员配置尺寸测量方法模板：为末级类目上传 SVG 示意图，配置槽位与尺寸属性的映射，前台自动渲染标注
9. 运营人员录入实物商品：关联标品 SKU → 填写实物信息 → 录入质检和鉴定 → 设定价格，4 步完成商品录入
10. 运营人员管理渠道商品：查看实物商品在各渠道的上架状态，执行上架/下架操作
11. 运营人员管理渠道：创建和配置销售渠道（线上自营、线下门店、三方平台）
12. 运营人员管理标签：创建和维护商品标签，按适用对象分类（实物商品/渠道商品/通用）
13. 运营人员配置尾差规则：按系统默认 / Market 级 / 货币级配置心理定价尾数策略，在汇率换算场景下控制展示价尾数调整
14. 运营人员批量上架导入：通过 Excel 模板批量创建渠道商品记录，在下载中心查看导入结果
15. 运营人员使用下载中心：查看批量导入/导出任务的处理状态，下载结果文件

### 1.6 术语说明

| 术语 | 说明 |
|------|------|
| 后台类目 | 商品主数据的分类维度，用于属性作用域配置和数据管理，不直接面向消费者 |
| 品牌 | 商品所属品牌，与类目为多对多关系 |
| 系列 | 品牌下的产品系列（如爱马仕的 Birkin、Kelly），与类目为多对多关系 |
| 属性定义 | 单个属性的元数据（名称、值类型、录入方式等） |
| 属性选项 | 枚举型属性的全局候选值 |
| 度量维度 | 度量单位的分类（如长度、重量、容量） |
| 度量单位 | 具体的计量单位（如 mm、cm、inch），归属于某个维度 |
| 属性作用域 | 控制属性在特定类目/品牌/系列组合下的启用状态、必填性、可选值范围 |
| 作用域层级 | 三层优先级：CATEGORY_SERIES > CATEGORY_BRAND > CATEGORY |
| SPU | 标准产品单元（Standard Product Unit），代表一个标准商品（如 Hermes Birkin 25），不区分具体规格 |
| 标品 SKU | 标准规格单元（Standard SKU），SPU 下按销售属性组合（如颜色×材质）拆分的具体规格 |
| 销售属性 | 影响 SKU 生成的规格属性（如颜色、材质），不同销售属性值的组合对应不同 SKU |
| 描述属性 | 补充描述信息的属性（如工艺、产地），不影响 SKU 拆分 |
| 尺寸测量方法模板 | 品类级的尺寸示意图 SVG 模板，含 data-slot 槽位，前端加载后用 SKU 实测值填充渲染。一个末级类目最多一套模板 |
| 实物商品 | 一物一码的实物商品（product），每件实物绑定一个标品 SKU，有独立的成色、质检和鉴定信息 |
| 渠道 | 销售渠道（如线上自营商城、线下门店、亚马逊等三方平台） |
| 渠道商品 | 一件实物商品在某个渠道的上架记录（listing），同一实物可在多个渠道同时上架 |
| 展示标题 | 渠道商品的前台展示标题（listing_title），默认使用商品原始名称，可按渠道差异化修改 |
| 成色等级 | 实物商品的外观状态分级（NWT 近全新带标签 / Excellent 几乎全新 / Good 轻微使用痕迹 / Fair 明显使用痕迹） |
| 标签 | 商品标签，用于分类和筛选，按适用对象分为实物商品标签、渠道商品标签和通用标签 |
| 尺码体系 | 标准尺码体系（如 IT 意大利尺码、FR 法国尺码、SHOE_EU 欧洲鞋码），定义一组有序的尺码值 |
| 尺码换算 | 不同标准尺码体系之间的对照关系（如 IT 38 = FR 34 = UK 6） |
| 品牌尺码体系 | 品牌专属的尺码体系（如 Moncler 0/1/2/3/4/5/6 码），独立于标准尺码体系 |
| 品牌尺码换算 | 品牌尺码到标准尺码的映射关系（如 Moncler 0 = IT 38） |
| 尾差规则 | 心理定价尾数策略（如 .99、.95、整十），在汇率换算场景下对展示价进行尾数调整，按系统默认 / Market 级 / 货币级三层优先级生效 |
| 批量上架导入 | 通过 Excel 模板批量创建渠道商品记录的导入功能，入口在实物商品列表 |
| 下载中心 | 集中管理批量导入/导出任务的处理状态和结果文件下载 |

### 1.7 多语言 / 多国家策略

- 当前版本仅支持美国市场，界面语言为英文
- 商品系统只存储原始值，不在各实体上维护多语言字段。所有面向买家的内容翻译（类目名称、品牌名称、系列名称、属性选项值、商品标题等）统一由平台级翻译模块管理，前台按用户语言从翻译模块获取对应版本，查不到则 fallback 到默认语言。翻译模块为独立模块，独立设计
- 度量单位已预留国家展示单位机制（country_display_unit），当前版本不启用前端交互，仅做数据结构预留

## 二、需求详细描述

> **全局约定**
>
> - **前置条件**：以下所有功能均要求用户已登录商品管理后台且具有对应模块的操作权限。各功能项不再逐个标注。当前版本不展开角色权限矩阵，页面默认按"具备对应模块权限的后台用户"设计；多角色协同、最小权限控制、审批角色拆分由后续独立权限体系建设。
> - **默认排序规则**：所有列表页默认按创建时间倒序排列（最新创建的记录排在最前）。如有特殊排序需求，在对应功能项中单独说明。
> - **列表列序基准**：各列表页的列顺序以原型为准。PRD 中的列表字段定义标注包含哪些列，具体列序参照原型实际渲染顺序。
> - **KPI 统计卡片基准**：各列表页的 KPI 统计卡片内容以原型为准。PRD 中未逐一定义 KPI 的列表页（如 SKU 列表、属性作用域列表、属性定义列表、渠道列表等），其 KPI 统计卡片的指标项、计算口径参照原型实际渲染内容。
> - **空值显示规范**：表格中的空值统一显示为"—"（中文破折号），不留空白。布尔型字段显示对应状态标签（如"启用/停用"），不显示 true/false。
> - **外部主数据引用规则**：当前 PRD 中如引用国家、权限、质检、仓库等外部基础域能力，若未在本模块中展开对应主数据或流程页面，则默认表示"引用外部模块能力"，不在商品域内独立建设。当前版本中的国家数据先采用受控枚举，后续由独立国家主数据模块统一提供接口支持。
> - **操作日志规范**：所有编辑页和详情页均包含"操作日志"区域，记录该实体的操作历史。操作日志为四列表格：操作时间、操作人、操作类型（创建/编辑/启用/停用/上架/下架/状态变更等）、操作内容（具体变更内容，如"挂牌价由 $72,000 调整为 $74,000"）。操作日志按时间倒序展示，最新操作在最上方。各功能项不再逐个标注操作日志区域，默认包含。
> - **影响范围预览规范**：停用操作（类目/品牌/系列/渠道/标签等）如涉及关联数据，系统展示影响范围预览列表，包含受影响实体的数量和名称列表（最多展示 10 条，超出显示"等 N 个{实体名称}"），预览列表支持滚动查看完整数据。用户确认后执行停用操作。影响范围的计算口径包含子级递归（如停用父类目时，统计数字包含其所有子类目的关联数据）。
> - **配置变更与存量数据规范**：商品数据通过 ID 引用配置项（属性定义、属性选项、类目、品牌等），配置内容变更不影响已存储的 ID 引用关系，存量数据不会因配置变更而损坏。具体处理规则：
>   - **已停用选项的回显**：编辑表单加载时，如果当前值引用的选项/配置项已停用，正常回显当前值并标记"已停用"标签；下拉候选列表中不展示已停用的选项，但当前值作为特例保留展示。用户可将已停用值切换为其他启用值，切换后不可再选回已停用值
>   - **必填校验统一按当前配置执行**：属性从选填变为必填后，新建和编辑均按当前必填规则校验。存量商品如缺少新增必填项，编辑保存时会被拦截，需补填后方可保存。运营变更必填规则前，通过影响范围预览确认受影响的存量商品数量
>   - **停用属性定义**：属性定义停用后，已引用该属性的存量商品保留已填写的值（只读展示），编辑表单中不再展示该属性的填写区域，新建商品时不出现该属性
> - **停用与删除规范**：
>   - **停用语义**：停用 = 逻辑上不可用，记录仍存在于数据库中。停用项不出现在新建/选择的候选列表中（存量引用的回显规则见「配置变更与存量数据规范」），可随时重新启用
>   - **唯一性约束包含停用项**：所有唯一性校验（品牌名称全局唯一、类目名称同级唯一、维度编码全局唯一等）的判定范围包含已停用的记录。停用的"Gucci"仍占用品牌名称，不允许新建同名品牌。如需释放名称，需先删除已停用记录（前提是无下游引用）
>   - **删除约束**：有下游引用的实体禁止删除，只能停用。"删除"按钮置灰并 tooltip 提示"该{实体名称}已被 N 个{下游实体名称}引用，无法删除"。无下游引用的实体允许删除（物理删除）。各实体的下游引用关系：类目→SPU；品牌→系列/SPU；系列→SPU；属性定义→SPU/SKU 属性值；属性选项→SPU/SKU 属性值；SPU→SKU；SKU→实物商品；渠道→渠道商品；标签→商品标签关联
>   - **列表页筛选默认值**：所有包含"启用/停用"状态筛选的列表页，默认筛选为"启用"状态，运营可切换为"全部"或"停用"查看
> - **价格精度规范**：所有涉及金额的字段（挂牌价、参考价等），小数位数由对应货币的 ISO 4217 标准决定（如 USD 2 位、JPY 0 位、KWD 3 位）。系统内置 ISO 4217 货币精度映射表，不可手动修改。输入时校验小数位数不超过货币精度。
> - **排序值规范**：所有模块的"排序"字段统一为非负整数，范围 0–9999，数字越小越靠前。
> - **页面状态变体**：所有表单页支持加载态（数据请求中显示加载指示器）、提交中置灰态（防止重复提交）、字段校验错误态（错误提示显示在对应字段下方）。所有列表页支持以下状态：
>   - **加载态**：数据请求中显示加载指示器
>   - **零数据引导态**：列表无任何数据时，隐藏搜索/筛选栏，展示居中引导区（图标 + 标题"暂无{实体名称}" + 描述"点击下方按钮创建第一个{实体名称}" + 主按钮"新增{实体名称}"）
>   - **筛选无匹配态**：搜索或筛选后无结果时，保留搜索/筛选栏，表格区域替换为居中提示（图标 + 标题"未找到匹配结果" + 描述"请尝试调整搜索关键词或筛选条件" + 按钮"清除筛选条件"）
>   - **网络异常态**：请求失败时，保留搜索/筛选栏，表格区域替换为居中提示（错误图标 + 标题"加载失败" + 描述"网络异常，请检查网络连接后重试" + 主按钮"重试"）
>   - 空态组件的视觉规范详见《Looply 后台原型 UI 规范》6.13 节
>   - 特殊状态变体在各功能项中单独说明。

>   | 实体 | 停用时的下游影响 | 影响范围预览内容 | 存量数据处理 |
>   |------|-----------------|-----------------|-------------|
>   | 类目 | 该类目及所有子类目标记停用；关联品牌/系列不级联停用（可能关联其他类目）；已挂载 SPU 保持原状态但无法在该类目下新建 | 关联品牌数+名称、挂载SPU数+名称（含子类目递归） | SPU 编辑时类目字段回显"已停用"标签 |
>   | 品牌 | 不级联停用系列；已挂载 SPU 保持原状态 | 关联系列数+名称、挂载SPU数+名称 | SPU/系列编辑时品牌回显"已停用" |
>   | 系列 | 已挂载 SPU 保持原状态 | 挂载SPU数+名称 | SPU 编辑时系列回显"已停用" |
>   | 属性定义 | 存量商品保留已填值（只读展示）；新建/编辑表单不再展示该属性 | 引用SPU数+名称、引用SKU数+名称 | 存量属性值只读，不参与校验 |
>   | 属性选项 | 同「配置变更与存量数据规范」中的已停用选项回显规则 | 引用SPU数+名称、引用SKU数+名称 | 存量值保留并标"已停用"，可切换为其他启用值 |
>   | 维度 | 关联的属性定义不级联停用 | 关联属性定义数+名称 | 存量属性的度量维度回显"已停用"，单位换算功能保留 |
>   | 单位 | — | 引用该单位的属性值数量 | 存量数值保留，但该单位不再出现在候选列表 |
>   | 尺码体系（标准） | 换算规则保留（引用侧回显"已停用"） | 引用的换算规则数 | 存量尺码值保留 |
>   | 尺码体系（品牌） | 映射规则保留 | 映射规则数 | 存量映射保留 |
>   | 渠道 | 该渠道下的渠道商品不可新增上架 | 渠道商品数+名称 | 已上架的渠道商品保持当前状态，可手动下架但不可重新上架 |
>   | 标签 | 不可用于新增绑定 | 绑定的商品数+名称 | 已绑定的商品保持标签关联，标签回显标记"已停用" |
>
> - **编辑限制汇总表**：
>
>   | 实体 | 字段 | 有引用时能否编辑 | 影响说明 |
>   |------|------|----------------|----------|
>   | 属性定义 | 属性名称 | ✅ 可编辑 | ID 引用不变，仅显示名变化 |
>   | 属性定义 | 值约束 | ❌ 有引用后锁定 | 从 enum 改 free 会导致存量枚举值无法解析 |
>   | 属性定义 | 属性类型（销售↔描述） | ❌ 有引用后锁定 | 销售属性已参与 SKU 组合生成，改为描述会破坏 SKU 结构 |
>   | 属性定义 | 输入控件 | ❌ 有引用后锁定 | 与值约束强关联 |
>   | 属性定义 | 关联维度 | ⚠️ 提示确认 | 切换维度后存量数值的单位语义可能改变 |
>   | 属性选项 | 选项值 | ✅ 可编辑 | 所有引用处显示名跟着变（通过 ID 引用） |
>   | 类目 | 父类目 | ⚠️ 提示确认 | 需校验不形成循环引用；移动后属性作用域可能失效 |
>   | 品牌 | 品牌名称 | ✅ 可编辑 | 仅显示名变化 |
>   | 品牌 | 覆盖类目（移除） | ⚠️ 提示确认 | 该类目下如有关联系列或 SPU 需确认 |
>   | 尺码体系 | 体系代码 | ❌ 创建后锁定 | 唯一标识，不可修改 |
>   | 尺码体系（品牌） | 品牌 | ❌ 创建后锁定 | 品牌绑定关系不可变更 |
>   | SPU | 归属关系（类目/品牌/系列） | ❌ 创建后锁定 | 已参与属性作用域和 SKU 关联，变更会破坏数据一致性 |
>   | 渠道 | 所属 Market | ❌ 创建后锁定 | 定价货币依赖 Market 默认货币，变更会导致已有渠道商品的货币不一致 |
>   | 系列 | 系列名称 | ✅ 可编辑 | 仅显示名变化，通过 ID 引用 |

#### 2.4.4 尺码体系

##### 模块概述

尺码管理采用统一实体设计，通过 `system_type`（STANDARD 标准 / BRAND 品牌）区分两类尺码体系：

- **标准尺码体系**（system_type = STANDARD）：行业通用尺码系统（如 IT 意大利尺码、FR 法国尺码、US 美国尺码、SHOE_EU 欧洲鞋码等），跨品牌共享
- **品牌尺码体系**（system_type = BRAND）：品牌专属尺码系统（如 Moncler 0-6 码、lululemon 尺码等），绑定特定品牌

两类体系共用同一套数据表（size_system / size_value / size_mapping），管理页面通过 Tab 切换查看。

**尺码体系选择规则**：SPU 创建时，系统根据选定的类目+品牌自动判断使用哪个尺码体系：
1. 检查该品牌是否有对应类目的品牌尺码体系
2. 有品牌体系 → 尺码候选值来自品牌体系
3. 无品牌体系 → 尺码候选值来自 attribute_size_system_scope_config 配置的标准体系
4. 运营在 SPU 表单上只需选择尺码值，系统自动判断来源

尺码体系按适用类目分为三类：服装、鞋类、配饰。每个类目可配置一个"基准标准体系"（如服装的基准是 IT），用于换算矩阵的行标识和新建体系时的默认映射目标。

### 2.5 属性作用域

#### 模块概述

属性作用域是商品属性体系的核心配置能力，用于控制属性在不同类目/品牌/系列组合下的启用状态、必填性、可选值范围和可用单位。

采用三层作用域模型，优先级从高到低：

| 层级 | 作用域类型 | 含义 | 示例 |
|------|-----------|------|------|
| 1（最高） | CATEGORY_SERIES | 类目 + 品牌 + 系列 | 手提包 × 爱马仕 × Birkin |
| 2 | CATEGORY_BRAND | 类目 + 品牌 | 手提包 × 爱马仕 |
| 3（最低） | CATEGORY | 仅类目 | 手提包 |

**解析规则**：

- 属性启用判断：按优先级查找第一个 status=1 的作用域配置。三层都没有 status=1 时，该属性不出现在商品配置中
- 属性选项判断：命中某一层则整体使用该层的可用选项集合，不跨层合并。三层都没有该属性的选项配置时，回退到全局属性选项
- 属性单位判断：与选项判断逻辑一致，命中某一层则使用该层的可用单位配置

**合并示例**：

以"手提包 × 爱马仕 × Birkin"创建 SPU 为例，假设三层作用域配置如下：

| 属性 | CATEGORY（手提包） | CATEGORY_BRAND（手提包×爱马仕） | CATEGORY_SERIES（手提包×爱马仕×Birkin） |
|------|-------------------|-------------------------------|---------------------------------------|
| 颜色 | 启用，必填，选项：黑色/白色/红色/棕色/金棕 | 启用，必填，选项：黑色/棕色/金棕 | 启用，必填，选项：黑色/红色/米色 |
| 材质 | 启用，必填，选项：牛皮/羊皮/鳄鱼皮 | 启用，必填，选项：Togo牛皮/鳄鱼皮 | 未配置 |
| 缝线工艺 | 未配置 | 启用，选填，选项：手工缝线/Saddle Stitch | 启用，必填，选项：Saddle Stitch |
| 尺寸 | 启用，必填，单位：mm/cm/m/inch | 未配置 | 未配置 |

最终生效结果（SPU 创建时加载的属性表单）：

| 属性 | 命中层级 | 必填 | 可用选项/单位 | 解析说明 |
|------|---------|------|-------------|---------|
| 颜色 | CATEGORY_SERIES | 必填 | 黑色/红色/米色 | 系列层有配置 → 直接用系列层，不合并上级 |
| 材质 | CATEGORY_BRAND | 必填 | Togo牛皮/鳄鱼皮 | 系列层未配置 → 向下找到品牌层 |
| 缝线工艺 | CATEGORY_SERIES | 必填 | Saddle Stitch | 系列层有配置 → 用系列层（注意必填性也被系列层覆盖为必填） |
| 尺寸 | CATEGORY | 必填 | mm/cm/m/inch | 系列层和品牌层都未配置 → 回退到类目层 |

关键要点：每个属性独立解析，逐属性按优先级查找，命中即停止，不跨层合并选项。

### 2.7 商品管理

商品管理涵盖实物商品的生命周期管理、渠道商品的上下架管理，以及销售渠道的创建与配置。

#### 2.7.1 实物商品管理

##### 模块概述

实物商品（product）是商品实物层的核心实体，采用一物一码模式——每件实物有唯一的内部条码，绑定一个标品 SKU。实物商品记录实物的来源、成色等级、成色与质检描述（成色描述、外观描述、补充描述、配件信息）、鉴定信息和生命周期状态。

商品录入采用 4 步流程：关联标品 → 实物录入 → 质检鉴定 → 信息确认。

##### 状态设计原则

实物商品状态（product_status）管理实物的完整生命周期，从质检录入到最终退出经营的全过程。状态设计遵循以下原则：

1. **生命周期完整性**：状态覆盖实物从进入系统到退出的完整流程，不仅仅是"有效/无效"的粗粒度划分
2. **类型统一性**：二手商品和标准配件共用同一套状态骨架，仅在终态上有差异
3. **职责清晰性**：product_status 管理实物生命周期，listing_status 管理渠道销售，inventory 管理库存数量，三层职责分离

##### 状态枚举定义

| 状态值 | 状态名称 | 适用商品类型 | 说明 |
|--------|---------|-------------|------|
| pending_check | 待核验 | 二手商品、标准配件 | 已进入实物商品管理范围，等待质检/验收录入 |
| checking | 核验中 | 二手商品、标准配件 | 正在进行质检、验收、资料补录或人工复核 |
| pending_sale | 待销售 | 二手商品、标准配件 | 核验通过，具备销售条件，但当前未处于销售承载中 |
| on_sale | 销售中 | 二手商品、标准配件 | 已进入销售阶段，当前至少存在一个有效销售承载 |
| sold | 已售出 | 二手商品 | 销售闭环完成，不再作为可售实物流转（二手商品终态） |
| discontinued | 已停售 | 标准配件 | 该配件已退出销售经营，不再继续销售（标准配件终态） |
| invalid | 已失效 | 二手商品、标准配件 | 因质检失败、损坏、报废、丢失、合规问题等退出流转（异常终态） |

##### 状态流转规则

**二手商品状态流转**：

```
待核验 → 核验中 → 待销售 ⇄ 销售中 → 已售出
                    ↓         ↓
                 已失效    已失效

核验中 ────────→ 已失效
```

| 序号 | 起始状态 | 目标状态 | 触发条件 |
|------|---------|---------|---------|
| 1 | 待核验 | 核验中 | 开始质检/录入 |
| 2 | 核验中 | 待销售 | 质检通过/信息完整 |
| 3 | 核验中 | 已失效 | 质检不通过/报废/真伪异常 |
| 4 | 待销售 | 销售中 | 创建有效销售承载/进入在售 |
| 5 | 待销售 | 已失效 | 确认无法继续经营 |
| 6 | 销售中 | 已售出 | 成交完成 |
| 7 | 销售中 | 待销售 | 全部停售但仍保留后续销售资格 |
| 8 | 销售中 | 已失效 | 损坏/丢失/异常终止 |

**标准配件状态流转**：

```
待核验 → 核验中 → 待销售 ⇄ 销售中 → 已停售
                    ↓         ↓
                 已失效    已失效

核验中 ────────→ 已失效
```

| 序号 | 起始状态 | 目标状态 | 触发条件 |
|------|---------|---------|---------|
| 1 | 待核验 | 核验中 | 开始验收/审核 |
| 2 | 核验中 | 待销售 | 验收通过/资料通过 |
| 3 | 核验中 | 已失效 | 验收失败/不合规/作废 |
| 4 | 待销售 | 销售中 | 上架销售/进入售卖阶段 |
| 5 | 待销售 | 已停售 | 确认不再经营 |
| 6 | 销售中 | 待销售 | 全部停售但后续还会继续卖 |
| 7 | 销售中 | 已停售 | 业务决策永久停销 |
| 8 | 销售中 | 已失效 | 损坏/作废/异常退出 |

##### 状态联动规则

**实物商品状态与渠道商品状态联动**：

| 触发条件 | 联动动作 | 说明 |
|---------|---------|------|
| product_status 从销售中变为非销售中 | 关联的所有 active listing 自动转为 off_shelf | 实物不可用时，所有在售渠道自动下架 |
| product_status 从非销售中恢复为待销售 | listing 不自动恢复 | 需运营手动重新上架 |
| product_status = 待销售 或 销售中 | 允许创建新 listing | 仅这两个状态可发起上架 |
| product_status = 待核验 或 核验中 | 禁止创建新 listing | 尚未完成核验，不可上架 |
| product_status = 已售出 | 禁止创建新 listing | 已售出商品不可再上架 |
| product_status = 已失效 | 禁止创建新 listing | 已失效商品不可再上架 |
| product_status = 已停售 | 禁止创建新 listing | 已停售配件不可再上架 |

**可卖判断规则**：

```
可卖 = listing_status = active AND available_qty > 0
```

product_status 不直接参与实时可卖判断，通过联动规则约束 listing 的创建和维持。

**功能描述**

选择后展示已选标品信息（只读）：SPU 名称、SKU ID、规格组合、品牌、系列、类目。

**步骤 2：实物信息录入**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 商品标题 | 文本输入 | 是 | 实物商品标题 |
| 商品 ID | 只读 | — | 系统自动生成，不可修改 |
| 商品来源 | 下拉选择 | 是 | 采购 / 回收 / 寄卖 |

| 字段 | 类型 | 必填 | 说明 |

| 字段 | 类型 | 必填 | 说明 |

鉴定信息：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 鉴定状态 | 下拉选择 | 是 | 未鉴定 / 已鉴定 |
| 鉴定机构 | 文本输入 | 条件必填 | 鉴定状态为"已鉴定"时必填 |
| 鉴定证书编号 | 文本输入 | 条件必填 | 鉴定状态为"已鉴定"时必填 |
| 鉴定日期 | 日期选择 | 条件必填 | 鉴定状态为"已鉴定"时必填 |

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|

| 实物细节图 | 图片上传 | 否 | 瑕疵、细节等多角度照片，支持多张 |

汇总展示前 3 步填写的所有信息，供运营人员最终确认。

**校验规则**

| 字段 | 规则 | 校验时机 |
|------|------|---------|
| 关联标品 SKU | 必须选择 | 进入步骤 2 时 |
| 商品标题 | 不能为空 | 提交时 |
| 商品来源 | 必须选择 | 提交时 |
| 成色等级 | 必须选择 | 提交时 |
| 鉴定信息 | 鉴定状态为"已鉴定"时，机构、证书编号、日期必填 | 提交时 |

**操作流程**

1. 步骤 1：搜索并选择标品 SKU
2. 步骤 2：填写实物信息（标题、来源、序列号）

- 未完成必填步骤：提示"请先完成步骤 N 的必填信息"

| 文件格式 | 仅 .xlsx / .csv | "仅支持 .xlsx 或 .csv 格式" |
| 文件大小 | ≤ 10MB | "文件不能超过 10MB" |
| 行数上限 | ≤ 10,000 行（不含表头） | "单次最多导入 10,000 条" |
| 模板版本 | 表头必须与当前模板版本匹配 | "模板版本不匹配，请下载最新模板" |
| 空文件 | 至少 1 行数据 | "文件无有效数据" |

**行级校验**（后台异步逐行处理）

| 字段 | 校验规则 | 错误信息 |
|------|------|---------|
| 商品 ID | 非空 + 系统中存在 | "商品 ID 不存在" |
| 商品 ID | 对应商品状态为"待销售"或"销售中" | "商品状态不允许上架（当前状态：XX）" |
| 渠道编码 | 非空 + 系统中存在 + 状态为启用 | "渠道不存在或已停用" |
| 商品 ID + 渠道编码 | 不存在已上架的渠道商品记录 | "该商品已在此渠道上架" |
| 挂牌价 | 非空 + 正数 | "挂牌价必须为正数" |
| 挂牌价 | 小数位数 ≤ 该渠道货币的 ISO 4217 精度 | "小数位数超出货币精度（USD 最多 2 位）" |
| 文件内去重 | 同一文件内 商品 ID + 渠道编码 不能重复 | "第 X 行与本行重复" |

**处理策略**

逐行独立校验，通过的行立即创建渠道商品，失败的行跳过（部分成功模式）。不是全部通过才执行。

**结果文件格式**

导入完成后生成结果文件（Excel），在下载中心提供下载：

| Sheet | 内容 |
|------|------|
| 汇总 | 总行数、成功数、失败数、处理时间 |
| 明细 | 原始数据所有列 + 追加 2 列："处理结果"（成功/失败）+"错误原因"（失败行填具体原因，成功行留空） |

结果状态根据处理结果自动设置：全部成功→处理完成、部分成功→部分成功、全部失败→处理失败。

**模板版本管理**

- 模板内置版本号（当前 v1），写在固定单元格
- 导入时校验版本号，不向前兼容——旧版模板直接拒绝，提示下载最新模板

#### 2.7.2 渠道商品管理

##### 模块概述

渠道商品（listing）记录一件实物商品在某个渠道的上架信息。同一件实物可在多个渠道同时上架，每个渠道有独立的展示标题、定价货币、挂牌价和上架状态。展示标题默认使用商品原始名称，运营可按渠道差异化修改。定价货币跟随渠道所属 Market 的默认货币，创建时自动填入，不可手动修改。渠道商品通过商品列表的"快捷上架"操作创建。

##### 状态枚举定义

| 状态值 | 状态名称 | 说明 |
|--------|---------|------|
| active | 在售 | 正在该渠道销售 |
| off_shelf | 已下架 | 主动撤卖或被动下架 |

创建渠道商品（上架操作）后初始状态为 active（在售）。

**扩展字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| off_shelf_reason | ENUM | 下架原因：manual（主动下架）/ out_of_stock（缺货下架）/ blocked（违规拦截）/ item_invalid（实物状态联动下架） |
| off_shelf_remark | VARCHAR | 下架原因详情（如拦截原因、违规说明等） |
| is_deleted | BOOLEAN | 软删除标记，默认 false |

##### 状态流转规则

```
在售 ⇄ 已下架
```

| 序号 | 起始状态 | 目标状态 | 触发条件 |
|------|---------|---------|---------|
| 1 | 在售 | 已下架 | 主动撤卖/缺货下架/违规拦截/实物状态联动 |
| 2 | 已下架 | 在售 | 重新上架（需实物状态为待销售或销售中） |

### 2.8 商品定价

商品定价当前版本仅包含尾差规则（心理定价尾数策略），后续版本将扩展促销价、折扣策略等高级定价能力。

#### 2.8.1 尾差规则

##### 模块概述

尾差规则用于配置心理定价尾数策略（如 .99、.95、整十），在汇率换算场景下对展示价进行尾数调整，使价格更具购买吸引力。

**适用场景**：运营按渠道所属 Market 的默认货币定价（如 USD），当前台用户使用其他币种浏览时（如 EUR），系统实时调用汇率服务将挂牌价换算为用户币种，再应用尾差规则调整尾数。换算后的价格即为用户看到和支付的价格。运营在后台看到的始终是自己设置的原始挂牌价，不受尾差规则影响。

**结算币种说明**：用户以换算后的币种支付，非原始定价币种。因此尾差规则的调整直接影响实际收入，而非仅影响展示。当前采用四舍五入策略，在保持价格竞争力的同时避免系统性亏损。

**换算时机**：每次前台请求实时调用汇率服务换算，不缓存换算结果。汇率波动直接反映在用户看到的价格上。汇率数据来源及刷新频率由汇率服务模块定义。

**展示价定义**：当前版本展示价 = 挂牌价（无促销模块）。后续如有促销降价，展示价取促销价。

规则按三层优先级生效：货币级 > Market 级 > 系统默认。给定一件渠道商品（已知货币和 Market），系统先查货币级规则，无则查 Market 级规则，无则取系统默认规则。

| 枚举值 | 含义 | 适用场景 |

| Market 级 | 针对特定 Market 的规则 | 同一 Market 下所有渠道共享 |

| 枚举值 | 含义 | 示例 | 适用场景 |
|------|------|------|---------|
| 继承上级 | 该层不配置，向上级查找生效规则 | — | 仅 Market 级和货币级可选（系统默认规则不允许选择"继承上级"，因为没有上级可继承） |
| .99 | 价格尾数调整为 .99 | $85,000 → $84,999.99 | 欧美市场常用心理定价 |
| .95 | 价格尾数调整为 .95 | $85,000 → $84,999.95 | 欧美市场备选策略 |
| .00 | 价格取整到整数 | $85,000.50 → $85,000.00 | 整数定价偏好市场 |
| 整十 | 价格取整到十位 | ¥85,123 → ¥85,120 | 日元等无小数货币 |
| 整百 | 价格取整到百位 | ¥85,123 → ¥85,100 | 大额商品或特定市场 |

**操作流程**

1. 点击"新增规则"进入新建页
2. 选择规则层级（系统默认 / Market 级 / 货币级）
3. 根据所选层级填写适用范围（Market 级选 Market，货币级选货币）
4. 配置尾数策略和适用价格类型
5. 点击"保存"提交

**校验规则**

| 字段 | 规则 | 校验时机 |
|------|------|---------|
| 规则名称 | 不能为空 | 提交时 |
| 适用 Market | 规则层级为 Market 级时必填；同一 Market 只能有一条规则 | 提交时 |
| 适用货币 | 规则层级为货币级时必填；同一货币只能有一条规则 | 提交时 |

**取数算法**

给定一件渠道商品，确定生效的尾差规则：

1. 查找该渠道商品定价货币对应的货币级规则 → 如存在且启用，使用该规则
2. 如无货币级规则，查找该渠道所属 Market 对应的 Market 级规则 → 如存在且启用，使用该规则
3. 如无 Market 级规则，使用系统默认规则
4. 尾数策略为"继承上级"时，等同于该层无规则，继续向上级查找

**尾数调整计算**

尾数调整对汇率换算后的价格进行四舍五入（就近取整）：
- .99 策略：€920.37 → €919.99（取整到最近的 X.99，€920.37 距 €919.99 比距 €920.99 更近）
- .95 策略：€920.37 → €919.95
- 整十策略：¥85,123 → ¥85,120
- 整百策略：¥85,123 → ¥85,100
- .00 策略：€920.37 → €920.00

四舍五入策略下，尾数调整可能向上或向下微调，长期来看平台不会产生系统性偏差。运营在配置尾数策略时需权衡策略粒度（策略粒度越粗如整百，单笔调整幅度越大）。

价格精度由 ISO 4217 标准决定（见全局约定"价格精度规范"），尾数策略的小数位数不能超过货币精度（如 JPY 为 0 位小数，不适用 .99 策略，适用整十/整百/不启用）。

**异常处理**

- 同一 Market 已有规则：提示"该 Market 已存在尾差规则，请编辑已有规则"
- 同一货币已有规则：提示"该货币已存在尾差规则，请编辑已有规则"
- 网络异常：提示"保存失败，请重试"

- 原型：looply-商品管理后台原型-v40-antd.html → 尾差规则新建（price-rule create）

## 三、依赖与风险

### 上下游系统依赖

本次覆盖的模块为商品系统全量 MVP 功能。外部系统依赖如下：

| 外部系统 | 依赖说明 |
|---------|---------|
| Market 模块 | 渠道归属 Market，定价货币由 Market 默认货币决定；尾差规则按 Market 级配置。Market 模块已独立设计并交付开发（PRD V1.2 + ER V5.0） |
| 库存模块 | 实物商品的库存数量和库存状态由库存模块管理，商品系统不维护库存状态字段。库存模块已独立设计。**关键依赖：库存模块需提供库存预占（锁定）能力**——二手商品为一物一件的孤品，同一实物可同时在多渠道上架，下单时必须通过库存预占防止多渠道并发超卖，具体机制（预占→扣减→超时释放）由库存模块定义 |
| 商家系统 | 实物商品列表和渠道商品列表展示卖家 ID 和卖家昵称，需从商家系统读取 |
| 图片存储服务 | SPU 图片、SKU 图片、实物图片的上传和存储 |
| 翻译模块 | 所有面向买家的内容翻译（类目名称、品牌名称、系列名称、属性选项值、商品标题、描述等）由平台级翻译模块统一管理。商品系统只存储原始值，不维护多语言字段。前台展示时按用户语言从翻译模块获取对应版本，查不到则 fallback 到默认语言。翻译模块为独立模块，独立设计 |
| 汇率服务 | 前台跨币种展示和结算时，商品系统实时调用汇率服务获取汇率进行价格换算。汇率来源、刷新频率、异常兜底策略由汇率服务模块定义。汇率服务为独立模块，已独立设计 |
| 国家主数据模块 | 品牌所属国家等国家/地区数据的标准来源。已在 Market 模块中设计（主数据 ER v1.7），当前版本商品域先使用受控枚举，后续对接国家主数据接口 |
| 风控系统 | 商品审核规则校验（商品状态机中 pending_check→checking 环节隐含审核链路）。预留依赖，当前版本降级为手动录入审核结果 |
| 鉴定服务商 | 实物商品的鉴定信息（鉴定状态/机构/证书编号/日期）。预留依赖，当前版本降级为运营手动录入鉴定结果 |

### 下游影响

| 下游模块 | 依赖说明 |
|---------|---------|
| 搜索系统 | 商品上架/下架时需通知搜索系统更新索引 |
| 订单系统 | 下单时需校验商品可售性（实物商品状态 + 渠道上架状态），并通过库存模块发起库存预占；支付完成后扣减库存并触发实物状态变更（→ 2.7.1 状态联动规则）；支付超时则释放预占 |

### 风险项

| 风险 | 影响 | 应对 |
|------|------|------|
| 属性作用域规则复杂度高 | 三层优先级叠加可能导致运营配置困难 | 提供"生效预览"功能，让运营人员在保存前确认最终效果 |
| 度量单位基准切换 | 切换基准单位影响已存储的属性值 | 切换时强制确认，并提示影响范围 |
| 一物多渠道并发超卖 | 同一实物在多渠道上架，多渠道可能同时下单导致超卖（二手孤品无法补货，超卖即业务事故） | **事前防超卖**：依赖库存模块的库存预占能力，下单瞬间锁定库存，其他渠道同时下单时预占失败即阻断（→ 上游依赖 · 库存模块）。**事后联动下架**：支付完成、实物状态变为已售出时，联动下架所有渠道的 listing（→ 2.7.1 状态联动规则）。两层机制缺一不可 |
| 商家系统对接 | 商品列表和渠道商品列表需展示卖家信息 | 需确认商家系统接口可用性和字段映射 |
