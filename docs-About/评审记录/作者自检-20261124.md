## 4. 健壮性与交付边界

- 逆向链路：本次没有用户编辑、删除业务对象的操作。更换图片后，主图与缩略图需保持对应；两个图库分别持有选中态。
- 下游依赖：介绍页负责跳转；预约、卖货、购物、鉴定与联系页负责后续业务判断，没有在本 PRD 重复定义下游流程。
- 用户走查：内容来自 Figma；交互来自用户本轮确认及 Demo；材料目标来自 Demo；公共返回和图片降级来自已有 About 规则。三种来源已分开。
- 跨模块收敛：图片降级统一写在 2.2；各模块只定义自身排列和操作，正文目标统一在第 6 节。
- 反例：直接访问 Mobile 且无返回历史有首页兜底；一张图片失败不替换整页；上海图片切换不影响北京。
