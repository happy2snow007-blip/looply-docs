# Looply V1.2 首页 Banner 多语言整图配置 PRD

版本：v1.0（开发交付版）  
日期：2026-09-24  
优先级：P0

## 1. 需求目标

支持首页 Banner 按语言上传图片，并按语言配置可选叠加文案和颜色，同时定义纯图片模式与图文模式的点击和埋点规则。

## 2. 首页 Banner 改为多语言整图配置

### 2.1 用户端展示

1. Banner 展示当前终端、当前语言对应的完整图片。
2. 图片可包含内嵌文字；每个语言图片下配置标题、副标题、标题颜色、副标题颜色、按钮文案。文案按语言保存，有配置值时以前台配置为准。标题、副标题和按钮文案均为空时为纯图片模式，整张图片可点击；任一叠加文案或按钮文案有值时为图文模式，图片和按钮分别可点击，按钮点击不触发图片点击。
3. 整张 Banner 图片为同一个点击区域，点击任意位置均进入该 Banner 配置的跳转目标。
4. 首页 Banner 最多展示 4 个，现有排序及轮播规则保持不变。
5. PC 与 Mobile 分别使用对应终端图片：

| 终端 | UI 1×展示基准 | 上传尺寸 |
|---|---:|---:|
| PC | `1920×747px` | `3840×1494px（2×）` |
| Mobile | `440×322px` | `880×644px（2×）` |

### 2.2 运营后台配置

**修改位置**：CMS > 首页配置 > 首页 Banner。

1. 每个语言图片块下配置标题、副标题、标题颜色、副标题颜色、按钮文案；图片 Alt 仍按语言配置。
2. 文案按语言保存；有配置值时以前台配置为准。图片配置跟随顶部所选终端：选择 PC 时配置 PC 图片，选择 Mobile（App）时配置 Mobile 图片。当前国家全部已启用语言的上传位从上到下直接展示，每种语言一张图，可直接上传或替换。
3. 同一 Banner 的各语言图片共用目标类型、目标配置、排序和上线状态。目标类型可选 `Collection` 或 `自定义 URL`；选择 `Collection` 时必填关联 Collection，选择 `自定义 URL` 时必填目标 URL。
4. 图片未齐可保存下线草稿；当前终端配置上线或保存上线状态时，校验该终端全部已启用语言图片，缺图则保留编辑内容并阻止上线，提示见 3.3。
5. 当前国家新增语言时，启用该语言前必须补齐所有已上线 Banner 对应的 PC、Mobile 图片；存在缺图时不允许启用该语言。

6. 右侧预览使用横向语言页签，选中语言显示紫色文字与下划线；绿点表示当前终端该语言已上传图片，红点表示缺图。切换页签后预览对应图片；缺图时显示空态。
7. 保留现有配置列表、新增、编辑、排序、上下线、关联 Collection 和落地页操作。

#### 2.2.1 配置字段

| 字段 | 类型 | 规则 |
|---|---|---|
| 配置名称 | 文本 | 运营内部备注，可选 |
| Banner 图片 | 多语言上传 | 当前终端每种支持语言一张 |
| 图片 Alt | 文本 | 按语言维护；支持自动填充后手动修改 |
| 目标类型 | Select | Collection / 自定义 URL |
| 关联 Collection | Select | 目标类型为 Collection 时必填 |
| 目标 URL | Input | 目标类型为自定义 URL 时必填 |
| 状态 | Switch | 生效中 / 已暂停 |

### 2.3 校验提示

| 场景 | 提示文案 |
|---|---|
| 当前语言缺少图片 | `请上传{语言}的{终端} Banner 图片` |
| 当前终端上线时多个语言缺图 | `请先上传以下语言的{终端} Banner 图片：{语言列表}` |
| 启用新语言时存在已上线 Banner 缺图 | `请先补齐以下 Banner 的{语言}图片：{Banner列表}` |

### 2.4 数据与埋点调整

1. 客户端公共参数新增 `locale_code`，由当前实际生效的站点语言上下文提供，并由统一客户端埋点 SDK 自动附加到全部客户端事件。
2. `locale_code` 使用产品实际生效的稳定 Locale Code，例如 `en-US`、`es-US`；不得从浏览器语言、IP 或 URL 推断。语言上下文尚未取得时允许不传，不使用默认语言补值。
3. Banner 切换继续使用现有 `ui_interaction`：
   - 点击轮播圆点：`interaction_name=home_banner`、`action=change`、`element_id=banner_dot`；
   - 手势滑动：`interaction_name=home_banner`、`action=change`、`element_id=banner_swipe`。
4. 纯图片模式的图片点击记录 `interaction_name=home_banner`、`action=select`、`element_id=banner_image`、`target_id=目标 page_id`。
5. 图文模式的图片点击记录 `element_id=banner_image`；按钮点击记录 `element_id=banner_cta`、`target_id=目标 page_id`，按钮点击不得同时发送图片点击；标题和副标题不产生独立点击事件。
6. Banner 切换与图片、按钮点击均增加 `position_id`，取值为当前 Banner 在首页轮播中的实际展示位置 `1–4`。排序调整后按事件发生时的位置上报，不使用 `0` 或空位序号。
7. 本期使用 `position_id` 分析第 1–4 个 Banner 展示位的使用情况，不将其解释为稳定 Banner 身份；运营替换图片或调整排序后，同一 `position_id` 可以对应不同素材。
8. 不上报图片 URL、图片中文字、按钮文案或其他素材内容。

## 3. 开发边界

- 本期只定义首页 Banner 多语言整图、按语言文案配置及其交互埋点，不包含 Shop 横向大图和 PC 导航推荐图。
