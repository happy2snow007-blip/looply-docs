# Looply 用户管理模块 PRD V1.0

## 一、概述

### 1.1 背景与目标

Looply 平台需要为运营团队提供用户管理后台，支持查看用户信息、管理用户状态、查阅登录与安全记录、维护用户标签体系。本模块是登录注册系统的运营侧延伸，数据来源于登录注册模块的用户体系。

**核心目标**：
- 为运营提供用户全景视图（账号信息、登录行为、设备、风控、合规）
- 支持用户状态管理（冻结/解冻）和会话管理（强制下线）
- 建立用户标签体系，支持手动打标和批量打标，为后续精细化运营提供基础

### 1.2 不做什么

| 不做的事 | 原因 |
|----------|------|
| 用户注册/登录流程 | 属于登录注册模块，本模块只做后台查看和管理 |
| 用户自助修改资料 | 属于 C 端个人中心，非后台功能 |
| 自动化标签（规则引擎自动打标） | MVP 阶段只做手动打标，自动化标签为后续迭代 |
| 用户画像/行为分析 | 属于数据分析模块，本模块只提供基础标签能力 |
| 权限管理（运营角色分级） | 当前运营团队规模小，暂不做角色权限细分 |
| 设备信任/不信任切换操作 | PRD 明确 MVP 阶段不启用信任设备功能，仅展示 |
| 用户数据导出 | 后续迭代 |

### 1.3 用户角色

| 角色 | 说明 |
|------|------|
| 运营人员 | 本模块唯一使用者，负责用户查询、状态管理、标签维护 |

### 1.4 核心场景

1. **用户查询**：运营通过 ID/昵称/邮箱搜索用户，或按渠道/状态/标签筛选用户列表
2. **用户详情查阅**：查看某用户的完整信息（账号、凭证、设备、登录记录、风控、变更日志、合规同意）
3. **用户状态管理**：冻结异常用户、解冻误冻结用户
4. **会话管理**：强制下线可疑会话
5. **标签管理**：新增/编辑/停用标签
6. **用户打标**：为单个用户或批量用户添加/移除标签

### 1.5 全局页面流转

```
用户列表 ──→ 用户详情（返回列表）
用户列表 ──→ [弹窗] 批量打标
用户列表 ──→ [弹窗] 单用户打标
用户详情 ──→ [弹窗] 单用户打标
用户标签列表 ──→ [弹窗] 新增标签
用户标签列表 ──→ [弹窗] 编辑标签
```

### 1.6 术语说明

| 术语 | 定义 |
|------|------|
| 打标 | 为用户添加标签 |
| 摘标 | 移除用户已有的标签 |
| 冻结 | 禁止用户登录和使用平台，已有会话立即失效 |
| 强制下线 | 使指定会话立即失效，用户需重新登录 |
| 设备指纹 | 系统为每台设备生成的唯一标识符 |

### 1.7 多语言 / 多国家策略

- 后台界面语言：中文（面向国内运营团队）
- 用户数据展示：保留原始语言（如英文昵称、英文简介原样展示）
- 时区：后台统一展示 UTC+8，用户注册时间等按北京时间显示
- 国家字段：展示 ISO 3166-1 国家代码（如 US、GB）

## 二、需求详细描述

### 2.1 用户列表

**功能类型**：页面型

#### 功能描述

展示平台所有注册用户的列表，支持搜索、筛选、分页浏览，以及从列表进入用户详情或执行打标操作。

#### 前置条件

运营人员已登录后台系统。

#### 页面元素

**统计卡片区**（4 列）：

| 指标 | 说明 |
|------|------|
| 用户总数 | 所有注册用户数量（含冻结、注销） |
| 正常 | 状态为"正常"的用户数 |
| 冻结 | 状态为"冻结"的用户数 |
| 已注销 | 状态为"已注销"的用户数 |

**筛选工具栏**：

| 筛选项 | 类型 | 选项 |
|--------|------|------|
| 搜索框 | 文本输入 | 支持用户ID、昵称、邮箱模糊搜索 |
| 渠道 | 下拉单选 | 全部渠道 / Web / App / H5 |
| 状态 | 下拉单选 | 全部状态 / 正常 / 冻结 / 已注销 |
| 标签 | 下拉单选 | 全部标签 / [动态加载启用中的标签列表] |

**列表表格**：

| 列名 | 说明 |
|------|------|
| 用户ID | 系统生成的唯一标识 |
| 昵称 | 用户设置的显示名称 |
| 邮箱 | 注册邮箱 |
| 渠道 | 注册渠道（Web/App/H5） |
| 国家 | 注册时的国家代码 |
| 状态 | 正常（绿）/ 冻结（黄）/ 已注销（红） |
| 标签 | 展示前 2 个标签，超出显示 +N |
| 注册时间 | 格式：YYYY-MM-DD HH:mm |
| 操作 | 详情 / 打标 / 冻结或解冻 |

**操作按钮逻辑**：

| 用户状态 | 操作列展示 |
|----------|-----------|
| 正常 | 详情 / 打标 / 冻结（红色） |
| 冻结 | 详情 / 打标 / 解冻 |
| 已注销 | 详情 |

**批量操作**：
- 页面顶部提供"批量打标"按钮
- 点击后弹出批量打标弹窗（需先在列表中勾选用户）

#### 操作流程

**主流程**：
1. 进入用户列表页，默认展示全部用户（按注册时间倒序）
2. 可通过搜索框或筛选条件缩小范围
3. 点击"详情"进入用户详情页
4. 点击"打标"弹出单用户打标弹窗
5. 点击"冻结/解冻"执行状态变更（见 2.3 节）

#### 校验规则

| 字段 | 规则 | 校验时机 |
|------|------|----------|
| 搜索框 | 最少输入 1 个字符 | 点击查询时 |
| 批量打标 | 至少选择 1 个用户 | 点击"批量打标"按钮时 |

#### 异常处理

| 场景 | 处理方式 |
|------|----------|
| 网络异常 | 展示网络异常空态，提供"重试"按钮 |
| 搜索/筛选无结果 | 展示筛选无匹配空态，提供"清除筛选条件"按钮 |
| 列表为空（零数据） | 展示零数据引导态 |

#### UI 关联

| 端 | 设计稿 |
|----|--------|
| PC 后台 | 原型：用户列表页（page-user-list-list） |
| APP | 不涉及（纯后台模块） |

3. 设备列表
4. 登录与会话
5. 风控记录
6. 账号变更日志

### 2.3 用户冻结/解冻

**功能类型**：流程型

#### 功能描述

运营人员可冻结异常用户（禁止登录）或解冻误冻结的用户（恢复登录能力）。

#### 前置条件

- 用户当前状态为"正常"时可执行冻结
- 用户当前状态为"冻结"时可执行解冻
- 用户状态为"已注销"时不可操作

#### 操作流程

**冻结流程**：
1. 运营在用户列表或用户详情页点击"冻结"按钮
2. 系统弹出确认弹窗："确认冻结用户 {用户ID}（{昵称}）？冻结后该用户将无法登录，所有活跃会话立即失效。"
3. 运营点击"确认冻结"
4. 系统执行：用户状态改为"冻结"，所有活跃 Session 立即失效
5. 页面刷新，状态标签更新为"冻结"，操作按钮变为"解冻"

**解冻流程**：
1. 运营在用户列表或用户详情页点击"解冻"按钮
2. 系统弹出确认弹窗："确认解冻用户 {用户ID}（{昵称}）？解冻后该用户可正常登录。"
3. 运营点击"确认解冻"
4. 系统执行：用户状态改为"正常"
5. 页面刷新，状态标签更新为"正常"，操作按钮变为"冻结"

#### 异常处理

| 场景 | 处理方式 |
|------|----------|
| 网络异常 | 提示"操作失败，请重试" |
| 用户已被其他运营冻结/解冻（并发） | 提示"用户状态已变更，请刷新页面" |
| 用户已注销 | 按钮置灰不可点击 |

#### UI 关联

| 端 | 设计稿 |
|----|--------|
| PC 后台 | 原型：用户列表操作列 + 用户详情顶部按钮 |

### 2.4 用户标签管理

维护平台的用户标签池，支持标签的新增、编辑和停用。标签用于对用户进行分类标记，为精细化运营提供基础。

#### 前置条件

运营人员已登录后台系统。

#### 页面元素

**统计卡片区**（4 列）：

| 指标 | 说明 |
|------|------|
| 标签总数 | 所有标签数量 |
| 启用中 | 状态为"启用"的标签数 |
| 已停用 | 状态为"停用"的标签数 |
| 累计打标次数 | 所有标签的打标总次数 |

**筛选工具栏**：

| 筛选项 | 类型 | 选项 |
|--------|------|------|
| 搜索框 | 文本输入 | 按标签名称搜索 |
| 状态 | 下拉单选 | 全部状态 / 启用 / 停用 |

**列表表格**：

| 列名 | 说明 |
|------|------|
| 标签ID | 系统生成的唯一标识 |
| 标签名称 | 标签的显示名称 |
| 状态 | 启用（绿）/ 停用（灰） |
| 说明 | 标签的定义和适用场景描述 |
| 已打标用户数 | 当前拥有该标签的用户数量 |
| 创建时间 | YYYY-MM-DD |
| 操作 | 编辑 / 停用或启用 |

#### 操作流程

**新增标签**：
1. 点击"新增标签"按钮
2. 弹出新增标签弹窗
3. 填写标签名称（必填）和标签说明（选填）
4. 点击"保存"，标签创建成功，默认状态为"启用"

**编辑标签**：
1. 点击列表中的"编辑"按钮
2. 弹出编辑标签弹窗（预填当前值）
3. 修改标签名称或说明
4. 点击"保存"

**停用/启用标签**：
1. 点击列表中的"停用"或"启用"按钮
2. 停用后：该标签不再出现在打标选项中，已打标的用户保留标签但不可新增
3. 启用后：该标签恢复出现在打标选项中

#### 校验规则

| 字段 | 规则 | 校验时机 |
|------|------|----------|
| 标签名称 | 必填，1-20 个字符，不可与已有标签重名 | 点击保存时 |
| 标签说明 | 选填，最多 100 个字符 | 点击保存时 |

#### 异常处理

| 场景 | 处理方式 |
|------|----------|
| 标签名称重复 | 提示"标签名称已存在" |
| 网络异常 | 提示"操作失败，请重试" |
| 停用有用户的标签 | 允许停用，已打标用户保留标签展示，但不可新增打标 |

#### 数据模型

**用户标签表（user_tag）**：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键 |
| name | VARCHAR(20) | 标签名称，唯一 |
| description | VARCHAR(100) | 标签说明 |
| status | TINYINT | 1=启用 2=停用 |
| user_count | INT | 已打标用户数（冗余计数） |
| created_at | DATETIME | 创建时间 |
| updated_at | DATETIME | 最后更新时间 |

**用户标签绑定表（user_tag_bindng）**：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键 |
| user_id | BIGINT | 用户ID，关联 user_account |
| tag_id | BIGINT | 标签ID，关联 user_tag |
| created_at | DATETIME | 打标时间 |
| created_by | VARCHAR(50) | 打标操作人 |

> 联合唯一约束：user_id + tag_id（同一用户同一标签只能绑定一次）

#### UI 关联

| 端 | 设计稿 |
|----|--------|
| PC 后台 | 原型：用户标签页（page-tag-mgmt-list）+ 新增/编辑标签弹窗 |

### 2.5 用户打标/摘标

**功能类型**：流程型

#### 功能描述

为用户添加或移除标签。支持单用户打标（从用户列表或详情页发起）和批量打标（从用户列表发起）。

#### 前置条件

- 至少有 1 个启用中的标签
- 批量打标需先在列表中勾选用户

#### 操作流程

**单用户打标/摘标**：
1. 在用户列表点击"打标"或在用户详情页点击"+ 打标"
2. 弹出打标弹窗，展示所有启用中的标签列表
3. 已有标签预勾选，运营可勾选（打标）或取消勾选（摘标）
4. 点击"确认"，系统执行打标/摘标操作
5. 用户标签区实时更新

**批量打标**：
1. 在用户列表勾选多个用户
2. 点击"批量打标"按钮
3. 弹出批量打标弹窗，显示已选用户数量
4. 勾选要添加的标签（批量打标只支持添加，不支持批量摘标）
5. 点击"确认打标"，系统为所有选中用户添加勾选的标签
6. 已有该标签的用户自动跳过（幂等）

**详情页快捷摘标**：
1. 在用户详情页标签区，点击标签右侧的"×"
2. 直接移除该标签（无确认弹窗，操作轻量）

#### 异常处理

| 场景 | 处理方式 |
|------|----------|
| 标签在操作期间被停用 | 提示"部分标签已停用，已跳过" |
| 网络异常 | 提示"操作失败，请重试" |
| 批量打标未选择用户 | 按钮点击时提示"请先选择用户" |
| 批量打标未勾选标签 | "确认打标"按钮置灰不可点击 |

#### UI 关联

| 端 | 设计稿 |
|----|--------|
| PC 后台 | 原型：单用户打标弹窗（add-tag-dialog）+ 批量打标弹窗（batch-tag-dialog） |

### 2.6 强制下线

**功能类型**：流程型

#### 功能描述

运营人员可强制终止用户的指定活跃会话，使其立即失效。

#### 前置条件

- 目标会话状态为"活跃"

#### 操作流程

1. 在用户详情"登录与会话" Tab 中，找到目标活跃会话
2. 点击"强制下线"按钮
3. 系统弹出确认弹窗："确认强制下线该会话？用户将需要重新登录。"
4. 运营点击"确认"
5. 系统执行：目标 Session 状态改为"已终止"
6. "登录与会话" Tab 新增一条"强制下线"事件记录
7. 该行会话状态更新为"已终止"，操作列变为"—"

#### 异常处理

| 场景 | 处理方式 |
|------|----------|
| 会话已过期或已终止（并发） | 提示"该会话已失效，请刷新页面" |
| 网络异常 | 提示"操作失败，请重试" |

#### UI 关联

| 端 | 设计稿 |
|----|--------|
| PC 后台 | 原型：用户详情 > 登录与会话 Tab > 强制下线按钮 |

## 四、版本规划
