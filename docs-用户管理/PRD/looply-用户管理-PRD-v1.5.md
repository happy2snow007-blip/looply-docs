# Looply 用户管理模块 PRD V1.5

## 一、概述

### 1.1 背景与目标

Looply 平台需要为运营团队提供用户管理后台，支持查看用户信息、管理用户状态、查阅登录与安全记录、维护用户标签体系。本模块是登录注册系统的运营侧延伸，数据来源于登录注册模块的用户体系。

**核心目标**：
- 为运营提供用户全景视图（账号信息、登录行为、设备、风控、合规）
- 支持用户状态管理（冻结/解冻）和会话管理（强制下线）
- 建立用户标签体系，支持手动打标和批量打标，为后续精细化运营提供基础

### 1.2 不做什么

| 不做的事 | 原因 |
|----------|------|
| 用户注册/登录流程 | 属于登录注册模块，本模块只做后台查看和管理 |
| 用户自助修改资料 | 属于 C 端个人中心，非后台功能 |
| 自动化标签（规则引擎自动打标） | MVP 阶段只做手动打标，自动化标签为后续迭代 |
| 用户画像/行为分析 | 属于数据分析模块，本模块只提供基础标签能力 |
| 权限管理（运营角色分级） | 当前运营团队规模小，暂不做角色权限细分 |
| 设备信任/不信任切换操作 | PRD 明确 MVP 阶段不启用信任设备功能，仅展示 |
| 用户数据导出 | 后续迭代 |

### 1.3 用户角色

| 角色 | 说明 |
|------|------|
| 运营人员 | 本模块唯一使用者，负责用户查询、状态管理、标签维护 |

### 1.4 核心场景

1. **用户查询**：运营通过 ID/昵称/邮箱搜索用户，或按渠道/状态/标签筛选用户列表
2. **用户详情查阅**：查看某用户的完整信息（账号、凭证、设备、登录记录、风控、变更日志、合规同意）
3. **用户状态管理**：冻结异常用户、解冻误冻结用户
4. **会话管理**：强制下线可疑会话
5. **标签管理**：新增/编辑/停用标签
6. **用户打标**：为单个用户或批量用户添加/移除标签

### 1.5 全局页面流转

```
用户列表 ──→ 用户详情（返回列表）
用户列表 ──→ [弹窗] 批量打标
用户详情 ──→ [弹窗] 单用户打标
用户标签列表 ──→ [弹窗] 新增标签
用户标签列表 ──→ [弹窗] 编辑标签
```

### 1.6 术语说明

| 术语 | 定义 |
|------|------|
| 打标 | 为用户添加标签 |
| 摘标 | 移除用户已有的标签 |
| 冻结 | 禁止用户登录和使用平台，已有会话立即失效 |
| 强制下线 | 使指定会话立即失效，用户需重新登录 |
| 设备指纹 | 系统为每台设备生成的唯一标识符 |

### 1.7 多语言 / 多国家策略

- 后台界面语言：中文（面向国内运营团队）
- 用户数据展示：保留原始语言（如英文昵称、英文简介原样展示）
- 时区展示：遵循《后台时区展示规范》（见全局规范文档）
- 国家字段：展示 ISO 3166-1 国家代码（如 US、GB）

### 1.8 状态机定义

#### 用户状态

```
正常 ──冻结操作──→ 冻结
冻结 ──解冻操作──→ 正常
正常 ──注销（用户自助/运营代操作）──→ 已注销（不可逆）
冻结 ──注销（运营代操作）──→ 已注销（不可逆）
```

| 状态 | 含义 | 可执行操作 |
|------|------|-----------|
| 正常 | 用户可正常登录和使用平台 | 冻结、注销、打标/摘标 |
| 冻结 | 禁止登录，已有会话立即失效 | 解冻、注销、打标/摘标 |
| 已注销 | 用户已注销账号，不可恢复 | 仅可查看详情，不可执行任何操作 |

> 注：注销可由用户自助发起（C 端）或运营代操作（后台），详见 2.1.6 运营代注销。注销不可逆。

#### 标签状态

| 状态 | 含义 | 默认值 |
|------|------|--------|
| 启用 | 标签可正常使用，出现在打标选项中 | 新建标签默认为"启用" |
| 停用 | 标签不出现在打标选项中，已打标用户保留标签展示 | — |

## 二、需求详细描述

本章按管理对象组织：2.1 用户管理围绕"用户"实体，包含页面和操作；2.2 用户标签管理围绕"标签"实体，包含标签池的维护。

### 2.1 用户管理

#### 2.1.1 模块概述

用户管理是本模块的核心功能，负责用户信息的查看和用户状态的管理。包含两个页面（用户列表、用户详情）和四个操作（冻结/解冻、强制下线、运营代注销、打标/摘标）。

页面章节描述布局和展示规则，操作章节描述业务逻辑和流程。操作可能从多个页面触发，每个操作章节开头标注所有入口位置。

---

#### 2.1.2 用户列表页

**功能类型**：页面型

**功能描述**

展示平台所有注册用户的列表，支持搜索、筛选、分页浏览，以及从列表进入用户详情或执行操作。

**前置条件**

运营人员已登录后台系统。

**页面元素**

**统计卡片区**（4 列）：

| 指标 | 说明 |
|------|------|
| 用户总数 | 所有注册用户数量（含冻结、注销） |
| 正常 | 状态为"正常"的用户数 |
| 冻结 | 状态为"冻结"的用户数 |
| 已注销 | 状态为"已注销"的用户数 |

**筛选工具栏**：

| 筛选项 | 类型 | 选项 |
|--------|------|------|
| 搜索框 | 文本输入 | 支持用户ID、昵称、邮箱模糊搜索 |
| 渠道 | 下拉单选 | 全部渠道 / Web / App / H5 |
| 状态 | 下拉单选 | 全部状态 / 正常 / 冻结 / 已注销 |
| 标签 | 下拉单选 | 全部标签 / [动态加载启用中的标签列表] |
| 注册时间 | 日期范围选择器 | 起止日期（YYYY-MM-DD），筛选注册时间在该范围内的用户 |

**列表表格**：

| 列名 | 说明 |
|------|------|
| 用户ID | 系统生成的唯一标识 |
| 昵称 | 用户设置的显示名称 |
| 邮箱 | 注册邮箱 |
| 渠道 | 注册渠道（Web/App/H5） |
| 国家 | 注册时的国家代码 |
| 状态 | 正常（绿）/ 冻结（黄）/ 已注销（灰） |
| 标签 | 展示前 2 个标签，超出显示 +N |
| 注册时间 | 格式：YYYY-MM-DD HH:mm |
| 操作 | 详情 / 冻结或解冻 / 注销 |

**操作按钮逻辑**：

| 用户状态 | 操作列展示 |
|----------|-----------|
| 正常 | 详情 / 冻结（红色）/ 注销（红色） |
| 冻结 | 详情 / 解冻 / 注销（红色） |
| 已注销 | 详情 |

> 操作按钮触发的业务逻辑分别见 2.1.4 冻结/解冻、2.1.6 运营代注销。

**批量操作**：
- 页面顶部提供"批量打标"按钮
- 列表左侧每行有 checkbox，支持多选用户
- 未勾选用户时，"批量打标"按钮置灰（disabled）
- 勾选至少 1 个用户后，按钮可点击，点击弹出批量打标弹窗

> 批量打标的业务逻辑见 2.1.7 打标/摘标。

**操作流程**

1. 进入用户列表页，默认展示全部用户（按注册时间倒序）
2. 可通过搜索框或筛选条件缩小范围
3. 点击"详情"进入用户详情页

**校验规则**

| 字段 | 规则 | 校验时机 |
|------|------|----------|
| 搜索框 | 最少输入 1 个字符 | 点击查询时 |
| 批量打标 | 至少选择 1 个用户 | 点击"批量打标"按钮时 |

**异常处理**

| 场景 | 处理方式 |
|------|----------|
| 网络异常 | 展示网络异常空态，提供"重试"按钮 |
| 搜索/筛选无结果 | 展示筛选无匹配空态，提供"清除筛选条件"按钮 |
| 列表为空（零数据） | 展示零数据引导态 |

**UI 关联**

| 端 | 设计稿 |
|----|--------|
| PC 后台 | 原型：用户列表页（page-user-list-list） |
| APP | 不涉及（纯后台模块） |

#### 2.1.3 用户详情页

**功能类型**：页面型

**功能描述**

展示单个用户的完整信息，通过 Tab 切换查看不同维度的数据。顶部常驻用户标签区，支持快捷打标/摘标。

**前置条件**

从用户列表点击"详情"进入。

**页面布局**

**顶部区域**：
- 页面标题：用户详情 — {用户ID}
- 副标题：{昵称} / {邮箱}
- 操作按钮：返回列表、冻结账号（红色）/ 解冻账号、注销账号（红色）

> 顶部操作按钮触发的业务逻辑分别见 2.1.4 冻结/解冻、2.1.6 运营代注销。

**标签区**（常驻，Tab 上方）：
- 展示该用户当前所有标签
- 每个标签右侧有"x"可快捷摘标
- 末尾有"+ 打标"按钮，点击弹出打标弹窗

> 标签区的打标/摘标业务逻辑见 2.1.7 打标/摘标。

**Tab 区域**（7 个 Tab）：
1. 基本信息
2. 登录凭证
3. 设备列表
4. 登录与会话
5. 风控记录
6. 账号变更日志
7. 合规同意

**设备表格**：

**2.1.3.4 登录与会话 Tab**

合并展示用户的登录事件和会话生命周期，包括登录、退出、强制下线等所有会话相关事件。

**表格列定义**：

| 列名 | 说明 |
|------|------|
| 时间 | 事件发生时间 |
| 设备 | 设备指纹 + 操作系统（如 fp_xxx (macOS)） |
| 方式 | 登录方式：密码 / 验证码 / 三方(平台名)。退出和强制下线显示"—" |
| IP地址 | 事件来源 IP |
| 地理位置 | IP 对应的地理位置（国家 / 城市） |
| 事件 | 见下方事件类型枚举 |
| 会话状态 | 见下方会话状态枚举 |
| 操作 | 仅会话状态为"活跃"时显示"强制下线"按钮 |

**事件类型枚举**：

| 枚举值 | 含义 | 触发时机 | 标签颜色 |
|--------|------|----------|----------|
| 登录成功 | 用户成功完成身份验证并创建会话 | 密码/验证码/三方登录验证通过 | 绿色 |
| 登录失败 | 用户身份验证未通过 | 密码错误、验证码错误等 | 红色 |
| 登录拦截 | 触发风控规则被拦截 | 异地登录、暴力破解等风控命中 | 黄色 |
| 退出登录 | 用户主动退出 | 用户点击退出按钮 | 灰色 |
| 强制下线 | 管理员强制终止会话 | 运营在后台执行强制下线操作 | 粉色/危险 |

**会话状态枚举**：

| 枚举值 | 含义 | 说明 |
|--------|------|------|
| 活跃 | 会话有效，用户可正常使用 | 绿色标签 |
| 过期 | 会话超过有效期自动失效 | 灰色标签 |
| 已终止 | 会话被主动终止（用户退出或管理员强制下线） | 黄色标签 |

**会话状态展示规则**：
- 事件为"登录成功"→ 会话状态列展示该次登录创建的 Session 当前状态
- 事件为"登录失败"或"登录拦截"→ 会话状态列显示"—"（未创建会话）
- 事件为"退出登录"或"强制下线"→ 会话状态列显示"已终止"

**操作列规则**：
- 仅当会话状态为"活跃"时，显示"强制下线"按钮（红色边框）
- 其他状态显示"—"

> "强制下线"按钮触发的业务逻辑见 2.1.5 强制下线。

**2.1.3.5 风控记录 Tab**

**2.1.3.6 账号变更日志 Tab**

展示用户账号级别的变更记录（不含登录/退出等会话事件）。

**表格列定义**：

| 列名 | 说明 |
|------|------|
| 操作时间 | 变更发生时间 |
| 操作类型 | 见下方枚举 |
| 操作详情 | 具体变更内容描述 |

**操作类型枚举**：

| 绑定凭证 | 绑定邮箱或手机号 | 用户在个人设置中绑定 | 凭证类型 + 凭证值 |
| 解绑凭证 | 解绑邮箱或手机号 | 用户在个人设置中解绑 | 凭证类型 + 凭证值 |

| 解冻 | 运营解冻账号 | 运营在后台执行解冻操作 | 操作人 + "解冻用户账号" |

| 用户协议 | Terms of Service |

#### 2.1.4 冻结/解冻

**功能类型**：操作型

**入口**：
- 用户列表页 > 操作列 > "冻结"/"解冻"按钮
- 用户详情页 > 顶部 > "冻结账号"/"解冻账号"按钮

**功能描述**

运营人员可冻结异常用户（禁止登录）或解冻误冻结的用户（恢复登录能力）。

**前置条件**

- 用户当前状态为"正常"时可执行冻结
- 用户当前状态为"冻结"时可执行解冻
- 用户状态为"已注销"时不可操作

**操作流程**

**冻结流程**：
1. 运营点击"冻结"按钮
2. 系统弹出确认弹窗："确定冻结用户 {用户ID}（{昵称}）吗？冻结后该用户将无法登录，所有活跃会话立即失效。"
3. 运营点击"确认冻结"
4. 系统执行：用户状态改为"冻结"，所有活跃 Session 立即失效
5. 页面刷新，状态标签更新为"冻结"，操作按钮变为"解冻"

**解冻流程**：
1. 运营点击"解冻"按钮
2. 系统弹出确认弹窗："确定解冻用户 {用户ID}（{昵称}）吗？解冻后该用户可正常登录。"
3. 运营点击"确认解冻"
4. 系统执行：用户状态改为"正常"
5. 页面刷新，状态标签更新为"正常"，操作按钮变为"冻结"

**异常处理**

| 场景 | 处理方式 |
|------|----------|
| 网络异常 | 提示"操作失败，请重试" |
| 用户已被其他运营冻结/解冻（并发） | 提示"用户状态已变更，请刷新页面" |
| 用户已注销 | 按钮置灰不可点击 |

#### 2.1.5 强制下线

**功能类型**：操作型

**入口**：
- 用户详情页 > 登录与会话 Tab > 活跃会话行 > "强制下线"按钮

**功能描述**

运营人员可强制终止用户的指定活跃会话，使其立即失效。

**前置条件**

- 目标会话状态为"活跃"

**操作流程**

1. 在用户详情"登录与会话" Tab 中，找到目标活跃会话
2. 点击"强制下线"按钮
3. 系统弹出确认弹窗："确认强制下线该会话？仅终止当前这一条会话，不影响其他设备。用户将需要重新登录。"
4. 运营点击"确认"
5. 系统执行：目标 Session 状态改为"已终止"
6. "登录与会话" Tab 新增一条"强制下线"事件记录
7. 该行会话状态更新为"已终止"，操作列变为"—"

**异常处理**

| 场景 | 处理方式 |
|------|----------|
| 会话已过期或已终止（并发） | 提示"该会话已失效，请刷新页面" |
| 网络异常 | 提示"操作失败，请重试" |

#### 2.1.6 运营代注销

**功能类型**：操作型

**入口**：
- 用户列表页 > 操作列 > "注销"按钮
- 用户详情页 > 顶部 > "注销账号"按钮

**功能描述**

运营人员代用户执行账号注销，适用于用户通过邮件等渠道要求注销账号的场景。逻辑等同于用户自助注销（参见登录注册 PRD SS4.6），触发方为运营。

**前置条件**

- 用户当前状态为"正常"或"冻结"
- 用户状态为"已注销"时不可重复操作

**操作流程**

1. 运营点击"注销"/"注销账号"按钮
2. 系统弹出确认弹窗："确定注销用户 {用户ID}（{昵称}）吗？注销后所有活跃会话立即失效，30 天内可恢复，超过 30 天数据永久删除。"
3. 运营点击"确认注销"
4. 系统执行：
   - 用户状态改为"已注销"，记录 deactivated_at
   - 吊销所有活跃 Session（立即失效）
   - 写入审计日志（账号变更日志），操作类型"注销"，详情"运营代操作注销，原因：用户邮件要求"
5. 页面刷新，状态标签更新为"已注销"，操作列仅保留"详情"

**数据保留策略**

与用户自助注销一致（参见登录注册 PRD SS4.6）：
- 账号信息：软删除，30 天后物理删除
- 交易记录：永久保留（脱敏）
- 用户内容：下架但保留
- 个人信息：30 天后物理删除

**冷静期**

- 注销后 30 天内可通过客服恢复账号
- 超过 30 天数据永久删除，不可恢复

**与用户自助注销的区别**

| 维度 | 用户自助注销 | 运营代注销 |
|------|-------------|-----------|
| 触发方 | 用户在 C 端发起 | 运营在后台发起 |
| 身份验证 | 需密码或 OAuth 验证 | 无（运营已确认邮件来源） |
| 审计日志记录 | 操作人=用户 | 操作人=运营，详情含"运营代操作" |
| 其他逻辑 | 完全一致 | 完全一致 |

**异常处理**

| 场景 | 处理方式 |
|------|----------|
| 网络异常 | 提示"操作失败，请重试" |
| 用户已被其他运营注销（并发） | 提示"用户状态已变更，请刷新页面" |
| 用户状态为已注销 | 按钮不展示 |

#### 2.1.7 打标/摘标

**功能类型**：操作型

**入口**：
- 用户列表页 > 顶部 > "批量打标"按钮（需先勾选用户）
- 用户详情页 > 标签区 > "+ 打标"按钮
- 用户详情页 > 标签区 > 标签右侧"x"（快捷摘标）

**功能描述**

为用户添加或移除标签。支持单用户打标（从详情页发起）和批量打标（从用户列表发起）。

**前置条件**

- 至少有 1 个启用中的标签
- 批量打标需先在列表中勾选用户

**操作流程**

**单用户打标/摘标**：
1. 在用户详情页点击"+ 打标"
2. 弹出打标弹窗，展示所有启用中的标签列表
3. 已有标签预勾选，运营可勾选（打标）或取消勾选（摘标）
4. 点击"确认"，系统执行打标/摘标操作
5. 用户标签区实时更新

**批量打标**：
1. 在用户列表勾选多个用户
2. 点击"批量打标"按钮
3. 弹出批量打标弹窗，显示已选用户数量
4. 勾选要添加的标签（批量打标只支持添加，不支持批量摘标）
5. 点击"确认打标"，系统为所有选中用户添加勾选的标签
6. 已有该标签的用户自动跳过（幂等）
7. 操作结果提示：
   - 部分跳过："已为 {N} 个用户添加标签，{M} 个用户已有该标签已跳过"
   - 全部成功："已为 {N} 个用户添加标签"
   - 全部跳过："所选用户均已拥有该标签"

**详情页快捷摘标**：
1. 在用户详情页标签区，点击标签右侧的"x"
2. 直接移除该标签（无确认弹窗，操作轻量）

**异常处理**

| 场景 | 处理方式 |
|------|----------|
| 标签在操作期间被停用 | 提示"部分标签已停用，已跳过" |
| 网络异常 | 提示"操作失败，请重试" |
| 批量打标未选择用户 | 按钮点击时提示"请先选择用户" |
| 批量打标未勾选标签 | "确认打标"按钮置灰不可点击 |

### 2.2 用户标签管理

#### 2.2.1 模块概述

维护平台的用户标签池，支持标签的新增、编辑和停用。标签用于对用户进行分类标记，为精细化运营提供基础。本模块管理标签本身的生命周期，标签与用户的关联操作见 2.1.7 打标/摘标。

---

#### 2.2.2 标签列表页

**功能类型**：页面型

**前置条件**

运营人员已登录后台系统。

**页面元素**

**统计卡片区**（4 列）：

| 指标 | 说明 |
|------|------|
| 标签总数 | 所有标签数量 |
| 启用中 | 状态为"启用"的标签数 |
| 已停用 | 状态为"停用"的标签数 |
| 累计打标次数 | 所有标签的打标总次数 |

**筛选工具栏**：

| 筛选项 | 类型 | 选项 |
|--------|------|------|
| 搜索框 | 文本输入 | 按标签名称搜索 |
| 状态 | 下拉单选 | 全部状态 / 启用 / 停用 |

**列表表格**：

| 列名 | 说明 |
|------|------|
| 标签ID | 系统生成的唯一标识 |
| 标签名称 | 标签的显示名称 |
| 状态 | 启用（绿）/ 停用（灰） |
| 说明 | 标签的定义和适用场景描述 |
| 已打标用户数 | 当前拥有该标签的用户数量 |
| 创建时间 | YYYY-MM-DD |
| 操作 | 编辑 / 停用或启用 |

> 默认排序：按创建时间倒序排列。

**操作流程**

- 点击"新增标签"→ 弹出新增标签弹窗（见 2.2.3）
- 点击"编辑"→ 弹出编辑标签弹窗（见 2.2.3）
- 点击"停用"→ 弹出确认弹窗："确定停用标签"{标签名}"吗？停用后新打标不可选该标签，已打标用户保留标签展示。"确认后标签状态改为"停用"
- 点击"启用"→ 弹出确认弹窗："确定启用标签"{标签名}"吗？"确认后标签状态恢复为"启用"

**异常处理**

| 场景 | 处理方式 |
|------|----------|
| 网络异常 | 提示"操作失败，请重试" |
| 停用有用户的标签 | 允许停用，已打标用户保留标签展示，但不可新增打标 |

**UI 关联**

| 端 | 设计稿 |
|----|--------|
| PC 后台 | 原型：用户标签页（page-tag-mgmt-list） |

#### 2.2.3 新建/编辑标签

**功能类型**：弹窗型

**入口**：
- 标签列表页 > "新增标签"按钮
- 标签列表页 > 操作列 > "编辑"按钮

**功能描述**

通过弹窗表单新建或编辑标签。编辑时预填当前值。

**表单字段**

| 字段 | 必填 | 说明 |
|------|------|------|
| 标签名称 | 是 | 1-20 个字符 |
| 标签说明 | 否 | 最多 200 个字符 |

**校验规则**

| 字段 | 规则 | 校验时机 |
|------|------|----------|
| 标签名称 | 必填，1-20 个字符，不可与已有标签重名。前后空格自动去除，去除后不可为空；允许中英文、数字、常用标点；不允许纯空格和 HTML 标签 | 点击保存时 |
| 标签说明 | 选填，最多 200 个字符 | 点击保存时 |

**操作流程**

**新建**：
1. 填写标签名称（必填）和标签说明（选填）
2. 点击"保存"，标签创建成功，默认状态为"启用"
3. 列表刷新

**编辑**：
1. 弹窗预填当前标签名称和说明
2. 修改后点击"保存"
3. 标签改名后全局即时生效，所有已打标用户处展示新名称

**异常处理**

| 场景 | 处理方式 |
|------|----------|
| 标签名称重复 | 提示"标签名称已存在" |
| 网络异常 | 提示"操作失败，请重试" |

**UI 关联**

| 端 | 设计稿 |
|----|--------|
| PC 后台 | 原型：新增/编辑标签弹窗（tag-dialog） |

## 四、版本规划

### MVP（V1.0）

- 用户列表（搜索、筛选、分页）
- 用户详情（7 个 Tab 全量信息展示）
- 用户冻结/解冻
