# Looply 售后政策活动时效迭代 PRD V1.0

> 文档日期：2026-11-16  
> 关联原型：`looply-售后管理后台原型-v18-antd.html`  
> 适用范围：售后政策配置、订单售后政策快照、售后原因系统预置数据

## 一、概述

### 1.1 背景与目标

现有售后政策统一提供 15 天售后时效，无法覆盖黑五期间订单享受 30 天售后时效的业务要求；同时，当前订单下单时未固化售后政策，直到创建售后单时才记录政策，导致订单权益可能被后续政策调整影响。

本次目标：

1. 售后政策支持按订单下单时间配置长期政策与指定时段政策。
2. 支持按市场、商品范围、适用用户和订单下单时间筛选候选政策，再按优先级确定唯一政策。
3. 日常订单适用 15 天售后时效；黑五活动订单适用 30 天售后时效。
4. 黑五预热期面向老用户的订单，可通过适用用户和下单时间配置命中同一套 30 天政策。
5. 将售后政策快照的固化时点从“售后建单时”前移至“订单下单时”，确保订单权益不受后续政策修改影响。
6. 新增系统预置、C 端不展示的“物流退回”售后原因码，供运营代建售后单时使用。

### 1.2 本期范围

| 范围 | 本期处理 |
|---|---|
| 售后政策列表 | 调整字段、筛选项和适用条件展示 |
| 售后政策新增/编辑 | 增加适用用户、生效周期、订单下单时间和全局优先级配置 |
| 政策匹配 | 按市场、商品范围、适用用户、订单下单时间及优先级确定政策 |
| 订单政策快照 | 下单时固化命中政策；售后建单读取订单快照 |
| 售后原因 | 新增系统预置原因码 `ASR_PACKAGE_RETURNED` |
| 操作记录 | 记录政策创建、编辑、启用、停用及字段变化 |

### 1.3 不在本期范围

- 不修改售后工单的状态机。
- 不修改审核、驳回重提、退货运单、物流追踪、验货判责、退款失败重试、撤销和关闭流程。
- 不调整现有原因码的展示文案、举证要求和排序。
- 不在 C 端新增“物流退回”原因选项。
- 不在本次原型中展示订单政策快照前移或新增系统预置原因码；两项均为系统规则和初始化数据改动。
- 不新增政策删除能力。

### 1.4 用户角色

| 角色 | 本期操作 |
|---|---|
| 运营人员 | 查看、新增、编辑、复制、启用或停用售后政策；运营代建售后单时可选择系统预置原因 |
| 买家 | 无新增操作；按订单固化的政策享受对应售后权益 |
| 系统 | 下单时匹配并固化政策；售后建单时读取订单政策快照 |

### 1.5 核心场景

| 场景 | 预期结果 |
|---|---|
| 日常订单 | 命中长期有效的日常政策，售后时效为签收后 15 天 |
| 黑五活动订单 | 下单时间位于活动区间内，命中黑五政策，售后时效为签收后 30 天 |
| 黑五预热老用户订单 | 用户符合老用户或指定标签条件，且下单时间位于预热区间内，命中 30 天政策 |
| 政策后续被修改或停用 | 已下单订单继续读取原政策快照，权益不变化 |
| 运营代建物流退回售后单 | 可选择 `ASR_PACKAGE_RETURNED`，买家侧申请页不展示该原因 |

### 1.6 页面流转

```
售后政策列表 ──新增政策──▶ 新增售后政策 ──保存/取消──▶ 售后政策列表
售后政策列表 ──编辑──────▶ 编辑售后政策 ──保存/取消──▶ 售后政策列表
售后政策列表 ──复制──────▶ 新增售后政策（预填源政策配置）
```

### 1.7 术语

| 术语 | 定义 |
|---|---|
| 生效周期 | 判断政策是否限制订单下单时间，取值为长期有效或指定下单时段 |
| 订单下单时间 | 订单创建成功时间；活动边界按该时间判断 |
| 适用用户 | 政策面向的用户范围，包括全部用户、新人、老用户、指定用户标签、指定邮箱 |
| 政策优先级 | 一个订单商品同时命中多条政策时的排序字段，数值越小优先级越高 |
| 订单政策快照 | 下单时固化在订单商品行上的完整售后政策副本，供后续申请与售后建单使用 |
| 原因码快照 | 售后建单时固化的原因码副本；与订单政策快照的固化时点不同 |

## 二、需求详细描述

### 2.1 售后政策列表

#### 2.1.1 功能描述

运营查看和维护所有售后政策。菜单“售后政策”与线上保持一致，为售后模块一级菜单。

#### 2.1.2 筛选项

| 筛选项 | 类型 | 规则 |
|---|---|---|
| 政策编号 / 范围值 | 文本输入 | 支持按政策编号、品类名称/编号、商品名称/编号模糊查询 |
| Market | 单选下拉 | 默认全部 Market |
| 范围类型 | 单选下拉 | 全部、全市场、品类、商品 |
| 状态 | 单选下拉 | 全部、启用、停用 |

列表不提供“适用用户”和“生效周期”筛选。

#### 2.1.3 列表字段

| 字段 | 展示规则 |
|---|---|
| 政策编号 | 展示系统生成的唯一编号 |
| 适用市场 | 展示 Market 名称及编码 |
| 适用条件 | 分三行展示范围、用户、生效周期；指定条件同时展示对应值 |
| 优先级 | 展示政策全局优先级 |
| 是否支持退货 | 支持 / 不支持 |
| 售后时效 | 支持退货时展示“签收后 N 天”；不支持时展示“—” |
| 退货服务费 | 支持退货时按 Market 币种展示；不支持时展示“—” |
| 状态 | 启用 / 停用 |
| 更新时间 | 展示最近更新时间 |
| 操作 | 编辑、复制、启用/停用 |

列表不展示订单下单时间范围和退货地址，完整值在新增/编辑页维护。

#### 2.1.4 页面状态

| 状态 | 页面表现 |
|---|---|
| 正常数据 | 展示表格和分页 |
| 零数据 | 展示“暂无售后政策”和新增政策入口 |
| 无匹配 | 保留筛选条件，展示无匹配结果和清除筛选入口 |
| 加载中 | 表格显示加载状态 |
| 请求失败 | 展示加载失败和重试入口 |

### 2.2 售后政策新增/编辑

#### 2.2.1 基本信息

| 字段 | 类型 | 必填 | 规则 |
|---|---|---:|---|
| 政策名称 | 文本 | 是 | 用于运营识别政策 |
| 适用市场 | 单选 | 是 | Market 决定币种和业务时区 |
| 优先级 | 整数 | 是 | 1～100；数值越小优先级越高 |
| 状态 | 单选 | 是 | 启用 / 停用 |

#### 2.2.2 适用条件

| 字段 | 类型 | 必填 | 规则 |
|---|---|---:|---|
| 范围类型 | 单选 | 是 | 全市场 / 品类 / 商品 |
| 适用品类 | 单选 | 条件必填 | 范围类型为品类时出现 |
| 适用商品 | 多值输入 | 条件必填 | 范围类型为商品时出现；支持输入多个商品 ID |
| 适用用户 | 单选 | 是 | 全部用户 / 新人 / 老用户 / 指定用户标签 / 指定邮箱 |
| 用户标签 | 多选 | 条件必填 | 适用用户为指定用户标签时出现；命中任一标签即可 |
| 指定邮箱 | 多行输入 | 条件必填 | 每行一个邮箱，同时兼容逗号、分号和空格分隔 |
| 生效周期 | 单选 | 是 | 长期有效 / 指定下单时段 |
| 订单下单时间 | 时间范围 | 条件必填 | 指定下单时段时出现；开始时刻包含，结束时刻不包含 |
| 业务时区 | 只读 | 条件必填 | 根据适用市场自动确定，不允许手动修改 |

#### 2.2.3 退货与时效

| 字段 | 类型 | 必填 | 规则 |
|---|---|---:|---|
| 是否支持退货 | 单选 | 是 | 支持退货 / 不支持退货 |
| 售后时效 | 整数 | 条件必填 | 支持退货时出现，1～365 天；从买家签收时点开始计算 |
| 服务费金额 | 金额 | 条件必填 | 支持退货时出现；币种跟随 Market |
| 退货地址 | 多行文本 | 条件必填 | 支持退货时出现 |

日常政策配置 15 天，黑五及黑五预热政策配置 30 天。下单时间只用于确定订单命中哪条政策，不改变售后时效从签收时点起算的规则。

#### 2.2.4 操作

| 操作 | 规则 |
|---|---|
| 新增 | 保存后生成新政策编号 |
| 编辑 | 修改政策配置；不回溯修改已经固化的订单政策快照 |
| 复制 | 进入新增页并预填源政策配置；不复制政策编号和更新时间 |
| 停用 | 停用后不参与后续新订单的政策匹配；不影响已有订单快照 |
| 启用 | 启用后参与后续新订单匹配 |

#### 2.2.5 操作记录

编辑页展示操作记录，记录创建、编辑、启用和停用。编辑记录需展示关键字段修改前后的值，至少覆盖：适用市场、范围、适用用户、生效周期、下单时间、优先级、是否支持退货、售后时效、服务费、退货地址和状态。

### 2.3 政策匹配规则

#### 2.3.1 触发时点

订单创建成功时，以订单下单时间为每个订单商品行匹配售后政策并固化快照。售后建单不再使用当时的政策配置重新匹配。

#### 2.3.2 候选政策筛选

一条政策同时满足以下全部条件时进入候选集合：

1. 政策状态为启用。
2. 适用市场与订单 Market 一致。
3. 商品命中政策范围：全市场、指定品类或指定商品。
4. 买家命中适用用户条件。
5. 生效周期为长期有效，或订单下单时间位于指定区间 `[开始时间, 结束时间)`。

#### 2.3.3 最终政策选择

- 将全部候选政策按优先级从小到大排序。
- 取优先级最高的一条作为该订单商品行的售后政策。
- 不再采用“商品 → 品类 → 全市场，命中即停”的固定层级匹配方式。
- 相同优先级同时命中时，系统必须能够识别冲突并记录异常；最终裁决方式需在开发前由产品与技术共同确认，不允许静默随机选择。

#### 2.3.4 无政策命中

未命中支持退货的售后政策时，该订单商品行不可发起常规售后申请。运营的超期特批仍只豁免时效校验，不豁免“商品不支持售后”。

### 2.4 订单售后政策快照

#### 2.4.1 规则调整

| 项目 | 调整前 | 调整后 |
|---|---|---|
| 固化时点 | 售后建单时记录政策 | 订单下单时固化政策 |
| 固化粒度 | 售后单 | 订单商品行 |
| 售后建单 | 按建单时政策记录 | 直接读取订单商品行政策快照 |
| 政策修改影响 | 可能影响尚未建售后的历史订单 | 不影响已下单订单 |

#### 2.4.2 快照内容

订单商品行政策快照至少包含：

- 政策编号、政策名称
- 适用市场
- 商品范围类型及范围值
- 适用用户类型及范围值
- 生效周期
- 活动开始时间、活动结束时间、业务时区
- 优先级
- 是否支持退货
- 售后时效天数
- 退货服务费金额及币种
- 退货地址
- 快照时间

#### 2.4.3 使用规则

1. C 端售后入口根据订单商品行政策快照判断是否支持退货及是否超期。
2. 售后建单将订单政策快照关联或复制到售后单，供后续审核、判责和退款读取。
3. 政策后续编辑、停用或复制，不更新历史订单快照。
4. 买家被驳回后在原售后单重新提交，不刷新订单政策快照。
5. 原因码快照仍在售后建单时生成；若买家重提时修改原因，按现有规则刷新原因码快照。

#### 2.4.4 历史订单兼容

- 上线后新下单的订单必须在下单链路完成政策快照固化。
- 上线前已经存在且没有政策快照的订单，不因本次上线自动改变既有售后权益。
- 历史订单发起售后时沿用当前线上兼容方式，在首次售后建单时补记政策快照，并标识快照来源为历史兼容。
- 如需对指定黑五预热历史订单批量补发 30 天权益，应另行提供明确订单范围并执行专项数据处理，不包含在本次常规政策配置操作中。

#### 2.4.5 异常处理

| 异常 | 处理 |
|---|---|
| 下单时未命中政策 | 记录无政策命中结果；该商品行不可发起常规售后 |
| 下单时政策冲突 | 记录冲突政策及优先级，阻止静默随机固化；异常需可追踪 |
| 快照写入失败 | 下单链路不得产生“订单成功但售后权益未知”的结果；按订单链路既有失败机制处理 |
| 售后建单读取不到新订单快照 | 阻止建单并提示系统异常，不使用当前政策静默覆盖新订单权益 |
| 历史订单无快照 | 走历史兼容逻辑，并记录补记来源和时间 |

### 2.5 新增系统预置售后原因

#### 2.5.1 原因码定义

| 字段 | 值 |
|---|---|
| 原因码 | `ASR_PACKAGE_RETURNED` |
| 展示文案 | `Package was returned` |
| 中文备注 | 物流退回 |
| 类型 | 系统预置 |
| C 端展示 | 否 |
| 使用入口 | 仅运营代建售后单时可选 |

#### 2.5.2 规则

1. 原因码全局唯一，创建后不可修改。
2. 该原因不出现在买家 C 端售后申请原因列表。
3. 运营代建售后单的原因下拉中可以选择该原因。
4. 建单后按现有原因码快照规则记录原因码、展示文案和中文备注。
5. 本次为新增原因码，不自动删除或改写现有 `ASR_DELIVERY_FAILED`；如需替换旧码，应另行明确存量数据与历史单据迁移规则。
6. 本次不擅自改变该原因对应的寄回/不寄回流程分支；流程分组按售后原因现有配置与后端规则执行。

### 2.6 权限与审计

- 沿用现有售后政策和售后原因管理权限，不新增角色。
- 政策新增、编辑、复制、启用和停用均需记录操作人、操作时间及变更内容。
- 订单政策快照需记录来源政策及快照时间，便于排查订单权益。
- 历史订单兼容补记需记录“历史兼容”来源，不与正常下单快照混淆。

## 三、依赖与风险

### 3.1 系统依赖

| 依赖模块 | 依赖内容 |
|---|---|
| 订单域 | 提供订单 Market、商品行、品类、买家、下单时间；在下单链路固化政策快照 |
| 用户管理 | 提供新人/老用户判断、用户标签及邮箱匹配数据 |
| 商品系统 | 提供商品与品类归属 |
| 售后域 | 提供政策配置、售后入口判断、建单及原因码快照 |
| Market | 提供业务时区和币种 |

### 3.2 风险

| 风险 | 应对 |
|---|---|
| 相同优先级多条政策同时命中 | 上线前确定最终裁决规则；系统不得随机选择 |
| 订单链路新增快照写入影响下单稳定性 | 联调覆盖成功、失败、重试及重复事件场景 |
| 用户标签变化导致历史权益变化 | 快照在下单时固化，后续标签变化不回溯 |
| 历史订单无快照 | 保留历史兼容补记逻辑并明确来源 |
| 新旧物流退回原因码并存 | 不自动替换旧码；运营手册明确新码使用入口 |

- 售后政策配置和列表调整。

## 五、验收标准

### 5.1 政策配置与匹配

| 编号 | 场景 | 前置条件 | 预期结果 |
|---|---|---|---|
| AC-P01 | 日常政策 | 下单时间不在任何活动区间 | 命中日常政策，快照时效为 15 天 |
| AC-P02 | 黑五开始边界 | 下单时间等于活动开始时间 | 命中黑五政策，快照时效为 30 天 |
| AC-P03 | 黑五结束边界 | 下单时间等于活动结束时间 | 不命中该活动政策 |
| AC-P04 | 时区 | 美国站订单处于活动边界 | 按美国站业务时区判断，不按服务器时区判断 |
| AC-P05 | 老用户预热 | 老用户符合适用用户条件且下单时间命中预热区间 | 命中 30 天政策 |
| AC-P06 | 用户不匹配 | 新用户下单时间命中仅面向老用户的活动区间 | 不进入该政策候选集合 |
| AC-P07 | 商品范围 | 商品同时命中全市场和指定品类政策 | 从全部候选政策中按全局优先级选择 |
| AC-P08 | 优先级 | 同时命中优先级 10 和 50 的政策 | 选择优先级 10 的政策 |
| AC-P09 | 停用政策 | 政策为停用 | 不参与新订单匹配 |
| AC-P10 | 不支持退货 | 最终政策不支持退货 | 订单商品行不可发起常规售后 |
