# 竞品专题：多语言翻译模块设计

## 一、功能对比总表

| 维度 | Amazon | Temu | SHEIN | Shopify |
|------|--------|------|-------|---------|
| **平台模式** | 三方卖家自运营 | 全托管/半托管 | 自营+三方Marketplace | SaaS建站工具 |
| **翻译主体** | 卖家负责（平台提供工具辅助） | 平台全权负责 | 平台负责（自营）/ 平台辅助（三方） | 商家负责（平台提供框架+生态） |
| **翻译方式** | 机器翻译（BIL工具）+ 人工服务商 | 平台AI自动翻译 | 机器翻译+人工本地化团队 | AI自动翻译 + 手动编辑 + 三方App |
| **卖家输入语言** | 任意（通常为母语） | 中文/英文（平台翻译到目标语言） | 英文（US Marketplace） | 商家自定默认语言 |
| **支持语言数** | 20+站点对应语言 | 70+国家/地区语言 | 150+国家/地区语言 | 理论无限（取决于App） |
| **翻译粒度** | 标题/五点/描述/关键词 | 全站内容（商品+UI+营销） | 全站内容 | 商品/集合/页面/博客/政策/结账 |
| **SEO本地化** | 卖家自行优化关键词 | 平台统一处理 | 平台统一处理 | 商家通过App处理（hreflang/URL slug） |
| **翻译质量控制** | 卖家自审/付费人工校对 | 平台内部QA | 专职本地化团队+AI | 商家自审/侧边栏对照编辑器 |
| **翻译覆盖内容** | 仅商品listing | 商品+平台UI+营销+客服 | 商品+平台UI+营销+客服 | 商家可控的所有内容 |
| **费用** | BIL免费；人工翻译按词/按listing收费 | 卖家免费（平台承担） | 卖家免费（平台承担） | Translate&Adapt免费（2语言自动）；三方App付费 |
| **技术架构** | 按站点隔离（每个站独立listing） | 中心化翻译引擎 | 中心化翻译引擎 | Translation API + 三方App生态 |
| **商家端体验** | 需主动操作BIL工具/找服务商 | 零操作（全托管） | 低操作（按模板上传即可） | 自主度高，需自行配置 |

## 二、各平台详细分析

### 2.1 Amazon

**翻译机制：**
- **Build International Listings (BIL)**：卖家在 Seller Central 中指定"源站点"，选择"目标站点"，工具自动同步 offer 并尝试机器翻译商品详情页
- BIL 本质是 offer 同步工具 + 附带机器翻译，不是专业翻译服务
- 机器翻译覆盖：标题、五点描述、商品描述
- 价格自动按汇率换算，支持百分比/固定金额加价

**卖家操作流程：**
1. 在各目标站点注册账号
2. 在 Seller Central → Inventory → Sell Globally 启用 BIL
3. 选择源站点和目标站点
4. 系统自动翻译并创建 listing（约4小时生效）
5. 卖家可手动覆盖翻译内容

**质量问题：**
- 机器翻译关键词选择不准确，影响搜索排名
- 缺乏方言/文化适配
- 可读性差，转化率低
- Amazon 官方建议：机器翻译做初稿，再找 Service Provider Network 中的专业翻译服务商优化

**核心特点：**
- 按站点隔离架构（每个国家是独立站点，listing 独立存在）
- 卖家对翻译有完全控制权
- 平台不保证翻译质量，责任在卖家

---

### 2.2 Temu

**翻译机制：**
- **全托管模式**：卖家提交中文/英文商品信息，平台AI自动翻译到所有目标市场语言
- 卖家无需关心翻译，也无法干预翻译结果
- 平台统一处理：商品标题、描述、规格参数、营销文案、UI界面、客服话术

**卖家操作流程：**
1. 在 Temu Seller Center 上传商品（中文或英文）
2. 平台自动翻译到70+国家/地区语言
3. 卖家无翻译相关操作

**技术特点：**
- 中心化翻译引擎，统一管理所有语言版本
- AI驱动，结合市场数据实时调整
- 翻译与商品上架流程完全解耦（卖家感知不到翻译环节）

**核心特点：**
- 卖家零成本、零操作
- 翻译质量由平台兜底
- 卖家无法自定义翻译（牺牲灵活性换取效率）
- 部分卖家通过第三方代运营服务优化listing质量

---

### 2.3 SHEIN

**翻译机制：**
- **自营商品**：内部本地化团队 + AI翻译，覆盖150+国家
- **三方Marketplace**：卖家用英文上传（US Marketplace），平台负责翻译到其他语言
- 翻译策略混合使用：直译、意译、本地化适配（学术研究确认）
- 有专职 Localization 岗位负责质量把控

**卖家操作流程（Marketplace）：**
1. 在 seller-us.shein.com 注册
2. 按模板上传英文商品信息
3. 平台自动处理多语言翻译
4. 卖家无需额外操作

**技术特点：**
- 中心化翻译引擎
- AI翻译 + 人工审校混合模式
- 针对不同市场做文化适配（如节日氛围、营销话术本地化）
- 翻译覆盖：商品信息、平台UI、营销活动、推送通知

**核心特点：**
- 平台强控制，保证品牌一致性
- 翻译质量高于纯机器翻译（有人工介入）
- 三方卖家只需提供英文内容
- 学术研究指出仍存在机器翻译质量不足的问题

---

### 2.4 Shopify

**翻译机制：**
- **平台层**：提供 Translation API（GraphQL）作为基础设施
- **官方App**：Translate & Adapt（免费），支持2种语言自动翻译 + 无限手动翻译
- **三方App生态**：Weglot、LangShop、T Lab、BulkTranslate 等数十款翻译App
- 商家拥有完全控制权

**Translate & Adapt 功能：**
- 免费，Shopify官方出品
- 自动翻译：最多2种语言（AI翻译）
- 手动翻译：无限语言，侧边栏对照编辑器
- 内容适配：同语言不同市场的内容差异化（如美式英语 vs 英式英语）
- SEO：URL slug翻译 + hreflang标签自动生成
- 覆盖：商品、集合、博客、政策页、结账页

**Translate & Adapt 局限：**
- 自动翻译仅限2种语言
- 年度字符上限1亿
- 无术语表/品牌词典功能
- 不支持图片内文字翻译
- 新内容不会自动触发翻译（需手动）
- 切换默认语言会清空已有翻译
- 不兼容未接入Translation API的三方App

**Translation API 技术架构：**
- GraphQL Admin API
- TranslatableResource 查询：获取可翻译字段（key、value、digest）
- 支持的资源类型：Product、Collection、Page、Blog、EmailTemplate、Metaobject、Metafield 等
- 三方App通过API读取可翻译内容 → 调用翻译引擎（DeepL/GPT-4等）→ 写回翻译结果
- 主题层通过 Liquid `{% if %}` 条件渲染多语言内容

**核心特点：**
- 开放生态，商家自主选择翻译方案
- API标准化，三方App可无缝集成
- 商家对翻译质量负全责
- 适合有本地化团队或预算的品牌商家

## 三、共性总结

| 共性维度 | 说明 |
|---------|------|
| **AI/机器翻译为基础** | 4家都以机器翻译作为基础能力，降低翻译成本和门槛 |
| **商品信息是核心翻译对象** | 标题、描述、规格参数是所有平台必翻内容 |
| **翻译质量仍是痛点** | 纯机器翻译的转化率、可读性、SEO效果普遍不如人工 |
| **本地化 > 翻译** | 各平台都在从"语言翻译"走向"市场本地化"（关键词、文化、度量衡、货币） |
| **卖家端趋向低操作** | 趋势是平台承担更多翻译工作，降低卖家门槛 |
| **按市场/国家组织内容** | 翻译内容最终按目标市场维度存储和展示 |

## 四、核心差异

| 差异维度 | 平台托管型（Temu/SHEIN） | 卖家自主型（Amazon/Shopify） |
|---------|------------------------|--------------------------|
| **翻译控制权** | 平台全权控制 | 卖家可覆盖/自定义 |
| **翻译成本** | 平台承担 | 卖家承担（或使用免费工具） |
| **质量保证** | 平台兜底 | 卖家自负 |
| **灵活性** | 低（无法干预） | 高（完全可控） |
| **适用场景** | 中小卖家快速出海 | 品牌商家精细化运营 |
| **SEO优化** | 平台统一策略 | 卖家自行优化 |
| **术语一致性** | 平台统一管理 | 卖家自行维护 |

## 五、looply 建议

### 值得借鉴

1. **Shopify 的 Translation API 架构**：标准化的可翻译资源模型（TranslatableResource），字段级翻译粒度，适合 looply 作为平台的技术底座设计
2. **Temu 的"卖家零操作"体验**：looply 作为 B2C 平台，应尽量降低商家翻译门槛，平台提供自动翻译兜底
3. **Amazon 的"卖家可覆盖"机制**：允许商家对自动翻译结果进行人工覆盖，兼顾效率和质量
4. **SHEIN 的混合翻译策略**：AI翻译做初稿 + 关键内容人工审校，平衡成本和质量
5. **Shopify 的侧边栏对照编辑器**：商家手动编辑翻译时的最佳交互模式

### 要避开的

1. **Amazon 的"按站点隔离"架构**：每个国家独立listing，管理成本高，不适合 looply 的统一平台模式
2. **Shopify Translate & Adapt 的"新内容不自动翻译"**：商品上架后应自动触发翻译，不能依赖手动
3. **Temu 的"卖家完全无法干预"**：品牌商家需要对翻译有一定控制权，尤其是品牌名、专业术语
4. **纯机器翻译无审校**：Amazon BIL 的翻译质量问题已被广泛吐槽，不能只靠机器

### 差异化机会

1. **"平台兜底 + 商家可覆盖"混合模式**：默认AI自动翻译（卖家零操作），但允许商家对任意字段手动覆盖翻译
2. **品牌术语表**：商家可维护品牌专属术语表（品牌名、产品线名、专业术语），翻译引擎优先使用术语表
3. **翻译质量分级**：区分"机器翻译"和"人工审校"状态，关键内容（标题、首屏描述）优先人工审校
4. **二手商品特有翻译**：质检报告、瑕疵描述、成色等级等二手特有内容的标准化翻译模板
5. **多渠道翻译同步**：looply 支持多渠道销售（线上/门店/三方平台），翻译内容可按渠道差异化适配

## 六、looply 翻译模块初步设计方向（待确认）

基于竞品分析，建议 looply 翻译模块采用以下设计方向：

```
┌─────────────────────────────────────────────────┐
│              翻译模块架构方向                      │
├─────────────────────────────────────────────────┤
│                                                 │
│  商家端体验：                                    │
│  ├─ 默认：上传商品时只需填写一种语言              │
│  ├─ 平台自动翻译到所有目标市场语言               │
│  ├─ 商家可选：手动覆盖任意字段的翻译             │
│  └─ 商家可选：维护品牌术语表                     │
│                                                 │
│  平台能力：                                      │
│  ├─ 翻译引擎：AI翻译（主）+ 人工审校（辅）       │
│  ├─ 翻译粒度：字段级（标题/描述/规格/质检报告）   │
│  ├─ 翻译状态：未翻译/机器翻译/人工审校/商家覆盖   │
│  ├─ 术语管理：平台术语表 + 商家术语表            │
│  └─ 翻译触发：商品上架自动触发，内容变更自动重翻  │
│                                                 │
│  技术底座：                                      │
│  ├─ 可翻译资源模型（参考Shopify TranslatableResource）│
│  ├─ 按市场维度存储翻译内容                       │
│  ├─ 翻译API（支持三方翻译服务接入）              │
│  └─ 翻译缓存 + 增量翻译（只翻变更字段）          │
│                                                 │
└─────────────────────────────────────────────────┘
```
