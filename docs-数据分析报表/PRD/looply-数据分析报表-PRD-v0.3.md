# Looply 数据分析报表 PRD

> 版本：v0.3  
> 日期：2026-08-26  
> 状态：产品工作稿；用于重新定义五模块数据分析需求，不代表所有数据已经接入  
> 适用页面：Looply C 端数据报表后台（PC Web）  
> 正式入口：`http://127.0.0.1:8767/dashboard`

## 一、概述

### 1.1 背景与目标

当前 Looply 已形成一套包含数据总览、获客、搜索与推荐、站内参与和成交归因的本地 Dashboard。现有报表文档与正式 Demo 的迭代时间不同，部分指标已有 GA4 真实数据，部分仅完成页面结构，订单、支付、退款、售后及一方链路仍有未接入项。

本 PRD 以当前正式 Dashboard 的五个一级模块和最新机器生成页面为展示基线，重新收口以下内容：

1. 每个模块回答的业务问题；
2. 指标、维度、统计对象与计算关系；
3. 公共筛选、页面关系、主表与下钻；
4. 已接入、部分接入、未接入、空数据和异常状态；
5. 与数据来源和采集方案的边界。

本 PRD 定义报表最终需要表达的业务结果。指标数据来源与采集影响分别由《报表指标与数据来源对照表》《数据分析需求对采集方案影响评估》承接。

### 1.2 当前版本边界

当前版本包含五个一级模块：

1. 数据总览；
2. 获客与渠道表现；
3. 搜索与推荐效果；
4. 站内使用与参与；
5. 成交归因。

独立生成的“Checkout 与订单交易”页面未进入正式 Dashboard 五模块菜单，本版本不将其扩成第六个一级模块。Checkout、订单、支付、退款和售后数据作为数据总览、成交归因及后续按需下钻的数据来源。

本版本不建设 App 报表、多触点贡献度、数据驱动归因、推荐增量实验或用户级完整旅程页面。未写入本 PRD 的平级报表默认不属于本版本。

### 1.3 用户角色

| 角色 | 主要任务 |
|---|---|
| 业务负责人 | 判断经营规模、用户质量、成交结果和主要问题方向 |
| 产品／运营 | 定位获客、搜索、推荐、页面使用和用户意向问题 |
| 市场投放 | 比较首次获客质量、站外订单归因、成本和 ROAS |
| 搜推团队 | 分析搜索供给、搜索承接和推荐模块效果 |
| 数据／研发 | 核对数据状态、来源、链路断点和口径一致性 |

### 1.4 核心分析对象

| 分析对象 | 稳定标识／统计单位 | 主要使用模块 |
|---|---|---|
| GA4 用户 | GA4 Reporting Identity 下的去重用户 | 获客、站内使用、当前 GA4 汇总 |
| Looply 匿名访客 | `anonymous_id` | 一方用户行为、跨事件关联 |
| Looply 登录用户 | 内部用户 ID | 新客 Cohort、跨设备确定性关联、订单关联 |
| GA4 Session | GA4 自动 Session | GA4 官方互动与交叉校验 |
| Looply 一方 Session | `session_id` | 用户旅程、站内链路和成交回指 |
| 搜索提交／结果上下文 | `search`事件、结果事件`event_id`、结果页`page_instance_id`及URL搜索上下文 | 搜索次数、结果状态、搜索词和后续承接 |
| 推荐请求／曝光 | 推荐请求 ID、曝光事实、商品标识 | 推荐曝光、点击和模块效果 |
| 商品／上架商品 | `product_id`、`listing_id`、`listing_public_code` | 搜索、推荐、意向和订单商品关联 |
| 订单 | `order_id` | 成交规模、站外归因、售后与退款关联 |
| 订单商品行 | `order_item_id` | 站内订单归因与商品级金额 |
| 支付尝试 | 支付尝试 ID | 支付漏斗与失败诊断；本版不设一级页面 |
| 退款／售后单 | 退款 ID、售后单 ID | 数据总览中的售后与退款结果 |

```text
Looply C 端数据报表
├─ 数据总览
├─ 获客与渠道表现
├─ 搜索与推荐效果
```

## 二、公共报表规则

### 2.1 公共筛选

| 筛选项 | 默认值 | 作用范围 | 规则 |
|---|---|---|---|
| 统计周期 | 最近 7 个完整自然日 | 五个模块 | 不包含当天；获客当前查询上限为 T-2 |
| 对比 | 上一等长周期 | 支持对比的模块 | 周期等长、相邻且不重叠；未取得时显示“—” |
| 国家／地区 | 全部 | 五个模块 | 支持多选；同维度 OR |
| 设备类别 | 全部 | 五个模块 | Desktop、Mobile、Tablet；同维度 OR |
| 时间粒度 | 日 | 各业务主表 | 支持日／周／月；人数按对应周期重新去重，比例重算分子分母 |
| 新客观察窗口 | 7 天 | 获客模块 | 7 天、30 天、累计；与首次到访日期范围分开 |
| 归因方式 | 末次来源 | 站外订单归因 | 首次来源、末次来源；切换后整张主表重算 |

不同筛选维度之间使用 AND。公共筛选只改变当前分析范围，不改写原始数据。

### 2.2 时间与去重

- 原始事件保留 UTC 发生时间，报表按统一业务时区切分日、周、月。
- 当前 GA4 属性时区为 `America/New_York`；是否作为长期业务时区仍需产品／数据确认。
- 人数和 Session 数按所选周期整体去重，不由日值相加。
- 事件次数先按`event_id`去重；GA4当前仅有聚合时明确标注无法核验事件级去重。
- 成交指标按订单首次支付成功时间统计。
- 售后和退款指标按订单创建 Cohort 圈定订单，并以所选周期结束日作为观察截止日。
- 一方首次识别和一方 Session 均为派生事实，不主动新增 `first_visit` 或 `session_start` 统一事件；GA4 可继续使用其自动平台口径。

### 2.3 数据状态

| 状态 | 页面展示 |
|---|---|
| 已接入 | 展示真实值、来源和最近更新时间 |
| 部分接入 | 已取得项展示真实值；缺失项显示“— / 未接入”并说明缺口 |
| 未接入 | 展示结构和所需数据，不填 0 或示例经营数 |
| 数据为 0 | 仅在查询成功且来源完整时展示 0 |
| 无符合条件数据 | 展示空状态和当前筛选条件 |
| 加载中 | 保留页面骨架和筛选；仅结果区加载 |
| 查询失败 | 优先保留上一份已验证结果，展示其更新时间、失败提示和重试入口 |
| 数据处理中 | 标明 GA4 T-1／T-2 或回补风险，不把低值解释为最终结果 |
| 运行态异常 | 明确标记页面未完成加载，不把静态副本当作运行态通过 |

单个模块失败只降级该模块，其余成功模块继续展示。页面框架或全部内容不可用时才使用整页错误状态。

### 2.4 主视图与去重

- 数据总览是全站经营规模、关键行为覆盖和成交售后结果的唯一概览主视图。
- 获客模块只回答首次来源规模与新客质量，不重复建设订单归因。
- 搜索与推荐模块只回答找货效率；成交结果集中在成交归因页。
- 站内使用与参与的页面主表、功能主表分别回答页面使用和功能覆盖，不替代严格漏斗。
- 成交归因页保留站外、站内两张主表；站内搜索、推荐、收藏不再拆平级归因表。

## 三、需求详细描述

### 3.1 数据总览

**3.1.1 业务问题**

回答全站经营规模、用户关键行为覆盖、成交产出和售后退款影响是否发生变化。

**3.1.2 页面结构**

1. 订单目标与趋势；
2. 站内关键行为表现；
3. 成交与售后结果。

网站访客与购买转化双轴趋势作为关键行为的辅助趋势展示，不新增第四个平级主区。

**3.1.3 订单目标与趋势**

| 指标 | 统计对象 | 口径 | 维度／交互 |
|---|---|---|---|
| 周期结束日成交订单数 | 订单 | 周期最后一天 GA4 `ecommercePurchases`；完成订单对账前保留 GA4 口径说明 | 结束日 |
| 每日目标完成度 | 订单 | 周期结束日成交订单数 ÷ 每日目标 | Demo 当前配置为 100 单／天；业务目标审批状态待确认 |
| 近 7 日平均成交订单数 | 订单 | 截至周期结束日最近 7 个自然日每日成交订单数算术平均 | 固定 7 日 |
| 近 7 日平均目标完成度 | 订单 | 近 7 日平均成交订单数 ÷ 每日目标 | 固定 7 日 |
| 成交订单趋势 | 订单 | 日／周／月对应周期的成交订单数 | 粒度切换；目标线仅用于日 |

**3.1.4 站内关键行为表现**

支持“访客／Session”统计对象切换。各行是独立行为覆盖，不解释为同一批对象严格依次完成的漏斗。

| 指标 | 访客口径 | Session 口径 |
|---|---|---|
| 网站访问基准 | 发生 `page_view` 的去重访客 | 包含 `page_view` 的去重 Session |
| 商详渗透率 | `view_item` 去重访客 ÷ 网站访客 | 包含 `view_item` 的 Session ÷ 网站访问 Session |
| 购买意向渗透率 | 收藏或加购访客并集 ÷ 网站访客 | 包含收藏或加购的 Session 并集 ÷ 网站访问 Session |
| Checkout 渗透率 | `begin_checkout` 去重访客 ÷ 网站访客 | 包含 `begin_checkout` 的 Session ÷ 网站访问 Session |
| 购买转化率 | `purchase` 去重访客 ÷ 网站访客 | 回指成交的原始 Session ÷ 网站访问 Session |

收藏未接入期间，页面只展示真实加购覆盖并标注“仅加购口径”，不命名为完整购买意向并集。

**3.1.5 成交与售后结果**

| 指标 | 统计对象 | 口径 |
|---|---|---|
| 成交订单数 | 订单 | 所选成交时间周期内首次支付成功的去重订单数 |
| 客单价 | 订单 | 总成交金额 ÷ 成交订单数 |
| 总成交金额 | 订单 | 首次支付成功时退款前成交金额合计 |
| 已完成售后订单数 | 订单 | 订单创建 Cohort 中截至周期结束日至少一笔售后进入完成终态的去重订单数 |
| 售后率 | 订单 | 已完成售后订单数 ÷ 同一订单创建 Cohort 订单数 |
| 退款订单数 | 订单 | 同一 Cohort 中截至截止日至少发生一笔实际完成退款的去重订单数 |
| 退款率 | 订单 | 退款订单数 ÷ 同一订单创建 Cohort 订单数 |
| 退款金额 | 退款 | 同一 Cohort 截至截止日实际完成退款金额累计 |
| 退款金额占成交金额比例 | 订单／退款 | 退款金额 ÷ 同一 Cohort 总成交金额 |

售后完成与实际退款是两类独立事实。拒绝结案属于已完成售后，但未发生资金退回时不计退款。

**辅助趋势：访客与购买转化**

在同一张双轴图中展示每日网站访客和每日购买转化率。两轴从 0 开始，共享日期和 Tooltip。该图仅提供概览，不替代站内关键行为主表。

### 3.2 获客与渠道表现

**3.2.1 业务问题**

回答用户首次从哪里来，各首次渠道带来的新客规模与后续购买质量如何，以及新客分布在哪些国家、州和城市。

**3.2.2 页面结构**

1. 首次获客渠道表现主表；
2. Organic Social 表内平台下钻；
3. 来源／媒介分期表现；
4. 地理地图按需下钻；
5. 首次渠道说明。

首次来源／媒介质量平级表当前隐藏；底层原始明细保留用于来源说明和后续下钻。

**3.2.3 首次获客渠道主表**

所选日期先圈定首次到访新客 Cohort，再观察这批新客在 7 天、30 天或累计窗口内的购买结果。

| 指标／维度 | 统计对象 | 口径 |
|---|---|---|
| 首次默认渠道组 | 新用户 | GA4 `firstUserDefaultChannelGroup`；Looply 中文名称仅用于展示 |
| 新用户数 | 新用户 | 所选首次到访周期内的 `newUsers` |
| 新用户占比 | 新用户 | 当前渠道新用户 ÷ 全渠道新用户 |
| 新客购买率 | 新用户 | 观察窗口内完成购买的 Cohort 去重新用户 ÷ Cohort 新用户 |
| 成交订单数 | 订单 | 当前 Cohort 在观察窗口内产生的成交订单数 |
| 成交收入 | 订单 | 当前 Cohort 在观察窗口内产生的退款前成交收入 |
| 成交客单价 | 订单 | Cohort 成交收入 ÷ Cohort 成交订单数 |

固定观察窗口未走满时展示“观察中”。累计窗口截止到查询结束时间。

**3.2.4 Organic Social 表内下钻**

Organic Social 主行支持展开 Instagram、TikTok、Facebook、其他社媒。子行只在 Organic Social 范围内按原始 source／medium 归并；主行保持 GA4 官方总计。子行新用户占比以 Organic Social 新用户为分母，主行以全渠道新用户为分母。子行合计与主行不一致时展示质量提示，不静默调平。

**3.2.5 来源分期与地理下钻**

- 来源分期支持日／周／月，展示新用户数、购买率和成交客单价；人数按对应周期直接查询。
- 地理默认展示国家分布；点击美国后下钻 Region／州，再按需加载城市。
- 国家、州、城市人数分别去重，城市人数不得相加还原国家人数。
- 非美国访客占比使用独立排除美国的查询，不用 `100% - 美国占比` 反推。

**3.2.6 当前运行状态**

最新机器副本已取得渠道组、新用户和 Cohort 购买质量数据。正式 Dashboard 的获客模块本次运行态按需加载未完成，页面验收状态为“结构和数据副本可核，正式运行态待修复”。搜索与推荐、站内使用与参与、成交归因也未在本次运行态成功加载，均不能宣称完成视觉与交互验收。

### 3.3 搜索与推荐效果

**3.3.1 业务问题**

回答用户能否通过主动搜索或推荐找到感兴趣的商品，问题发生在搜索供给、结果承接、意向形成还是具体推荐模块。

**3.3.2 页面关系**

页面顶部使用“搜索效果／推荐效果”一级切换，不再设置重复的“找货方式”筛选。

搜索效果固定结构为：搜索明细表 → 搜索触发方式表现 → 搜索词诊断。搜索入口表现当前隐藏，不再保留依赖单次搜索关联ID的请求漏斗。

推荐效果固定结构为：推荐明细表 → 商品发现入口表现。成交订单明细统一进入成交归因页；本页只保留入口级归因购买用户数和订单数，用于衡量入口效果，不重复展示订单明细。

**3.3.3 搜索明细表**

| 指标 | 统计对象 | 口径 |
|---|---|---|
| 搜索商详到达率 | 访客 | 搜索归因商详访客 ÷ 搜索访客 |
| 无结果率 | 结果事件 | `result_status=no_results`的`view_search_results`事件数 ÷（`success`＋`no_results`的`view_search_results`事件数）；不得除以`search`提交数 |
| 搜索意向形成率 | 访客 | 搜索归因收藏／加购访客并集 ÷ 搜索归因商详访客 |
| 搜索访客 | 访客 | 周期内至少提交一次搜索的去重访客 |
| 搜索渗透率 | 访客 | 搜索访客 ÷ 网站访客 |
| 搜索次数 | 搜索提交 | 去重`search`事件的`event_id`数；GA4聚合只提供事件次数时按`eventCount`展示 |
| 人均搜索次数 | 访客／请求 | 搜索次数 ÷ 搜索访客 |

**3.3.4 搜索事件与来源链路**

搜索提交规模、结果页状态和后续商品来源链路分别统计，不使用`search_id`，也不强制把`search`与`view_search_results`按单次请求一一配对。

提交规模：用户正式提交搜索形成`search`。  
结果状态：初始结果及筛选／排序后的每次结果更新分别形成一条`view_search_results`，由`event_id`区分并记录`success`、`no_results`、`failed`或`cancelled`。  
访客链路：搜索访客 → 有结果访客 → 搜索归因商详访客 → 搜索归因意向访客 → 搜索归因购买访客。

搜索结果中的商品点击形成`item_click`，进入商详形成`view_item`，商详后的收藏／加购沿用来源链路。同一Session多次搜索同一商品时，后续商详和意向归给行为发生前最近一次、确实点击过该商品的搜索结果点击。关联使用用户、Session、`listing_public_code`、`source_event_id`、来源结果页`page_instance_id`、URL结构化搜索上下文和事件时间。购买只作为找货质量下游信号，订单和金额集中在成交归因。

**3.3.5 搜索明细与诊断**

搜索明细支持日／周／月，至少展示搜索访客、搜索次数、有结果／无结果、商详到达和意向形成。搜索触发方式按稳定枚举比较手动输入、历史搜索、搜索建议、猜你想搜和热门搜索；具体枚举仍需与搜索产品字典对齐。

搜索词诊断按清洗和标准化后的搜索词聚合。搜索访客数和搜索次数来自`search`；无结果搜索次数、无结果率和无结果贡献度来自同一搜索词下的`view_search_results`结果事件；结果点击率按搜索结果商品点击次数 ÷ 搜索结果商品有效曝光次数计算；商品详情访客数、搜索商详到达率和收藏／加购访客数按商品来源链路计算。各项指标不依赖`search_id`。

**3.3.6 商品发现入口表现**

| 指标 | 统计对象 | 口径 |
|---|---|---|
| 曝光商品数 | 商品 | 周期内该入口产生有效商品曝光的去重`listing_public_code`数 |
| 曝光用户数 | 访客 | 周期内在该入口至少有效曝光一个商品的联合去重用户数 |
| 兴趣用户数 | 访客 | 对该入口已曝光商品发生点击、收藏或加购的联合去重用户数 |
| 用户兴趣率 | 访客 | 兴趣用户数 ÷ 曝光用户数 |
| 归因购买用户数 | 购买用户 | 按已确认的站内订单商品归因规则归因到该入口的去重购买用户数 |
| 归因订单数 | 订单 | 按已确认的站内订单商品归因规则归因到该入口的去重`order_id`数 |
| 购买用户转化率 | 访客 | 归因购买用户数 ÷ 曝光用户数 |
| 人均归因订单数 | 访客／订单 | 归因订单数 ÷ 曝光用户数；不得命名为“订单转化率” |

商品发现入口表现以入口为行，首期固定为：首页Feed、Collection、商详You May Also Like、搜索热词。入口由采集PRD第6.2节定义的`entry_type`派生；原始事件仍使用`page_id`、`module_id`、`scene_id`、`entry_context`及关联ID。

- 首页Feed可按实际`scene_id`继续下钻For You、New Arrivals等场景。
- 商详推荐只包含You May Also Like，不与Recently Viewed混合。
- 搜索热词的曝光用户必须先通过`trigger_type=popular_term_select`进入结果页，再在该结果页`page_instance_id`下产生有效商品曝光；仅看到或点击热词但没有商品曝光的用户不计入曝光用户。
- 人数和商品数均在用户选择的完整周期内整体去重，不得将每日去重结果相加得到周或月结果。
- 同一商品可在多个入口分别产生曝光；购买结果按已确认的站内订单商品归因规则最终只归入一个入口。

当前商品发现入口经营指标尚未接入，页面只能展示结构和“— / 未接入”，不得宣称已有运行数据。

### 3.4 站内使用与参与

**3.4.1 业务问题**

回答用户进入网站后是否真正开始使用、使用了哪些页面和能力，以及使用深度如何。

**3.4.2 GA4 官方互动报表**

| 指标 | 统计对象 | 口径 |
|---|---|---|
| 活跃用户数 | GA4 用户 | GA4 `activeUsers` |
| 感兴趣的会话数 | GA4 Session | GA4 `engagedSessions` |
| 感兴趣的会话占比 | GA4 Session | `engagedSessions ÷ sessions` |
| 每位活跃用户感兴趣会话数 | 用户／Session | `engagedSessions ÷ activeUsers` |
| 每位活跃用户平均互动时长 | 用户／时长 | `userEngagementDuration ÷ activeUsers` |

日、周、月均由 GA4 对对应周期直接计算。最近一天可能回补时提示优先使用 T-2 复核。

**3.4.3 页面使用表现**

主维度为页面标题／路径，支持标题或路径搜索、日／周／月切换和网站访客数排序。

| 指标 | 口径 |
|---|---|
| 网站访客数 | 当前页面维度下的 GA4 `totalUsers` |
| 浏览次数 | `screenPageViews` |
| 人均浏览次数 | 浏览次数 ÷ 页面网站访客数 |
| 平均互动时长 | 页面 `userEngagementDuration ÷ 页面网站访客数` |

自有平台同时需要稳定 `page_type`、`page_id`、`page_version`，避免长期只依赖标题与路径。

**3.4.4 功能使用明细**

行为行包括搜索、浏览商详、收藏、加购、开始 Checkout、购买。每个行为展示去重访客数、行为覆盖率、事件次数、使用者人均次数和访客趋势。

收藏未接入时收藏行显示“— / 未接入”；加购保持真实值，不合并为完整意向指标。本表是独立功能覆盖与使用深度，不解释为严格漏斗。

### 3.5 成交归因

**3.5.1 业务问题**

站外订单归因回答哪一次站外首次或末次非 Direct 触点促成订单；站内订单归因回答订单商品由哪个站内找货入口／模块促成，以及成交前末次关键动作是什么。

**3.5.2 站外订单归因**

统计对象为 `order_id`。支持首次来源和末次来源两种方式；存在非 Direct 时忽略 Direct，全部历史只有 Direct 时归 Direct，订单、身份或触点无法关联时归“无法归因”。不设置固定回溯天数，以仍在合规留存期内的可关联历史触点为准。

主表维度：日期／周／月、渠道、来源／媒介、Campaign。  
主表指标：归因订单数、归因成交金额、成交金额占比、花费、成交订单成本、ROAS。

当前首次／末次历史触点、广告花费和订单系统权威对账尚未接入。成交 Session 来源不能代填首次或末次历史触点。

**3.5.3 站内订单归因**

统计对象为 `order_item_id`，保留 `order_id` 和商品三 ID。成交前回看 30 个自然日，同一确定用户、同一商品的有效商品点击和收藏参与候选，取最近一次。商品曝光、加购、Checkout 和商详页面本身不作为候选来源。

页面只保留一张统一主表：

| 字段 | 说明 |
|---|---|
| 日期／周／月份 | 按成交时间和所选粒度 |
| 归因来源类型 | 搜索、推荐、首页非推荐、类目／品牌、活动／专题、站内来源未知 |
| 具体入口／模块 | 搜索入口／触发方式／搜索词、推荐模块或其他找货入口 |
| 来源细分 | Feed Tab、页面场景、展示位置等 |
| 末次关键动作 | 商品点击或收藏 |
| 动作发生页面 | 动作实际发生页，不替代归因来源 |
| 归因订单数 | 当前维度按 `order_id` 去重；跨来源可能重叠 |
| 归因订单商品数 | 成功归因的去重 `order_item_id` 数 |
| 归因成交金额 | 订单商品退款前成交金额 |
| 成交金额占比 | 当前维度金额 ÷ 全部成功归因订单商品金额 |
| 成交转化率 | 触点访客中 30 天内购买同一商品的去重访客比例 |
| 客单价 | 归因成交金额 ÷ 当前维度归因订单数 |

收藏发生在商详时继续回溯把用户带入商详的原找货来源；无法确定时标记站内来源未知。取消收藏不撤销历史收藏触点。

当前站内订单商品级数据未接入，主表展示结构和缺失态，不生成示例经营数。

无前序站内来源的商详成交究竟归为“直接商详”还是“站内来源未知”，当前总方案与成交归因 PRD 不一致，本稿暂归为“站内来源未知”并列入产品待确认；确认前不得据此改写归因枚举。

### 8.2 PRD 验收要点

- 五个一级模块与正式 Dashboard 菜单一致；
- “浏览与找货效率”统一映射为“搜索与推荐效果”；

- 无前序来源的直接商详归为独立来源还是站内来源未知，保留为产品待确认；
- 本 PRD 完成不会自动修改四份数据采集基线。
