# Looply C 端订单列表页 & 订单详情页 PRD v1.5

> 买家侧"我的订单"列表页 + 订单详情页完整需求定义
>
> Version 1.5 · 2026-07-19 · 面向：前端 / 后端开发

---

## 一、概述

### 1.1 背景与目标

本 PRD 定义买家在 looply 平台查看已购订单的完整体验，包含"我的订单"列表页和单笔订单详情页（含物流追踪、退款详情）。

**核心目标：**

- 让买家清晰查看所有历史订单及其当前状态
- 按状态筛选快速定位目标订单
- 在详情页内查看完整订单信息：商品、物流、支付、退款
- 物流追踪和退款详情通过弹窗/底部抽屉展示，减少页面跳转
- PC 和 APP 双端适配，体验一致

### 1.2 前置依赖

| 依赖模块 | 说明 |
|---------|------|
| 订单状态模型 | 引用《looply 订单支付 PRD v1.2》第二章分层状态模型（待付款态在 parent_order.parent_status，支付后拆子订单） |
| 订单快照（下单落库） | **商品信息（名称/品牌/成色）、收货地址等「下单时点确定的内容」由订单模块在下单流程冻结落库、并记录下单语言 snapshot_lang（对订单模块的接口依赖，见 §1.5）。本页面消费快照展示，不实时回查商品/翻译/字典** |
| checkout_session | **提交订单未支付时，订单（parent_order）与结算会话（checkout_session）并存、作用不同：会话仅支付成功后真实有效；订单用于提前锁定库存/发起支付。二者不冲突、无需二选一** |
| 支付渠道 | 引用《支付渠道对接集成说明文档 v1.0》 |
| 物流管理 | 物流轨迹数据由物流模块提供（物流轨迹页面属他人负责项目，本 PRD 不定义其时区/展示规则） |
| 用户管理 | 登录态、地址管理 |

### 1.3 术语说明

引用《looply 订单支付 PRD v1.1》1.6 术语说明，本文档额外定义：

| 术语 | 说明 |
|------|------|
| 发货组（Fulfillment Group） | 一个订单可能分多个包裹发货，每个包裹对应一个发货组 |
| 物流状态卡 | 详情页内每个已发货包裹组顶部的物流信息卡片，展示最新物流动态 |
| 追踪弹窗 | 展示完整物流轨迹的模态弹窗（PC）或底部抽屉（APP） |
| 退款弹窗 | 展示单笔退款详细信息的模态弹窗（PC）或底部抽屉（APP） |
| 下单时间 | = `parent_order.created_at`（下单那一刻），列表/详情统一按此展示；子订单回溯父订单取值，不用 `order.created_at`（那是支付后拆单时间） |
| 时区 | C 端所有订单时间统一存 UTC、按买家浏览器本地时区渲染并标注（见 §1.4） |
| 快照语言（snapshot_lang） | 订单级字段，记录下单那一刻的语言。订单快照中的商品/地址等文本均按此语言冻结、展示时原样显示 |

### 1.4 时间与时区展示规则（全局）

适用于列表页与详情页的所有 C 端时间展示（下单时间、预计送达等）。

| 规则 | 说明 |
|------|------|
| 存储 | 后端统一存 UTC |
| 展示 | 前端按买家浏览器本地时区渲染，并标注时区（示例：`Jun 4, 2026 · 10:32 AM PT`）|
| 适用范围 | 仅订单模块自身产生的 C 端时间（下单时间、预计送达等） |
| 不含 | 物流轨迹页面属他人负责的项目，其时间/时区展示不在本 PRD 定义范围；物流事件时间保持物流服务返回值直接展示（见 §4.2.2） |

> 说明：经核实，商详 v1.6 / 购物车 v1.2 前台无面向 C 端的时间展示，故本期时区规则在订单模块内定义即可，不升格为全局规范；未来其他模块出现 C 端时间展示时再评估升格。

### 1.5 订单数据与快照依赖（对订单模块的字段要求）

本页面展示的商品/地址等内容一律读取「下单时冻结的订单快照」，不实时回查商品/翻译/字典，从根本上消除商品下架、改名、字典变更导致的漂移/丢失。以下为对订单模块实体（订单支付 ER）的字段依赖，需订单模块在下单流程落库：

**order_item（子订单商品行）：**

| 字段 | 用途 | 说明 |
|------|------|------|
| item_name | 展示（快照冻结） | 「下单语言冻结展示文本」，展示原样显示 |
| brand_snapshot | 展示（快照冻结） | 品牌冻结文本（如 "LOUIS VUITTON"） |
| brand_id | 引用（不展示） | 品牌非展示引用，仅跳转/统计 |
| condition_snapshot | 展示（快照冻结） | 成色冻结文本（如 "Very Good"） |
| condition_code | 引用（不展示） | 成色非展示引用 |
| listing_id | 引用（不展示） | 成交渠道商品（buyer 前台购买对象） |
| product_id | 引用（不展示） | 实物一物一码，退款/物流/鉴定用 —— **listing_id 与 product_id 两者都记录** |

**parent_order（父订单）：**

| 字段 | 用途 | 说明 |
|------|------|------|
| snapshot_lang | 元数据 | 下单语言，标明该单所有冻结文本的语言 |
| created_at | 展示 | 下单时间（列表/详情统一按此展示，见 §1.3） |

**快照内容分类（展示冻结 vs 附带引用）：**

| 快照内容 | 冻结存储（展示用） | 附带保留（仅跳转/统计，不展示） |
|---------|-------------------|------------------------------|
| 商品标题 | 冻结文本（下单时 listing_title） | listing_id + product_id（均记录） |
| 成色 | 冻结文本（如 Very Good） | condition_code |
| 品牌 | 冻结文本（如 LOUIS VUITTON） | brand_id |
| 类目 | （当前列表/详情不展示，可暂不加） | category_id |
| 收货地址 | 冻结文本（原文，不翻译） | address_id |
| 价格/数量/优惠 | 冻结数值 | — |
| 语言标识 | 订单级一个 snapshot_lang（= 下单语言） | — |

**拆单结构（数据落点）：** 拆单只按商家维度——订单内商品全部同一商家（无论 1 件或多件）→ 父子同单、不建子订单 order，发货/物流/退款直接挂 parent_order；跨 M 个商家 → 拆 M 个子订单 order。拆单唯一驱动力是按商家结算/发货，与商品数量无关。

## 二、我的订单列表页（My Orders）

### 2.1 页面入口

- 登录后，顶部导航 → 用户头像 → My Account → Orders
- 底部 Tab（APP 端）→ My Account → Orders

**前置条件：** 用户必须已登录。未登录用户访问时 redirect 到登录页，登录后跳回。

### 2.2 页面布局

| 端 | 布局方式 |
|----|---------|
| PC 端 | 左右分栏：左侧 MY ACCOUNT 侧边导航（Orders / Address / Settings），右侧为订单列表主内容 |
| APP 端 | 顶部导航栏（返回 + "My Orders" 标题 + 搜索按钮）+ Tab 筛选栏 + 垂直滚动列表 |

### 2.3 页面元素

#### 2.3.1 PC 端侧边导航

| 元素 | 说明 |
|------|------|
| 标题 | "MY ACCOUNT"（大写灰色小字） |
| Orders | 带订单图标 + 右侧数字角标（总订单数），当前页高亮 |
| Address | 带定位图标 |
| Settings | 带齿轮图标 |

> 侧边导航内容为示意，后续以"我的"个人中心需求为准。本期点击 Address / Settings 等非当前页菜单时，刷新当前页面即可。

#### 2.3.2 页面标题与搜索

| 端 | 元素 | 说明 |
|----|------|------|
| PC | 页面标题 | "My Orders"，左对齐 |
| PC | 搜索框 | 右侧，placeholder "Search orders by number or item..."，支持按订单号、商品名模糊搜索 |
| APP | 顶部导航 | 左侧返回箭头 + 居中标题 "My Orders" + 右侧搜索图标 |

#### 2.3.3 状态 Tab 筛选栏

水平 Tab 栏，用于按订单状态筛选：

| Tab | 显示文案 | 筛选条件 | 角标 |
|-----|---------|---------|------|
| All | "All" | 显示全部订单 | 无 |
| Confirmed | "Confirmed" | order_status = paid | 该状态数量（有则显示） |
| On its way | "On its way" | order_status = shipped | 该状态数量（有则显示） |
| Completed | "Completed" | order_status = completed | 无 |
| Cancelled | "Cancelled" | order_status = cancelled | 无 |

**交互说明：**

- 默认选中 "All" Tab
- 切换 Tab 不刷新页面，前端筛选（数据量小于 50 时）或接口重新请求
- APP 端 Tab 栏支持水平滑动（当 Tab 数量多时）
- Tab 角标仅在数量 > 0 时显示
- 待付款订单（parent_status = pending_payment）不单独设 Tab，仅在 All 列表展示

**待付款订单进列表口径（v1.5）：**

- **未提交付款的订单也进 My Orders 列表**。买家点「Buy Now / 去支付」那一刻 parent_order 即已创建，订单已生成、理应可见。
- C 端列表口径：显示全部 `pending_payment`（含支付单 pending「未提交付款」和 processing「已付款、渠道审核中」两个子态）。

**待付款一条、支付后按商家多条：** 待付款期间订单尚未拆单，列表展示 1 条整体订单 parent_order（买家一次下单只显一条、只需付一次款）；支付到账后按商家拆成子订单 order —— 同一商家（含多商品）不拆、父子同单，跨 M 商家拆 M 条 order，列表按子订单分别展示（与已有「每卖家独立发货/跟踪」一致）。即待付款 parent_order 与已支付后的 order 在同一列表按各自维度展示。

#### 2.3.4 订单卡片

每条订单以卡片形式展示，卡片内包含：

**PC 端订单卡片结构：**

```
┌─────────────────────────────────────────────────────────────┐
│  #订单号          Jun 4, 2026       [状态标签]    │
│                                                             │
│  商品图  品牌 / 商品名 / Condition: XX              $单价   │
│  商品图  品牌 / 商品名 / Condition: XX              $单价   │
│  ...                                                        │
│                                                             │
│  Total: $总金额  (Total N Items)            [View Details]  │
└─────────────────────────────────────────────────────────────┘
```

- 每件商品以完整行展示（商品图 + 品牌 + 名称 + 成色 + 单价）
- 如有退款商品，商品图上叠加 "Refund" 角标
- 底部左侧显示 "Total: $金额 (Total N Items)"，右侧显示 "View Details" 按钮

**APP 端订单卡片 — 单商品：**

```
┌──────────────────────────────────────────────┐
│  #订单号                     [状态标签]       │
│  Jun 4, 2026                       │

│          商品名称                            │
│          Condition: XX                       │
│                                              │
│                        [View Details]        │
└──────────────────────────────────────────────┘
```

- 单件商品以完整行展示（商品图 + 品牌 + 名称 + 成色 + 单价）
- 如有退款，商品图上叠加 "Refund" 角标

**APP 端订单卡片 — 多商品：**

```
┌──────────────────────────────────────────────┐
│  #订单号                     [状态标签]       │
│  Jun 4, 2026                       │
│                                              │

│                        [View Details]        │

```

- 商品以缩略图水平排列，最多展示 3 张
- 如有退款商品，对应缩略图上叠加 "Refund" 角标

#### 2.3.5 订单卡片字段说明

| 字段 | 数据来源 | 说明 |
|------|---------|------|
| 订单号 | order.order_no | 格式 "#" + 真实订单号，如 "#2026060408471234"（订单号格式由订单支付模块定义） |
| 状态标签 | order.order_status | 见下方状态标签样式 |
| 下单日期 | **parent_order.created_at** | 统一下单时间，父子一致（子订单回溯父订单取值）；格式 "Jun 4, 2026"，按买家本地时区展示（见 §1.4） |
| 商品图片 | order_item.product_image | PC 端：每件商品完整行展示；APP 端：单商品完整行展示，多商品最多展示 3 张缩略图 |
| 品牌 / 商品名 / 成色 | **订单快照冻结文本**（brand_snapshot / item_name / condition_snapshot，见 §1.5） | 展示原样显示，不实时回查商品/翻译 |
| 总金额 | order.total_amount | PC 端格式 "Total: $1,524 (Total N Items)"；APP 端单商品显示单价，多商品格式 "$1,524" + "(N Items)" |
| 商品件数 | count(order_items) | 单件商品不显示件数标注；多件显示件数 |
| 退款标记 | 聚合 order_item.refund_status | 若有 refunded 的商品，对应商品图上叠加 "Refund" 角标 |

**状态标签样式：**

| order_status | 标签文案 | 标签样式 |
|-------------|---------|---------|
| pending_payment（父订单待付款） | **"Placed（已下单）"** | 以 Figma 设计稿为准 |
| paid | "Confirmed" | 以 Figma 设计稿为准 |
| shipped | "On its way" | 以 Figma 设计稿为准 |
| completed | "Completed" | 以 Figma 设计稿为准 |
| cancelled | "Cancelled" | 以 Figma 设计稿为准 |

> **状态标签口径（v1.5）：** 待付款态统一标签「Placed（已下单）」，中英一致（英文站显示 "Placed"）。该标签需同时覆盖两个子态（未提交付款 / 已付款渠道审核中），中性的「已下单」对两者都成立（旧文案 "Payment Processing / Awaiting Payment" 对「已付款审核中」子态语义不符，故废弃）；具体行动引导交给详情页按钮（见 §6.1）。

#### 2.3.6 分页与排序

| 规则 | 说明 |
|------|------|
| 排序 | 按 **parent_order.created_at** 倒序（最新在前，父子统一按下单时间） |
| 分页 | PC 端每页 10 条，底部分页器；APP 端无限滚动加载，每次 10 条 |
| 空态 | 无订单时显示空态插图 + "You haven't placed any orders yet" + "Continue Shopping" 按钮 |

### 2.4 操作流程

1. 用户进入 "My Orders" 页面，默认加载 "All" Tab 下全部订单
2. 用户可通过 Tab 筛选查看特定状态的订单
3. 用户可通过搜索框输入订单号或商品名搜索
4. 点击订单卡片或 "View Details" 按钮 → 进入订单详情页

### 2.5 异常处理

| 异常 | 处理方式 |
|------|---------|
| 网络异常 | 显示错误提示 + 重试按钮 |
| 接口超时 | 列表区域 skeleton 加载态，超时后显示 "Loading failed, please try again" |
| 搜索无结果 | 显示 "No orders found for 'xxx'" |

## 三、订单详情页（Order Detail）

### 3.1 页面入口

- 订单列表页 → 点击订单卡片
- 邮件通知中的 "View Order" 链接：邮件 #4（订单已接收）、#5（取消通知）的 "View Order" 均进订单详情页
- 「订单已提交页（Order Placed）」跳转：**仅在「用户已提交付款、但未及时返回支付成功结果」时**跳转到订单详情的待付款（Placed）变体；若用户未提交付款即返回，则回退至上一级页面（不进详情）

**入口 → 变体映射：**

| 入口 | 目标 |
|------|------|
| 邮件 #4（订单已接收） / Order Placed 页 | §6.1 已下单（Placed）变体 |
| 邮件 #5（取消通知） | §6.5 ① 待付款失败取消变体 |

### 3.2 页面布局

| 端 | 布局方式 |
|----|---------|
| PC 端 | 左右分栏（同列表页侧边导航），右侧为订单详情主内容，垂直排列各信息卡片 |
| APP 端 | 顶部导航栏（返回 + "Order Details" 标题 + Contact Us 入口）+ 垂直滚动内容 |

### 3.3 页面头部

#### 3.3.1 面包屑导航（仅 PC 端）

格式：`My Orders > Order #2026060408471234`

"My Orders" 可点击返回列表页。

#### 3.3.2 订单标识信息

| 字段 | 说明 |
|------|------|
| 订单号 | 格式 "Order #2026060408471234"（PC 端），"#2026060408471234"（APP 端，附带复制按钮）。订单号格式由订单支付模块定义，本页面前置 "#" 展示 |
| 状态标签 | 同列表页状态标签样式 |
| 下单日期 | "Jun 4, 2026"，数据来源 **parent_order.created_at**（统一下单时间，子订单回溯父订单取值），按买家本地时区展示；PC 端右对齐，APP 端在订单号下方 |

### 3.4 商品分组区域

订单详情页的核心内容区域。商品根据 order item 的状态和物流包裹情况进行分组展示。

最复杂的场景可能出现以下组合：

- 待发货组（尚未发货的商品）
- 已发货包裹 1
- 已发货包裹 2
- 退款商品组 1
- 退款商品组 2

#### 3.4.1 分组原则

- 一个商品只属于一个分组：待发货组、已发货包裹组、或退款商品组
- 已发货的商品按物流包裹分组，每个包裹独立一组
- 未发货的商品归入待发货组
- 已退款的商品按退款单分组，每笔退款独立一组
- 各组在页面上平级排列，展示顺序：已发货包裹组 → 待发货组 → 退款商品组

#### 3.4.2 待发货组

当订单内有尚未发货的商品时展示。

| 元素 | 说明 |
|------|------|
| 状态标题 | "Preparing for shipment" |
| 配送时效说明 | "shipped within 1–3 business days after payment, with delivery in 3–7 business days after shipment." |
| 图标 | 📦 |
| 可点击 | 否 |
| 商品行 | 该组内所有待发货商品（见 3.4.5 商品行信息） |

#### 3.4.3 已发货包裹组

每个物流包裹独立一组，可能有多个。

| 元素 | 说明 |
|------|------|
| 物流状态卡 | 展示该包裹最新物流动态：主状态文案 + 预计送达日期，数据来自物流服务实时接口 |
| 可点击 | 是，点击打开物流追踪弹窗（PC：模态弹窗 / APP：底部抽屉），见第四章 |
| 商品行 | 该包裹内的商品（见 3.4.5 商品行信息） |

#### 3.4.4 退款商品组

## 六、订单详情页状态变体

以下列出不同 order_status 下详情页的关键差异。状态标签样式统一以 Figma 设计稿为准，PRD 不单独定义颜色。

### 6.1 已下单（Placed）变体（parent_status = pending_payment，父订单维度）

| 区域 | 展示内容 |
|------|---------|
| 展示维度 | 整体订单 parent_order（尚未拆单，一次下单的全部商品都在这一条内展示，跨商家商品一并列出） |
| 状态标签 | "Placed（已下单）" |
| 覆盖子态 | ① 未提交付款（支付单 pending，处于 payment_deadline 窗口内）；② 已付款、渠道审核中（支付单 processing） |
| 商品分组 | 全部商品归入待发货组（尚未发货、尚未按商家拆单） |
| 物流 | 无物流信息 |
| 操作按钮 | 提供「去支付」入口，**按子状态区分**：① 未提交付款 → 显示「去支付」按钮，引导继续支付；② 已付款、渠道审核中 → 隐藏「去支付」按钮，仅显示确认中提示文案 |
| payment_deadline | = 下单 + 30 分钟（仅对「未提交付款」的 pending 支付单生效）；超时/失败后转 §6.5 ① 待付款失败取消变体 |

> 入口来源：邮件 #4（订单已接收）/ Order Placed 页跳转至本变体（见 §3.1）。Order Placed 页仅在「已提交付款未及时返回结果」时跳转本变体；未提交付款即返回则回退上一级。

### 6.2 Confirmed 状态（order_status = paid）

| 区域 | 展示内容 |
|------|---------|
| 状态标签 | "Confirmed" |
| 商品分组 | 全部商品归入待发货组（"Preparing for shipment" + 配送时效说明） |
| 退款商品 | 若有退款状态的商品，需单独分组展示（退款商品组） |
| 操作按钮 | 无额外操作（本期不提供买家侧取消功能） |

### 6.3 On Its Way 状态（order_status = shipped）

| 区域 | 展示内容 |
|------|---------|
| 状态标签 | "On its way" |
| 商品分组 | 按实际情况分组展示，该状态下可能出现多种组合：已发货包裹组 + 待发货组 + 退款商品组（一个订单内可能同时存在发货、待发货、退款的商品） |
| 已发货包裹 | 每个包裹的物流状态卡展示最新物流轨迹状态（动态数据，非固定文案）+ 预计送达日期，可点击查看追踪 |
| 待发货商品 | 尚未发货的商品归入待发货组 |
| 退款商品 | 已退款的商品独立分组展示 |

### 6.4 Completed 状态（order_status = completed）

| 区域 | 展示内容 |
|------|---------|
| 状态标签 | "Completed" |
| 商品分组 | 已发货包裹组 + 退款商品组（若有） |
| 已发货包裹 | 物流状态卡展示最新轨迹状态 + 实际送达日期（动态数据），可点击查看追踪 |
| Order Summary | Refund 行显示退款汇总（若有） |

### 6.5 Cancelled 状态（order_status = cancelled）

Cancelled 分两个变体，判定依据：有无子订单 / 退款单。

#### 6.5.① 待付款失败取消（parent 层 cancelled，无子订单 / 无退款）

| 区域 | 展示内容 |
|------|---------|
| 状态标签 | "Cancelled" |
| 顶部提示卡 | "Order cancelled — payment wasn't completed"（含原因：未付款超时 / 风控未通过） |
| 商品列表 | 取父订单快照展示，无退款角标 |
| Payment 区块 | 显示 "Payment not completed"，无脱敏卡号 |
| Order Summary | 无 Refund 行 |
| 操作按钮 | 底部 "Continue Shopping" 按钮 |

#### 6.5.② 已付款取消（order 层 cancelled，有退款）

| 区域 | 展示内容 |
|------|---------|
| 状态标签 | "Cancelled" |
| 物流状态卡 | "Order cancelled (N Refunds completed)" + 退款总额，可点击查看退款汇总 |
| 商品列表 | 全部商品（不标记退款角标——因全部已退） |
| 操作按钮 | 底部 "Continue Shopping" 按钮 |

### 6.6 已付款取消处理中（中间态）

本期买家侧不发起取消（见 §6.2），取消均由运营发起，C 端被动展示。已付款订单在退款处理期间的中间态：

| 阶段 | 展示内容 |
|------|---------|
| 退款处理中 | 订单标签保持原态（Confirmed / On its way）+ 详情顶部提示条 "Cancellation in progress — your refund is being processed"；相关商品进退款商品组、退款摘要卡显示 "Processing"（复用退款弹窗 pending 态） |
| 退款成功 | 转 §6.5 ② 已付款取消变体 |
| 退款失败 | 订单保持原态，退款卡显示 "Refund is taking longer than expected — our team is on it"，引导联系客服（不暴露失败细节） |

## 七、多语言

### 7.1 静态 UI 文案 — 前端语言包

本模块所有静态文案（Tab 文案、区块标题、按钮文案、状态文案、提示语、Toast、空状态等）均通过前端语言包（i18n）实现，不通过翻译模块注册 Key。含变量的文案（如 `(N Items)`、`Refund (n item)`）由前端渲染时注入数值。

主要静态文案清单（节选，出现位置见正文）：

| 文案 | 出现位置 |
|------|---------|
| All / Confirmed / On its way / Completed / Cancelled | §2.3.3 Tab |
| Placed（已下单）/ Confirmed / On its way / Completed / Cancelled | 状态标签 |
| Order cancelled — payment wasn't completed / Payment not completed | §6.5① |
| Cancellation in progress — your refund is being processed | §6.6 |
| Refund is taking longer than expected — our team is on it | §6.6 |
| Preparing for shipment / Continue Shopping / View Details / View Order | 各处 |

### 7.2 动态业务内容 — 订单快照（非翻译服务实时）

本模块的动态业务内容**不走翻译服务实时查询**，而是读取「下单时冻结的订单快照」，按快照语言（snapshot_lang）原样展示：

| 动态内容 | 来源 | 展示规则 |
|---------|------|---------|
| 商品名称 / 品牌 / 成色 | 订单快照冻结文本（item_name / brand_snapshot / condition_snapshot） | 按下单语言冻结，展示原样显示 |
| 收货地址 | 订单地址快照 | 原文展示，不翻译 |

> 仅「下单时点确定的内容」（商品信息、地址等）用订单快照冻结；物流状态、订单状态标签等**实时动态内容不冻结**（状态标签走前端语言包，物流状态由物流服务返回）。

### 7.3 Fallback 规则

- 静态文案：语言包缺少某语言时降级显示英文。
- 订单快照：快照按下单语言一次性冻结，展示时原样读取、不做实时翻译，故不存在译文缺失的 fallback 场景（消除商品下架/改名/字典变更导致的漂移丢失）。

**v1.5 修改明细：**

来源：《订单列表详情-变更影响范围清单 v2》（订单支付迭代 V1.2 待付款上移 + 支付后拆单评审 + 两轮评论处理）。改动点全部落到本 PRD。

1. **状态标签统一「Placed（已下单）」**：待付款态标签由 "Payment Processing" 改为 "Placed（已下单）"，中英一致。标签需同时覆盖「未提交付款 / 已付款审核中」两个子态，中性「已下单」对两者都成立（旧文案对已付款审核中语义不符）（§2.3.5、§3.3.2、§6.1）
2. **下单时间口径**：确认日期数据来源 order.created_at → parent_order.created_at（父子统一下单时间，子订单回溯父订单取值）；列表排序基准同步为 parent_order.created_at（§2.3.5、§2.3.6、§3.3.2）
3. **新增 §1.4 时间与时区展示规则**：C 端订单时间存 UTC、前端按买家浏览器本地时区渲染并标注；物流轨迹页属他人项目，其时区不在本 PRD 定义（§1.4、§3.5、§4.2.2）
4. **新增 §1.5 订单数据与快照依赖**：商品名称/品牌/成色等改为读订单快照冻结文本（item_name / brand_snapshot / condition_snapshot），附带保留 brand_id / condition_code 非展示引用；order_item 同时记录 listing_id（成交渠道）与 product_id（实物一物一码）；parent_order 新增 snapshot_lang；含快照内容分类表与拆单结构说明（§1.5、§2.3.5、§3.4.5）
5. **拆单口径精确化**：拆单只按商家维度——同一商家（含多商品）不拆、父子同单、发货/物流/退款挂 parent_order；跨 M 商家才拆 M 个 order（§2.3.3、§1.5）
6. **未提交付款进列表**：未提交付款订单也进 My Orders 列表（parent_order 在点 Buy Now 时已创建）；C 端显示全部 pending_payment（含 pending 与 processing 子态），与订单支付后台「仅显示 processing」口径不同，需区分实现（§2.3.3）
7. **§6.1 待付款文案**：删除 "within 1 day"，改为 "We're confirming your payment. We'll email you once it's confirmed."（§6.1）
8. **§6.1 去支付入口**：提供「去支付」，按子状态区分——未提交付款显示按钮；已付款渠道审核中隐藏按钮 + 显示确认中提示（§6.1）
9. **§6.1 payment_deadline**：= 下单 + 30 分钟（仅对未提交付款 pending 支付单生效）（§6.1）
10. **§3.1 详情入口 + 变体映射**：邮件 #4/#5 View Order 均进详情；Order Placed 页仅「已提交付款未及时返回结果」时跳 §6.1 变体，未提交付款回退上一级（§3.1、§6.1）
11. **§6.5 Cancelled 拆两变体**：① 待付款失败取消（parent 层，无子订单/无退款）；② 已付款取消（order 层，有退款）。判定依据：有无子订单/退款单（§6.5）
12. **新增 §6.6 已付款取消处理中（中间态）**：运营发起取消，C 端被动展示退款处理中/成功/失败三态（§6.6）
13. **§七 多语言重写**：结构化为静态文案（前端语言包）/ 动态内容（订单快照，非翻译服务实时）/ Fallback 三部分；仅「下单时点确定的内容」用快照，实时动态内容不冻结；地址原文不翻译（§七）
14. **§1.2 前置依赖 / §1.3 术语**：前置依赖新增订单快照、checkout_session 并存说明；术语补「下单时间 / 时区 / 快照语言」（§1.2、§1.3）
