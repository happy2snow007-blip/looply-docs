# Looply C 端订单列表页 & 订单详情页 PRD v1.4

> 买家侧"我的订单"列表页 + 订单详情页完整需求定义
>
> Version 1.3 · 2026-07-13 · 面向：前端 / 后端开发

---

## 一、概述

### 1.1 背景与目标

本 PRD 定义买家在 looply 平台查看已购订单的完整体验，包含"我的订单"列表页和单笔订单详情页（含物流追踪、退款详情）。

**核心目标：**

- 让买家清晰查看所有历史订单及其当前状态
- 按状态筛选快速定位目标订单
- 在详情页内查看完整订单信息：商品、物流、支付、退款
- 物流追踪和退款详情通过弹窗/底部抽屉展示，减少页面跳转
- PC 和 APP 双端适配，体验一致

### 1.2 前置依赖

| 依赖模块 | 说明 |
|---------|------|
| 订单状态模型 | 引用《looply 订单支付 PRD v1.2》第二章分层状态模型（待付款态在 parent_order.parent_status，支付后拆子订单） |
| 支付渠道 | 引用《支付渠道对接集成说明文档 v1.0》 |
| 物流管理 | 物流轨迹数据由物流模块提供 |
| 用户管理 | 登录态、地址管理 |

### 1.3 术语说明

引用《looply 订单支付 PRD v1.1》1.6 术语说明，本文档额外定义：

| 术语 | 说明 |
|------|------|
| 发货组（Fulfillment Group） | 一个订单可能分多个包裹发货，每个包裹对应一个发货组 |
| 物流状态卡 | 详情页内每个已发货包裹组顶部的物流信息卡片，展示最新物流动态 |
| 追踪弹窗 | 展示完整物流轨迹的模态弹窗（PC）或底部抽屉（APP） |
| 退款弹窗 | 展示单笔退款详细信息的模态弹窗（PC）或底部抽屉（APP） |

## 二、我的订单列表页（My Orders）

### 2.1 页面入口

- 登录后，顶部导航 → 用户头像 → My Account → Orders
- 底部 Tab（APP 端）→ My Account → Orders

**前置条件：** 用户必须已登录。未登录用户访问时 redirect 到登录页，登录后跳回。

### 2.2 页面布局

| 端 | 布局方式 |
|----|---------|
| PC 端 | 左右分栏：左侧 MY ACCOUNT 侧边导航（Orders / Address / Settings），右侧为订单列表主内容 |
| APP 端 | 顶部导航栏（返回 + "My Orders" 标题 + 搜索按钮）+ Tab 筛选栏 + 垂直滚动列表 |

### 2.3 页面元素

#### 2.3.1 PC 端侧边导航

| 元素 | 说明 |
|------|------|
| 标题 | "MY ACCOUNT"（大写灰色小字） |
| Orders | 带订单图标 + 右侧数字角标（总订单数），当前页高亮 |
| Address | 带定位图标 |
| Settings | 带齿轮图标 |

> 侧边导航内容为示意，后续以"我的"个人中心需求为准。本期点击 Address / Settings 等非当前页菜单时，刷新当前页面即可。

#### 2.3.2 页面标题与搜索

| 端 | 元素 | 说明 |
|----|------|------|
| PC | 页面标题 | "My Orders"，左对齐 |
| PC | 搜索框 | 右侧，placeholder "Search orders by number or item..."，支持按订单号、商品名模糊搜索 |
| APP | 顶部导航 | 左侧返回箭头 + 居中标题 "My Orders" + 右侧搜索图标 |

#### 2.3.3 状态 Tab 筛选栏

水平 Tab 栏，用于按订单状态筛选：

| Tab | 显示文案 | 筛选条件 | 角标 |
|-----|---------|---------|------|
| All | "All" | 显示全部订单 | 无 |
| Confirmed | "Confirmed" | order_status = paid | 该状态数量（有则显示） |
| On its way | "On its way" | order_status = shipped | 该状态数量（有则显示） |
| Completed | "Completed" | order_status = completed | 无 |
| Cancelled | "Cancelled" | order_status = cancelled | 无 |

**交互说明：**

- 默认选中 "All" Tab
- 切换 Tab 不刷新页面，前端筛选（数据量小于 50 时）或接口重新请求
- APP 端 Tab 栏支持水平滑动（当 Tab 数量多时）
- Tab 角标仅在数量 > 0 时显示
- 待付款订单（parent_status = pending_payment，卡风控审核中，少量场景）不单独设 Tab，仅在 All 列表展示
- **待付款一条、支付后按商家多条**（v1.4）：待付款期间订单尚未拆单，列表展示 1 条整体订单 parent_order（买家一次下单只显一条、只需付一次款）；支付到账后按商家拆成多条子订单 order，列表按子订单分别展示（与已有「每卖家独立发货/跟踪」一致）。即待付款 parent_order 与已支付后的 order 在同一列表按各自维度展示

#### 2.3.4 订单卡片

每条订单以卡片形式展示，卡片内包含：

**PC 端订单卡片结构：**

```
┌─────────────────────────────────────────────────────────────┐
│  #订单号          Confirmed Jun 4, 2026       [状态标签]    │
│                                                             │
│  商品图  品牌 / 商品名 / Condition: XX              $单价   │
│  商品图  品牌 / 商品名 / Condition: XX              $单价   │
│  ...                                                        │
│                                                             │
│  Total: $总金额  (Total N Items)            [View Details]  │
└─────────────────────────────────────────────────────────────┘
```

- 每件商品以完整行展示（商品图 + 品牌 + 名称 + 成色 + 单价）
- 如有退款商品，商品图上叠加 "Refund" 角标
- 底部左侧显示 "Total: $金额 (Total N Items)"，右侧显示 "View Details" 按钮

**APP 端订单卡片 — 单商品：**

```
┌──────────────────────────────────────────────┐
│  #订单号                     [状态标签]       │
│  Confirmed Jun 4, 2026                       │
│                                              │
│  商品图  品牌名                       $单价  │
│          商品名称                            │
│          Condition: XX                       │
│                                              │
│                        [View Details]        │
└──────────────────────────────────────────────┘
```

- 单件商品以完整行展示（商品图 + 品牌 + 名称 + 成色 + 单价）
- 如有退款，商品图上叠加 "Refund" 角标

**APP 端订单卡片 — 多商品：**

```
┌──────────────────────────────────────────────┐
│  #订单号                     [状态标签]       │
│  Confirmed Jun 4, 2026                       │
│                                              │
│  商品图1  商品图2  商品图3   $总金额         │
│                              (N Items)       │
│                                              │
│                        [View Details]        │
└──────────────────────────────────────────────┘
```

- 商品以缩略图水平排列，最多展示 3 张
- 如有退款商品，对应缩略图上叠加 "Refund" 角标

#### 2.3.5 订单卡片字段说明

| 字段 | 数据来源 | 说明 |
|------|---------|------|
| 订单号 | order.order_no | 格式 "#" + 真实订单号，如 "#2026060408471234"（订单号格式由订单支付模块定义） |
| 状态标签 | order.order_status | 见下方状态标签样式 |
| 确认日期 | order.created_at | 格式 "Confirmed Jun 4, 2026" |
| 商品图片 | order_item.product_image | PC 端：每件商品完整行展示；APP 端：单商品完整行展示，多商品最多展示 3 张缩略图 |
| 总金额 | order.total_amount | PC 端格式 "Total: $1,524 (Total N Items)"；APP 端单商品显示单价，多商品格式 "$1,524" + "(N Items)" |
| 商品件数 | count(order_items) | 单件商品不显示件数标注；多件显示件数 |
| 退款标记 | 聚合 order_item.refund_status | 若有 refunded 的商品，对应商品图上叠加 "Refund" 角标 |

**状态标签样式：**

| order_status | 标签文案 | 标签样式 |
|-------------|---------|---------|
| pending_payment（父订单待付款） | "Payment Processing" | 以 Figma 设计稿为准 |
| paid | "Confirmed" | 以 Figma 设计稿为准 |
| shipped | "On its way" | 以 Figma 设计稿为准 |
| completed | "Completed" | 以 Figma 设计稿为准 |
| cancelled | "Cancelled" | 以 Figma 设计稿为准 |

#### 2.3.6 分页与排序

| 规则 | 说明 |
|------|------|
| 排序 | 按 order.created_at 倒序（最新在前） |
| 分页 | PC 端每页 10 条，底部分页器；APP 端无限滚动加载，每次 10 条 |
| 空态 | 无订单时显示空态插图 + "You haven't placed any orders yet" + "Continue Shopping" 按钮 |

### 2.4 操作流程

1. 用户进入 "My Orders" 页面，默认加载 "All" Tab 下全部订单
2. 用户可通过 Tab 筛选查看特定状态的订单
3. 用户可通过搜索框输入订单号或商品名搜索
4. 点击订单卡片或 "View Details" 按钮 → 进入订单详情页

### 2.5 异常处理

| 异常 | 处理方式 |
|------|---------|
| 网络异常 | 显示错误提示 + 重试按钮 |
| 接口超时 | 列表区域 skeleton 加载态，超时后显示 "Loading failed, please try again" |
| 搜索无结果 | 显示 "No orders found for 'xxx'" |

## 三、订单详情页（Order Detail）

### 3.1 页面入口

- 订单列表页 → 点击订单卡片
- 邮件通知中的 "View Order" 链接

### 3.2 页面布局

| 端 | 布局方式 |
|----|---------|
| PC 端 | 左右分栏（同列表页侧边导航），右侧为订单详情主内容，垂直排列各信息卡片 |
| APP 端 | 顶部导航栏（返回 + "Order Details" 标题 + Contact Us 入口）+ 垂直滚动内容 |

### 3.3 页面头部

#### 3.3.1 面包屑导航（仅 PC 端）

格式：`My Orders > Order #2026060408471234`

"My Orders" 可点击返回列表页。

#### 3.3.2 订单标识信息

| 字段 | 说明 |
|------|------|
| 订单号 | 格式 "Order #2026060408471234"（PC 端），"#2026060408471234"（APP 端，附带复制按钮）。订单号格式由订单支付模块定义，本页面前置 "#" 展示 |
| 状态标签 | 同列表页状态标签样式 |
| 确认日期 | "Confirmed Jun 4, 2026"，PC 端右对齐，APP 端在订单号下方 |

### 3.4 商品分组区域

订单详情页的核心内容区域。商品根据 order item 的状态和物流包裹情况进行分组展示。

最复杂的场景可能出现以下组合：

- 待发货组（尚未发货的商品）
- 已发货包裹 1
- 已发货包裹 2
- 退款商品组 1
- 退款商品组 2

#### 3.4.1 分组原则

- 一个商品只属于一个分组：待发货组、已发货包裹组、或退款商品组
- 已发货的商品按物流包裹分组，每个包裹独立一组
- 未发货的商品归入待发货组
- 已退款的商品按退款单分组，每笔退款独立一组
- 各组在页面上平级排列，展示顺序：已发货包裹组 → 待发货组 → 退款商品组

#### 3.4.2 待发货组

当订单内有尚未发货的商品时展示。

| 元素 | 说明 |
|------|------|
| 状态标题 | "Preparing for shipment" |
| 配送时效说明 | "shipped within 1–3 business days after payment, with delivery in 3–7 business days after shipment." |
| 图标 | 📦 |
| 可点击 | 否 |
| 商品行 | 该组内所有待发货商品（见 3.4.5 商品行信息） |

#### 3.4.3 已发货包裹组

每个物流包裹独立一组，可能有多个。

| 元素 | 说明 |
|------|------|
| 物流状态卡 | 展示该包裹最新物流动态：主状态文案 + 预计送达日期，数据来自物流服务实时接口 |
| 可点击 | 是，点击打开物流追踪弹窗（PC：模态弹窗 / APP：底部抽屉），见第四章 |
| 商品行 | 该包裹内的商品（见 3.4.5 商品行信息） |

物流已签收时，物流状态卡展示最新轨迹状态 + 实际送达日期。

#### 3.4.4 退款商品组

每笔退款独立一组，可能有多个。

| 元素 | 说明 |
|------|------|
| 退款摘要卡 | 标题："Refund completed on Jun 5, 2026"（退款完成日期）；副标题："$873.00 returned to Visa ending in 6324"（退款金额 + 退回渠道） |
| 可点击 | 是，点击打开退款详情弹窗（PC：模态弹窗 / APP：底部抽屉），见第五章 |
| 商品行 | 该笔退款关联的商品（见 3.4.5 商品行信息） |

多笔退款则有多个退款商品组，各自展示对应的退款摘要和商品。

#### 3.4.5 商品行信息

每件商品以行卡片展示：

| 字段 | 说明 |
|------|------|
| 商品图片 | 圆角，具体尺寸以 Figma 设计稿为准 |
| 品牌 | 大写灰色小字，如 "LOUIS VUITTON" |
| 商品名称 | 主文字，如 "Silver tone metal silver necklace" |
| 成色等级 | 标签样式 "Condition: Very Good" |
| 价格 | 右对齐，加粗，如 "$651" |

#### 3.4.6 页面结构示意

```
┌─ 已发货包裹 1 ──────────────────────────────┐
│ [物流最新状态 + 预计送达日期]            >   │
│  商品 A（品牌 / 名称 / 成色）         $单价  │
│  商品 B（品牌 / 名称 / 成色）         $单价  │

┌─ 已发货包裹 2 ──────────────────────────────┐

│  商品 C（品牌 / 名称 / 成色）         $单价  │
└──────────────────────────────────────────────┘

┌─ 待发货组 ───────────────────────────────────┐
```

### 3.5 Shipping & Delivery 区块

PC 端为左右两列布局，APP 端为上下堆叠。

| 字段 | 说明 |

### 3.7 Order Summary 区块

| 字段 | 说明 | 格式示例 |
|------|------|---------|
| Subtotal | 商品小计 + 件数 | "Subtotal (2 items)" → "$1,524.00" |
| Shipping | 运费 | "Shipping" → "Free" 或 "$XX.XX" |
| Tax | 本期暂不支持税费计算，tax = 0 时不展示该行 | — |

**金额计算规则：**
- Total = Subtotal + Shipping + Tax - Discount（如有优惠）
- Refund 行仅展示已退款成功的金额总和，不参与 Total 计算，作为附加信息展示

## 四、物流追踪弹窗（Tracking Details）

### 4.1 触发方式

| 端 | 触发交互 | 展示形式 |
|----|---------|---------|
| PC | 点击物流状态卡 | 页面居中模态弹窗（遮罩层） |
| APP | 点击物流状态卡 | 底部抽屉（Bottom Sheet），全屏覆盖 |

### 4.2 弹窗内容

#### 4.2.1 头部信息表

三行表格展示关键物流信息：

| 字段 | 说明 | 示例 |
|------|------|------|
| Carrier | 承运商名称 | "FedEx" |
| Tracking No. | 运单号 + 复制图标（点击复制到剪贴板） | "7489 2104 5678" |
| Est. delivery / Status | 运输中时为预计送达日期范围；已签收时为 "Delivered"（紫色文字） | "May 22 - May 24, 2026" 或 "Delivered" |

#### 4.2.2 追踪历史（Tracking History）

以时间线形式展示物流事件，从最新到最早：

**每条事件包含：**

| 字段 | 说明 |
|------|------|
| 主状态（status） | 物流主状态文案，如 "In Transit" / "Delivered" / "Out for Delivery" |
| 描述信息（message） | 物流详情描述，如 "Arrived at transit hub" / "Signed by John D. at front door" |
| 地点（location） | 📍 地标格式："Los Angeles, CA" 或 "Shanghai, CN" |
| 时间（timestamp） | "May 19, 2026 · 10:32 AM" |

> 物流轨迹的状态枚举由物流服务定义和维护，本 PRD 不做枚举约束。前端按物流服务返回的 status 和 message 字段直接展示。

**时间线样式：**

- 最新事件（第一条）：左侧实心紫色圆点 + 状态文字为紫色加粗
- 历史事件：左侧空心灰色圆点 + 状态文字为黑色加粗
- 圆点之间用竖线（虚线或实线）连接

#### 4.2.3 弹窗关闭

- PC 端：右上角 × 按钮，或点击遮罩层
- APP 端：右上角 × 按钮，或下滑关闭

## 六、订单详情页状态变体

以下列出不同 order_status 下详情页的关键差异。状态标签样式统一以 Figma 设计稿为准，PRD 不单独定义颜色。

### 6.1 Payment Processing 状态（parent_status = pending_payment，父订单维度）

| 区域 | 展示内容 |
|------|---------|
| 展示维度 | 整体订单 parent_order（尚未拆单，一次下单的全部商品都在这一条内展示，跨商家商品一并列出） |
| 状态标签 | "Payment Processing" |
| 说明文案 | "We're processing your payment. We'll confirm within 1 day."（卡风控审核中） |
| 商品分组 | 全部商品归入待发货组（尚未发货、尚未按商家拆单） |
| 物流 | 无物流信息 |
| 操作按钮 | 无额外操作（本期不提供买家侧取消） |

### 6.2 Confirmed 状态（order_status = paid）

| 区域 | 展示内容 |
|------|---------|
| 状态标签 | "Confirmed" |
| 商品分组 | 全部商品归入待发货组（"Preparing for shipment" + 配送时效说明） |
| 退款商品 | 若有退款状态的商品，需单独分组展示（退款商品组） |
| 操作按钮 | 无额外操作（本期不提供买家侧取消功能） |

### 6.3 On Its Way 状态（order_status = shipped）

| 区域 | 展示内容 |
|------|---------|
| 状态标签 | "On its way" |
| 商品分组 | 按实际情况分组展示，该状态下可能出现多种组合：已发货包裹组 + 待发货组 + 退款商品组（一个订单内可能同时存在发货、待发货、退款的商品） |
| 已发货包裹 | 每个包裹的物流状态卡展示最新物流轨迹状态（动态数据，非固定文案）+ 预计送达日期，可点击查看追踪 |
| 待发货商品 | 尚未发货的商品归入待发货组 |
| 退款商品 | 已退款的商品独立分组展示 |

### 6.4 Completed 状态（order_status = completed）

| 区域 | 展示内容 |
|------|---------|
| 状态标签 | "Completed" |
| 商品分组 | 已发货包裹组 + 退款商品组（若有） |
| 已发货包裹 | 物流状态卡展示最新轨迹状态 + 实际送达日期（动态数据），可点击查看追踪 |
| Order Summary | Refund 行显示退款汇总（若有） |

### 6.5 Cancelled 状态（order_status = cancelled）

| 区域 | 展示内容 |
|------|---------|
| 状态标签 | "Cancelled" |
| 物流状态卡 | "Order cancelled (N Refunds completed)" + 退款总额，可点击查看退款汇总 |
| 商品列表 | 全部商品（不标记退款角标——因全部已退） |
| 操作按钮 | 底部 "Continue Shopping" 按钮 |
