# Looply｜数据总览 / 经营概览 PRD v0.2

**状态**：已确认，开发与验收基线  
**更新日期**：2026-08-03  
**页面基线**：`outputs/looply-数据总览-经营概览-GA4自动同步副本-v1.html`  
**关联页面**：获客与渠道表现、浏览与找货效率  

## 1. 目标

经营概览用于回答四个问题：

1. 最近一周的访问、首次访问、购买与成交规模如何，较上一周怎样变化；
2. 访问、看商品、购买意向、Checkout、购买分别覆盖多少访客；
3. 流量规模变化时，购买转化效率是否同步改善；
4. 所选周期成交订单截至当前产生了多少退款影响。

页面以 Looply 已确认 Demo 为业务结构基线，通过本机交互服务实时查询 GA4。GA4 未取得或不具备业务定义的数据必须显示“— / 待接入”，不得补模拟值。

## 2. 页面与交互

### 2.1 页面入口

- 本机入口：`http://127.0.0.1:8767/dashboard`。
- 左侧保留三个一级视图：数据总览、获客与渠道表现、浏览与找货效率。
- 三个视图共用同一筛选上下文，切换页面不重置筛选条件。

### 2.2 全局筛选

- 默认周期：最近 7 个完整自然日，不含当天。
- 默认对比：上一等长 7 日。
- 国家/地区：全部或 GA4 实际返回值。
- 设备：全部、Mobile、Desktop、Tablet。
- 结束日期不得晚于昨天；开始日期不得晚于结束日期。
- 点击“查询”后实时请求 GA4；查询中显示加载状态，失败时保留当前已成功页面并展示错误，不用 0 替代失败。
- 页面展示最近成功查询时间；本机页面结果可短期缓存，但不覆盖 Demo、静态快照或用户手动文件。

## 3. 顶部核心 KPI

七个指标均采用“成交发生时口径”，后续退款不回改：

| 指标 | 定义 | 数据源 |
|---|---|---|
| 访问访客数 | 周期内至少发生一次 `page_view` 的去重访客 | `page_view` + `totalUsers` |
| 首次访问访客数 | 周期内至少发生一次 `first_visit` 的去重访客；不等于新注册用户 | `first_visit` + `totalUsers` |
| 购买访客数 | 周期内至少发生一次 `purchase` 的去重访客；后续退款不移除购买身份 | `purchase` + `totalUsers` |
| 购买转化率 | 周期去重购买访客数 ÷ 周期去重访问访客数 | 由上述两项计算 |
| GA4 Purchase 数 | 成交发生次数；后续退款不冲减 | `ecommercePurchases` |
| GA4 成交客单价 | 退款前成交金额 ÷ GA4 Purchase 数 | `grossPurchaseRevenue ÷ ecommercePurchases` |
| GA4 成交收入 | 退款前成交金额；不得称为财务 GMV | `grossPurchaseRevenue` |

规则：

- KPI 默认展示上一等长周期对比。
- 周期指标必须直接查询周期去重值；不得累加每日去重访客。
- GA4 Purchase 数与成交收入在订单、财务对账前保留“GA4”标识。
- 不得使用 `totalRevenue` 或含退款后的 `purchaseRevenue` 代替 GA4 成交收入。

## 4. 售后影响（成交订单 Cohort）

### 4.1 模块位置与结构

- 位于两组核心 KPI 下方、订单目标与趋势上方。
- 展示两张紧凑指标卡：成交订单退款数、成交订单退款金额。
- 卡片下方展示一行口径说明与“查看售后明细”入口。
- 没有订单级明细时，入口保留但禁用，不生成假明细。

### 4.2 成交订单退款数

- 先按支付成功时间选出落入用户所选周期的成交订单 Cohort。
- 截至本次查询完成时间，Cohort 中至少发生一次已完成退款的订单计入。
- 同一订单多次退款、部分退款只计 1 个退款订单。
- 按 `order_id` 或 `transaction_id` 去重。

### 4.3 成交订单退款金额

- 订单范围与成交订单退款数使用同一成交订单 Cohort。
- 截至本次查询完成时间，累计该批订单所有已完成退款的实际退款金额。
- 同一订单多次或部分退款的金额累加。

### 4.4 观察与对比规则

- 页面必须展示观察截止时间。
- 后续发生的退款允许回补其所属历史成交订单 Cohort，因此同一历史周期的售后值可能随时间增加。
- 售后指标与上方七个成交发生时指标完全分离，不反向修改访问、购买、转化、Purchase、成交客单价或成交收入。
- 不同成交订单 Cohort 的退款观察成熟度不同。在订单系统支持统一固定观察窗口前，不直接展示上一周期对比，也不展示简单退款率。
- 如后续计算退款率，分子与分母必须来自同一批原支付订单 Cohort，并使用相同观察窗口。

### 4.5 当前数据状态

- 当前 GA4 Data API 可查询 `refundAmount` 和 refund 事件，但尚未建立“支付成功订单 → 后续退款”的订单级关联。
- 因此成交订单退款数和成交订单退款金额均显示“— / 订单级数据待接入”。
- GA4 refund 事件数和按退款发生日汇总的 `refundAmount` 仅作埋点诊断，不能代替本模块两项指标；即使查询返回 0，也不能据此宣称成交订单 Cohort 退款为 0。

## 5. 订单目标与趋势

- 目标：年底达到 100 个 GA4 Purchase / 天。
- 展示所选周期结束日的 GA4 Purchase、目标完成度、距目标差值、近 7 日日均及近 14 日趋势。
- 每日 Purchase 使用 `ecommercePurchases`，退款不冲减。
- 目标属于经营观察值；订单系统对账前不称为最终支付订单数。

## 6. 关键行为覆盖

### 6.1 分析链路

访问访客 → 商详访客 → 购买意向（收藏访客｜加购访客）→ Checkout 访客 → 购买访客。

- 箭头仅表达经营分析方向，不表示同一批访客严格按顺序完成全部步骤。
- 收藏与加购在购买意向阶段并列，不得画成“收藏 → 加购”。
- 游客与登录用户均纳入访客统计。

### 6.2 指标

- 商详访客：周期内发生 `view_item` 的去重访客。
- 收藏访客：周期内发生收藏事件的去重访客。
- 加购访客：周期内发生 `add_to_cart` 的去重访客。
- 购买意向访客：收藏访客与加购访客按同一访客标识联合去重，不包含购买访客本身。
- 购买意向覆盖率：购买意向访客 ÷ 访问访客。
- Checkout 访客：周期内发生 `begin_checkout` 的去重访客。

当前收藏事件未真实接入时：收藏访客显示“— / 收藏事件待接入”；购买意向访客与覆盖率显示“— / 数据不完整”；加购访客继续展示真实值。列表页可直接收藏，因此收藏访客不得视为商详访客子集，也不展示“商详 → 收藏转化率”。

## 7. 访问与购买转化趋势

### 7.1 图表

- 使用一张双轴组合图。
- 横轴：所选周期内自然日。
- 左轴：每日访问访客数，柱状图。
- 右轴：每日购买转化率，折线图。
- 两个纵轴均从 0 开始。
- 共用同一日期轴和 Tooltip；Tooltip 同时展示当日访问访客数与购买转化率。
- 不展示每日购买访客折线，不使用标准化指数。

### 7.2 口径

- 每日访问访客：当日发生 `page_view` 的去重访客。
- 每日购买转化率：当日购买访客 ÷ 当日访问访客。
- 周期购买转化率：周期内去重购买访客 ÷ 周期内去重访问访客。
- 周期购买转化率不得使用每日购买转化率的算术平均值。
- 双轴用于同日期观察规模与效率是否同向变化，不代表两种数值可直接比较大小。

## 8. 关注与下钻

- 保留获客与渠道表现、浏览与找货、购买意向与交易、访客与商品分析入口。
- 已建页面跳转到对应主视图；未建页面只保留入口状态，不生成模拟内容。
- 购买前行为路径属于交易转化下钻，不在总览重复完整建设。

## 9. 数据与异常规则

- 所有展示值必须来自本次成功 GA4 查询或已接入订单数据。
- 查询成功且字段已接入、真实结果为 0 时可展示 0。
- 字段未接入、事件未观测且无法判断是否漏埋时，展示“— / 待接入”，不得展示 0。
- 任一必需 GA4 查询失败时，本次查询整体失败，不用半套新数据替换当前成功结果。
- 服务账号密钥仅保存在项目外安全目录，不进入 HTML、JSON 输出、日志、文档或 Git。

## 10. 验收标准

1. 默认打开最近 7 个完整自然日，默认对比上一等长 7 日。
2. 七个核心 KPI 使用成交发生时口径，退款不回改；页面不出现 `totalRevenue` 作为成交收入数据源。
3. 售后两张卡名称为“成交订单退款数”“成交订单退款金额”，当前均显示“— / 订单级数据待接入”，且不出现“已关闭周期对比”。
4. 售后说明包含成交订单 Cohort、观察截止时间、多次退款订单数去重、金额累计、历史 Cohort 回补和固定观察窗口要求。
5. 趋势为一张双轴图：访问访客柱状、购买转化率折线；两轴从 0 开始，共用 Tooltip，不含每日购买访客线。
6. 购买意向并列展示收藏与加购；收藏未接入时不以加购人数冒充联合人数。
7. 国家/地区与设备筛选使用 GA4 实际值，查询失败和未接入状态可区分。
8. 三个独立 Demo 不被修改；实时查询输出仅写入明确命名的自动同步副本。

## 11. 依赖

- GA4 Data API 与 Property `531542304` 只读权限。
- `page_view`、`first_visit`、`view_item`、`add_to_cart`、`begin_checkout`、`purchase` 事件及相应指标。
- 收藏指标依赖线上确认并稳定上报收藏事件。
- 成交订单 Cohort 售后指标依赖订单系统提供支付成功时间、稳定订单 ID、退款完成时间、退款状态和实际退款金额。
