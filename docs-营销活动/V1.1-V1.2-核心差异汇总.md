## 3. 新增功能

### 3.1 促销打标（Sale 标签）· PRD §2.11 —— 本次最大的一块

判定商品是否处于「降价中」，驱动商品域给它打 / 摘 Sale 标签，支撑买家在搜索页筛「在打折的商品」。

| 项 | 内容 |
|---|---|
| **两类成因** | ①**折扣型**：到手价 < 挂牌价，跟随折扣生效期<br>②**挂牌价下调型**：当前挂牌价 < 上次记录挂牌价且降幅 ≥ 门槛，挂 N 天 |
| **⚠️ 最易实现错的一点** | **折扣型是「当期比较」，不需要历史基线**——「上架时就命中活动」的商品从没「贵过」，但到手价确实低于挂牌价，**首次扫描即打标**。详见 §2.11.1 的对照表 |
| **反面边界** | 到手价只计自动折扣 ⇒ **只配了优惠码的活动，命中商品不打 Sale 标签** |
| **打标粒度** | 渠道商品（listing）级，多渠道各自独立判定 |
| **新增触发源** | §2.12 触发清单新增「时间侧 · N 天窗口到期」——它不由任何动作驱动、是时间到了，现有触发面识别不到 |
| **下架/售出口径** | **不摘标、标签保留**，重新可售时重算 |

### 3.2 对外数据供给三形态 · PRD §2.10

把营销的对外输出收成一套统一定义：

| 形态 | 服务谁 | 内容 |
|---|---|---|
| A · 单品实时查询 | 商详、商品卡 | 到手价 + 促销优惠金额 + 划线价 + Save + 生效折扣的规则变量 |
| B · 批量索引供给 | 搜索 / Collection 的排序、价格区间筛、Sale 筛选 | 每个在售商品的当前到手价 + Sale 标记 |
| C · 订单级试算 | 购物车、checkout | 规则二（既有，未变） |

> **A 与 B 不是两套数据**：同一份「当前到手价」，A 是实时问一件、B 是全量推给索引。
> **B 不能用 A 实现**——排序要对整个结果集做，逐件实时取不成立。

### 3.3 价格状态基线 · PRD §2.11.3

新增一份 listing × market 级的持久状态：上次/当前挂牌价与到手价、最近降价时间、当前 Sale 资格与成因。
**同时补齐一个既有缺口**——v2.1 §2.3.4 要求「更新到手价基线」，但 ER v2.2 里该基线只存在于告警表，没触发告警的商品无处可存。

### 3.4 运营端新页面 · 营销中心 > 促销打标设置 · PRD §2.11.6 / 原型 v15

两个全局配置项：**最小降幅门槛**（默认 5%，1–50）、**Sale 保持天数**（默认 30 天，1–180）。
修改**即时生效于下一轮判定、不追溯**已打标商品。

> **刻意独立成页，不并入价格监控的「监控设置」弹窗**：价格监控是「发现异常降价 → 告警给运营」，
> 促销打标是「标记降价商品 → 供买家筛选」，两件事，只是恰好都以降幅为输入。

### 3.5 PRD 版本说明 · v2.2 → v2.3（无业务变更）

本包内 PRD 为 **v2.3**。相对 v2.2 **只有一处结构调整：删除了原 §〇「实现导航」**，**业务规则、章节号、章节顺序一字未改**（已逐行 diff 校验，§一 之后零差异）。

> **为什么删**：§〇 原本列「必读区 / 本期涉及章节 / 可跳过章节」，本意是让开发少读点。但 PRD 的规则依赖大量散落在「本期一个字没改」的章节里——照导航挑读反而会漏。**PRD 定位是全量口径载体，请通读，不要按章节挑读。**
> 本次改动**不产生任何实现工作量**，按 v2.2 已开工的部分完全不受影响。

## 4. 既有功能调整

### 4.1 ⚠️ 到手价接口输出：从 1 项扩到 5 项（改造点，必看）

| | V1.1 | V1.2 |
|---|---|---|
| 输出 | 只有「到手价」 | 到手价 + **促销优惠金额** + **划线价** + **Save** + **生效折扣的规则变量** |

- **「减免额」在对外输出语境改名为「促销优惠金额」**。§2.12 成因判定与 §2.8.3 规则二内部仍叫「减免额」，指同一个量——那两处描述的是计算过程，不是对外输出。术语表已说明两者关系。
- **规则变量共 7 个**（门槛类型 / 折扣值类型 / 百分比 / 固定金额 / 满额门槛 / 满件门槛 / 封顶），供前端按六模板拼活动规则标签。
- **只输出「计入到手价的那一条」折扣**——未达门槛的折扣不输出（与到手价计算同口径）。

### 4.2 ⚠️ 取价职责边界改写（§2.4）

**V1.1**：「价格展示逻辑归商详模块，营销侧只负责供给到手价」
**V1.2**：**数值由营销统一计算并输出**（到手价 / 促销优惠金额 / 划线价 / Save），**展示版式仍归各页面**。
取值规则本身未变，变的是**谁来算**。

### 4.3 ⚠️ C 端展示：Save 徽章与活动规则标签改为互斥（§2.4）

| 场景 | V1.1 | V1.2 |
|---|---|---|
| 有折扣 | 划线价 + Save 徽章 + 活动规则标签（三者并存） | 划线价 + **活动规则标签**；**不出 Save 徽章** |
| 无折扣但有对比价 | 划线价 + Save 徽章 | 不变 |

> **「数值」与「展示」是两回事**：营销侧**始终输出** Save 数值，只是商详与商品卡在有折扣时不渲染成徽章。**别把"不展示"实现成"不输出"。**

### 4.4 ⚠️ 活动规则标签文案：句子式 → Badge 式（§2.4）

| 配置 | V1.1 | V1.2 |
|---|---|---|
| 无门槛 × 百分比 | `20% off` | `20% OFF` |
| 无门槛 × 百分比 + 封顶 | `20% off (up to $100)` | `20% OFF` ← **封顶不再体现** |
| 无门槛 × 固定 | `$80 off` | `$80 OFF` |
| 满额 × 百分比 | `Spend $300, get 20% off` | `20% OFF $300+` |
| 满额 × 固定 | `Spend $300, get $80 off` | `$80 OFF $300+` |
| 满件 × 百分比 | `Buy 2+, get 20% off` | `20% OFF 2+` |
| 满件 × 固定 | `Buy 2+, get $80 off` | `$80 OFF 2+` |

- 最长串由 38 字符降至 13 字符，仍要求单行不换行、超出省略号截断
- **中文 Badge 文案待设计 / 运营确认**，PRD 只给英文源文案；⚠️ **不要沿用旧的折率换算规则自行拼中文**（那套是给句子式设计的）

### 4.5 下游取价改造表（C1）增补两行

| 页面 | 改造 |
|---|---|
| 搜索 / Collection **列表排序** | 按挂牌价 → **按到手价**。搜索 PRD §6.3 的「当前销售价」即到手价 |
| 搜索 / Collection **价格筛选滑块** | 按挂牌价区间 → **按到手价区间**，与排序同口径 |

> **实现归搜索 / Collection 模块**，营销侧只保证供给。**两者必须同口径**，否则同页两套价格：商品挂牌 $1,200 / 到手 $960，买家把滑块拉到 `$0–$1,000` 时，按到手价该出现、按挂牌价不出现，而他切到价格排序又能在 $960 附近看到它。

### 4.6 §2.3.4 扫描机制 → 独立为 §2.12（章节结构调整）

原挂在「§2.3 运营端 · 价格监控」下，现升为 **§2.12「到手价扫描与变更识别」**。
**原因**：它已不只服务价格监控——§2.11 促销打标、§2.10.3 索引供给都依赖同一套扫描与触发面。
**内容本身没变**（除新增「时间侧 · N 天窗口到期」一行 + 下架/售出对标签的口径说明），只是位置和引用改了。
> 扫描**只跑一遍**，价格监控 / 促销打标 / 索引供给三方各取所需。

## 7. 已知敞口与未决项（交付时请知悉）

### 7.1 ⏸ 唯一未决项：C4'（不阻塞开工）

**§2.4 有一条规则**：「门槛类折扣不达标时，仅以活动规则标签表达（如 `满 $100 减 $20`），引导买家凑单」。
**它与 §2.8.2「不输出未达门槛的折扣」冲突** —— 不输出，这条凑单标签就没有数据源。

> **产品尚未拍板删规则还是改口径。在拍板前，开发按 §2.8.2 口径实现（不输出未达门槛的折扣）**，
> 即 §2.4 那条凑单引导标签**本期先不做**。拍板后另行同步。

### 7.2 已接受的敞口（本期不处理）

| 敞口 | 后果 |
|---|---|
| 系统标签无管控 | ①运营手工解绑 Sale 标签后，系统下一轮又打回来，双方互相覆盖 ②标签若被停用，打标持续失败且无人察觉 |
| 索引异步的不一致窗口 | 筛出 Sale 点进去已无折扣，或反之。**以商详实时到手价为准**，列表不做二次校验 |
| 标签「使用次数」统计偏高 | 下架 / 售出不摘标的连带 |
| 封顶不在标签上体现 | 配了封顶 $100 的 20% 折扣，标签仍显示 `20% OFF` |
