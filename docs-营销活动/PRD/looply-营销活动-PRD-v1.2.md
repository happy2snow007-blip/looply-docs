# 一、概述

## 1.1 背景与目标

looply 作为面向美国+香港市场的二手奢侈品 B2C 平台(三方+自营商家入驻),V1 阶段需要具备基础促销能力驱动转化。本期参考 Shopify discount 模型,仅落地 **Amount off products(按商品/品类/品牌减价)** 一种促销类型,由平台运营配置、平台承担优惠成本。

目标:
1. 运营可配置自动折扣与优惠码两类触发的商品减价活动,多市场按币种独立控制力度
2. 买家在商详/购物车/checkout/订单详情看到一致、合规的促销价格与优惠明细
3. 资损三道防线落地:事前(配置试算拦截+封顶/限次)、事中(实付兜底+核销原子扣减+到手价监控)、事后(退款回滚+日对账+一键熔断)

## 1.2 不做什么(V1 明确边界)

| 不做项 | 说明 |
|---|---|
| Buy X get Y / Amount off order(订单满减) / Free shipping / 限时闪购 | V2 促销类型扩展 |
| 商家自建促销(商家出资、账单结算) | V2;V1 仅平台运营配置、平台出资(A1) |
| 预算池封顶(budget_total/spent) | 字段已预留,V1 不落逻辑 |
| 上线审批流 | V1 运营直接发布;靠试算拦截+监控兜底 |
| 定向码(一人一码,max_uses)/营销侧自建用户标签 | V2;V1 一码通用(D7),用户标签仅引用用户管理模块现有(含新客) |
| 折扣叠加(任何形式) | **V1 一律不叠加**(本版决策,取代原 can_combine 开关);combines_with 类别模型 V2 |
| 部分退款的优惠重算/追回 | V1 部分退款不回滚不重算(D3);依赖订单改价能力,V2 精细化 |
| 活动维度聚合统计/效果报表(转化、ROI) | V2;V1 仅核销计数与告警工作台 |
| 监控阈值按活动/品类覆盖、邮件告警通知 | V2;V1 全局单一阈值+站内提醒 |

## 1.3 用户角色

| 角色 | 端 | 职责 |
|---|---|---|
| 平台运营 | 运营后台 | 配置/发布/暂停/结束促销活动;处置到手价告警;查看核销与对账 |
| 买家(Buyer) | C 端(APP/PC) | 浏览促销价、输优惠码、下单享受折扣、查看订单优惠明细 |
| 系统 | — | 命中试算/行级分摊/核销/退款回滚/到手价扫描告警/日对账 |

## 1.4 核心场景

1. **配置发布**:运营新建折扣(选触发方式/折扣值/圈选商品/投放市场/使用条件/生效时间)→ 保存前价格试算拦截确认 → 发布生效
2. **C 端曝光转化**:买家商详页看到到手价+划线原价+促销标签 → 加购(购物车行级优惠+汇总)→ checkout 输码 → 试算(门槛/限次/封顶)→ 支付
3. **核销与回滚**:支付成功订单事件驱动原子核销(计数+1);整单退款事件驱动核销回滚(计数-1、限次释放)
4. **监控处置**:系统扫描在售商品到手价,降幅超阈值落告警 → 运营在价格监控排查计算链路 → 一键暂停活动/标记处理/忽略
5. **对账**:每日汇总核对有效核销 vs 订单优惠记录,不平即告警排查

## 1.5 全局页面流转

**运营端**(营销中心):
```
促销活动列表 → 新建折扣 → (价格试算确认弹窗) → 返回列表
促销活动列表 → 活动详情(基本信息 Tab / 核销记录 Tab) → 编辑折扣
促销活动列表 → [结束活动弹窗] [删除弹窗]
价格监控(一级菜单,与「营销中心」分组平级)→ 告警列表 → 排查抽屉(Drawer) / 监控设置弹窗
促销活动列表 告警轻量入口 → 价格监控
```

**C 端**(仅标注营销触点,页面本体归各自模块):
```
商详页(到手价/标签/用码提示) → 购物车(行级优惠+汇总优惠行) → checkout(优惠码输入+订单摘要优惠行) → 支付 → 订单详情(优惠快照)
```

## 1.6 术语说明

| 术语 | 定义 |
|---|---|
| 促销活动 / 折扣(discount) | V1 采用 1:1 简化:一个活动 = 一条折扣规则(promotion 与 promotion_rule 一一对应)。运营视角只感知"折扣活动"一个概念 |
| 自动折扣(auto) | 命中圈选商品即自动生效,无需输码 |
| 优惠码(code) | 买家在 checkout 输入优惠码触发;V1 一码通用 |
| 到手价 | C 端展示层的单品折后价 = 原价按**自动折扣**计算的结果;优惠码、用户级限次、订单门槛不计入,以提示形式表达 |
| 试算 | checkout/购物车的订单级优惠计算:带用户上下文,判定门槛/限次/封顶与同商品取优,输出可用优惠、减免额与**行级分摊明细** |
| 核销 | 支付成功后对一次优惠使用的计数记录(promotion_redemption),不记金额 |
| 回滚 | 整单退款后释放该次核销:status→reverted、已用次数-1、限次释放 |
| 不叠加(V1 硬性) | 同一商品行同时命中多条折扣时,**只取优惠最大的一条**生效;一单内不同商品各自享受各自命中的折扣(等同分开下单)。V1 不提供任何叠加配置项 |
| 最大优惠封顶 | percentage 折扣单件最大减免金额,按市场币种录值 |
| 划线价 | C 端展示的原价(line-through);口径 = 商品原售价(standard listed price),FTC reference pricing 合规要求 |

## 1.7 多语言支持

本模块为混合模块:**运营后台部分(促销活动管理、价格监控)仅面向内部运营,本期仅中文,不接入多语言**;以下三段仅覆盖 C 端部分。

**A. 静态 UI 文案**:C 端营销相关静态文案(促销标签模板、优惠码输入区按钮与校验提示、订单摘要行标题、合规说明等类别)由前端语言包实现(语言包落地,运营可在多语言后台查看/修改)。

**B. 动态业务内容 — 翻译服务接入**:

| 域名 | 卡片名 | 卡片编码 | 字段(fieldName) | 中文显示名 | 数据类型 | 展示面 | 备注 |
|---|---|---|---|---|---|---|---|
| marketing | 促销活动 | promotion | promotion_name | 活动名称 | text | 商详促销标签、购物车/checkout/订单详情优惠行、订单优惠快照 | 运营录入;订单侧展示为成交时快照值 |
| marketing | 优惠码 | promotion_code | code | 优惠码 | — | checkout 输入回显 | **不翻译**:优惠码为标识符,各语种原样展示(判定留痕) |

折扣力度标签(如 -20%)为计算值非录入文本,由前端按语种数字格式渲染,不接翻译。上游模块产生的内容(商品标题、品牌名等)由商品模块负责接入,本模块不代列。

**C. Fallback 规则**:引用多语言 PRD §4.6 统一策略——有译文返回译文 → 有过期译文返回旧译文 → 无记录返回英文源文本。产品不自定义。

# 二、需求详细描述

## 2.1 全局约定

1. **活动-市场 1:1(A6,硬性)**:一个折扣活动只属于一个市场,建活动第一步选定、创建后不可更改;活动的全部金额字段按所属市场币种显式录值,起止时间按所属市场本地时区判定。系统不做实时汇率换算,买家下单/结算/核销全程不用汇率(汇率模块仅可作运营录值时的等值参考)。
2. **时区口径(D5 更新)**:活动起止时间按所属市场本地时区判定,无需配置(单市场化后原 timezone_mode 废弃)。
3. **金额展示**:C 端所有促销金额按当前市场币种展示;运营端按市场行分币种录入与展示。
   **跨市场运营口径**:同一促销策略要在多个市场上线 = 在各市场分别建活动(列表"复制"操作支持以现有活动为模板复制后改所属市场与金额);活动名建议带市场标识。
4. **状态机(活动)**:

| 枚举值 | 含义 | 进入条件 | 退出条件 |
|---|---|---|---|
| draft 草稿 | 已保存未发布 | 新建时"存为草稿" | 发布→scheduled 或 active(按开始时间);删除→物理删除 |
| scheduled 未开始 | 已发布但未到开始时间,对 C 端不生效 | 发布时 now < start_at | 到达开始时间→active(定时任务);手动结束→ended |
| active 进行中 | 对 C 端生效 | 发布时 now ≥ start_at,或 scheduled 到达开始时间 | 暂停→paused;到达结束时间(定时任务)或手动结束→ended |
| paused 已暂停 | 临时停止生效(熔断) | 运营手动暂停 / 监控处置一键暂停 | 恢复→active;结束→ended |
| ended 已结束 | 终态,不可恢复 | 到期自动 / 运营手动结束 | 仅可删除(物理删除,已产生核销与订单快照不受影响) |

**scheduled 说明(本版新增)**:此前"已发布未到开始时间"的活动在列表显示为"进行中",与实际不生效相矛盾,运营易误判为已在打折。本版落为正式状态枚举:发布时按 `now` 与 `start_at` 比较落 scheduled 或 active;**需新增两个定时任务**——① scheduled→active(到达 start_at)、② active→ended(到达 end_at)。扫描周期建议 ≤1 分钟,生效判定仍以时间为准(定时任务延迟不影响 C 端计算,C 端候选集判定同时校验状态与时间)。scheduled 活动可编辑、可提前结束,不可删除(与 active/paused 一致,需先结束)。
**"已暂停"歧义消除**:paused 是可逆态(可随时恢复为 active),ended 才是终态。运营端状态标签需带 Tooltip 说明:"可随时恢复为进行中;如需彻底停止请用「结束活动」(不可恢复)"。
**状态存储分层说明**:paused 物理上落在规则层(promotion_rule.status=paused,即监控"一键暂停"的写入点),活动容器层(promotion.status)保留 draft/scheduled/active/ended 生命周期;1:1 模型下运营看到的活动状态 = 容器状态与规则状态的合成展示。分层保留 V2 活动容器多规则时"暂停单条规则≠暂停活动"的演进空间。
5. **操作记录**:运营端编辑页/详情页默认含操作记录区(操作时间/操作人/操作类型/操作详情);操作类型枚举:创建、编辑、发布、暂停、恢复、结束、删除、监控处置(告警侧)。
6. **空值显示**:运营端表格空值统一"—";上限类字段留空 = 不限。
7. **删除约束**:仅 draft/ended 可删除;active/paused 需先结束。结束/删除弹窗展示影响信息(名称/ID/已核销次数)。
8. **视觉细节**:运营端以原型 v8 为准;**C 端以 Figma 设计稿为准(出图中)**——本地 `UI/` 下的 8 份营销改动 html 自本版起**仅作历史参考,不再作为开发依据**(其中的价格故事线、FTC 合规文案、行级优惠展示等推演结论可供 Figma 出图参考)。PRD 不定义颜色/字号/尺寸。
9. **优惠资格锁定时点**:买家的优惠资格与金额以**订单创建(提交)时刻**的试算结果锁定;活动此后暂停/结束/到期不影响已创建订单(含未支付)的已锁优惠;支付成功核销时不再校验活动状态,仅执行唯一约束与原子计数。码类在支付发起前做总量/每人限次二次校验(§2.6)。

## 2.2 运营端 · 促销活动管理(页面型)

### 2.2.1 促销活动列表

**功能描述**:营销中心默认页,活动的查询、状态总览与操作入口。
**前置条件**:运营已登录后台(权限本期不分级)。
**页面元素**:
- KPI:进行中活动数 / 草稿数 / 本月累计核销次数 / 7 天内即将结束数
- 价格监控轻量入口:**左侧一级菜单「价格监控」的红色角标**(数字=待处理告警数,点击进入价格监控页);角标为 0 时不显示。**本版调整**:菜单由「优惠监控」更名为「价格监控」(该页监控的是商品到手价降幅,不是优惠本身),并由「营销中心」子项提升为一级菜单;「营销中心」分组保留,当前仅含「促销活动」。原列表页顶部告警 Alert 条已于 v1.1 移除——告警处置是价格监控页的职责,列表页常驻横幅挤占页面且与本页任务无关,改为全局菜单角标引导
- 筛选:关键词(活动名称/ID/优惠码)、状态(草稿/未开始/进行中/已暂停/已结束)、触发方式、起止日期、查询/重置
- 列表列:活动名称(+ID)、触发方式(自动折扣/优惠码+码值)、折扣内容(+封顶)、适用商品、市场(单值,A6)、状态(paused 带可恢复 Tooltip)、已核销(有效核销次数,整单退款回滚后自动核减)、生效时间、**创建信息(创建人 + 创建时间,两行)**、操作
- 默认排序:按创建时间倒序(全局约定 A.11)
- 头部操作:导出(当前筛选结果,含优惠码值列——兼作码投放的列表导出,D7)、新建折扣
- 操作(按状态驱动):详情、编辑(非 ended)、发布生效(draft)、暂停(active)、恢复(paused)、结束活动(scheduled/active/paused)、复制(可作为模板复制后改所属市场,A6)、操作日志、删除(draft/ended,红色)
- **操作列形态(规范 A.1.1)**:按该行自身的操作数**逐行判定**——操作数 ≤4 个全部平铺;>4 个则**前 3 个平铺、第 4 个起全部收进「更多」**下拉,可见元素恒为 4(3 按钮 + 更多)。排序优先级:详情 > 编辑 > 状态主操作(发布/暂停/恢复/结束)> 复制/操作日志 > 删除。各状态实际形态:

| 状态 | 操作数 | 平铺 | 更多下拉 |
|---|---|---|---|
| 草稿 | 6 | 详情 / 编辑 / 发布生效 | 复制 / 操作日志 / 删除(红) |
| 未开始 | 5 | 详情 / 编辑 / 结束活动 | 复制 / 操作日志 |
| 进行中 | 6 | 详情 / 编辑 / 暂停 | 结束活动 / 复制 / 操作日志 |
| 已暂停 | 6 | 详情 / 编辑 / 恢复 | 结束活动 / 复制 / 操作日志 |
| 已结束 | 4 | 详情 / 复制 / 操作日志 / 删除(红) | —(全平铺) |
- **复制规则**:复制生成 draft 新活动——名称加"副本"后缀;所属市场默认原值、保存前可改选(改市场时金额类字段清空,强制按新市场币种重录);圈选/条件/时间随模板复制;已核销计数归零;**优惠码不复制**(码类活动需重新生成或输入,避免优惠码全局唯一冲突)
**页面状态变体**:正常数据 / 零数据引导(新建折扣 CTA) / 筛选无匹配(清除筛选) / 网络异常(重试)。
**校验规则**:关键词模糊匹配活动名称、活动 ID、优惠码;日期范围与生效时间取交集。
**异常处理**:列表加载失败展示异常态;操作接口失败 Toast 提示并保持原状态;并发状态冲突(如他人已结束)提示"状态已变更,请刷新"。
**UI 关联**:运营端原型 v8 · 促销活动列表页(含 4 空态演示)。

### 2.2.2 新建 / 编辑折扣

**功能描述**:折扣活动的配置表单,7 分区;编辑页复用新建结构并追加操作记录区。
**前置条件**:新建无;编辑仅 draft/active/paused(active/paused 编辑后即时生效,谨慎提示见交互说明)。
**进行中(active/paused)编辑的字段范围**:锁定不可改——所属市场(A6)、触发方式、优惠码、折扣值类型;可改——活动名称、圈选明细、使用门槛、限次(总量不得小于已核销)、封顶、生效时间;修改保存即时生效并触发试算拦截(§2.2.3)与监控增量扫描(§2.3.4)。draft 状态全字段可改。
**页面元素与字段**:

| 分区 | 字段 | 控件 | 必填 | 规则 |
|---|---|---|---|---|
| 基本信息 | 所属市场 market_id | 大卡片单选(美国/香港) | 是 | **第一字段**;决定全表单金额币种与生效时区;创建后锁定不可改(A6) |
| | 活动名称 promotion_name | 输入框 | 是 | 1-100 字符;作为 C 端标签与订单快照(rule_name)来源;建议带市场标识 |
| | 触发方式 trigger_type | 大卡片单选 | 是 | auto 自动折扣 / code 优惠码 |
| | 优惠码 code(trigger=code 时) | 输入框+随机生成按钮 | 是 | 手动输入或系统随机生成;防猜校验:长度≥8、字母数字混合、禁纯连续序列(如 ABC12345 合法,12345678 拒绝);**全局唯一**——不同活动不可使用同一优惠码(含不同市场也不可重复);不区分大小写去重(存储归一为大写);V1 不提供码级单独停用(码随活动暂停/结束即失效),promotion_code.status=disabled 为 V2 定向多码预留 |

| | 折扣百分比 percentage_value | 数字(1-100,% off) | percentage 时必填 | 全市场统一;整数 |
| | 固定减价金额 fixed_amount | 数字(带所属市场币种符号) | fixed 时必填 | >0;不得 ≥ 圈选商品该市场最低原价(保存时试算校验提示) |

| 使用条件 | 使用门槛 min_type | 单选 | 是 | none / amount 满额 / quantity 满件 |

| 适用用户 | 适用用户 eligibility_type | 单选 | 是 | all 全部(默认)/ tag 指定用户标签;自动折扣与优惠码均受约束 |

**操作流程(主流程)**:填写 → 点"保存并发布"(或"存为草稿"/编辑页"保存")→ **保存前价格试算弹窗**(§2.2.3)→ 确认 → 落库并按状态生效 → 返回列表。
**分支流程**:试算发现降幅超阈值 → 返回修改;字段校验失败 → 定位到分区并标红提示。
**校验时机**:字段失焦即时校验;提交时全量校验;金额字段按币种区间合理性校验(>0,≤该市场最高原价)。
**交互说明**:所属市场用**下拉选择**(选项来自 market 模块的已开设市场,支持后续扩展至更多市场;编辑态禁用),选中后行内实时提示"金额以 X 录入 · 按 XX 时区判定生效";触发方式用**普通单选**(说明文案随选项联动)——两者原为大卡片式单选,占用大量纵向空间且市场数 >2 时横向挤爆,本版改为标准控件;金额类字段的币种符号随所属市场联动展示;适用用户选 tag 时展开用户标签多选;适用范围选「指定商品标签」/「指定 Collection」时展开对应多选,其中 Collection 下拉**仅列出与所属市场一致且已上线的集合**(切换市场时清空已选);叠加规则改为只读说明块(V1 一律不叠加,无配置项);active/paused 状态编辑保存时二次确认"活动进行中,保存后立即生效";存为草稿跳过试算弹窗(未发布无资损)。
**异常处理**:保存接口失败保留表单内容并提示;优惠码重复提示"该码已存在";商品圈选对象已下架时保存不拦截(下单动态判定,见 §2.8)。
**UI 关联**:运营端原型 v8 · 新建折扣 / 编辑折扣页。

### 2.2.3 保存前价格试算(资损事前拦截,机制+弹窗)

**功能描述**:发布(含进行中编辑保存)前,系统对圈选商品逐市场试算到手价,弹窗展示抽样结果与风险,运营确认后才落库。
**触发条件**:点"保存并发布"/进行中活动"保存"。
**处理流程**:
1. 系统按当前配置计算圈选商品到手价(仅计本折扣;若该商品同时命中其他进行中折扣,按不叠加规则取优惠最大的一条参与试算)
2. 弹窗展示:命中商品总数、抽样商品明细(现价/到手价/降幅)、降幅最大项
3. 存在降幅 > 全局监控阈值(§2.3.4)的商品 → 顶部警示,抽样必含该商品,降幅标红
4. 运营选择:返回修改 / 确认无误保存(弹窗操作记入操作记录)
**规则说明**:抽样规则=降幅 Top3(不足 3 件全量);试算仅为提示不强制阻断(V1 无审批流,确认权在运营)。
**异常处理**:试算服务超时 → 提示"试算暂不可用",允许"跳过试算继续保存"(记录操作日志"未试算发布")。
**UI 关联**:运营端原型 v8 · 价格试算确认弹窗(PriceCheckModal)。

## 2.3 运营端 · 价格监控(页面型)

### 2.3.1 告警列表

**功能描述**:到手价降幅监控告警工作台(独立二级菜单),发现→排查→处置闭环。
**页面元素**:
- 头部:监控设置入口、导出
- KPI:今日新增告警 / 待处理 / 本周已处置 / 监控中活动数
- 筛选:状态、活动、市场、降幅区间、时间范围
- 列表列:告警时间、商品(名称+listing ID)、命中活动(可多条)、市场、**价格对比(按类型区分基准:cumulative=原价→当前到手价;sudden_drop=上次到手价→本次到手价,辅注原价)**、**降幅**、状态、操作(排查;pending 另有忽略)
- **降幅列口径(本版调整)**:原独立的"类型"列已取消,比较基准直接写进降幅列——第一行是触发本次告警的那个降幅(含基准与阈值),第二行是另一维度的参考值:
  - cumulative:`较原价 -55% /阈值50%`(单行)
  - sudden_drop:`较上次 -25% /阈值20%` + 第二行 `较原价 -40%`(参考,未超阈值不显示阈值)
  取消独立类型列的原因:"类型"本身是抽象命名,运营看了仍需再查比较基准;把基准写进数据列后信息自解释,页面也少一列。类型名仅保留在**筛选器**与**排查抽屉**中,措辞统一为大白话:`比原价降太多` / `比上次降太多`(枚举 key `cumulative` / `sudden_drop` 不变)
- 筛选增加:告警类型
**状态机(告警)**:

| 枚举值 | 含义 | 进入条件 | 退出条件 |
|---|---|---|---|
| pending 待处理 | 新告警 | 扫描发现降幅超阈值且该商品+市场无未处置告警 | 处置→resolved/ignored |
| resolved 已处理 | 已处置 | 运营"标记已处理"(备注必填);记录处置动作/人/时间 | 终态 |
| ignored 已忽略 | 预期内降幅 | 运营"忽略"(列表行或抽屉内) | 终态 |

**告警类型(双阈值监控)**:

| 枚举值 | 含义 | 触发条件 | 记录内容 |
|---|---|---|---|
| cumulative **比原价降太多** | 深折监控 | 到手价相对**商品原价**的累计降幅 > 累计降幅阈值(默认 50%) | 原价/到手价/累计降幅/阈值快照/链路快照 |
| sudden_drop **比上次降太多** | 突变监控(捕捉折扣力度调整等配置变更导致的价格跳水) | 当前到手价相对**上一次扫描到手价**的单次降幅 > 环比降幅阈值(默认 20%),即使累计降幅未超阈值 | 上次到手价(prev_final_price)/当前到手价/环比降幅(change_pct)/阈值快照/链路快照 |

**告警生成与去重规则**:系统周期扫描进行中活动命中的在售商品各市场到手价,按上表双阈值分别判定并落告警(一次扫描可同时触发两类)。到手价基线(上一次扫描值)由监控服务内部维护,不落业务表。同一商品+同一市场+**同一告警类型**已存在 pending 告警时不重复生成,更新该告警至最新;处置后再次超阈值则生成新告警。
**UI 关联**:运营端原型 v8 · 价格监控列表页(含 4 空态)。

### 2.3.2 告警排查(抽屉)

**功能描述**:单条告警的排查与处置,核心是价格计算链路拆解。
**页面元素**:商品/市场/告警时间/告警类型(比原价降太多 / 比上次降太多)/累计降幅(对比阈值)/突降幅度(比上次降太多类:上次到手价→当前到手价+单次降幅,对比环比降幅阈值)/状态与处置记录;**价格计算链路表**(环节/命中规则/变动金额/小计,来自 calc_snapshot 快照,非实时重算);主因初判提示;处置区(仅 pending):按命中活动逐个"暂停「活动名」"(红)、处置备注、标记已处理、忽略本条。
**处理流程**:
1. 一键暂停活动 → 该活动 status→paused(即时对 C 端止损),告警记录 handle_action=pause_promotion;**告警不自动转已处理**——商品可能同时命中其他活动仍超阈值,需运营确认后手动"标记已处理"
2. 标记已处理 → 备注必填 → status→resolved,记录处置人/时间/动作
3. 忽略 → status→ignored(适用预期内深折,如清仓)
**异常处理**:暂停活动失败(已被他人结束等)提示并刷新;快照缺失时链路区显示"快照缺失,仅展示汇总"。
**UI 关联**:运营端原型 v8 · 告警排查抽屉(AlertDrawer)。

### 2.3.3 监控设置(弹窗)

**功能描述**:全局监控参数配置。
**字段**:累计降幅阈值(%,默认 50,范围 1-95,全局唯一)、环比降幅阈值(%,默认 20,范围 1-95,全局唯一;两者按活动/品类覆盖均为 V2);监控范围(固定:全部进行中活动命中的在售商品,只读);告警通知(V1 站内提醒,只读说明)。
**规则说明**:阈值修改即时生效于下一轮扫描;修改记录进操作日志。两个阈值均为系统配置项,不落 ER 业务表。
**UI 关联**:运营端原型 v8 · 监控设置弹窗。

### 2.3.4 扫描机制(机制型)

**触发条件**:周期扫描(建议频率:到手价变更事件驱动 + 兜底定时,具体周期由技术方案定);活动发布/恢复/编辑生效后触发一次增量扫描。
**处理流程**:取进行中活动命中的在售商品 × 投放市场 → 按 §2.8 到手价口径计算 → 分别与商品原价(累计)、上一次扫描到手价(环比)比对 → 超对应阈值按去重规则落告警,并更新到手价基线。
**规则说明**:扫描口径与 C 端到手价一致(仅自动折扣,同商品取优惠最大一条);监控只针对在售商品,售出/下架商品不扫描。

## 2.4 C 端 · 商详页与商品卡片营销展示(页面型)

**功能描述**:商品命中进行中自动折扣时,商详页展示促销价格组与提示。
**前置条件**:商品在售、命中至少一条进行中(时间已生效)自动折扣、当前市场在投放范围。
**页面元素**:
1. 促销到手价(替代原价格位,强调样式)
2. 划线原价(line-through)+ FTC 合规说明(一行小字:划线价为本商品的标准列表价)
3. 折扣标签(如 -20%)+ 活动名标签(如 Summer Sale,取 promotion_name 译文)
4. "用码另减"提示(存在进行中的、商品命中的 code 类折扣时):Extra $X off with code XXX at checkout;文案不计入到手价
**展示规则**:
- 到手价口径 = §2.8 展示口径(仅自动折扣、同商品取优惠最大一条、不计用户级限次与订单门槛、封顶生效)
- 门槛类折扣(满额/满件)不改变商详价格位,以标签+说明表达(如 Spend $100 save $20);V1 简化:满额/满件门槛折扣在商详只出活动标签不改价格
- 未命中任何自动折扣:价格区维持原定稿样式
- **商品列表页/推荐位等商品卡片**:同到手价口径展示促销价+划线原价+折扣标签(单品维度,不含码提示);样式以各模块卡片设计稿为准(商详改动稿推荐位卡片为样例)
- 适用用户限定(指定标签)的折扣:商详无登录用户上下文时按"可能可享"展示到手价,加购/结算按登录用户校验,不符合则该优惠不生效并提示(避免商详虚报);V1 商详不做用户级隐藏
- 活动暂停/结束/商品移出投放市场后,C 端即时恢复原价展示
**异常处理**:促销数据获取失败 → 降级展示原价(不阻塞商详);到手价计算结果 ≥ 原价 → 不展示促销组(防错配反向展示)。
**UI 关联**:C 端 Figma 设计稿(出图中,待定稿后回填链接);本地 `UI/` 旧 html 仅历史参考,不作开发依据。

## 2.5 C 端 · 购物车营销展示(页面型)

**页面元素**:

## 2.6 C 端 · checkout 营销功能(页面型)

**功能描述**:优惠码输入与订单级优惠试算展示;checkout 是优惠码唯一输入入口。
**页面元素**:
1. Promo code 输入区:输入框+Apply;成功态(码标签+减免金额+Remove);失败态提示
2. Order summary:Subtotal → Item discounts(自动折扣合计,含活动名)→ Promo code 行(码+减免)→ Shipping → Total(Tax 行有则展示,以 checkout 模块口径为准)
3. 兜底说明:Total 不会低于 $0
**操作流程(优惠码)**:输入 → Apply → 系统校验(§2.8 码校验)→ 成功:显示减免并重算 Total;失败:按失败原因提示 → Remove 移除后重算。
**校验失败枚举**:

| 失败原因 | 提示口径(语言包类别,具体文案以设计稿为准) |
|---|---|
| 码不存在/已停用/活动非进行中 | 无效或过期(码全局唯一,直接定位活动) |
| 未达满额/满件门槛 | 未达门槛(含门槛值) |
| 总量已用尽 | 已抢完 |
| 每人限次已用完 | 已达使用上限 |
| 与已享折扣互斥(V1 一律不叠加,该商品行已命中优惠更大的折扣) | 不可与当前优惠同享(同商品行取优惠最大一条,见 §2.8) |
| 商品范围不命中 | 所购商品不适用 |
| 码所属活动市场 ≠ 买家当前市场 | 该优惠码不适用于当前地区 |
| 用户不符合适用用户(未命中任一指定用户标签) | 该优惠码不适用于当前账户 |
**规则说明**:V1 单订单仅支持输入 1 个优惠码;**码不做预占**——Apply 仅校验可用性,使用次数的唯一占用时点 = 支付成功核销;支付发起前系统对码做总量/每人限次二次校验,失败则提示码已失效并重算(并发用尽场景);订单摘要各优惠行金额为试算分摊结果,支付成功后固化为订单优惠快照。
**异常处理**:试算服务异常 → 优惠不可用提示,买家可原价继续结算或稍后重试;码并发用尽(Apply 成功后支付时总量耗尽)→ 支付前二次校验失败,提示码已失效并重算。
**UI 关联**:C 端 Figma 设计稿(出图中,待定稿后回填链接);本地 `UI/` 旧 html 仅历史参考,不作开发依据。

## 2.7 C 端 · 订单详情营销展示(页面型)

**功能描述**:订单维度优惠快照展示(成交时口径,不随活动后续变化)。
**页面元素**:
1. 费用明细:Subtotal 后展示优惠行——Item discounts(活动名快照)−$X、Promo code XXX −$Y(来自订单 order_discount,活动名为 rule_name 成交快照)
2. 商品行:成交价(促销后)+划线原价小字+折扣标签
3. 退款说明行:优惠按比例参与退款金额计算(具体退款金额规则归订单模块)
**展示规则**:快照数据,活动结束/改名不影响历史订单展示;整单退款后订单详情仍展示原优惠明细(退款金额展示归订单模块)。

## 2.8 机制 · 优惠命中与试算 + 行级分摊(机制型)

**功能描述**:营销域对外供给的统一计算能力,商详到手价/购物车/checkout/监控扫描共用同一规则引擎,口径差异仅在输入维度。
**触发条件**:商详/列表到手价查询(单品,无用户上下文)、购物车/checkout 试算(订单级,带用户与码)、监控扫描(单品×市场)。
**处理流程(订单级试算)**:
1. **候选集**:所属市场=买家当前市场的、进行中(状态+按该市场本地时区的时间双判定)的折扣;逐商品行判定圈选命中(product_scope:all / 品类 / 品牌 / **商品标签** / **Collection** / 指定商品)。tag 与 collection 均为**命中任一即算(OR)**;collection 命中以**判定时刻**的商品池为准(池由 Collection 模块动态维护)
2. **可售动态判定(A5)**:指定商品圈选关系不物理删除;命中判定时按商品域实时可售状态——售出/下架商品暂不可享,退款回可售自动恢复
3. **门槛判定**:满额(min_amount,按所属市场币种)基准 = 命中商品行**当前售价(未计本折扣)的合计**;满件(min_quantity)按命中商品件数;不达门槛剔除
4. **适用用户判定**(带用户上下文时):eligibility_type=all 全部通过;tag 校验用户是否命中规则关联的任一用户标签(promotion_eligibility,标签含"新客"等、由用户管理模块打标);自动折扣与优惠码均执行此判定;不命中则剔除该折扣
5. **限次判定**(带用户上下文时):总量(有效核销 used_count<total_usage_limit)、每人((rule,user) 有效核销<per_user_limit);码类另判码有效性
6. **取优(V1 不叠加,硬性)**:所有折扣互相排斥。**同一商品行**命中多条时,取该行优惠金额最大的一条;**不同商品行**各自独立取优,一单内可同时存在多条不同折扣各作用于不同商品——等同于把这些商品分开下单分别享受各自折扣。整单优惠 = 各行生效折扣减免额之和
7. **单件计算**:percentage:减免=round(现价×比例),再按市场 max_discount_amount 封顶;fixed:减免=min(fixed_amount,现价)。**本版移除 max_item_count(每单作用件数)**:评估前期使用频次低,固定减价类的多件资损由实付兜底(§2.8)与到手价双阈值监控(§2.3)承接
8. **行级分摊**:订单级减免按行(按各行折后金额占比)分摊到商品行,尾差进金额最大行;输出分摊明细
9. **实付兜底(A2)**:最终实付 = max(应付合计 − 优惠合计, 0),由订单计算引擎统一夹逼执行一次;分摊结果随订单落 order_discount
**展示口径差异**:商详/卡片到手价=步骤 1/2/6/7(仅自动折扣、无用户与门槛判定,故适用用户(标签)限定的折扣在商详按未登录/全部展示,登录后购物车与结算再按用户标签校验);购物车=+门槛与适用用户判定(无码);checkout=全量。
**规则说明**:计算过程对齐 §2.3.4 扫描口径;所有金额计算按市场币种,无汇率参与。
**异常处理**:任一环节数据获取失败按各页面降级规则处理;引擎必须保证幂等(同输入同输出)。

## 2.9 机制 · 核销与退款回滚(机制型)

**功能描述**:优惠使用的计数与逆向释放,保证限次与对账一致。
**触发条件**:订单支付成功事件(核销);订单整单退款事件(回滚)。
**处理流程**:
1. **核销**:支付成功 → 订单事件 → 营销原子核销:写 promotion_redemption(status=valid,含 rule/code/user/order/redeemed_at),used_count+1;(rule_id,order_id) 组合唯一约束防重复;计数校验与自增在同一原子操作内完成,达 total_usage_limit 即拒绝(该情形支付前二次校验已拦截,此处为最终兜底)
2. **回滚(D3)**:整单退款 → 订单事件 → 该订单核销 status→reverted、记 reverted_at,used_count−1、每人限次释放;**部分退款不回滚不重算**,买家仍占用使用次数,不因退款后不再满足门槛而追回优惠(重算依赖订单改价能力,V2)
3. 限次判定、KPI、对账均只统计 status=valid 的核销
**异常处理**:核销事件消费失败重试(幂等保证不重复计数);回滚事件晚到/重复:reverted 终态幂等;**核销兜底拒绝**(总量被并发击穿后的最终拒绝):该订单已锁定的优惠保留、不向买家追回(体验优先),核销记录不写入,由日对账(§2.10)捕捉为差异记录供运营处理;订单事件与营销记录不一致由日对账兜底发现。

## 2.10 机制 · 资损对账(机制型)

**功能描述**:每日核对营销核销与订单优惠记录,发现资损或链路故障。
**触发条件**:每日定时(离线任务);支持手动触发。
**处理流程**:按活动×日汇总,三向核对——①valid 核销笔数 vs 订单 order_discount 记录笔数 ②回滚核销 vs 整单退款订单 ③used_count vs valid 核销实际计数。任一不平 → 生成对账差异记录并站内提醒运营(V1 提醒形式复用告警条,不落 alert 表;差异明细以导出文件承载,报表化 V2)。
**规则说明**:优惠金额合计以订单侧 order_discount 为准(营销不记金额)。
