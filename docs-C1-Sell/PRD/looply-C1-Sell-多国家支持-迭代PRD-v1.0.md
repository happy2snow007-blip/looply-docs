# Looply C1 Sell 多国家支持迭代 PRD

版本：v1.0

日期：2026-10-09
范围：C1 用户端、C1 运营后台及 C2/CMS 跨模块联动

## 一、需求概述

### 1.1 背景与目标

当前 C1 Sell 以美国业务为基础建设。随着 Looply 增加站点国家，C1 需要支持运营提前准备尚未开放国家的服务配置，并在国家满足开放条件后，按当前站点国家展示入口、读取业务内容和接收预约。

本次目标：

1. 建立国家级 Sell 业务开关，统一控制该国家的 C1 展示和预约资格。
2. 允许运营提前维护尚未开放国家的 C1 配置；当前版本只明确美国 ZIP、Category 和 Brand 的业务规则。
3. C1 用户端和运营后台的数据读取、写入、查询、导入及导出均按国家隔离。
4. 明确 PC Header、Mobile 底部导航、Footer、Contact Us 和个人中心的跨模块联动。

### 1.2 改造范围

| 范围 | 本次改造 |
|---|---|
| C1 用户端 | 按当前站点国家判断入口、访问资格、配置内容和预约提交 |
| C1 运营后台 | 新增服务国家；ZIP、Category、Brand 和 Appointment 支持国家维度 |
| C2 业务国家管理 | 作为国家主数据和 C2 启用状态来源 |
| CMS | PC 导航、Mobile 导航、Footer、Contact Us 和个人中心按国家联动 Sell 状态 |
| 数据 | C1 配置与预约增加稳定 `country_code` |

### 1.3 页面与系统流转

```text
C2 业务国家管理
  → C1「服务国家」选择国家
  → 提前维护 ZIP / Category / Brand
  → C2 启用国家
  → C1 运营手动开放 Sell
  → 各前台模块按当前站点国家展示 Sell 内容
  → 用户提交预约
  → Appointment 记录提交时国家
```

## 二、国家与 Sell 状态

### 2.1 国家来源

- C1 不创建国家，统一读取「C2 业务国家管理」中全部有效、未删除国家。
- 国家选择范围不受 C2 当前启用状态限制；C2 未启用国家允许提前加入 C1。
- 已加入 C1 服务国家列表的国家不再出现在新增国家下拉选项中。
- C2 国家名称、国家代码和启用状态在 C1 中只读，并随 C2 更新。

### 2.2 状态模型

| C2 国家状态 | C1 Sell 状态 | 是否可维护配置 | 前台是否生效 | 是否接收新预约 |
|---|---|---:|---:|---:|
| 未启用 | 未开放 | 是 | 否 | 否 |
| 未启用 | 开放 | 不允许出现 | 否 | 否 |
| 已启用 | 未开放 | 是 | 否 | 否 |
| 已启用 | 开放 | 是 | 是 | 是 |

前台生效条件固定为：

```text
C2 国家状态 = 已启用
且 C1 Sell 业务状态 = 开放
```

### 2.3 状态变化

- C2 未启用时，C1 的开放操作置灰，但允许保存国家并提前维护配置。
- C2 从未启用变为已启用后，Sell 保持未开放，不自动生效；运营需要手动开放。
- 第一版不在后台检查该国家是否已完成 C1 业务适配。产品、开发和运营需在上线前人工确认地址、表单、法律文件及相关前后台能力已具备，再由运营开放 Sell。
- 运营停用 Sell 时需二次确认。停用后隐藏入口并停止接收新预约，保留配置和历史预约。
- C2 停用一个已开放 Sell 的国家时，系统同步将 Sell 改为未开放并立即停止前台生效。
- C2 删除或不再提供某个国家时，C1 将其视为不可用国家，Sell 改为未开放并停止前台生效；该国家已有配置和历史 Appointment 保留，不再接受新的配置写入或预约。
- C2 重新启用后，Sell 仍保持未开放，需运营重新开放。
- Sell 停用或 C2 国家停用成功后，服务端立即拒绝该国家的新预约。用户刷新页面、重新进入页面或切换国家时，相关入口按最新状态隐藏。
- 对已经打开 Sell 页面或预约流程的用户，不强制关闭当前页面；用户继续下一步或提交时重新校验状态。Sell 已不可用时阻止继续并提示 `Sell service is currently unavailable in your country.`。

## 三、C1 用户端多国家改造

### 3.1 当前国家来源

C1 使用全站当前实际生效的站点国家，不自行重新判断国家。通过带国家子目录 URL 进入网站时，以 URL 对应国家为准，不被 IP 覆盖；裸域国家识别沿用 C2 全站规则。

前台不得使用以下数据替代当前站点国家：

- 运营后台最近选择的国家；
- 其他国家的 C1 配置；
- 默认美国配置。

### 3.2 入口和访问资格

| 位置 | 展示条件 | 未满足时 |
|---|---|---|
| PC Header | 当前国家 C2 已启用且 Sell 已开放 | 隐藏 Sell |
| Mobile 底部导航 | 当前国家 C2 已启用且 Sell 已开放 | 隐藏 Sell |
| PC Footer | 当前国家 C2 已启用且 Sell 已开放 | 隐藏 C1 内容 |
| Contact Us | 当前国家 C2 已启用且 Sell 已开放 | 隐藏 Sell 联系选项 |
| 个人中心 | 当前国家 C2 已启用且 Sell 已开放 | 隐藏 Seller Agreement |

所有 C1 相关入口和内容统一跟随当前国家的 Sell 业务开关，不再额外设置入口级或内容级 Active 展示条件。Sell 已开放时，各模块读取当前国家的对应配置；Sell 未开放时，隐藏对应 C1 入口和内容。

用户通过 URL 直接进入 Sell 页面时，页面仍需校验当前国家。当前国家未开放 Sell 时，不允许开始或提交预约；新预约接口必须在服务端再次校验，不能只依赖前端隐藏入口。

当前国家 Sell 未开放时，直接访问 Sell 页面展示当前国家暂未提供 Sell 服务的受限状态，并提供返回首页入口。

### 3.3 Footer、Contact Us 和个人中心

当前国家不满足 Sell 生效条件时：

- Footer 隐藏整个 `SELL` 栏及 `Sell with Looply`、`Accepted Brands`、`Condition Guidelines`、`In-Home Service Area` 等链接。
- Footer 的 `SUPPORT` 栏隐藏 `Seller FAQ`，保留 `My Account`、`Shipping`、`Returns & Refunds`、`Contact Us` 等非 C1 内容。
- Footer 底部隐藏 `Seller Agreement`，保留通用法律链接。
- 个人中心隐藏 `Seller Agreement`。
- Contact Us 隐藏 `Selling to Looply` 和 Sell 联系邮箱，保留 Buy 或其他联系选项。

当前国家满足 Sell 生效条件后，上述位置读取本模块当前国家的配置；入口展示本身不再单独配置启停。
本条国家级 Sell 开关规则优先于 Footer PRD v0.5 中关于入口单独维护展示或排序的旧规则；本期 C1 入口不增加独立启停配置。

### 3.4 ZIP Coverage

- Service Area 和预约流程只读取当前站点国家下的 Active ZIP 配置。
- 覆盖结果只决定 In-Home Service 是否可用，不决定国家级 Sell 入口是否展示。
- 当前版本仅定义美国规则：用户端接受 5 位 ZIP（如 `90048`）和 ZIP+4（如 `90048-1234`）；查询 In-Home Service 覆盖范围时统一取前 5 位。
- 其他国家的地址字段、服务区域标识和表单校验不在本 PRD 中预设，开通该国家 C1 前另行定义。
- 无 Active 配置时按 Service Area 空数据规则处理，不回退其他国家。
- 当前国家无 Active ZIP 时，按没有可用 In-Home Service 区域处理，不阻止用户选择其他可用 Sell 方式。

### 3.5 Categories & Brands

- Accepted Brands 和预约表单只读取当前站点国家下的 Active Category 和 Brand。
- 只有 Category 与 Brand 均为 Active 时，该 Brand 才进入前台配置结果。
- Category 按后台顺序展示。预约表单中的 Brand 按所属 Category 内的后台顺序展示。
- Accepted Brands 页面先按当前国家、Active 状态和所选 Category 过滤，再按 Brand name 大小写不敏感去重，最后按品牌标准名称的首字母分组；同一首字母分组内保留后台顺序。
- 配置为空时按对应页面空数据规则处理，不回退其他国家。
- Sell 已开放但无 Active Category 时，相关内容区域展示空状态；预约流程进入品类选择步骤后阻止继续，不允许使用其他国家配置补足。

### 3.6 Appointment 国家归属

- 预约提交时记录当前实际生效的 `country_code`，此后不因 IP、Cookie、账号偏好或用户切换国家而变化。
- 表单的 ZIP、Category 和 Brand 均读取该国家配置。
- 服务端创建预约前再次校验 C2 已启用且 Sell 已开放。
- 国家关闭 Sell 后不接受新预约；历史预约继续保留和查询。

### 3.7 预约草稿与国家切换

- 预约草稿按保存时的站点国家隔离，并记录对应 `country_code`。
- 用户回到同一国家时，可按既有草稿有效期恢复该国家草稿；切换到其他国家时不恢复原国家草稿，展示该国家的新预约表单。
- 用户切回原国家后，原国家仍在有效期内的草稿可继续恢复；草稿不在国家之间迁移。
- 提交前重新按当前国家校验 Sell 状态、ZIP、Category 和 Brand。校验失败时阻止提交并保留可继续使用的表单内容。

## 四、C1 运营后台多国家改造

本章只定义运营后台增加国家维度后的变化。ZIP、Category、Brand 和 Appointment 未发生变化的字段、操作与异常规则分别沿用[运营后台 PRD v1.13 第三至六章](./looply-C1-Sell-运营后台-PRD-v1.13.md#三zip-coverage)；其中其他国家的 Postal Code、地址字段和校验示例不属于本期范围。

### 4.1 服务国家

新增一级入口「服务国家」，列表字段如下：

| 字段 | 规则 |
|---|---|
| 国家 | 来源于 C2 业务国家管理 |
| 国家代码 | C2 回填，只读 |
| C2 国家状态 | 已启用 / 未启用，只读 |
| Sell 业务状态 | 开放 / 未开放 |
| 操作 | 开放、停用或查看配置 |

列表中的状态与开放、停用规则以第二章为唯一口径。新增国家默认不开放；C2 已启用后允许运营开放 Sell，后台不额外检查该国家的 C1 业务适配状态，运营须在开放前完成人工上线确认。

### 4.2 国家配置上下文

ZIP Coverage 和 Categories & Brands 页面顶部展示当前国家。切换国家后：

- 重新读取目标国家数据；
- 清空搜索词、勾选记录和页面展开状态；
- 新增、编辑、排序、启停、导入、导出和删除只作用于当前国家；
- 唯一性只在当前国家及对应业务层级内校验。
- 表单或抽屉存在未保存内容时，切换国家前提示内容将丢失；用户确认后关闭当前编辑并切换，取消则保留当前国家和输入内容。
- 新增、编辑、导入和删除操作在启动时固定目标国家。已提交的导入或批量删除任务允许用户切换页面国家，但任务及其结果仍归属于原目标国家。
- 失败任务的 Retry 继续作用于原目标国家，不因页面当前国家变化而改变。

### 4.3 ZIP Coverage

- ZIP Coverage 的既有操作均作用于当前配置国家。
- 运营后台仅维护美国 5 位 ZIP。ZIP 去除首尾空格后按 5 位数字校验，同一国家内必须唯一；不同国家之间允许相同 ZIP。
- Import 使用当前国家模板并写入当前国家；Export 导出当前国家和搜索条件下的匹配记录；批量 Delete 只删除任务目标国家内的记录。

### 4.4 Categories & Brands

- Category 和 Brand 按国家维护；Brand 归属于当前国家下的一个 Category。
- 既有新增、编辑、启停、排序、删除和 Brand Import 均作用于当前配置国家。
- 同一国家、同一 Category 下的 Brand name 大小写不敏感且唯一；不同国家允许同名 Category 和 Brand。
- Category 级联删除、Brand 批量删除或停用只影响任务目标国家，不影响其他国家配置。

### 4.5 Appointments

- 列表提供「全部国家」及单一国家筛选，默认全部国家。
- 每条预约展示提交时固定记录的 Country。
- 国家筛选与关键词、Submitted at 日期范围共同生效。
- Download 导出当前筛选条件匹配的全部记录，并包含 Country。
- 关闭 Sell 不删除历史预约；详情、确认邮件重发和 Internal note 功能继续可用。

## 五、数据与跨模块一致性

### 5.1 数据要求

以下对象必须保存稳定 `country_code`：

- Sell 服务国家；
- ZIP Coverage；
- Category；
- Brand；
- Appointment；
- PC/Mobile Sell 导航配置；
- Footer、Contact Us 和个人中心的 C1 配置。

查询、写入、唯一性校验、排序、导入、导出、删除和前台读取均使用该国家维度。

存量数据处理：

- 上线前已有且缺少 `country_code` 的 ZIP Coverage、Category、Brand 和 Appointment 统一归属美国。
- 美国 Sell 初始状态设为开放；其他新增国家默认未开放。
- 存量配置的启停状态、排序和历史 Appointment 保持不变。

### 5.2 一致性与失败处理

- 国家或 Sell 状态变更成功后，前台在用户刷新页面、重新进入页面或切换国家时读取最新状态；无论页面是否仍展示旧内容，下一步和预约提交均以服务端最新状态为准。
- 国家切换请求失败时保留原国家和原数据，不展示目标国家的部分结果。
- 状态保存、排序、导入或删除失败时保留当前输入或恢复原状态，并提供 Retry。
- C2 国家状态或当前国家配置读取失败时展示加载失败和 Retry，不展示缓存中的其他国家数据，也不允许提交新预约。
- 不允许在某一国家无数据或加载失败时静默回退美国或其他国家数据。
- 历史 Appointment 保存用户提交时的 Category、Brand、ZIP 和协议信息，不随后续配置删除或改名变化。

## 六、依赖与边界

| 依赖 | 要求 |
|---|---|
| C2 业务国家管理 | 提供全部有效、未删除国家和实时启用状态 |
| 全站国家识别 | 提供当前实际生效国家；C1 不重复判断 |
| 上线确认流程 | 国家 C1 业务适配完成度由产品、开发和运营人工确认，不在后台增加检查状态 |
| PC/Mobile 导航 CMS | 按国家维护 Sell 入口内容，并消费国家级 Sell 状态 |
| Footer / Contact Us / 个人中心 | 按国家维护 C1 内容，并消费国家级 Sell 状态；不单独配置入口启停 |
| 地址能力 | 用户端接受美国 5 位 ZIP 和 ZIP+4，覆盖查询取前 5 位；运营后台仅维护 5 位 ZIP，并回填 City、State |
| 翻译能力 | Category 等动态内容按既有翻译资源规则处理 |

新增国家可提前加入 C1 服务国家列表；当前版本只实现并验收美国的 ZIP、地址和预约表单规则。其他国家的具体业务字段和校验需在开通前另行确认，不由本 PRD 预设。

## 七、验收标准
1. C1 可读取 C2 全部有效国家；C2 未启用国家可加入并提前配置，但不能开放 Sell。
2. C2 启用国家后 Sell 不自动开放；完成上线前人工确认后，运营可手动开放，后台不额外检查 C1 业务适配状态，开放后前台生效。
3. C2 或 Sell 停用后，PC Header、Mobile 底导、Footer、Contact Us 和个人中心按规则隐藏 C1 内容，新预约被服务端阻止。
4. Footer 在 Sell 未开放国家隐藏整个 SELL 栏、Seller FAQ 和 Seller Agreement，同时保留非 C1 内容。
5. 当前站点国家只读取本国 Active ZIP Coverage、Category 和 Brand，不回退其他国家；美国用户端接受 5 位 ZIP 和 ZIP+4，覆盖查询取前 5 位，运营后台仅允许维护 5 位 ZIP。
6. ZIP、Category 和 Brand 各自已定义的新增、编辑、启停、排序、导入、导出和删除操作均只影响当前或任务目标国家；本条不为任一对象新增原 PRD 未定义的操作能力。
7. 同一国家重复 ZIP、Category 或同一 Category 下的 Brand 无法保存；不同国家允许相同业务值。
8. Appointment 固定保存提交时国家；后台可查看全部国家或单一国家，Download 包含 Country。
9. Sell 停用或 C2 国家停用不删除配置和历史 Appointment；重新启用 C2 后仍需手动开放 Sell。
10. 国家切换、加载失败和保存失败均不会展示或写入其他国家数据。
11. 美国存量 ZIP、Category、Brand 和 Appointment 在改造后归属美国，原启停状态、排序和历史记录保持不变；美国 Sell 初始为开放，其他国家默认未开放。
12. 预约草稿按国家隔离；切换国家不恢复或迁移原国家草稿，切回原国家后仍可在既有有效期内恢复。
13. 后台存在未保存内容时切换国家需用户确认；已提交的导入、批量删除及 Retry 始终作用于任务启动时的国家。
14. Sell 停用后服务端立即阻止新预约；已打开页面在继续下一步或提交时重新校验并展示不可用提示。
15. 当前国家 Sell 未开放、业务配置为空和数据读取失败分别展示对应状态，且均不回退其他国家配置。
16. C2 删除或不再提供某个国家后，该国家 Sell 不再生效、不接受新配置写入或预约，但历史配置和 Appointment 仍可按原国家查询。

### 7.1 Demo 对齐要求

本 PRD 进入开发交付前，后台 Demo 需同步体现以下规则：

- Appointment 下载结果包含 Country；
- 切换配置国家后清空搜索词、勾选记录和展开状态；
- ZIP 批量删除单次最多 500 条；
- Brand 批量删除展示实际选中数量；
- 不将其他国家的具体 Postal Code、地址字段或校验规则作为本期实现示例；
