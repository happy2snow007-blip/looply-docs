# C1 Sell：C2 公共埋点规范引用入口

> 版本：v1.1｜日期：2026-09-10｜用途：C1 开发附件

## 1. 使用方式

C1 不建立第二套身份、Session 或页面上下文。开发直接复用 C2 公共采集层和机器字段；本页只提供可访问的原始文件入口、C1 需要关注的章节和冲突升级规则，不复制或改写 C2 规范。

规范读取顺序：

1. `looply-一方埋点公共实施规则-v1.8.md`（跨事件生命周期与字典）；
2. `Looply-v1.4-公共基础字段需求定稿-v1.1.xlsx`（公共字段、来源和缺失处理）；
3. `Looply-v1.4-详细埋点需求定稿-v1.3.xlsx`（事件和点位）；
4. C1 PRD 与 C1 点位清单（仅补充 C1 业务语义）。

如开发环境无法访问文档中心，使用项目内 `looply-docs/docs-数据采集与埋点/一方平台开发基线/` 下的同名文件，或由数据平台提供上述文件的只读副本。不得按本页重新实现一套公共字段。

## 2. C1 复用范围

- 身份：`domain_userid`、`anonymous_id`、登录态 `user_id`，按公共采集层提供的真实上下文复用；扩展字段存在下节冲突，C1 不自行新增。
- Session：复用 Snowplow `domain_sessionid`（一方 `session_id`），不生成 C1 专用 Session，也不使用 GA4 Session 代替。
- 页面：复用 `page.page_type`、`page.page_id`、`page_instance_id`、`previous_page_type` 及公共来源/设备/语言/市场字段。
- 事件通用规则：复用 `event_id`、事件时间、重试去重、页面实例生成和敏感数据边界；C1 只增加自身业务字段（如 `selling_method`、ZIP 结果状态、预约步骤）。
- C2 → C1 → C2 在同一浏览器配置下应保持身份和 Session 连续；页面实例按真实打开、刷新和有效路由切换生成。

## 3. 必须升级确认的冲突

当前本地存在两份口径不一致的 C2 文档，不能静默合并：

| 主题 | 公共实施规则 v1.8 | 数据采集与埋点 PRD v1.9 | C1 处理 |
|---|---|---|---|
| Snowplow Session 续期 | 任一实际发送的 Snowplow 客户端事件续期；30 分钟无此类事件后新建 | 仅前台有效事件创建/续期，技术事件不续期 | 暂停冲突字段联调，由数据平台负责人确认最终实施基线 |
| 身份字段 | 明确不新增 `identity_state`、`canonical_person_id` | 定义了上述扩展字段 | C1 暂不自行增加；以数据平台确认结果为准 |
| 事件命名 | 保留既有物理事件名 | 部分示例改用 GA4 推荐名 | C1 以已确认机器契约为准，不自行改名 |

在冲突关闭前，可以继续盘点 C1 业务点位和已有公共采集层接入位置，但不按任一冲突口径新建或改写身份、Session 逻辑，也不得宣称已完成公共字段联调。数据平台负责人需提供当前实际采用的规范版本、SDK/机器契约位置及脱敏样例；确认后在 C1 PRD 和点位 Excel 的“公共字段复用”页记录确认版本及日期。

## 5. 验收最小用例

同一浏览器依次访问 C2 → C1 Sell → C2：核对三段事件的 `domain_userid`、`anonymous_id`（可取得时）和 `session_id` 连续；C1 页面切换时核对 `page_instance_id` 按页面实例变化。发现字段缺失或 Session 口径不一致，记录实际事件载荷并升级，不以猜测补值。
