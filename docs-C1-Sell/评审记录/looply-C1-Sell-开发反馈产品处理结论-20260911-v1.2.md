# C1 Sell 埋点开发反馈：产品处理结论

> 版本：v1.2｜日期：2026-09-11｜状态：待开发评审
>
> 本文仅处理本轮反馈中的产品需求问题；不规定 SDK、事件传输、GA4 配置、数据平台查询实现或其他技术方案。

## 1. 最终 UI 事实源

产品确认以 [Figma《1.1-C1业务》](https://www.figma.com/design/XIl3SfaIL8y2xy6yJnrrJE/1.1-C1%E4%B8%9A%E5%8A%A1?node-id=0-1&p=f&m=dev) 为 C1 全量 UI 基线；预约流程节点见 [`3:6738`](https://www.figma.com/design/XIl3SfaIL8y2xy6yJnrrJE/1.1-C1%E4%B8%9A%E5%8A%A1?node-id=3-6738&m=dev)。PRD v1.4 已写入上述链接。

埋点只覆盖 Figma 中实际呈现、且会改变页面/流程、影响转化或回答业务问题的控件与状态；PC 与 Mobile 采用相同业务语义，只有真实控件不同才区分 `element_id`。

## 2. 四类核心运营指标

产品同时保留两套口径：核心业务结果采用“流程与结果口径”，页面浏览、点击和用户偏好采用“原始事件量口径”。原始行为量不作为转化主口径：

- 需求规模：主指标为唯一 C1 `page_instance_id` 的页面访问量；会话和用户只作为辅助切分。
- 预约漏斗：按唯一 `seller_flow_id` 统计预约开始、各步骤到达和前台接口成功；返回、刷新、草稿恢复、重复点击和 Retry 不重复增加同一流程的主漏斗计数。
- 售卖方式：最终方式按前台接口成功时的方式互斥统计；用户主动切换方式按每次实际选择或切换统计，可跨方式、跨次数重复出现，不作为互斥占比。
- 服务区域：按明确终态的唯一 `coverage_check_id` 统计；覆盖率仅以 covered 与 uncovered 的成功查询为分母，非法和失败单列。

页面到达、首页有效内容曝光、字典内点击、筛选与展开，以及表单内用户主动选择均保留原始行为量；自动推荐、自动恢复和自动切换不计为用户偏好。后台预约创建量按唯一 `request_id` 独立展示，不与前台提交成功率拼接、相除或逐条对账。完整分子、分母、去重和并列规则见 PRD v1.4 第 9.1、9.2 节。

## 3. 已有产品结论，不再新增需求

| 反馈项 | 产品结论 |
|---|---|
| PRD 与 Excel 字典 | Excel v1.2 维护逐点执行定义；PRD 维护业务口径与同源索引。同一 `point_id + variant_id` 的字段成组匹配，不自由拼接。 |
| 前台提交与后台创建 | 两类事实独立统计；本期不新增提交关联 ID，也不要求逐条关联。 |
| GA4 | 产品只定义进入 GA4 的业务事件、参数白名单、隐私边界与可查询验收结果。 |

## 4. 不是新增产品需求的问题

- Excel v1.2、C2 引用附件与开发输入清单作为同一批开发输入交付；开发未取得最新文件属于交付材料可得性问题，不改变埋点产品口径。
- C2 公共字段的实际运行基线由平台统一管理。C1 产品要求仅为“复用平台公共字段，不另建 C1 身份或 Session”；不在本需求中裁决平台内部版本差异。

本轮产品需求已通过 PRD v1.4 关闭 UI 事实源与四类指标口径两项缺口；其他实现与平台依赖按各自责任处理。
