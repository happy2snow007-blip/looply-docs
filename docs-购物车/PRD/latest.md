## 1. 模块概述

### 1.1 定位

购物车是用户从"浏览商品"到"下单结算"的中转站。用户可将感兴趣的商品加入购物车，后续统一选择、管理并发起结算。

### 1.2 核心特征

- **二手单品模式**：每件商品为唯一实物，数量固定为 1，不可修改数量
- **匿名可用**：未登录用户可正常使用购物车（通过设备标识识别），登录后自动合并
- **实时库存**：商品随时可能被他人购买导致售罄，购物车需实时反映可购状态
- **双端差异形态**：APP 为全屏独立页面，PC 为侧边抽屉（从右侧滑出）

### 1.3 范围

本文档覆盖购物车的前端交互与业务逻辑，不涉及：
- 结算/支付流程（属于订单模块）
- Wishlist 详情页（属于收藏模块，本文仅涉及"Save for Later"入口）
- 商品推荐算法（本文仅定义推荐区位置和展示规则）

### 1.4 术语

| 术语 | 说明 |
|---|---|
| Listing | 渠道商品记录，包含具体实物商品在某渠道的上架信息和售价 |
| Unavailable | 购物车中已售罄或已下架的商品，不可结算 |
| Save for Later | 将商品从购物车移入 Wishlist（收藏夹） |

## 2. 购物车基础规则

### 2.1 用户识别

| 场景 | 识别方式 | 说明 |
|---|---|---|
| 未登录 | 设备标识（Cookie UUID） | 购物车数据存服务端，设备标识由浏览器 Cookie 生成 |
| 已登录 | 用户 ID | 登录后购物车绑定账号，跨设备可见 |

### 2.2 登录合并

用户登录时，系统自动将当前设备的匿名购物车合并到账号下：
- 同一商品（同一 listing）已存在于账号购物车 → 保留账号侧，丢弃匿名侧
- 不冲突的商品 → 迁移到账号购物车

合并过程对用户无感知，无需弹窗或提示。

### 2.3 容量上限

- 单用户购物车上限 **100 件**（登录/匿名各自独立计数）
- 达到上限时加购失败，Toast 提示：  
  *"Your cart is full (100 items). Remove or move items to your Wishlist to add more."*

### 2.4 商品生命周期

| 事件 | 行为 |
|---|---|
| 加入购物车 | 创建购物车项，默认选中 |
| 商品售罄/下架 | 自动标记为 Unavailable（实时查询 listing 状态，不冗余存储） |
| 商品重新上架 | 自动恢复为可购状态 |
| 用户删除 | 永久移除（硬删除） |
| Save for Later | 从购物车移除 + 加入 Wishlist |

### 2.5 勾选状态

- 每个购物车项有 `selected` 字段，加入时默认 `true`
- 勾选状态持久化：用户下次进入购物车保持上次的勾选状态
- 售罄商品自动取消勾选，不参与结算
- 结算接口统一按 `selected = true` 的可购商品结算，不按端做分支逻辑

**两端差异仅在 UI 层：**

| 端 | 勾选 UI | 行为 |
|---|---|---|
| APP | 复选框（单选 + Select All） | 用户可手动切换 `selected` |
| PC | 无勾选 UI | 加购后始终 `selected = true`，用户不可修改 |

## 3. 加入购物车（Add to Cart）

本章定义"加入购物车"的通用能力，供商详页、列表页、推荐区等业务场景接入。

### 3.1 触发入口

| 场景 | 入口形式 |
|---|---|
| 商详页 | Add to Cart 按钮 |
| 商品列表/搜索结果页 | 商品卡片上的 Add to Cart 按钮 |
| 购物车内推荐区（You May Also Like） | 推荐卡片上的 Add to Cart 按钮 |
| 收藏夹（Wishlist） | Move to Cart 按钮 |

### 3.2 加购成功反馈

**购物车模块职责（接口 + 自身 UI）：**
- 接口返回加购成功结果（含最新购物车商品数量）
- 导航栏购物车徽标数字同步更新（规则见 7.4）

**接入方职责（各业务页面自行实现）：**
- 页面跳转策略、成功动画、Toast 提示等前端反馈效果，由各接入页面根据自身场景决定

### 3.3 加购失败场景

| 场景 | 反馈 |
|---|---|
| 商品已在购物车中 | Toast：*"Already in your cart"* |
| 购物车已满（100 件） | Toast：*"Your cart is full (100 items). Remove or move items to your Wishlist to add more."* |
| 商品已售罄/下架 | Toast：*"This item is no longer available"*，按钮置灰 |

### 3.4 加购数据写入

- 创建一条购物车项，关联当前 listing
- 默认 selected = true（勾选）
- 默认 quantity = 1（二手单品）
- 记录 price_at_added = 当前 listing 价格

### 3.5 接入方说明

各业务页面接入 Add to Cart 时需关注：
- **按钮状态**：商品已在购物车时，按钮文案可切换为 *"In Cart"* 或保持 *"Add to Cart"*（由各页面自行决定）
- **库存前置校验**：点击时先检查 listing 实时状态，已售罄则走失败逻辑
- **登录状态无关**：未登录用户也可加购（匿名购物车），无需拦截跳登录

## 4. APP 端 — 购物车页面

### 4.1 页面结构

从上到下依次为：

```
┌─────────────────────────┐
│ 顶部导航栏               │
├─────────────────────────┤
│ 可购商品列表             │
├─────────────────────────┤
│ Unavailable 区域         │
├─────────────────────────┤
│ 免运费提示               │
├─────────────────────────┤
│ You May Also Like 推荐   │
├─────────────────────────┤
│ 底部结算栏（固定）        │
└─────────────────────────┘
```

### 4.2 顶部导航栏

- 左侧：返回按钮（X 图标，关闭购物车页）
- 中间：标题 "Shopping Cart"
- 右侧：无

### 4.3 可购商品列表

每个商品卡片包含：

| 元素 | 说明 |
|---|---|
| 复选框 | 左侧，控制是否参与结算 |
| 商品图片 | 缩略图 |
| 品牌名 | 品牌名称 |
| 商品名称 | 最多 2 行，超出截断 |
| 成色标签 | Like New / Very Good / Good |
| 价格区 | 当前价 + 原价（划线）+ 节省金额 |
| 删除按钮 | 右上角 X 图标 |

**排序规则**：按加入时间倒序（最新加入的在上方）

### 4.4 右滑操作

商品卡片支持右滑露出操作按钮：

| 按钮 | 行为 |
|---|---|
| Save for Later | 从购物车移除，加入 Wishlist |
| Delete | 直接删除，无确认 |

### 4.5 Unavailable 区域

当购物车中存在售罄/下架商品时，显示该区域：

- **区域标题**：`Unavailable (N)` — N 为不可购商品数量
- **Clear all 按钮**：右侧，点击一次性删除所有 Unavailable 商品（无确认弹窗）
- **商品卡片**：与可购商品卡片结构相同，但：
  - 无复选框
  - 图片半透明 + "SOLD OUT" 角标
  - 文字信息半透明
  - 仍可右滑删除或 Save for Later

### 4.6 免运费提示

- 位置：Unavailable 区域下方（或可购列表下方，若无 Unavailable）
- 内容：固定文案，如 *"Free shipping on orders over $100"*

> V1 为固定文案，后续接入运费模块后改为动态计算差额。

### 4.7 You May Also Like 推荐区

- 位置：免运费提示下方
- 布局：水平滚动卡片列表
- 每张卡片：商品图 + 品牌 + 商品名 + 价格 + 收藏按钮 + Add to Cart 按钮
- 点击 Add to Cart：加入购物车，卡片从推荐区消失，商品出现在可购列表顶部

### 4.8 底部结算栏（固定）

固定在页面底部，包含：

| 位置 | 元素 | 说明 |
|---|---|---|
| 左侧 | Select All 复选框 + 文字 | 全选/取消全选所有可购商品 |
| 中间 | 总价 | 已勾选商品的价格总和 |
| 右侧 | Check Out 按钮 | 进入结算页 |

**Check Out 按钮状态**：
- 有勾选商品 → 可点击，进入结算页
- 无勾选商品 → 置灰禁用

### 4.9 空状态

购物车无任何商品时显示：
- 空状态插图（购物袋图标）
- 标题：*"Your cart is empty"*
- 描述：*"Browse our collection and find something you love"*
- CTA 按钮：*"Start Shopping"* → 跳转首页

## 5. PC 端 — 购物车侧边抽屉

### 5.1 触发方式

点击页面顶部导航栏的购物车图标，从页面右侧滑出抽屉。

### 5.2 抽屉结构

```
┌──────────────────────┐
│ 标题栏 + 关闭按钮     │
├──────────────────────┤
│ 可购商品列表          │
├──────────────────────┤
│ Unavailable 区域      │
├──────────────────────┤
│ Total + Check Out     │
├──────────────────────┤
│ You May Also Like     │
└──────────────────────┘
```

### 5.3 标题栏

- 标题：`Shopping Bag` + 商品数量标记（如 `7 items`）
- 右上角：关闭按钮（X），点击收起抽屉

### 5.4 可购商品列表

每个商品卡片包含：

| 元素 | 说明 |
|---|---|
| 商品图片 | 缩略图 |
| 品牌名 | 品牌名称 |
| 商品名称 | 单行或两行 |
| 价格区 | 原价（划线）+ 当前价 |
| 删除按钮 | 右上角 X 图标，点击直接删除（无确认） |

**与 APP 的差异**：
- 无复选框 → PC 端默认所有可购商品参与结算
- 无成色标签（空间有限）
- 无右滑操作（无 Save for Later 入口）

### 5.5 Unavailable 区域

结构同 APP（区域标题 + Clear all + 商品列表），但展示更紧凑：
- 商品图半透明 + Sold Out 标记
- 无单独删除按钮，统一通过 Clear all 批量清除

### 5.6 结算区

- **Total**：所有可购商品价格总和（PC 无勾选，默认全选），格式 `$XXX`
- **Check Out 按钮**：全宽
- 有可购商品 → 可点击
- 无可购商品（全部售罄或空车）→ 按钮不显示或置灰

### 5.7 You May Also Like 推荐区

- 位于 Check Out 按钮下方
- 卡片纵向排列（抽屉宽度有限）
- 每张卡片：商品图 + 品牌 + 商品名 + 价格 + 收藏按钮 + Add to Cart 按钮

### 5.8 遮罩层

抽屉打开时，左侧页面覆盖半透明黑色遮罩：
- 点击遮罩 → 关闭抽屉
- 页面内容不可交互

### 5.9 空状态

购物车为空时，抽屉内显示：
- 空状态文案（简洁）
- 可选：继续浏览入口

## 6. 结算入口行为

### 6.1 点击 Check Out

| 步骤 | 行为 |
|---|---|
| 1 | 对已勾选商品（APP）/ 全部可购商品（PC）执行实时库存校验 |
| 2a | 全部有货 → 跳转结算页 |
| 2b | 部分售罄 → 弹窗提示哪些商品已售罄，用户确认后将售罄商品移入 Unavailable，剩余商品继续进入结算页 |
| 2c | 全部售罄 → 提示"所选商品已全部售罄"，留在购物车页 |

### 6.2 登录与购物车合并

- 未登录用户进入结算流程的登录引导逻辑由结算模块负责
- 购物车模块职责：用户登录成功时自动执行匿名购物车合并（规则见 2.2）

## 7. 边界场景

### 7.1 并发售罄

用户浏览购物车期间，某商品被他人购买：
- 下次刷新/重新进入购物车时，该商品出现在 Unavailable 区域
- 不做实时推送（V1），依赖页面刷新

### 7.2 同一商品重复加购

同一 listing 已在购物车中 → 加购操作提示 *"Already in your cart"*（Toast），不重复添加。

### 7.3 跨设备一致性

已登录用户在 A 设备加购，B 设备刷新后可见（基于 user_id 查询）。

### 7.4 购物车徽标

- 导航栏购物车图标右上角显示数字徽标
- 数字 = 可购商品数量（不含 Unavailable）
- 0 件时不显示徽标
- 超过 99 显示 "99+"
