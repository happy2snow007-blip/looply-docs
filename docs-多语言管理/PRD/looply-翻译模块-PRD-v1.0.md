# looply 翻译模块 PRD

> 版本：V1.0
> 日期：2026-05-17
> 状态：初稿

---

## 一、概述

### 1.1 背景与目标

looply 作为面向全球市场的二手电商平台，需要将商品信息、类目名称、UI 文案、帮助文档等内容翻译为多种目标语言，以支撑多国销售。

翻译模块是 looply 的基础能力模块，为所有业务模块提供统一的多语言翻译服务。

**核心目标**：
1. 提供统一的翻译管理后台，运营人员可集中管理所有业务内容的翻译
2. 支持 AI 翻译 + 人工审核的混合模式，平衡翻译效率和质量
3. 通过注册表模式，让各业务模块按需接入翻译能力，无需翻译模块了解业务细节
4. 通过术语表管理，保证品牌名、专业术语在所有语言中的翻译一致性

**设计策略**（参考竞品分析）：
- 借鉴 Shopify Translation API 的可翻译资源模型（字段级翻译粒度）
- 借鉴 Temu 的"平台兜底"体验（业务模块推送内容后自动翻译）
- 借鉴 Amazon 的"可覆盖"机制（允许人工覆盖 AI 翻译结果）
- 借鉴 SHEIN 的混合翻译策略（AI 初稿 + 关键内容人工审校）

### 1.2 不做什么（明确边界）

| 不做的事 | 理由 |
|---------|------|
| 不管理语言列表 | 语言归属 Market 模块管理，翻译模块只引用 |
| 不提供商家端翻译界面 | 本期只做运营后台，商家端翻译体验属于后续迭代 |
| 不做多渠道差异化翻译 | 本期所有渠道使用同一份翻译，渠道差异化属于后续迭代 |
| 不做翻译历史版本管理 | 翻译表只保留当前有效版本，历史变更通过审计日志追溯 |
| 不做图片内文字翻译 | 本期只处理文本内容 |
| 不做 SEO 本地化 | URL slug、hreflang 等 SEO 相关翻译属于后续迭代 |
| 不校验 resource_type 取值 | 翻译模块不限定资源类型，由业务模块自行定义 |

### 1.3 用户角色

| 角色 | 说明 | 主要操作 |
|------|------|---------|
| 翻译运营 | 负责翻译内容管理和质量审核 | 查看翻译进度、审核翻译、创建翻译任务、管理术语表 |
| 系统管理员 | 负责翻译模块配置 | 注册可翻译字段（Key管理）、配置翻译规则 |
| 业务模块（系统） | 推送翻译请求的上游系统 | 自动推送 translation_request |

### 1.4 核心场景

1. **即时翻译**：运营人员在翻译详情页对单个资源的字段执行 AI 翻译或手动编辑，翻译结果直接写入翻译表
2. **批量翻译**：运营人员通过创建翻译任务，批量选择待翻译内容，统一执行 AI 翻译或分配给人工处理
3. **翻译审核**：运营人员对 AI 翻译结果进行人工审核，通过或驳回
4. **术语管理**：运营人员维护术语表（禁译词、强制术语、推荐术语），翻译时自动应用术语约束
5. **字段注册**：系统管理员注册业务模块的可翻译字段，只有注册的字段才会进入翻译流程

### 1.5 全局页面流转

```
翻译内容列表 ──点击资源──→ 翻译详情页
     │                         │
     │                         ├── 编辑翻译
     │                         ├── AI翻译
     │                         ├── 审核通过/驳回
     │                         └── 返回列表
     │
     ├──创建翻译任务──→ 创建翻译任务向导（3步）
     │                         │
     │                         └── 创建完成 → 翻译任务列表
     │
翻译任务列表 ──点击详情──→ 翻译任务详情页
     │                         │
     │                         ├── 执行翻译
     │                         └── 返回列表
     │
Key管理 ──注册/编辑/导入──→ 弹窗操作（不跳转）
     │
术语表列表 ──点击详情──→ 术语详情页
                              │
                              ├── 编辑源词
                              ├── 编辑翻译
                              └── 返回列表
```

### 1.6 术语说明

| 术语 | 说明 |
|------|------|
| Key | 可翻译字段的唯一标识，格式为 `resource_type.field_name`（如 `product.title`） |
| 资源类型（resource_type） | 业务实体类型，如 product、category、ui、help 等，由业务模块自行定义 |
| 翻译方向 | 从源语言到目标语言的翻译路径，如 en → fr |
| EAV 模式 | Entity-Attribute-Value 模式，翻译表用 resource_type + resource_id + field_name 三列定位一条翻译记录 |
| 翻译请求 | 业务模块推送到翻译模块的待翻译内容（翻译模块的收件箱） |
| 术语概念 | 术语表中的一个源词条目，可对应多个目标语言的标准译法 |
| 业务映射 Key | 由业务模块注册的可翻译字段，对应业务数据库中的实际字段 |
| 自管理 Key | 翻译模块自行管理的翻译内容（如 UI 文案），不对应业务模块的数据库字段 |

### 1.7 多语言 / 多国家策略

- **语言标识**：使用 ISO 639-1 语言代码（如 en、fr、de、es）
- **不建 locale 实体**：BCP 47 locale（如 en-US、fr-FR）在运行时由 language_code + country_code 拼接，翻译模块只管语言维度
- **源语言**：默认英文（en），所有翻译以英文为源语言
- **目标语言**：由 Market 模块管理的已开通语言决定，翻译模块不限制目标语言范围
- **RTL 支持**：语言表标记是否从右到左（rtl），前端渲染时据此调整布局方向

## 二、需求详细描述

### 2.1 翻译内容管理

#### 模块概述

翻译内容管理是翻译模块的核心功能，提供按资源维度查看和管理翻译进度的能力。运营人员可以在此查看所有业务内容的翻译状态，对单个资源执行即时翻译或审核操作。

---

#### 2.1.1 翻译内容列表

**功能类型**：页面型

**功能描述**

按资源聚合展示翻译进度，运营人员可以快速了解各资源的翻译完成情况，并进入详情页执行翻译或审核操作。

**前置条件**
- 用户已登录翻译管理后台
- 至少有一种目标语言已开通

**页面布局**

页面顶部为语言选择器和整体进度概览，中部为筛选工具栏，下方为资源列表表格。

- 语言选择器：选择当前查看的目标语言，切换后刷新列表数据
- 进度概览：显示当前语言的整体翻译进度（已翻译/总数）、已审核数、待审核数、译文过期数
- 筛选工具栏：支持按资源名称/ID 搜索、按资源类型筛选、按状态筛选
- 资源列表：表格形式展示每个资源的翻译进度

**页面元素**

| 元素 | 说明 |
|------|------|
| 语言选择器 | 下拉框，显示所有已开通的目标语言，默认选中第一个 |
| 翻译方向标签 | 显示"en → {目标语言代码}" |
| 整体进度条 | 已翻译字段数 / 总字段数，百分比 |
| 已审核数 | 已审核通过的字段数 / 总字段数 |
| 待审核标签 | 显示待审核数量 |
| 译文过期标签 | 显示源内容变更导致翻译过期的数量 |
| 搜索框 | 支持按资源名称或资源 ID 搜索 |
| 资源类型筛选 | 下拉框：全部类型 / 商品 / 类目 / 帮助文章 / UI文案 / 法律条款 / 通知模板 |
| 状态筛选 | 下拉框：全部状态 / 已完成 / 进行中 / 未开始 / 译文过期 |
| 资源列表表格 | 列：资源、资源类型、翻译进度、已审核、状态、操作 |
| 创建翻译任务按钮 | 跳转到创建翻译任务向导 |

**页面状态变体**

| 状态 | 说明 | 触发条件 |
|------|------|---------|
| 默认态 | 显示资源列表和进度概览 | 有翻译数据时 |
| 零数据态 | 显示引导文案"暂无翻译内容" | 无任何翻译数据时 |
| 筛选无匹配态 | 显示"未找到匹配结果" | 筛选条件无匹配时 |
| 网络异常态 | 显示"加载失败" | 请求失败时 |

**操作流程**

主流程：
1. 用户进入翻译内容列表页
2. 系统默认选中第一个目标语言，加载该语言的翻译进度数据
3. 用户可切换目标语言，列表数据刷新
4. 用户可使用搜索框和筛选条件缩小范围
5. 用户点击某资源行的"翻译"或"查看"按钮，跳转到翻译详情页

分支流程：
- 用户点击"创建翻译任务"按钮 → 跳转到创建翻译任务向导

**校验规则**

| 字段 | 规则 | 校验时机 |
|------|------|---------|
| 搜索关键词 | 最大 100 字符 | 输入时 |
| 资源类型筛选 | 必须是已注册的 resource_type | 选择时 |

**交互说明**
- 切换语言选择器后，整体进度概览和列表数据同步刷新
- 表格行 hover 时背景变为浅紫色
- 翻译进度列使用进度条 + 数字（如 3/5）展示
- 状态列使用 Tag 组件，颜色区分：已完成（绿）、进行中（蓝）、未开始（灰）、译文过期（橙）

**异常处理**

| 异常场景 | 处理方式 |
|---------|---------|
| 网络请求失败 | 显示网络异常态，提供"重试"按钮 |
| 目标语言列表为空 | 提示"请先在 Market 模块开通目标语言" |
| 资源数据加载超时 | 显示加载中状态 3 秒后超时，提示重试 |

**UI 关联**
- PC 端：`looply-翻译管理后台原型-v7.html` → page-translation-content

#### 2.1.2 翻译详情页

**功能类型**：页面型

**功能描述**

展示单个资源在指定目标语言下的所有字段翻译对照，支持逐字段编辑、AI 翻译、审核通过、驳回等操作。

**前置条件**
- 从翻译内容列表页点击进入
- 已确定资源 ID 和目标语言

**页面布局**

页面顶部为面包屑导航和资源基本信息，中部为字段翻译对照区域（每个字段一个卡片），底部为操作日志。

**页面元素**

| 元素 | 说明 |
|------|------|
| 面包屑导航 | 翻译内容 / {资源ID} · {资源名称} |
| 资源信息栏 | 资源类型 Tag、Key 类型 Tag、资源 ID、翻译进度条、已审核数 |
| 一键AI翻译按钮 | 对所有未完成字段执行 AI 翻译 |
| 返回列表按钮 | 返回翻译内容列表页 |
| 字段翻译卡片 | 每个可翻译字段一个卡片，包含：字段名、Key 标识、状态 Tag、源文本、译文、操作按钮 |
| 操作日志表格 | 列：操作时间、操作人、操作类型、操作内容 |

**字段翻译卡片结构**

每个字段卡片包含：
- 标题行：字段名（如 title）+ 状态 Tag + Key 标识（如 product.title）
- 左侧：源文本区域（只读，显示源语言内容）
- 右侧：译文区域（可编辑，显示目标语言翻译）
- 操作按钮：根据状态不同显示不同按钮组合

**字段状态与操作按钮对应关系**

| 字段状态 | 含义 | 可用操作 |
|---------|------|---------|
| 未翻译 | 该字段尚无翻译记录 | 编辑、AI翻译 |
| 待审核 | AI/人工翻译完成，等待审核 | 编辑、审核通过、驳回 |
| 已审核 | 审核通过 | 编辑 |
| 译文过期 | 源内容已变更，翻译可能不准确 | 编辑、重新翻译 |

**操作流程**

主流程 - 编辑翻译：
1. 用户点击某字段卡片的"编辑"按钮
2. 译文区域变为可编辑状态
3. 用户输入或修改译文
4. 用户点击"保存"
5. 系统写入 translation 表，status 设为 pending_review，translation_source 设为 manual

主流程 - AI 翻译：
1. 用户点击某字段卡片的"AI翻译"按钮
2. 系统调用 AI 翻译服务
3. 翻译结果写入译文区域
4. 系统写入 translation 表，status 设为 pending_review，translation_source 设为 ai

主流程 - 一键AI翻译未完成字段：
1. 用户点击页面顶部"一键AI翻译未完成字段"按钮
2. 系统查询 translation_request 表，获取该资源 status=pending 的字段列表
3. 对每个未完成字段调用 AI 翻译服务
4. 翻译结果逐个写入 translation 表
5. 页面刷新显示翻译结果

主流程 - 审核通过：
1. 用户点击某字段卡片的"审核通过"按钮
2. 系统将 translation.status 更新为 approved
3. 记录 reviewed_by 和 reviewed_at
4. 状态 Tag 变为"已审核"

主流程 - 驳回：
1. 用户点击某字段卡片的"驳回"按钮
2. 弹出驳回原因弹窗
3. 用户输入驳回原因，点击确认
4. 系统将 translation.status 更新为 pending_review
5. 驳回原因记录到审计日志的 detail 字段
6. 状态 Tag 变为"待审核"

**校验规则**

| 字段 | 规则 | 校验时机 |
|------|------|---------|
| 译文内容 | 不能为空 | 保存时 |
| 译文内容 | 最大 10000 字符 | 输入时 |
| 驳回原因 | 不能为空，最大 500 字符 | 提交时 |

**交互说明**
- 字段卡片左右对照布局：左侧源文本（灰色背景，只读），右侧译文（白色背景，可编辑）
- AI 翻译执行中显示 loading 状态
- 审核通过后状态 Tag 立即变为绿色"已审核"
- 驳回弹窗为模态弹窗，点击遮罩可关闭

**异常处理**

| 异常场景 | 处理方式 |
|---------|---------|
| AI 翻译服务不可用 | 提示"AI翻译服务暂时不可用，请稍后重试或手动编辑" |
| 保存译文失败 | 提示"保存失败，请重试"，保留用户输入内容 |
| 资源不存在 | 提示"资源不存在或已删除"，提供返回列表按钮 |
| 并发编辑冲突 | 提示"该字段已被其他人修改，请刷新后重试" |

**UI 关联**
- PC 端：`looply-翻译管理后台原型-v7.html` → page-translation-detail

### 2.2 翻译任务管理

#### 模块概述

翻译任务管理提供批量翻译的能力。运营人员可以创建翻译任务，批量选择待翻译内容，指定翻译方式（AI 翻译或人工翻译），统一执行翻译。任务完成后自动回写翻译表。

---

#### 2.2.1 翻译任务列表

**功能类型**：页面型

**功能描述**

展示所有翻译任务的列表，支持按状态、语言筛选，查看任务进度。

**前置条件**
- 用户已登录翻译管理后台

**页面元素**

| 元素 | 说明 |
|------|------|
| 创建翻译任务按钮 | 跳转到创建翻译任务向导 |
| 搜索框 | 按任务名称搜索 |
| 状态筛选 | 全部状态 / 进行中 / 已完成 / 待处理 / 已取消 |
| 语言筛选 | 全部语言 / 各目标语言 |
| 任务列表表格 | 列：任务ID、任务名称、语言方向、翻译方式、优先级、进度、截止日期、状态、操作 |
| 分页器 | 居中紧凑式 |

**任务状态枚举**

| 枚举值 | 含义 | 进入条件 | 退出条件 |
|--------|------|---------|---------|
| pending | 待处理 | 任务创建完成 | 开始执行翻译 |
| in_progress | 进行中 | 任务开始执行（至少一个条目开始翻译） | 所有条目完成或任务被取消 |
| completed | 已完成 | 所有条目翻译完成 | — |
| cancelled | 已取消 | 运营人员手动取消 | — |

**操作流程**

1. 用户进入翻译任务列表页
2. 系统加载任务列表，默认按创建时间倒序
3. 用户可使用筛选条件缩小范围
4. 用户点击"详情"按钮 → 跳转到翻译任务详情页
5. 用户点击"创建翻译任务"按钮 → 跳转到创建翻译任务向导

**页面状态变体**

| 状态 | 说明 | 触发条件 |
|------|------|---------|
| 默认态 | 显示任务列表 | 有任务数据时 |
| 零数据态 | 显示"暂无翻译任务" | 无任何任务时 |
| 筛选无匹配态 | 显示"未找到匹配结果" | 筛选无匹配时 |
| 网络异常态 | 显示"加载失败" | 请求失败时 |

**异常处理**

| 异常场景 | 处理方式 |
|---------|---------|
| 网络请求失败 | 显示网络异常态 |
| 任务数据加载超时 | 显示加载中 3 秒后超时，提示重试 |

**UI 关联**
- PC 端：`looply-翻译管理后台原型-v7.html` → page-job-list

#### 2.2.2 翻译任务详情

**功能类型**：页面型

**功能描述**

展示翻译任务的基本信息和任务内容（条目列表），支持执行翻译、查看条目状态。

**前置条件**
- 从翻译任务列表页点击"详情"进入

**页面元素**

| 元素 | 说明 |
|------|------|

### 2.5 翻译请求消费（后台机制）

#### 模块概述

翻译请求是业务模块与翻译模块之间的解耦机制。业务模块在资源创建或变更时主动推送翻译请求，翻译模块自动消费处理。

---

#### 2.5.1 翻译请求自动消费

**功能类型**：机制型

**功能描述**

翻译模块自动消费 translation_request 表中的待处理请求，将业务内容纳入翻译管理。

**触发条件**
- 业务模块向 translation_request 表写入新记录（status=pending）
- 定时任务扫描 translation_request 表中 status=pending 的记录

**处理流程**

1. 系统读取 translation_request 记录
2. 检查 translatable_field_config 表，确认该 resource_type + field_name 已注册
3. 如果未注册 → 忽略该请求，status 保持 pending（等待字段注册后再处理）
4. 如果已注册 → 检查 translation 表是否已有该资源字段的翻译记录
5. 如果无翻译记录 → 创建新的 translation 记录（status=pending_review，translated_value 为空）
6. 如果已有翻译记录 → 比对 source_hash
   - hash 相同 → 源内容未变更，忽略
   - hash 不同 → 源内容已变更，将已有翻译记录的 status 更新为 outdated
7. 更新 translation_request.status 为 completed

**规则说明**

| 规则 | 说明 |
|------|------|
| 幂等性 | 同一 resource_type + resource_id + field_name + source_hash 的请求只处理一次 |
| 字段注册前置 | 未注册的字段不会被处理，避免垃圾数据进入翻译表 |
| 源内容变更检测 | 通过 source_hash 比对，自动标记过期翻译 |
| 不反向查询 | 翻译模块不主动查询业务模块数据，所有信息从 translation_request 获取 |

**异常处理**

| 异常场景 | 处理方式 |
|---------|---------|
| translation_request 数据不完整 | 记录错误日志，status 保持 pending |
| 写入 translation 表失败 | 记录错误日志，status 保持 pending，下次重试 |
| 队列堆积超过阈值 | 触发监控告警（阈值建议：1000 条） |

**技术说明**
- translation_request 是翻译模块的收件箱，业务模块只写不读
- resource_name 字段冗余存储资源显示名，避免翻译模块反向查询业务模块
- 消费频率：建议每 30 秒扫描一次，或使用消息队列实时消费

---

### 2.6 翻译状态生命周期（后台机制）

**功能类型**：机制型

**功能描述**

定义翻译记录（translation 表）的状态流转规则。

**触发条件**
- 翻译内容被创建、编辑、审核、或源内容变更时

**处理流程**

```
                    ┌─────────────────┐
                    │  pending_review  │
                    │  （待审核）       │
                    └────────┬────────┘
                             │
              ┌──────────────┼──────────────┐
              │              │              │
              ▼              │              ▼
    ┌─────────────┐          │     ┌──────────────┐
    │  approved   │          │     │  （驳回后）    │
    │  （已审核）  │          │     │  重新编辑     │
    └──────┬──────┘          │     │  → 回到      │
           │                 │     │  pending_review│
           │                 │     └──────────────┘
           ▼                 │
    ┌─────────────┐          │
    │  outdated   │──重新翻译─┘
    │  （译文过期） │
    └─────────────┘
```

**规则说明**

| 状态 | 进入条件 | 退出条件 |
|------|---------|---------|
| pending_review | ① AI/人工翻译完成保存 ② 驳回后重新编辑保存 | 审核通过 → approved |
| approved | 审核通过 | 源内容变更 → outdated |
| outdated | 源内容变更（source_hash 不匹配） | 重新翻译 → pending_review |

**关键规则**：
- 无 draft 状态：编辑保存即进入 pending_review
- 驳回不是独立状态：驳回后 status 保持 pending_review，驳回原因记录在审计日志
- outdated 由系统自动触发：业务模块推送新的 translation_request 时，翻译模块比对 source_hash 自动标记

## 三、依赖与风险

### 3.1 上下游系统依赖

| 依赖方 | 依赖内容 | 影响 |
|--------|---------|------|
| Market 模块 | 语言列表（language 表） | 翻译模块引用语言代码，不自行管理 |
| 商品模块 | 推送商品翻译请求 | 商品创建/变更时自动推送 translation_request |
| 类目模块 | 推送类目翻译请求 | 类目创建/变更时自动推送 translation_request |
| CMS 模块 | 推送帮助文档/法律条款翻译请求 | 内容发布时自动推送 |
| 通知模块 | 推送通知模板翻译请求 | 模板创建/变更时自动推送 |

### 3.2 外部服务依赖

| 服务 | 用途 | 风险 |
|------|------|------|
| AI 翻译服务（GPT-4o / GPT-4o-mini） | 执行 AI 翻译 | 服务不可用时翻译功能降级为纯人工 |

### 3.3 风险项

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| AI 翻译服务不可用 | 无法执行 AI 翻译 | 降级为人工翻译，提示用户 |
| 业务模块未正确推送翻译请求 | 翻译内容不完整 | 监控队列堆积，定期对账 |
| 翻译量突增（如大批量商品上架） | 翻译任务积压 | 设置优先级机制，核心内容优先处理 |

## 四、版本规划

### 4.1 当前版本（MVP）

本期实现的功能：
- 翻译内容管理（列表 + 详情 + 即时翻译 + 审核）
- 翻译任务管理（列表 + 详情 + 创建向导）
- Key 管理（注册 + 编辑 + 批量导入）
- 术语表管理（列表 + 详情 + 添加 + 导入）
- 翻译请求自动消费机制
- AI 翻译集成（GPT-4o-mini / GPT-4o）

### 4.2 后续迭代方向

| 方向 | 说明 | 优先级 |
|------|------|--------|
| 商家端翻译体验 | 商家可在商品编辑页查看和覆盖翻译结果 | 高 |
| 多渠道差异化翻译 | 不同销售渠道使用不同翻译版本 | 中 |
| 翻译记忆库 | 相似内容复用已有翻译，降低翻译成本 | 中 |
| 第三方翻译服务商接入 | 支持接入专业翻译服务商（如 DeepL、Google Translate） | 中 |
| SEO 本地化 | URL slug 翻译、hreflang 标签生成 | 低 |
| 翻译质量评分 | 对 AI 翻译结果自动评分，低分内容优先人工审核 | 低 |
| 图片内文字翻译 | 商品图片中的文字自动翻译 | 低 |
