## V1.5 — 2026-07-23

**商详接多语言触发的能力迭代：建卡 + 页面聚合 + 静态文案后台管理**

产出：ER v2.4 · 原型 v13 · PRD v3.2 · 接入规范（产品版）v3.2

### 新增（ER v2.4，3 张表）
- `translation_domain`（翻译域）：域元数据，驱动导航按域分 Tab（商品域/前端页面/通知模板）
- `resource_group`（资源分组·页面聚合）：把一个 C 端页面下的多个资源卡片聚合成一个导航单元
- `translation_resource`（翻译资源·建卡）：翻译中心一级对象，一张卡=一个 resource_type；含 storage_mode、integration_status、group_code、key_type 等

### 变更（ER v2.4）
- `translatable_field_config` 改造：`resource_type` 由开放字段 → FK 指向 `translation_resource`；卡片级属性（display_name / key_type / source_system）上移到 translation_resource
- 新增枚举：storage_mode（translation_table 翻译中心 / language_pack 语言包）、integration_status（connected / pending / placeholder）

### 新增能力（PRD v3.2，增量文档，其余沿用 v3.1）
- 能力一 建卡 + 域元数据：先建卡再注册字段（未建卡拒写源文），建卡走 migration
- 能力二 页面聚合：导航聚合卡 + 详情页子导航，数据层 N 卡 / 展示层 1 卡，向后兼容
- 能力三 静态文案后台管理（追认已实现）：storage_mode 区分翻译中心/语言包，静态文案语言包落地 + 后台可查改

### 原型（v11 → v13）
- 翻译详情页：商详页从扁平列表重构为 5 分组子导航（页面文案 / 鉴定认证 / 成色等级 / 成色展示名 / 属性展示名），元数据驱动 Tag（翻译中心 / 语言包）
- Key 管理页：从"可注册/导入/编辑/启停" → **纯只读**（"业务 Key 管理"，只读查看业务模块注册的翻译 key，静态语言包字段不进列表），对齐开发 v1 实现

### 接入规范（v3.1 → v3.2，产品用·不入交付包）
- §4.2：动态套动态从"超纲提需求" → "页面聚合已支持，拆 resource_type + resource_group 聚合接入"
- §三/§七A：静态文案从"后台不碰" → "语言包落地 + 后台可查改"

### 后续诉求（本期不做）
- 卡片/分组/域 运营编辑 + 排序管理（ER 已预留 sort_order，届时只加运营界面）

## V1.2 — 2026-06-22

**架构升级：Localized Content 分离**

产出：PRD v3.0 · 原型 v11

### 变更
- 删除 translation_request 表（数据模型精简为 5 表）
- 统一触发路径：源语言记录编辑 → 其他语言标记 outdated → 自动重译
- 所有源文本可编辑；key_type 降级为 UI 分类标签，不决定数据流
- 业务表不存任何文本字段（含源语言），全部存翻译模块
