## P0（规则缺失或制品矛盾，阻塞开发）

### 1. [设计] 术语表页面结构矛盾

- **位置**：PRD §6.4 + 原型 GlossaryListPage / GlossaryDetailPage
- **问题**：PRD §6.4 描述术语表为"左侧为术语概念列表，右侧为选中概念的各语言译法（与翻译详情页类似的 Master-Detail 结构）"。但原型实现为两个独立页面——GlossaryListPage 是标准列表页（带表格+筛选+KPI），点击"详情"按钮后跳转到 GlossaryDetailPage 独立页面。两者布局方案完全不同：PRD 描述的是同屏左右分栏，原型是列表→导航→详情。
- **建议**：以原型为准修改 PRD 描述，将术语表拆为"术语列表页"和"术语详情页"两个独立功能描述。

### 2. [开发] "翻译任务"概念未定义

- **位置**：PRD §4.4 首次翻译触发、§4.5 字段注册触发回扫
- **问题**：PRD §4.4 写"为所有已开通目标语言自动创建翻译任务"，§4.5 写"自动创建翻译任务"。但 translation_request 表已删除，PRD 通篇没有定义"翻译任务"是什么实体。当开发看到这句话时会问：任务存在哪？是内存队列？是直接调 AI API？是另一张表？PRD 没有答案，开发无法继续。
- **建议**：明确"翻译任务"的产品含义——要么说清楚是"系统直接调用 AI 翻译服务并写入结果"（无中间持久化），要么说明有其他机制。建议统一措辞为"系统自动触发 AI 翻译"，避免"任务"这个会让人联想到任务表的词。

## P1（规则不完整，影响质量）

### 3. [设计] Translation 导航 Tab 与原型不一致

- **位置**：PRD §6.1 页面元素表 + 原型 TranslationNavPage line 697-706
- **问题**：PRD 定义域分组标签为"全部 / 商品域 / 前端页面 / 通知模板"，操作流程写"默认显示'全部'标签"。但原型只有三个 Tab（商品域 / 前端页面 / 通知模板），没有"全部"选项，默认激活"商品域"。
- **建议**：以原型为准删除 PRD 中的"全部"Tab，修改操作流程为"默认显示'商品域'标签"。

### 4. [设计] 资源类型显示名称不一致

- **位置**：PRD §6.1 资源类型列表 + 原型 DOMAINS 数据 line 229-250
- **问题**：三处命名不同：

  | resource_type | PRD 显示名 | 原型显示名 |
  |---------------|-----------|-----------|
  | page-order-success | 下单成功 | 支付成功页 |
  | page-account | 账户中心 | 用户中心 |
  | page-help | 帮助中心 | 帮助 / 错误页 |

- **建议**：统一命名。以原型为准更新 PRD（原型命名更准确：page-order-success 是支付完成后的页面，不是下单；page-help 包含错误页）。

### 5. [开发] 添加术语弹窗缺少"各语言翻译"流程

- **位置**：PRD §6.4 添加术语弹窗 + 原型 AddTermModal line 1047-1073
- **问题**：PRD §6.4 添加术语弹窗只定义了 4 个字段（source_term、source_language_code、rule_type、context）。但原型在选择"强制术语"规则后，弹窗下方动态展示各目标语言的翻译输入框（法语/德语/西班牙语），允许创建时直接填写各语言译法。这个功能流程 PRD 完全没有描述。
- **建议**：在 §6.4 添加术语弹窗中补充规则：当 rule_type=mandatory 时，弹窗下方展示所有已开通目标语言的翻译输入框，运营可选填（不填则待后续补充）。禁译词则不展示。

### 6. [测试] 术语"删除"操作未定义

- **位置**：PRD §7.3 术语状态管理 + 原型 GlossaryListPage line 985
- **问题**：PRD §7.3 只定义了"废弃术语"（status=deprecated）和"恢复术语"两种操作。但原型列表页每行有"删除"按钮（`<Button size="small" danger>删除</Button>`）。测试无法写用例：删除是物理删除还是等同于废弃？删除后还能恢复吗？已关联翻译的术语能删吗？
- **建议**：在 §7.3 明确"删除"的业务规则。建议：删除 = 物理删除（仅允许对从未被使用过的术语执行），已被引用的术语只能"废弃"。或者将原型的"删除"按钮改为"废弃"。

### 7. [开发] 资源列表的"资源名称"数据来源未定义

- **位置**：PRD §6.2 左侧面板元素 + §3.1 核心原则
- **问题**：PRD §6.2 左侧面板说"每行显示：资源名称、翻译进度"。但 §3.1 明确"业务表不存任何文本字段"。原型展示的资源名称如"Vintage Leather Handbag"本质上就是 product.title 的源语言翻译。开发需要知道：这个"资源名称"从哪查？是固定取某个字段（如 translatable_field_config 中 sort_order=1 的字段的源语言值）？还是需要在 translatable_field_config 中标记哪个字段是"显示名称"字段？
- **建议**：在 §6.2 或 §2 数据架构中明确：资源列表的显示名称取该 resource_type 注册字段中的第一个 text 字段的源语言值（即 translation 表中 field_name=第一个注册字段 且 language_code=source_language_code 的 translated_value）。或者在 translatable_field_config 中增加 `is_display_name` 标记。

### 8. [测试] 批量导入格式描述不一致

- **位置**：PRD §6.3 批量导入 + 原型 BatchImportModal line 1144
- **问题**：PRD §6.3 写"支持 CSV 格式导入"，但原型 BatchImportModal 的文件格式选择下拉框包含三个选项：Excel(.xlsx) / CSV / JSON。如果测试按 PRD 写用例只覆盖 CSV，会漏测 xlsx 和 json。
- **建议**：PRD 更新为"支持 xlsx / CSV / JSON 格式导入"，与原型一致。

## P2（描述可更精确）

### 9. [开发] 注册 Key static_content 模式下 resource_type 来源不明

- **位置**：PRD §6.3 注册 Key 模式二
- **问题**：static_content 模式的表单中，PRD 没有显式的 resource_type 输入框（只有 source_system/field_name/field_label/field_type/源文本）。但 translatable_field_config 表需要 resource_type 字段。原型中用"归属页面"选择器暗示了 resource_type 的来源（如选"首页"→ resource_type=page-home），但 PRD 没有说明这个映射关系。
- **建议**：在模式二表格中补充说明：resource_type 由"归属页面"自动映射生成（首页→page-home，商详页→page-pdp，服务条款→legal-tos 等），或显式列出映射表。

### 10. [设计] 术语列表页列定义不完整

- **位置**：PRD §6.4 左侧列表元素 + 原型 GlossaryListPage columns line 974-988
- **问题**：PRD 描述术语列表"每行：源词、规则类型标签、翻译覆盖率"，但原型表格有 6 列：源词 / 规则 / 已翻译语言 / 更新时间 / 备注 / 操作。PRD 少了"更新时间"和"备注"两列。
- **建议**：以原型为准更新 PRD 列定义，补充更新时间和备注。

### 11. [开发] 资源删除通知方式不明确

- **位置**：PRD §3.5 资源删除处理
- **问题**：PRD 写"业务模块通知翻译服务删除对应的所有翻译记录"，但没有说明通知方式。当商品模块删除一个商品时，是同步调翻译服务 DELETE API（与写入时 POST API 对称），还是发事件消息异步处理？
- **建议**：补充说明为"调用翻译服务删除接口"（与写入接口对称的 RESTful 设计），或标注"具体通知方式由技术方案确定，产品侧只要求：删除后该资源的翻译记录不再返回"。
