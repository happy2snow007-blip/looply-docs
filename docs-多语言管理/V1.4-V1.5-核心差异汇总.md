# 多语言模块 V1.4 → V1.5 核心差异汇总（面向开发）

> 基线（上次交付）：V1.4-20260623 = 原型 v11 · PRD v3.1 · ER v2.3
> 本次交付：V1.5-20260723 = 原型 v13 · PRD v3.2 · ER v2.4
> 对比口径：基于两个交付包内的实际文件逐一核对（非记忆、非中间迭代版）。

---

## 1. 本次交付范围

| 交付物 | 基线 V1.4 | 本次 V1.5 |
|--------|-----------|-----------|
| 实体关系图 | v2.3（`resource_type` 开放字段，单层模型） | **v2.4**（新增 3 表 + 改造 1 表） |
| 后台原型 | v11-antd | **v13-antd** |
| PRD | v3.1（全量） | **v3.2**（能力增量文档，未列章节沿用 v3.1） |

**一句话概括**：本次把 v3.1 的"一个业务对象一张卡、卡内字段平铺"的**单层模型**，升级为"**建卡 + 域元数据 + 页面聚合**"的可承载"动态套动态"结构（商详接多语言触发），并追认"静态文案语言包落地 + 后台可查改"能力、把 Key 管理页对齐 v1 的只读实现。

## 3. 新增功能

### 3.1 ER v2.3 → v2.4（数据模型增量）

**新增 3 张表：**

| 表 | 作用 | 关键字段 |
|----|------|---------|
| `translation_domain` | 翻译域元数据，驱动导航 Tab（不再前端硬编码） | domain(PK) / domain_name / sort_order / status |
| `resource_group` | 页面聚合，把一个 C 端页面下多个卡片聚成一个导航单元 | group_code(PK) / group_name / domain(FK) / sort_order / status |
| `translation_resource` | **建卡**，一张卡 = 一个 resource_type | resource_type(PK) / display_name / domain(FK) / group_code(FK,可空) / key_type / **storage_mode** / source_system / **integration_status** / sort_order |

**改造 1 张表 `translatable_field_config`：**

- `resource_type`：由**开放字符串字段** → **FK 指向 translation_resource**（未建卡则源文写入被拒）。
- 卡片级属性 `display_name / key_type / source_system` **上移到 translation_resource**；本表只保留字段级属性：config_id / resource_type(FK) / field_name / field_label / field_type / sort_order / status。

**新增枚举：**
- `storage_mode`：`translation_table`（翻译中心，写翻译服务触发 AI 翻译）/ `language_pack`（静态文案，后台查改后同步回语言包）。
- `integration_status`：`connected` 已对接 / `pending` 待对接 / `placeholder` 占位。

> 核对结论：v2.3 ER 中 `storage_mode`/`language_pack`/`integration_status` 均为 0 处，`resource_type` 为开放字段；v2.4 三张新表 + 三个新枚举均已落图，`resource_type` 已标 FK。`translation` / `language` / `glossary_*` 三表不变。
> `sort_order` 已在三张新表预留，为后续"运营编辑/排序卡片-分组-域"铺路（本期不做运营界面）。

### 3.2 PRD v3.1 → v3.2（能力增量）

v3.2 是**增量文档**（只写新增/变更，其余沿用 v3.1）。三项能力：

1. **能力一 · 翻译资源目录（建卡 + 域元数据）**：`resource_type` 开放字段 → 显式建卡 `translation_resource` + 域元数据 `translation_domain`；先建卡再注册字段，未建卡拒写源文。**本期建卡走 migration/config，不做运营自助建卡界面。**
2. **能力二 · 页面聚合（resource_group）**：同 `group_code` 的卡片在导航层合并为一张聚合卡；数据层仍是 N 个独立 resource_type、各自单层（不破坏 v3.1 字段模型）。未归组资源保持独立卡（向后兼容）。**本期分组配置走 migration/config。**
3. **能力三 · 静态文案后台管理（追认已实现）**：`storage_mode` 区分翻译中心/语言包；静态文案语言包落地 + 后台可查改（保存后同步语言包）。静态文案后台入口在**翻译详情页**（作为"页面文案"分组），**不在 Key 管理页**。

配套：接入规范 v3.2 同步升版（§4.2 "动态套动态"从"超纲提需求"→"页面聚合已支持"；§三/§七A 静态文案从"仅语言包、后台不碰"→"语言包落地 + 后台可查改"）。

## 4. 既有功能调整（原型 v11 → v13）

> 重要澄清：导航页的"商详页"卡片 **v11 已存在，本次未新增卡片**。真正的改动是商详页**详情页结构**从扁平重构为分组子导航，以及 Key 管理页改只读。

### 4.1 商详页详情：扁平 items → 分组 groups（本次最大结构改动）

- v11：`page-pdp` 是扁平 `items` 数组，静态页面区块与 CMS 模板 key 混在同一列表，命名混乱，无 resourceType 概念。
- v13：`page-pdp` 改为 `groups` 数组，每 group 带 `key/label/resourceType/granularity`，**5 个分组**：

| 分组 | resourceType | 配置粒度 | 落地 |
|------|-------------|---------|------|
| ⓪ 页面文案 | `page-pdp` | 页面区域 × 文案 | 语言包(static_content) |
| ① 鉴定认证 | `pdp_template` | 模板级 | 翻译中心(CMS) |
| ② 成色等级 | `pdp_condition_grade` | 模板 × 等级 | 翻译中心(CMS) |
| ③ 成色展示名 | `pdp_condition_display` | 类目 × 字段(display_name) | 翻译中心(CMS) |
| ④ 属性展示名 | `pdp_description_display` | 类目 × 属性(display_name，含 Size Guide) | 翻译中心(CMS) |

### 4.2 翻译详情页新增子导航 + 元数据驱动

- v11 详情页无子导航，直接左右分栏。
- v13：`groups` 存在时详情页顶部渲染 `<Segmented>` 子导航（5 分组，label 带条数）；Tag/Alert/信息行由 group 元数据（resourceType、granularity、storage 语义）**动态渲染**——`page-pdp` 显示蓝 Tag"语言包"，其余显示紫 Tag"翻译中心"，Alert 随分组切换（语言包组=可查改保存后同步；CMS 组=写翻译服务触发自动翻译）。

### 4.3 Key 管理页改只读（对齐 v1 实现）

- v11：`KeyManagementPage` 有"注册Key/批量导入"按钮 + 每行"编辑/启停"操作列，含 5 类写操作弹窗（RegisterKeyModal / batch-import / edit-key / confirm-enable / confirm-disable），静态文案 key（home.hero.image 等）也混进列表。
- v13：改为**纯只读表格**，title 改为"业务 Key 管理"，无任何头部按钮/操作列，5 类弹窗与 openDialog 调用全部删除；数据源改为 `KEY_CARDS`（一卡=一 resource_type），**页面静态语言包字段不进列表**；列重整为 Key / 资源类型 / 字段 / 字段类型 / 源语言 / 来源 / 状态。

### 4.4 resourceType / key 命名体系统一

- 商品域 key 从 v11 的 `product.title`/`category.name` 点号业务字段，改为 v13 的 `catalog_*`/`listing`/`product` 资源类型前缀；商详旧 key（`pdp_template.grade_name_1`、`pdp.info.*`、`content.*`）作废，规范化到 `pdp_template.*`、`pdp_condition_grade.*`、`pdp_condition_display.display_name`、`pdp_description_display.display_name`。

## 5. 开发关注重点（增量要开发什么）

1. **建表 + migration**：新建 `translation_domain`、`resource_group`、`translation_resource` 三表；改造 `translatable_field_config`（`resource_type` 升 FK，卡片级属性迁到 translation_resource）。**未建卡拒写源文**约束要落。
2. **建卡 / 分组数据靠 migration/config 落地**（本期无运营自助界面）；上线前核对各 group 成员清单 + sort_order。
3. **导航 Tab 由 `translation_domain` 元数据驱动**（去掉前端硬编码域分组）。
4. **商详页详情按 group 建模**：每 group 一个 resourceType；前端详情页做 `<Segmented>` 分组切换（切换重置选中项），Tag/Alert/信息行从 group 元数据动态渲染。
5. **两条落地链路要分开实现**：
   - `storage_mode = language_pack`（页面文案）：走语言包读写，后台可查改，保存后同步语言包，**不进翻译服务**。
   - `storage_mode = translation_table`（CMS 4 类）：写翻译服务、触发 AI 自动翻译。
6. **Key 管理页做成只读**：数据来自各业务模块自动注册的 resource_type（KEY_CARDS），无手动注册/导入/编辑入口；静态语言包字段单独走语言包管理、不聚合进本列表。
7. **resource_type / key 命名规范化**：按新 resource_type 前缀建注册表，旧 key 结构作废。
