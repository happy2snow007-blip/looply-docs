一、概述

1.1 背景与目标

Looply 是面向美国市场的跨境二手电商平台，从二手奢侈品（包袋、首饰、配饰）切入。平台以 USD 为系统基准货币，需要为欧洲、英国、日本等多国用户提供本地货币价格展示。

汇率管理模块是平台的用户价格换算基础设施，核心目标：

  1. 从外部数据源定时采集原始汇率
  2. 通过点差规则加工生成平台汇率
  3. 每日定时发布，保证用户端价格稳定
  4. 支持运营监控、手动干预与异常兜底
  5. 提供完整的操作记录与审计追溯

1.2 不做什么

明确不做原因
金额换算计算调用方自行计算：目标金额 = USD 底价 × 平台汇率
金额格式化与展示符号、千分位、小数点由前端/格式化服务负责
报价锁定属于结算/支付模块职责
心理价修正属于商品定价/营销模块职责
支付结算与财务对账属于支付/财务模块职责
多汇率源智能比价MVP 后续迭代
自动汇率对冲策略MVP 后续迭代

1.3 用户角色

角色说明
运营人员通过后台管理汇率：配置点差、查看平台汇率、处理异常告警、设置汇率模式
系统（定时任务）每小时采集原始汇率、每日 UTC 00:00 自动发布平台汇率、触发异常告警

本模块为纯后台管理模块，无 APP 端，无终端用户直接交互。

1.4 核心场景

  1. 日常运营：系统每日自动采集并发布汇率，运营通过"平台汇率"页面监控当前状态
  2. 点差调整：运营根据业务需要调整全局或单币种点差，下次发布时自动生效
  3. 异常处理：采集汇率波动超过阈值时，系统暂停自动发布并告警，运营审核后决定发布或忽略
  4. 手动干预：市场剧烈波动时，运营可将币种切换为固定模式手动设定汇率
  5. 问题排查：通过各页面底部的操作记录回溯历史操作，支持订单核对与审计

1.6 术语说明

术语说明
基准货币汇率换算的基准，Looply 统一使用 USD
目标货币需要换算到的货币（如 EUR、GBP、JPY）
原始汇率从第三方数据源采集的未加工汇率
点差平台在原始汇率基础上叠加的调整比例
平台汇率应用点差后实际对外提供的汇率
自动模式币种跟随市场汇率 + 点差，每日定时自动发布
固定模式运营手动设定汇率值，定时发布跳过该币种
采集系统从第三方数据源获取原始汇率的动作
发布将加工后的平台汇率推送给业务系统使用的动作
汇率版本每次发布的唯一标识，格式：SNAP-YYYYMMDD-序号
最近成功率数据源最近 24 小时内成功采集次数 / 总采集次数 × 100%

1.7 多语言 / 多国家策略

本模块为内部运营后台，仅支持中文界面，不涉及多语言。汇率数据本身以 ISO 4217 币种代码标识，天然支持国际化。

二、需求详细描述

2.1 平台汇率

模块概述

平台汇率是运营日常使用频率最高的页面，展示当前对外生效的平台汇率。每日 UTC 00:00 系统定时发布，每个币种支持"自动"和"固定"两种汇率模式。

2.1.1 平台汇率列表（页面型）

功能描述

展示所有已启用币种对的当前平台汇率，包括汇率模式、原始汇率、点差、涨跌幅、发布信息等，支持筛选、搜索和导出。

前置条件

  • 至少有一个数据源已启用且采集成功
  • 至少有一个币种已启用

页面布局

  • 顶部：页面标题 + 说明
  • KPI 卡片：生效币种对数、最近发布时间、发布方式、异常告警数（可点击跳转）
  • 工具栏：搜索币种对、筛选模式（全部/自动/固定）、筛选状态（全部/生效/停用）、发布时间范围（默认近一周）、查询按钮、导出 CSV 按钮
  • 数据表格 + 分页

页面元素

列名说明
币种对如 USD → EUR，tooltip：仅支持币种管理页面已启用的币种
汇率模式自动（蓝色标签）/ 固定（黄色标签），tooltip：自动=每日定时发布取最新汇率×(1+点差)；固定=运营手动设定值，定时发布跳过
汇率版本如 SNAP-20260428-0001，tooltip：每次发布的唯一标识，格式：SNAP-YYYYMMDD-序号
原始汇率最近一次发布时的快照值，非实时数据
点差当前应用的点差比例，固定模式显示"-"
平台汇率当前对外生效的汇率值
涨跌与上一次发布的变化幅度，绿色上涨/红色下跌
发布方式定时 / 手动
发布人系统 / 运营人员姓名
数据源采集来源名称
发布时间最近一次发布的时间
状态生效 / 停用
操作设置汇率、历史

操作流程

主流程——查看当前汇率：

  1. 进入页面，默认展示所有生效币种对
  2. 可通过搜索框、筛选条件和时间范围缩小范围
  3. 查看各币种的汇率模式、平台汇率、涨跌幅等信息

分支流程——导出 CSV：

  1. 设置筛选条件和时间范围
  2. 点击"导出 CSV"按钮
  3. 按当前筛选条件导出完整记录（不受分页限制）

交互说明

  • KPI 区域"异常告警"数字可点击，跳转到异常告警页面
  • 表格行 hover 高亮
  • 分页：默认每页 10 条
  • 时间范围默认为近一周（开始日期：7天前，结束日期：今天）

异常处理

  • 数据源全部不可用时，列表仍展示最近一次发布的数据，KPI 区域提示"数据源异常"
  • 导出失败：提示"导出失败，请稍后重试"
  • 网络异常：提示"网络异常，请稍后重试"

UI 关联

  • PC 端：V7.1 原型「平台汇率」页面
  • APP 端：不涉及

2.1.2 设置汇率（页面型——子页面）

功能描述

对单个币种设置汇率模式（自动/固定）和汇率值。自动模式下展示当前原始汇率和点差计算结果；固定模式下运营手动输入平台汇率值。无变更时禁用保存按钮和原因输入框。

前置条件

  • 从平台汇率列表点击"设置汇率"按钮打开

页面布局

  • 独立子页面，包含：页面标题、返回按钮、基本信息区（币种对、当前平台汇率）、汇率模式选择区、变更原因输入区、操作按钮区、底部操作记录区

页面元素

元素说明
币种对只读，如 USD → EUR
当前平台汇率只读，展示当前值
汇率模式卡片式单选：自动模式 / 固定模式，当前模式高亮
自动模式内容区展示当前原始汇率、点差规则、计算后的平台汇率（均只读）
固定模式内容区输入框：固定平台汇率（数字，精度 4 位小数）
变更原因文本域，无变更时禁用（灰色背景）
确认保存按钮无变更时禁用（灰色、不可点击）
操作记录页面底部展示该币种的历史操作记录，支持筛选和分页

页面状态变体

  • 默认态：展示当前模式对应的内容区，保存按钮和原因输入框禁用
  • 有变更态：切换模式或修改汇率值后，保存按钮和原因输入框启用

操作流程

主流程——保持当前模式修改：

  1. 打开子页面，默认展示当前模式，保存按钮和原因输入框禁用
  2. 自动模式下为只读展示，固定模式下可修改汇率值
  3. 修改后，保存按钮和原因输入框自动启用
  4. 填写变更原因
  5. 点击"确认保存"

分支流程——切换汇率模式：

  1. 点击另一个模式卡片
  2. 内容区切换，保存按钮和原因输入框自动启用
  3. 填写变更原因
  4. 点击"确认保存"

校验规则

字段规则校验时机
固定平台汇率必填（固定模式下）、大于 0、最多 4 位小数提交时
变更原因必填（有变更时）、最少 2 个字符提交时

交互说明

  • 无变更时：保存按钮置灰不可点击，原因输入框禁用（灰色背景）
  • 有变更时：保存按钮和原因输入框自动启用
  • 模式切换无需二次确认，直接切换内容区
  • 页面底部展示该币种的历史操作记录，支持按操作类型、操作人、时间筛选

异常处理

  • 提交失败：提示"保存失败，请稍后重试"，停留在当前页面
  • 网络异常：提示"网络异常，请检查网络连接"

UI 关联

  • PC 端：V7.1 原型「设置汇率」子页面
  • APP 端：不涉及

2.1.3 汇率历史（页面型——子页面）

功能描述

查看单个币种对的历史发布记录，展示每次发布时的原始汇率、点差、平台汇率和涨跌幅。

前置条件

  • 从平台汇率列表点击"历史"按钮打开

页面布局

  • 独立子页面，顶部显示币种对名称和返回按钮，下方为历史记录表格，底部为操作记录区

页面元素

列名说明
发布时间每次发布的时间
原始汇率发布时的原始汇率
点差发布时应用的点差比例
平台汇率发布时的最终汇率
涨跌与上一次发布的变化幅度
发布方式定时 / 手动

数据范围与分页

  • 默认展示最近 30 天的发布记录
  • 支持分页，每页 20 条
  • 支持按时间范围筛选

异常处理

  • 无历史数据时展示空状态

UI 关联

  • PC 端：V7.1 原型「汇率历史」子页面
  • APP 端：不涉及

2.2 点差规则

模块概述

点差规则决定了平台汇率与市场原始汇率之间的差值。支持全局默认点差和单币种覆盖，单币种优先级高于全局默认。

2.2.1 点差规则列表（页面型）

功能描述

展示全局默认点差和各币种的单独点差配置，支持新增、编辑、停用操作。

前置条件

  • 无

页面布局

  • 顶部：页面标题 + 说明 + "新增币种点差"按钮
  • 公式说明区：平台汇率 = 原始汇率 × (1 + 点差比例)，优先级说明
  • KPI 卡片：规则总数、全局规则数、单币种规则数、默认点差值
  • 工具栏：搜索币种、筛选状态
  • 数据表格

页面元素

列名说明
规则类型全局默认（灰色标签）/ 单币种（蓝色标签）
适用币种全局默认显示"所有币种"，单币种显示具体币种代码
点差比例如 2.0%、0.8%
状态启用 / 停用
更新时间最近修改时间
操作编辑；单币种规则额外支持停用

操作流程

主流程——查看规则列表：

  1. 进入页面，展示全局默认规则（置顶）和所有单币种规则
  2. 可通过搜索和筛选缩小范围

分支流程——停用单币种规则：

  1. 点击"停用"按钮
  2. 弹出确认提示"确认停用该点差规则？"
  3. 确认后该币种回退使用全局默认点差

校验规则

  • 全局默认规则不可停用，不可删除
  • 同一币种不可重复创建规则

异常处理

  • 网络异常：提示"操作失败，请稍后重试"

UI 关联

  • PC 端：V7 原型「点差规则」页面
  • APP 端：不涉及

2.2.2 新增/编辑点差规则（页面型——子页面）

功能描述

新增单币种点差规则或编辑已有规则的点差比例和状态。

前置条件

  • 新增：点击"新增币种点差"按钮
  • 编辑：点击列表中的"编辑"按钮

页面布局

  • 独立子页面，包含：页面标题、返回按钮、编辑表单、操作按钮区、底部操作记录区

页面元素

元素说明
适用币种下拉选择，新增时可选，编辑时只读
点差比例（%）数字输入，支持 1 位小数
状态启用 / 停用

校验规则

字段规则校验时机
适用币种必选，不可与已有规则重复提交时
点差比例必填、≥ 0、最多 1 位小数提交时

异常处理

  • 币种已存在规则：提示"该币种已有点差规则，请直接编辑"
  • 提交失败：提示错误信息，停留在当前页面

UI 关联

  • PC 端：V7.1 原型「新增/编辑币种点差」子页面
  • APP 端：不涉及

2.3 数据源管理

模块概述

管理已接入的第三方汇率数据源，配置采集频率与优先级。主数据源优先使用，备用数据源在主源故障时自动切换。新数据源接入需联系开发团队。

2.3.1 数据源列表（页面型）

功能描述

展示所有已接入的数据源及其运行状态，支持编辑配置和测试连接。

前置条件

2.3.3 主备自动切换（机制型）

功能描述

当主数据源采集失败时，系统自动切换到备用数据源继续采集，保证汇率数据不中断。

触发条件

  • 主数据源连续 3 次采集失败

处理流程

  1. 主数据源采集失败，记录失败日志
  2. 连续 3 次失败后，系统自动切换到优先级次高的备用数据源
  3. 备用数据源采集成功后，后续采集任务使用备用源
  4. 同时触发"数据源失败告警"通知运营
  5. 运营修复主数据源后，可手动切回或等待系统下次尝试主源

规则说明

  • 切换判断基于连续失败次数，单次失败不触发切换
  • 所有数据源均失败时，系统保留最近一次成功采集的数据，不发布新汇率
  • 切换事件记录到变动日志

异常处理

  • 所有数据源均不可用：触发紧急告警，运营需手动介入

技术说明

  • 失败计数器在采集成功后重置
  • 切换动作写入系统日志，便于排查

2.4.2 定时采集任务（机制型）

功能描述

触发条件

处理流程

  1. 读取所有已启用数据源的配置
  2. 按优先级顺序调用数据源 API
  3. 获取所有已启用币种的 USD → 目标币种汇率
  4. 写入原始汇率记录表
  5. 与当前生效汇率对比，计算差异幅度
  6. 差异超过告警阈值时，触发异常告警

  • 连续失败触发主备切换（见 2.3.3）

2.6.3 异常告警触发机制（机制型）

功能描述

系统在每次采集完成后，自动对比最新原始汇率与当前生效汇率，超过阈值时生成告警并暂停该币种的自动发布。

触发条件

  • 每次采集任务完成后自动执行对比

处理流程

  1. 采集完成，获得最新原始汇率
  2. 计算与当前生效汇率的差异百分比：|(新值 - 旧值) / 旧值| × 100%
  3. 差异超过告警阈值时：

- 自动模式币种：生成"待处理"告警，暂停该币种的下次自动发布

- 固定模式币种：生成"固定模式提示"告警，仅提示不影响当前生效值

  1. 差异未超过阈值：不生成告警，正常流程

规则说明

  • 告警阈值默认 ±5%，运营可在告警页面修改
  • 自动模式币种触发告警后，该币种的自动发布被暂停，直到运营处理（确认发布或忽略）
  • 忽略后，下次采集如果差异仍超阈值，会再次生成新告警
  • 固定模式币种的告警仅为提示性质，不影响当前生效汇率

异常处理

  • 告警生成失败不影响采集流程本身

2.7 定时发布机制（机制型）

功能描述

系统每日 UTC 00:00 自动执行汇率发布，将最新原始汇率应用点差规则后生成新的生效汇率。

触发条件

  • 每日 UTC 00:00 定时触发

处理流程

  1. 读取所有已启用且为自动模式的币种
  2. 获取每个币种最近一次成功采集的原始汇率
  3. 查询每个币种当前生效的点差规则（单币种优先，无则用全局默认）
  4. 计算生效汇率：原始汇率 × (1 + 点差比例)
  5. 检查是否有未处理的异常告警：

- 有告警的币种：跳过，不发布

- 无告警的币种：写入新的生效汇率

  1. 固定模式币种：跳过，不发布
  2. 生成发布批次号，写入变动日志
  3. 旧的生效汇率标记为过期

规则说明

  • 发布频率：每日 1 次（UTC 00:00）
  • 固定模式币种不参与定时发布
  • 有未处理告警的币种不参与定时发布
  • 发布后所有业务系统查询到的汇率立即更新
  • 运营可通过"手动发布全部"按钮在任意时间触发发布
  • 同一批次发布的所有币种共享同一个批次号，在变动日志中可聚合查看

异常处理

  • 定时任务执行失败：记录错误日志，触发系统告警，等待下次手动触发
  • 部分币种发布失败：成功的币种正常生效，失败的币种保留旧值并告警

技术说明

  • 发布为原子操作，同一批次内的币种要么全部成功要么全部回滚（按币种粒度）
  • 发布完成后清除 Redis 缓存，业务系统下次查询获取最新值

2.8 币种停用联动（机制型）

功能描述

当币种管理模块将某币种设为停用后，汇率管理模块自动执行联动处理。

触发条件

  • 币种管理模块将某币种状态设为"停用"

处理流程

  1. 立即停止该币种的后续汇率采集
  2. 后续发布批次不再包含该币种
  3. 对外汇率查询接口默认不返回该币种
  4. 该币种的生效汇率状态标记为"因币种停用而失效"
  5. 写入变动日志（操作类型：币种停用）

规则说明

  • 变动日志、采集记录全部保留，不物理删除
  • 后台支持筛选"已停用币种"查看历史数据（只读）
  • 币种重新启用后，系统立即触发一次采集，成功后恢复正常流程

异常处理

  • 联动失败：记录错误日志，不影响币种管理模块的操作结果，后台提示运营手动处理

2.9 交叉汇率与逆向汇率（机制型）

功能描述

系统仅从外部数据源采集 USD 基准汇率（USD→EUR、USD→GBP、USD→JPY）。当调用方需要非 USD 基准的币种对汇率时，由汇率管理模块统一计算并提供，避免各调用方自行计算导致精度差异。

设计原则

  • 统一计算：所有非 USD 基准汇率由汇率模块集中计算，调用方不自行推导
  • 一致性保证：同一时刻所有调用方获取到的同一币种对汇率完全一致
  • 不落库：交叉汇率和逆向汇率为派生数据，不持久化存储，查询时实时计算
  • 可追溯：返回结果继承源 USD 汇率的版本号（snapshot_id），可追溯计算依据

计算逻辑

查询类型公式示例
直接汇率查表返回 USD→X 平台汇率USD→EUR = 0.9309
逆向汇率1 / (USD→X 平台汇率)EUR→USD = 1 / 0.9309 = 1.0742
交叉汇率(USD→TO 平台汇率) / (USD→FROM 平台汇率)EUR→GBP = 0.8000 / 0.9309 = 0.8594

查询接口统一返回格式

{
  "from": "EUR",
  "to": "GBP",
  "rate": 0.8594,
  "snapshot_id": "SNAP-20260508-0001",
  "derived": true
}
字段说明
from源币种 ISO 4217 代码
to目标币种 ISO 4217 代码
rate汇率值
snapshot_id汇率版本号（继承自源 USD 汇率发布批次）
derived是否为派生计算（true=逆向或交叉计算，false=直接发布的 USD 基准汇率）

规则说明

  • 调用方通过统一接口查询任意币种对，无需关心底层是直接查表还是派生计算
  • 交叉汇率不应用额外点差（点差已在 USD 基准汇率中体现）
  • 某币种停用时，涉及该币种的所有派生汇率同步不可查询
  • 源 USD 汇率缺失（某币种未发布）时，相关派生汇率查询返回无数据
  • 计算精度：保留 6 位小数，四舍五入
  • MVP 3 个非 USD 币种，可查询组合：直接 3 条 + 逆向 3 条 + 交叉 6 条 = 共 12 种

3.2 外部服务依赖

服务用途费用风险

  • 月度总成本约 $22

3.3 风险评估

风险影响应对措施
数据源服务中断无法获取最新汇率主备切换机制 + 保留最近成功数据
数据源返回异常数据可能导致错误汇率发布异常阈值检测 + 人工审核
汇率剧烈波动（黑天鹅事件）用户端价格大幅变动告警暂停发布 + 固定模式兜底
展示价与 PSP 结算价不一致用户投诉由结算/支付模块负责报价锁定（不在本模块范围）
API 调用额度耗尽采集中断监控剩余额度，提前预警

四、版本规划

4.1 当前版本（MVP）

目标：上线基础汇率管理能力，支撑多币种价格展示

功能范围：

  • 接入 1 主 + 1 备汇率数据源
  • 支持 USD → EUR / GBP / JPY 三个币种
  • 全局默认点差 + 单币种点差覆盖
  • 每日定时发布 + 手动发布
  • 自动/固定两种汇率模式
  • 异常告警与人工审核
  • 告警阈值可配置
  • 变动日志与批次聚合查看
  • 币种停用联动

4.2 后续迭代方向

方向说明优先级
多数据源智能比价自动选择最优汇率源中

自动化点差调整建议基于历史数据推荐点差低
结算汇率分层展示汇率与结算汇率分离高（业务验证后）

与支付网关汇率对比监控展示价与结算价差异中

五、数据与埋点

本模块为内部运营后台，暂无前端埋点需求。关键操作通过变动日志记录，满足审计追溯。

后续如需运营行为分析，可在以下节点增加埋点：

  • 手动发布操作频次
  • 告警处理响应时间
  • 固定模式使用频率

本模块不涉及终端用户行为埋点，故本章节省略详细埋点表。

六、权限与角色矩阵

本模块 MVP 阶段仅涉及"运营人员"单一角色，所有功能对运营人员全量开放，暂不做细粒度权限控制。

后续如需引入多角色（如只读查看者、审批者），再扩展权限矩阵。故本章节省略。
