## 一、概述

### 1.1 背景与目标

Looply 是面向美国市场的跨境二手电商平台，从二手奢侈品（包袋、首饰、配饰）切入。平台支持多地区本地币种定价，不同地区按本地货币定价。汇率管理模块负责管理所有有向币种对的平台汇率，数据源采集 USD 基准汇率，系统通过派生计算生成所有方向的中间价，每个方向独立配置点差并发布。

汇率管理模块是平台的**用户价格换算基础设施**，核心目标：

1. 从外部数据源定时采集原始汇率
2. 通过点差规则加工生成平台汇率
3. 每日定时发布，保证用户端价格稳定
4. 支持运营监控、手动干预与异常兜底
5. 提供完整的操作记录与审计追溯

### 1.2 不做什么

| 明确不做 | 原因 |
|----------|------|
| 金额换算计算 | 调用方自行计算：目标金额 = 源金额 × 平台汇率。汇率模块提供所有有向币种对的平台汇率（含派生方向），调用方不自行推导 |
| 金额格式化与展示 | 符号、千分位、小数点由前端/格式化服务负责 |
| 报价锁定 | 属于结算/支付模块职责 |
| 心理价修正 | 属于商品定价/营销模块职责 |
| 支付结算与财务对账 | 属于支付/财务模块职责 |
| 多汇率源智能比价 | MVP 后续迭代 |
| 自动汇率对冲策略 | MVP 后续迭代 |

### 1.3 用户角色

| 角色 | 说明 |
|------|------|
| 运营人员 | 通过后台管理汇率：配置点差、查看平台汇率、处理异常告警、设置汇率模式 |
| 系统（定时任务） | 每小时采集原始汇率、每日 UTC 00:00 自动发布平台汇率、触发异常告警 |

本模块为纯后台管理模块，无 APP 端，无终端用户直接交互。

### 1.4 核心场景

1. **日常运营**：系统每日自动采集并发布汇率，运营通过"平台汇率"页面监控当前状态
2. **点差调整**：运营根据业务需要调整全局或单方向点差，下次发布时自动生效
3. **异常处理**：采集汇率波动超过阈值时，系统暂停自动发布并告警，运营审核后决定发布或忽略
4. **手动干预**：市场剧烈波动时，运营可将币种切换为固定模式手动设定汇率
5. **问题排查**：通过各页面底部的操作记录回溯历史操作，支持订单核对与审计

### 1.5 全局页面流转

```
平台汇率 ──「设置汇率」──→ 设置汇率子页面（自动/固定模式切换 + 操作记录）
平台汇率 ──「历史」──→ 汇率历史子页面（该币种的发布历史 + 操作记录）
平台汇率 ──「异常告警数字」──→ 异常告警页面
平台汇率 ──「导出 CSV」──→ 导出当前筛选条件的数据

点差规则 ──「新增/编辑」──→ 点差规则子页面（编辑表单 + 操作记录）

数据源管理 ──「编辑」──→ 编辑数据源子页面（编辑表单 + 操作记录）
数据源管理 ──「测试连接」──→ 测试连接子页面（测试结果展示）

原始汇率 ──「导出 CSV」──→ 导出当前筛选条件的数据

异常告警 ──「编辑阈值」──→ 编辑告警阈值子页面（编辑表单 + 操作记录）
异常告警 ──「去处理」(自动模式)──→ 处理告警子页面（确认发布/忽略 + 操作记录）
异常告警 ──「去处理」(固定模式)──→ 处理告警子页面（恢复自动/忽略 + 操作记录）
```

**全局导航交互**
- 侧边栏菜单"异常告警"项旁显示红色数字 badge，数值为当前待处理告警数
- 待处理数为 0 时 badge 隐藏
- badge 数值在以下时机刷新：页面加载、告警处理完成、新告警生成

### 1.6 术语说明

| 术语 | 说明 |
|------|------|
| 基准货币 | 汇率换算的基准，Looply 统一使用 USD |
| 目标货币 | 需要换算到的货币（如 EUR、GBP、JPY） |
| 原始汇率 | 从第三方数据源采集的未加工汇率 |
| 点差 | 平台在中间价基础上叠加的调整比例 |
| 平台汇率 | 应用点差后实际对外提供的汇率 |
| 自动模式 | 币种跟随市场汇率 + 点差，每日定时自动发布 |
| 固定模式 | 运营手动设定汇率值，定时发布跳过该币种 |
| 采集 | 系统从第三方数据源获取原始汇率的动作 |
| 发布 | 将加工后的平台汇率推送给业务系统使用的动作 |
| 汇率版本 | 每次发布的唯一标识，格式：SNAP-YYYYMMDD-序号 |
| 交叉汇率 | 非 USD 基准的币种对汇率（如 EUR→GBP），由系统通过 USD 基准汇率派生计算得出，每个方向独立配置点差后发布 |
| 派生(derived) | 标记该汇率是否为系统计算得出（true=计算派生，false=直接发布） |
| 最近成功率 | 数据源最近 24 小时内成功采集次数 / 总采集次数 × 100% |

### 1.7 多语言 / 多国家策略

本模块为内部运营后台，仅支持中文界面，不涉及多语言。汇率数据本身以 ISO 4217 币种代码标识，天然支持国际化。

## 二、需求详细描述

### 2.1 平台汇率

#### 模块概述

平台汇率是运营日常使用频率最高的页面，展示当前对外生效的平台汇率。每日 UTC 00:00 系统定时发布，每个币种支持"自动"和"固定"两种汇率模式。

#### 2.1.1 平台汇率列表（页面型）

**功能描述**
展示所有已启用币种对的当前平台汇率，包括汇率模式、中间价、点差、涨跌幅、发布信息等，支持筛选、搜索和导出。

**前置条件**
- 至少有一个数据源已启用且采集成功
- 至少有一个币种已启用

**页面布局**
- 顶部：页面标题 + 说明
- KPI 卡片：生效币种对数、最近发布时间、发布方式、异常告警数（可点击跳转）
- 工具栏：搜索币种对、筛选模式（全部/自动/固定）、筛选状态（全部/生效/停用）、"显示已停用"复选框（勾选后以灰色禁用态展示历史停用币种对）、发布时间范围（默认近一周）、查询按钮、导出 CSV 按钮
- 数据表格 + 分页

**页面元素**

| 列名 | 说明 |
|------|------|
| 币种对 | 如 USD → EUR，tooltip：默认展示币种管理中已启用的币种组合，已停用币种对可通过"显示已停用"复选框查看 |
| 汇率模式 | 自动（蓝色标签）/ 固定（黄色标签），tooltip：自动=每日定时发布取最新汇率×(1+点差)；固定=运营手动设定值，定时发布跳过 |
| 汇率版本 | 如 SNAP-20260428-0001，tooltip：每次发布的唯一标识，格式：SNAP-YYYYMMDD-序号 |
| 中间价 | 最近一次发布时的快照值（含派生），非实时数据 |
| 点差 | 当前应用的点差比例，固定模式显示"-" |
| 平台汇率 | 当前对外生效的汇率值 |
| 涨跌 | 与上一次发布的变化幅度，绿色上涨/红色下跌 |
| 发布方式 | 定时 / 手动 |
| 发布人 | 系统 / 运营人员姓名 |
| 发布时间 | 最近一次发布的时间 |
| 状态 | 生效 / 停用 |
| 操作 | 设置汇率、历史 |

**操作流程**

主流程——查看当前汇率：
1. 进入页面，默认展示所有已启用币种对
2. 勾选"显示已停用"可查看历史停用币种对（灰色禁用态展示，标注停用时间）
3. 可通过搜索框、筛选条件和时间范围缩小范围
4. 查看各币种的汇率模式、平台汇率、涨跌幅等信息

分支流程——导出 CSV：
1. 设置筛选条件和时间范围
2. 点击"导出 CSV"按钮
3. 按当前筛选条件导出完整记录（不受分页限制）

**交互说明**
- KPI 区域"异常告警"数字可点击，跳转到异常告警页面
- 表格行 hover 高亮
- 分页：默认每页 10 条
- 时间范围默认为近一周（开始日期：7天前，结束日期：今天）

**异常处理**
- 数据源全部不可用时，列表仍展示最近一次发布的数据，KPI 区域提示"数据源异常"
- 导出失败：提示"导出失败，请稍后重试"
- 网络异常：提示"网络异常，请稍后重试"

**UI 关联**
- PC 端：V8.0 原型「平台汇率」页面
- APP 端：不涉及

#### 2.1.2 设置汇率（页面型——子页面）

**功能描述**
对单个币种对设置汇率模式（自动/固定）和汇率值。自动模式下展示当前中间价和点差计算结果；固定模式下运营手动输入平台汇率值。无变更时禁用保存按钮和原因输入框。

**前置条件**
- 从平台汇率列表点击"设置汇率"按钮打开

**页面布局**
- 独立子页面，包含：页面标题、返回按钮、基本信息区（币种对、当前平台汇率）、汇率模式选择区、变更原因输入区、操作按钮区、底部操作记录区

**页面元素**

| 元素 | 说明 |
|------|------|
| 币种对 | 只读，如 USD → EUR |
| 当前平台汇率 | 只读，展示当前值 |
| 汇率模式 | 卡片式单选：自动模式 / 固定模式，当前模式高亮 |
| 自动模式内容区 | 展示当前中间价、点差规则、计算后的平台汇率（均只读） |
| 固定模式内容区 | 输入框：固定平台汇率（数字，精度 4 位小数） |
| 变更原因 | 文本域，无变更时禁用（灰色背景） |
| 确认保存按钮 | 无变更时禁用（灰色、不可点击） |
| 操作记录 | 页面底部展示该币种的历史操作记录，支持筛选和分页 |

**页面状态变体**
- 默认态：展示当前模式对应的内容区，保存按钮和原因输入框禁用
- 有变更态：切换模式或修改汇率值后，保存按钮和原因输入框启用

**操作流程**

主流程——保持当前模式修改：
1. 打开子页面，默认展示当前模式，保存按钮和原因输入框禁用
2. 自动模式下为只读展示，固定模式下可修改汇率值
3. 修改后，保存按钮和原因输入框自动启用
4. 填写变更原因
5. 点击"确认保存"

分支流程——切换汇率模式：
1. 点击另一个模式卡片
2. 内容区切换，保存按钮和原因输入框自动启用
3. 填写变更原因
4. 点击"确认保存"

**校验规则**

| 字段 | 规则 | 校验时机 |
|------|------|----------|
| 固定平台汇率 | 必填（固定模式下）、大于 0、最多 4 位小数 | 提交时 |
| 变更原因 | 必填（有变更时）、最少 2 个字符 | 提交时 |

**交互说明**
- 无变更时：保存按钮置灰不可点击，原因输入框禁用（灰色背景）
- 有变更时：保存按钮和原因输入框自动启用
- 模式切换无需二次确认，直接切换内容区
- 页面底部展示该币种的历史操作记录，支持按操作类型、操作人、时间筛选

**异常处理**
- 提交失败：提示"保存失败，请稍后重试"，停留在当前页面
- 网络异常：提示"网络异常，请检查网络连接"

**UI 关联**
- PC 端：V8.0 原型「设置汇率 — USD → EUR」子页面
- APP 端：不涉及

#### 2.1.3 汇率历史（页面型——子页面）

**功能描述**
查看单个币种对的历史发布记录，展示每次发布时的中间价、点差、平台汇率和涨跌幅。

**前置条件**
- 从平台汇率列表点击"历史"按钮打开

**页面布局**
- 独立子页面，顶部显示币种对名称和返回按钮，下方为历史记录表格，底部为操作记录区

**页面元素**

| 列名 | 说明 |

| 中间价 | 发布时的中间价（含派生） |
| 点差 | 发布时应用的点差比例 |
| 平台汇率 | 发布时的最终汇率 |
| 涨跌 | 与上一次发布的变化幅度 |

**数据范围与分页**
- 默认展示最近 30 天的发布记录
- 支持分页，每页 20 条
- 支持按时间范围筛选

**异常处理**
- 无历史数据时展示空状态

**UI 关联**

- APP 端：不涉及

### 2.2 点差规则

#### 模块概述

点差规则决定了平台汇率与中间价之间的差值。支持全局默认点差和单方向覆盖，方向点差优先级高于全局默认。每个有向币种对（如 USD→EUR、EUR→USD）可独立配置点差。

#### 2.2.1 点差规则列表（页面型）

**功能描述**
展示全局默认点差和各方向的单独点差配置，支持新增、编辑、停用操作。

**前置条件**
- 无

**页面布局**
- 顶部：页面标题 + 说明 + "新增方向点差"按钮
- 公式说明区：平台汇率 = 中间价 × (1 + 点差比例)，优先级说明：方向点差 > 全局默认点差
- KPI 卡片：规则总数、全局规则数、方向规则数、默认点差值
- 工具栏：搜索币种对、筛选状态
- 数据表格

**页面元素**

| 列名 | 说明 |
|------|------|
| 规则类型 | 全局默认（灰色标签）/ 单方向（蓝色标签） |
| 币种对方向 | 全局默认显示"所有方向"，单方向显示具体有向币种对（如 USD → EUR） |
| 点差比例 | 如 2.0%、0.8% |
| 状态 | 启用 / 停用 |

#### 2.3.3 主备自动切换（机制型）

**功能描述**

**触发条件**

**处理流程**

2. 连续 3 次失败后，系统自动切换到优先级次高的备用数据源

**异常处理**
- 所有数据源均不可用：触发紧急告警，运营需手动介入

**技术说明**
- 失败计数器在采集成功后重置

### 2.4 汇率采集

- 工具栏：日期选择、币种筛选、来源筛选、数据源筛选、"显示已停用"复选框（勾选后展示已停用币种对的历史采集记录）、查询按钮

- 底部提示：颜色标注说明

**页面元素**

| 列名 | 说明 |
|------|------|
| 采集时间 | 数据采集/计算的时间点 |
| 币种对 | 如 USD → EUR，tooltip：默认展示币种管理中已启用的币种组合，已停用币种对可通过"显示已停用"复选框查看 |

2. 按当前筛选条件导出完整历史记录

  - 红色加粗：波动超过告警阈值（默认 ±5%），对应自动模式币种
  - 黄色加粗：固定模式币种的市场偏离超过阈值

#### 2.4.2 定时采集任务（机制型）

**功能描述**
系统按各数据源配置的采集间隔，定时从第三方 API 获取原始汇率数据。

**触发条件**
- 按数据源配置的采集间隔周期性触发（默认每 3600 秒 / 1 小时）

**处理流程**
1. 读取所有已启用数据源的配置
2. 按优先级顺序调用数据源 API
3. 获取所有已启用币种的 USD → 目标币种汇率
4. 写入原始汇率记录表

**异常处理**
- 单次采集超时（30 秒）：标记为失败，等待下次重试
- 数据源返回异常数据（如汇率为 0 或负数）：丢弃该条数据，标记为失败
- 连续失败触发主备切换（见 2.3.3）

#### 2.6.3 异常告警触发机制（机制型）

**功能描述**
系统在每次采集完成后，自动对比最新原始汇率与当前生效汇率，超过阈值时生成告警并暂停该币种的自动发布。

**触发条件**
- 每次采集任务完成后自动执行对比

**处理流程**
1. 采集完成，获得最新原始汇率
2. 计算与当前生效汇率的差异百分比：|(新值 - 旧值) / 旧值| × 100%
3. 差异超过告警阈值时：
   - 自动模式币种：生成"待处理"告警，暂停该币种的下次自动发布
   - 固定模式币种：生成"固定模式提示"告警，仅提示不影响当前生效值
4. 差异未超过阈值：不生成告警，正常流程

**规则说明**
- 告警阈值默认 ±5%，运营可在告警页面修改
- 自动模式币种触发告警后，该币种的自动发布被暂停，直到运营处理（确认发布或忽略）
- 忽略后，下次采集如果差异仍超阈值，会再次生成新告警
- 固定模式币种的告警仅为提示性质，不影响当前生效汇率

**异常处理**
- 告警生成失败不影响采集流程本身

### 2.7 定时发布机制（机制型）

**功能描述**
系统每日 UTC 00:00 自动执行汇率发布，将最新中间价应用点差规则后生成新的平台汇率。

**触发条件**
- 每日 UTC 00:00 定时触发

**处理流程**
1. 读取所有已启用且为自动模式的有向币种对
2. 获取每个方向的中间价（直接采集的 USD→X 或派生计算的逆向/交叉）
3. 查询每个方向当前生效的点差规则（方向点差优先，无则用全局默认）
4. 计算平台汇率：中间价 × (1 + 点差比例)
5. 检查是否有未处理的异常告警：
   - 有告警的方向：跳过，不发布
   - 无告警的方向：写入新的平台汇率
6. 固定模式的方向：跳过，不发布
7. 生成发布批次号，写入变动日志
8. 旧的生效汇率标记为过期

**规则说明**
- 发布频率：每日 1 次（UTC 00:00）
- 固定模式币种不参与定时发布
- 有未处理告警的币种不参与定时发布
- 发布后所有业务系统查询到的汇率立即更新
- 运营可通过"手动发布全部"按钮在任意时间触发发布
- 同一批次发布的所有币种共享同一个批次号，在变动日志中可聚合查看

**异常处理**
- 定时任务执行失败：记录错误日志，触发系统告警，等待下次手动触发
- 部分币种发布失败：成功的币种正常生效，失败的币种保留旧值并告警

**技术说明**
- 发布为原子操作，同一批次内的币种要么全部成功要么全部回滚（按币种粒度）
- 发布完成后清除 Redis 缓存，业务系统下次查询获取最新值

---

### 2.8 币种停用联动（机制型）

**功能描述**
当币种管理模块将某币种设为停用后，汇率管理模块自动执行联动处理。

**触发条件**
- 币种管理模块将某币种状态设为"停用"

**处理流程**
1. 立即停止该币种的后续汇率采集
2. 后续发布批次不再包含该币种
3. 对外汇率查询接口默认不返回该币种
4. 该币种的生效汇率状态标记为"因币种停用而失效"
5. 写入变动日志（操作类型：币种停用）

**规则说明**
- 变动日志、采集记录全部保留，不物理删除
- 后台支持筛选"已停用币种"查看历史数据（只读）
- 币种重新启用后，系统立即触发一次采集，成功后恢复正常流程

**异常处理**
- 联动失败：记录错误日志，不影响币种管理模块的操作结果，后台提示运营手动处理

### 2.9 派生中间价与有向币种对发布（机制型）

**功能描述**
系统仅从外部数据源采集 USD 基准汇率（USD→EUR、USD→GBP、USD→JPY）。系统通过派生计算（倒数/交叉）自动生成所有有向币种对的中间价，每个方向独立配置点差后发布为平台汇率。

**设计原则**
- 采集层不变：数据源仍只采集 USD→X 方向的原始汇率
- 派生中间价：系统自动计算所有方向的中间价（X→USD、X→Y），作为点差计算的基础
- 方向独立：每个有向币种对独立配置点差、独立发布平台汇率
- 一致性保证：同一时刻所有调用方获取到的同一币种对汇率完全一致
- 可追溯：所有方向的平台汇率继承源 USD 汇率的版本号（snapshot_id）

**派生中间价计算逻辑**

| 方向类型 | 公式 | 示例 |
|----------|------|------|
| 直接采集 | 数据源返回 USD→X | USD→EUR = 0.9235 |
| 逆向派生 | 1 / (USD→X) | EUR→USD = 1 / 0.9235 = 1.0828 |
| 交叉派生 | (USD→TO) / (USD→FROM) | EUR→GBP = 0.7921 / 0.9235 = 0.8578 |

**平台汇率发布流程**

每个有向币种对独立执行：
1. 获取该方向的中间价（直接采集或派生计算）
2. 查询该方向的点差规则（方向点差 > 全局默认）
3. 计算平台汇率 = 中间价 × (1 + 点差比例)
4. 发布为该方向的平台汇率

**查询接口统一返回格式**

```json
{
  "from": "EUR",
  "to": "GBP",
  "rate": 0.8647,
  "snapshot_id": "SNAP-20260508-0001",
  "source_type": "cross_derived"
}
```

| 字段 | 说明 |
|------|------|
| from | 源币种 ISO 4217 代码 |
| to | 目标币种 ISO 4217 代码 |
| rate | 平台汇率值（已应用点差） |
| snapshot_id | 汇率版本号（继承自源 USD 汇率发布批次） |
| source_type | 中间价来源类型：direct（直接采集）、reverse_derived（逆向派生）、cross_derived（交叉派生） |

**规则说明**
- 调用方通过统一接口查询任意币种对，无需关心底层中间价是直接采集还是派生计算
- 每个方向独立应用点差（不再是"交叉汇率不应用点差"）
- 某币种停用时，涉及该币种的所有方向平台汇率同步停用
- 源 USD 汇率缺失（某币种未发布）时，相关派生方向无法发布
- 计算精度：保留 6 位小数，四舍五入
- MVP 3 个非 USD 币种，有向币种对总数：直接 3 + 逆向 3 + 交叉 6 = 共 12 个方向

## 三、依赖与风险

### 3.1 上下游系统依赖

| 依赖方向 | 系统 | 依赖内容 |
|----------|------|----------|
| 上游 | 币种管理模块 | 已启用币种清单、币种启停事件通知 |
| 上游 | Open Exchange Rates | 主数据源，提供原始汇率 API |
| 上游 | ExchangeRate-API | 备用数据源，主源故障时自动切换 |
| 下游 | 商品系统 | 调用汇率查询接口获取生效汇率 |
| 下游 | 运费系统 | 调用汇率查询接口获取生效汇率 |
| 下游 | 购物车 / 结算页 | 调用汇率查询接口获取生效汇率 |
| 下游 | 支付路由 | 调用汇率查询接口获取生效汇率 |
| 下游 | 营销系统 | 调用汇率查询接口获取生效汇率 |

### 3.2 外部服务依赖

| 服务 | 用途 | 费用 | 风险 |
|------|------|------|------|
| Open Exchange Rates | 主汇率数据源 | ~$12/月（Developer 档） | API 限流、服务中断 |
| ExchangeRate-API | 备用汇率数据源 | ~$9.99/月（Basic 档） | 同上 |

**前置准备**：
- 两个数据源均需注册开发者账号并获取 API Key
- 月度总成本约 $22
- 需确认 API 调用额度是否满足每小时采集频率（Open Exchange Rates: 10,000 次/月，ExchangeRate-API: 30,000 次/月）

### 3.3 风险评估

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 数据源服务中断 | 无法获取最新汇率 | 主备切换机制 + 保留最近成功数据 |
| 数据源返回异常数据 | 可能导致错误汇率发布 | 异常阈值检测 + 人工审核 |
| 汇率剧烈波动（黑天鹅事件） | 用户端价格大幅变动 | 告警暂停发布 + 固定模式兜底 |
| 展示价与 PSP 结算价不一致 | 用户投诉 | 由结算/支付模块负责报价锁定（不在本模块范围） |
| API 调用额度耗尽 | 采集中断 | 监控剩余额度，提前预警 |

**目标**：上线基础汇率管理能力，支撑多币种价格展示

- 告警阈值可配置
- 变动日志与批次聚合查看
- 币种停用联动

本模块为内部运营后台，暂无前端埋点需求。关键操作通过变动日志记录，满足审计追溯。
